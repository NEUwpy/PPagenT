# PPagenT

**PPagenT 是一个面向可编辑演示文稿的 AI 制作系统：将用户稿件和演示要求转化为经过内容规划与视觉编排的原生可编辑 PPT，并通过检查—返工闭环保证内容忠实、表达清楚和视觉合理。**

2026-09-16 起按 [M1–M5 能力里程碑](docs/方向讨论/页面编排能力计划.md)推进，当前聚焦 **M1 内容规划，尚未通过**。已有运行器和真实 PPT 样本，不代表规划或制作质量成立。先证明每页讲什么及内容关系正确，再证明能制作出来、换稿仍然成立，之后扩展能力并产品化。

产品目标见[产品定义](docs/产品定义.md)，技术取舍见[产品目标与路径](docs/产品目标与路径.md)，执行从 [Harness 入口](harness/README.md)开始。Harness 是实现手段；[运行流程](harness/运行流程.md)维护两个检查点与返工。正常制作默认交付完整 PPT，M1 可单独审阅规划并用真实 PPT 反馈。旧 R0–R3、旧 M1–M5 与 A–H 保留历史，旧 API 生产线保留兼容。

当前 M1 灰稿实验使用根目录 `src/runner/gray-draft.mjs`，具体入口见[通用灰稿验证](docs/工作流/正式生成/通用灰稿验证.md)。它复用 provider、state 与 PPT 引擎，按“内容提炼 → 表达选择 → 实文测量与基础排版 → 灰稿 → 检查修订”运行，区别于 `src/runner/run.mjs` 的通用工具循环。生产工作台现在默认走这条灰稿线（上传稿件 → 五步规划与渲染 → 停在等待审阅，含步骤阅读器与运行对比），是同一 CLI 流程的图形入口。最新分区修订保留分支内条目、局部浅蓝制作说明及同排框线对齐；不绘制蓝区内部节点，不推进正式美化。根目录这轮代码与共享规则尚未迁移至 Harness 镜像，不能混用两个入口的能力说明。

结构库当前采用“一结构一份源设计，各 Skin 共用”的模式。35 个已审批结构已接入中性 Skin 的统一色阶转换；大中小保真适配仍为三个样板。修改范围、主色入口与验证边界见[当前结构架构](docs/产品定义.md#结构源设计与-skin-的共享方式2026-09-08)，预览见[统一转换记录](experiments/structure-unified-neutral/index.html)。

PPagenT 面向工作型演示，把用户内容整理为表达清楚、视觉合适、原生可编辑的 PowerPoint。第一正式场景是东北大学，目标是让设计经验可复用，而不是让每页都套结构图。

## 当前状态

兼容保留的旧生产线是内容导演编排、程序筛选候选、视觉导演选择、Native 生成与检查。它已支持已披露的文字加结构混合页，尚不是自主工具循环的 Agent Harness；正式 CLI 仍使用东北大学 Skin。

现行设计与角色规则集中到根目录 [rules/](rules/README.md)，通过索引按用途读取。暂定每个 Skin 一个颜色体系、绑定一套风格规则；多个 Skin 可复用同一套风格规则。当前中性 Skin 自动加载「杂志风」，东北大学 Skin 自动加载「麦肯锡式」六字段排版，可用于独立制作任务；中性 Skin 资产仍为 candidate，结构预览已接入共享转换，正式 CLI 仍限东北大学。规则拆分不等于已经实现通用图文、复合页或四类输入自动处理。

中性 Skin 与杂志风、东北大学 Skin 与麦肯锡式均已登记独立制作规则绑定，继续用仓库自建运行器（`src/runner/`）与当次实际配置的模型验证实际效果。独立制作入口已按需连接结构 Skill：通用组件跨 Skin 复用，适配则优先直接调用，不能直接套用则参考适配；项目库不适合时，关系图以 Archify 补充，数据图表以 Lieflat Charts 非商业试用补充；适用技能均不适合再自主编排；不强制每页使用结构，尚未证明跨稿稳定性。

## 入口

当前规划反馈及 M2 完整制作在任务中选择一种已有风格，不同时验证两套。选择「东北大学 Skin＋麦肯锡式」时使用六字段排版；结构按[大学结构入口](docs/工作流/正式生成/大学结构调用.md)复用原造型并适配区域。中性 Skin＋杂志风仍可显式选择。新入口的技术检查不等于整页审美验收。

独立制作的关系表达按[技能选择顺序](skills/references/selection.md)：项目结构技能优先，Archify 补充技术图示，Lieflat Charts 补充数据图表（当前非商业试用）。Skin 与绑定风格规则提供基础视觉；生成、编辑性和视觉检查仍须实际完成。

## 工作台使用与代码验证

安装 Node.js 20 或更高版本后：

```powershell
npm ci
npm run setup:workspace
npm run production:workbench
```

也可双击 `启动PPA生产工作台.cmd`／`启动PPA看板.cmd`。Provider 和密钥配置见[运行配置契约](docs/契约/运行配置信息.md)；真实密钥不进入 Git。

生产工作台默认走灰稿线：上传稿件 → 语义规划 → 表达选择 → 语义审稿 → 布局求解 → 灰稿渲染，停在等待审阅。每一步的提示词、规则快照、模型响应与程序检查可在步骤阅读器里点开；「对比运行」可并排两条运行逐步对照文件差异与灰稿页；停在灰稿后可在工作台直接续跑一轮修订。结构库、图片、图表与美化属于后半场，本线尚未接入。`启动PPA看板.cmd`（结构库与资产预览）未改动。

只读取独立制作所需规则，不启动模型或生成 PPT：

```powershell
npm run rules:load -- --profile generation --skin neutral-editorial-001
```

`npm test` 执行契约、程序测试和公开审计；本地有 `PPT源/` 时可额外运行 `npm run audit:local`。程序测试不能替代成品逐页视觉检查。

主要目录：`rules/` 管规则正文；`assets/` 管资产声明与实现（含候选）；`catalog/` 管目录数据；`src/` 管加载、编排与执行；`稿件/` 管原稿；`PPT源/` 是唯一原始 PPT 来源且被 Git 忽略。实验和历史文档不作为当前生成入口。
