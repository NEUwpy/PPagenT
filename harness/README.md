# PPT Harness 使用入口

PPagenT 的目标产品是专为 PPT 策划与制作服务的 Harness：Luna high 水平的模型 API，加上持久任务状态、上下文组织、工具执行、产物反馈、诊断返工及交付机制，共同完成真实 PPT。提示词是系统的一部分，单次模型响应不是产品完成单位。

## 从这里使用与维护

| 入口 | 用途 |
| --- | --- |
| [运行流程](运行流程.md) | 如何启动、推进、检查、返工、恢复和交付一个任务 |
| [角色与提示入口](角色与提示入口.md) | 总控与两个导演的职责，以及现行提示词来源 |
| [规范与能力索引](规范与能力索引.md) | 按需读取规则、技能、结构和执行能力 |

| [能力计划](../docs/方向讨论/页面编排能力计划.md) | 当前主验证问题与产物证据 |

这个目录是 Harness 运行资料的集中入口，也是新增通用运行流程、上下文交接方法和角色协议的维护位置。现有规则和资产通过索引引用，保持一份真源；不是要求执行者一次读完全部文档。以后若迁入正文或结构库，必须同步调用路径并撤除旧真源，不能维护两套副本。

## 当前状态与验证对象

当前在 Codex 等现有 Agent Harness 中，以实际设置的 `gpt-5.6-luna` / `high` 执行独立实验；这验证的是模型与宿主提供的工具循环、文件状态和反馈机制的组合，不是裸 API 单轮能力。项目旧正式 CLI 仍是受约束的模型请求生产线，不能因本目录建立或 Codex 实验成功，就宣称项目自身 Harness 已接入完成。

产品目标是让该等级的 API 模型在可复用 Harness 支持下完成任务，不依赖主任务的隐含历史、临场补答案或逐页代做。Codex 是当前可用的验证宿主和机制参考，不锁定未来 SDK。每轮记录实际使用的宿主能力及尚未迁入项目的依赖。

自主多轮是正常执行方式；不要求一次响应出成品，也不要求每一步由用户批准。用户审核的是 PPT 产物。任务失败后既检查提示与规则，也检查状态交接、工具可用性、反馈质量、审查执行和恢复机制，不能默认通过增加禁令解决一切。
