# PPT Harness 内容包

这是交给执行宿主的实际内容包。复制本目录后，流程、提示词、规范、配置和轻量检查工具都在包内读取，不需要返回父仓库找正文。当前用 Codex 项目中的 Luna high 执行；后续可以将同一内容包部署到其他 Harness，模型由宿主实际配置。

最初归拢保留了原文件字节。后续按用户要求维护统一提示协议与运行流程；共享正文仍从维护源同步，保证包内副本与维护源一致。外部原位置暂留以兼容现有生产入口，不另维护第二套规则。

## 目录内容

- `AGENTS.md`：执行约定。
- [体系架构与运行流程](运行流程.md)：当前架构图、职责协作、返工路径和实现边界；`产物审查.md` 保存审查方法。
- `角色与提示入口.md`：统一提示体系、内容/视觉角色职责与回归方法；`任务/新任务入口.md`：两套组合共用的启动模板。
- `docs/工作流/正式生成/生成任务提示词.md`：初模和完整制作的任务协议正文。
- `rules/`：内容组织、页面组合、排版、质量检查、角色执行协议、Skin 与排版体系的全部现行正文及加载清单。
- `skills/references/`：技能选择方法等通用规范正文。
- `docs/架构/`、`docs/工作流/正式生成/大学结构调用.md`：结构适配边界与调用说明。
- `assets/主题/`：规则加载需要的主题配置；`schemas/`：组合协议。
- `src/`：包内规则加载、语义检查与组合解析工具及依赖。
- `runs/`：每个任务的状态、输入、制作文件、PPT 和验收证据。
- `外部依赖.md`：外挂结构库、原生渲染与宿主工具的接入要求。

## 使用

先读 AGENTS.md 和运行流程.md。制作时直接读包内任务协议和相应规则，按需调用已接入的工具。规则可通过 `node src/tools/load-rules.mjs --profile generation --skin neutral-editorial-001` 输出；这条命令在本目录执行，不需要父仓库 npm 脚本。

当前初模不套品牌外壳，不自动加载完整 Skin 美化流程。保留双导演职责，内容提炼与宏观布局共同完成，多轮审查返工，交付可编辑 PPT 和实际渲染。

## 部署与维护

部署复制本目录，排除 `runs` 下旧任务、缓存和 node_modules；目标机器按外部依赖说明配置工具。目录中不包含密钥。包内代码片段出现的 `src/`、`assets/` 路径中，未随包带入的大型执行器和结构资产属于明确的外挂依赖，不默认为可用。

`内容包清单.json` 记录同步文件及 SHA256。`同步内容包.py` 仅供本仓库维护者重建发行内容，远端运行无需执行它，也无需父仓库。同步文件从原仓库维护源更新后重建；Harness 自有流程在本目录维护。先前文档中的历史研究、旧 CLI 和实验链接不是远端运行前提，当前执行方式以本说明和运行流程为准。

## Harness 工作方式

新任务在本项目运行，由宿主提供模型与工具循环，执行者读取本目录中的实际流程、提示与规范，持续完成策划、构建、检查、返工和交付。任务状态与产物保存在 runs，下一次对话从这些文件恢复，不把一次模型回复当成任务完成。结构库可外挂。当前使用 Codex＋Luna high，部署到其他宿主时仍使用同一套正文。

原文中的仓库相对路径和 npm 命令没有在本次归拢中改写。当前宿主可使用本说明列出的包内 Node 入口；其他大型执行器按外部依赖接入。目录归拢和内容一致性已校验，不等于所有旧命令已经可在远端直接运行。

已经具备可搬运的运行文档和轻量工具；完整远端 PPT 渲染环境仍需实际配置及验收，不能把文档包齐全当作部署完成。
