# PPT Harness 使用入口

PPagenT 的产品目标是可靠的可编辑 PPT 制作，Harness 只负责组织制作闭环。2026-09-16 起按 M1 内容规划、M2 端到端制作、M3 跨稿稳定、M4 能力扩展、M5 产品化推进；当前 M1 尚未通过。旧 API 保留兼容，旧 R0–R3 记录保留历史。

先读 [AGENTS.md](AGENTS.md)、[架构与运行流程](运行流程.md)、[角色与提示入口](角色与提示入口.md)。目标职责链为初步分页 → 页面构成规划 → 空间要求与布局候选 → 测量、灰稿及检查 → 美化与最终制作。四类资产为 Skin、风格、布局、逻辑与结构图，见[页面构成架构](docs/架构/页面构成与布局规范.md)。默认交付完整 PPT；初模仅在用户明确要求时作为交付终点。

```powershell
node src/tools/load-rules.mjs --profile generation --skin neutral-editorial-001
```

上述命令只加载规则。按当前职责加载所需规则和能力说明，保留相关内容关系，不默认装入全库或整套超级提示词；当前加载器和运行器的实际覆盖须分别核实。当前 M1 规划可单独审阅并用真实 PPT 反馈，M2 才验收完整制作；反馈和制作选择一种已有风格，记录输入与规则版本。

## 运行器

根目录工作台默认调用 `gray-agent.mjs`；旧 `gray-draft.mjs` 阶段链保留。实际入口见包内[灰稿验证说明](docs/工作流/正式生成/通用灰稿验证.md)，各入口不能互相继承续跑或交付能力。下列 `run.mjs` 示例仅属于通用运行器。

`src/runner/` 只拥有四件事：循环、状态落盘、工具派发、恢复。构建、字号/几何审计、规则加载、
来源核对调既有模块；结构与外部 Skill 尚未完整接入，其后续调用也应复用既有能力——这条边界写在代码注释里，别让它长成第二个 `workflow.mjs`。

```powershell
# 首次运行：读原稿建 state，跑完内容阶段与视觉阶段
node src/runner/run.mjs --input harness/runs/<任务名>/原稿.md --run-dir harness/runs/<任务名>

# 中断续跑：不重做已冻结的页面
node src/runner/run.mjs --run-dir harness/runs/<任务名> --resume

# 零模型重编译交付物（用于验证确定性，不调用模型）
node src/runner/run.mjs --run-dir harness/runs/<任务名> --replay
```

阶段闸门由**工具写下的状态字段**驱动，不由模型自述完成：内容阶段以 `finish_content` 冻结
（来源有遗漏即拒绝），视觉阶段以 `finish_visual` 收尾（每页必须是当前版本已通过）。
宿主依赖失败（缺引擎、缺浏览器）会记 `runtimeFailure` 并立即停止，不交给模型去补偿环境故障。

产物落在运行目录：`state.json`（唯一机器真源）、`state.md` / `content.md`（由它渲染）、
`blueprint.json`（实际被构建的蓝图）、`deck.pptx`、`qa/slide-NN.png` 与 `qa/montage.webp`（逐页预览）、
`tool-events.ndjson` 与各阶段 transcript（运行证据）。

## 内容包维护与部署边界

rules、部分 docs、配置及轻量工具由父仓库维护源同步；Harness 自有流程在本目录维护。`同步内容包.py` 重建包，`内容包清单.json` 记录镜像 SHA256；修改共享正文后同步，禁止两处分别维护。镜像正文里的相对链接会指向未随包搬运的证据（`assets/`、`experiments/` 等），这类链接逐字节保持源文、不改写，已逐条登记在清单的 `boundaryLinks` 里——包是给远端执行用的，不是导航用的。最初归拢是原字节复制，当前内容已随重构更新，不再将首次哈希当作永远冻结版本。

2026-09-24 使用 `同步内容包.py --docs-only` 更新说明镜像，不复制运行代码、规则、配置或产物。清单分别记录本次说明源哈希和其他文件原快照；未迁移的依赖与灰稿能力仍待处理。修改说明不能宣称完整包部署验证通过。

部署可复制本目录并排除旧 runs、缓存和 node_modules；执行不需要访问父仓库说明正文。大型结构资产、大学模板/执行器、PPT SDK 与字体仍是外部依赖，先核对实际接入。content/blueprint/state 的职责见运行流程，当前工具已有状态与阶段闸门，不表示具备通用工作流框架。目录完整不代表完整生产环境部署成功。

此前一次重建已修正镜像中的旧模型名称与总控职责表述，当时源哈希与镜像哈希一致。这是历史同步记录，不代表本轮灰稿修订已经同步。
