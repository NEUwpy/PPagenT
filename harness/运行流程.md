# Harness 架构与最小运行闭环

2026-09-30 当前生成线只有两大阶段：

    原稿 → 语义理解与分页 → 页面表达共同契约
       → 合法版式/结构候选 → JEV 选择 → 区域/槽位绑定 → 灰稿
       → Skin/风格/参数化结构 → 原生可编辑成品

页面表达和灰稿是一体两面。灰稿用于建设阶段直观检查；投入使用默认直接交付成品。两段共用来源、稳定 ID、关系和版本，不复制正文。

## 建设与使用

建设阶段由用户与 Codex coworker 完成规划、资产、程序和审阅。main 负责稿件到灰稿，home 负责灰稿到成品；home 可用模拟灰稿探索美化，再阶段性合并。Codex 视觉能力只用于建设。

投入使用阶段只有语义理解模型和 JEV。前者负责理解、分页、关系和内容填充；后者在程序提供的合法候选中选择。程序负责契约、来源、容量、参数、测量、几何、构建、检查和日志。当前 gray 入口已分离 JEV provider，完整成品链仍待验收。

## 当前入口

生产工作台 gray：`src/runner/gray-agent.mjs`；当前复用 `gray-plan-3`、来源绑定、实文测量、JEV 布局选择和渲染。每次模拟写事件与 trace，工作台从日志编译阶段状态和输入/输出。

旧 gray-draft、通用 runner、legacy 双导演和视觉表单只保留兼容/历史，不是新 MVP 主线。跨组比较/顺序、多图示、完整成稿和独立运行仍未通过；引擎缺实际字号/行盒证据时自动交付失败。视觉模型不属于生产目标。

## 返回路径

- 语义、分页、主次或关系问题：回共同契约。
- 内容到区域/槽位绑定问题：回映射或候选契约。
- 容量、参数或布局问题：回资产/程序或返回规划。
- PPT 对象、导出或字体问题：回构建环境。

所有返回保留首版、失败、修订、输入、输出和审阅状态。程序通过、日志完整、候选等待审阅和回放都不等于用户验收。
