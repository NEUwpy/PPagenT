# Harness 架构与最小运行闭环

2026-09-30 当前产品流程只有两大阶段：

    稿件 → 页面表达共同契约 → 灰稿编译检查
                         ↘ 受限选择与程序执行 → 原生可编辑成品

页面表达和灰稿是一体两面。灰稿用于建设阶段直观检查；投入使用默认直接交付成品。两段共用来源、稳定 ID、关系和版本，不复制正文。

## 建设与使用

建设阶段由用户与 Codex coworker 完成规划、资产、程序和审阅。后段可用模拟灰稿探索美化，再阶段性合并。Codex 视觉能力只用于建设。

投入使用阶段只有语义理解模型和 JEV：前者理解、分页、关系和填充；后者在程序提供的合法候选中选择。程序负责 Schema、来源、容量、参数、测量、几何、构建和检查。当前代码尚未完成 JEV 分离，按实际运行记录报告。

## 当前入口

工作台 gray：src/runner/gray-agent.mjs；当前复用 gray-plan-3、来源绑定、实文测量和渲染。旧 gray-draft、通用 runner、legacy 双导演保留兼容，不能视为新 MVP 主线。

当前限制：规划使用语义模型、布局选择使用 JEV；跨组比较/顺序、多图示和完整成稿未通过；引擎 v5 缺字号/行盒证据时自动交付失败。视觉模型不属于当前生产目标。

## 返回路径

- 语义、分页、主次或关系问题：回共同契约。
- 内容到区域绑定问题：回映射。
- 容量、参数或布局问题：回程序/能力或返回规划。
- PPT 对象、导出或字体问题：回构建环境。

所有返回保留首版、失败、修订、输入和审阅状态。程序通过、候选等待审阅和回放都不等于用户验收。
