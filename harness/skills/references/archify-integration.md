# Archify 在 PPagenT 中的边界

本技能为第二顺位，先按[选择规则](selection.md)判断项目结构库是否适合。用户明确指定时按本次任务执行。

PPT Agent 先理解整稿和编排页面，再决定是否需要图。交给本技能的是图示任务：本页论点、必须保留的实体/关系、可用区域、Skin/字号要求、编辑要求。不要为了使用本技能反向构造整份技术稿，也不要将独立网页替代所需的完整 PPT 页面。

PPT 任务的闭环：选型 → Archify 结构化图示与校验 → 原生 PPT 转换或重建 → 当前 Skin 和区域适配 → 完整页面渲染验收。记录上游节点/关系与 PPT 对象的对应，才能判断图示实际被利用。忠实重建属于 adapted-native，不等于原样转换器已支持所有 Archify 图类型。原型可按图类型实现，遇到未支持的路径/文字特征要明确报告。

用于需要架构、流程、时序、数据流或状态图的任务，按类型加载上游 Skill 及必要 schema/example。普通杂志风文字排版不必加载它；已有适配的原生 PPT 结构仍可直接调用。

上游包固定在 registry 指定 commit，保留 MIT 与原作者声明。不要运行不受控更新或直接修改 vendor；版本变更先作为独立候选复验。上游 check-update 只提示更新，不等于升级授权。

事实来自稿件或当前代码证据。目标流程须明确写为目标，不把概念图当成已实现运行链。

`deliver` 的成功只说明图示文件通过规定检查；`visual-check` 记录浏览器实际渲染；还需看图判断可读性。不得用失败后残留的旧 HTML 宣称当前候选成功。

Archify 的交付是 HTML/SVG 等图示，不直接生成原生可编辑 PPTX。HTML 的交互能力不随静态 SVG/PNG 进入 PPT。若 PPT 要求可编辑节点与文字，应经过另行验证的 Native 转换，或用项目原生结构重建并复核语义和视觉。当前没有完成这种转换器，不能把整张图片或单个 SVG 称作原生结构。

外部技能按任务范围使用，它的默认视觉风格不覆盖用户指定的中性 Skin／杂志风。若需换色，应走它支持的样式入口并重新验证；无需为了使用它替换现有合适结构。

已验证的局部例证见 `experiments/diagram-in-ppt-luna-09/REPORT.md`：Luna 读取 Archify sequence 的参与者和消息，再重建原生 PPT。该三页监督试验经过最终 PPT 渲染检查；构建脚本含页面专用位置，不是公共适配器，也不证明无监督路由稳定。
