# 最小产物审查与返工

实际渲染与基础检查是闭环本身，不推迟到优化阶段。当前由执行者切换检查视角即可，不要求独立 Reviewer、多轮会审或重复报告。检查实际文件，不能照抄制作计划的通过声明。

## 必查内容

| 对象 | 检查什么 |
| --- | --- |
| 实际文字与图示含义 | 对照原稿保留事实、必要条件、对象、时间与统计口径；连接线、分区和坐标轴表达的关系本身须有依据 |
| 原生对象 | 文字与生成的图形可编辑，不能用整页截图冒充；文件能导出并读取 |
| 实际逐页渲染 | 文字可读，无明显裁切/非预期遮挡/连线穿字，**无孤立单字或单标点独占一行的错误断行**，关系端点正确，主次与有效内容分布合理 |
| 最终版本 | 检查证据对应最新 PPT，修改后重新渲染受影响页，最终预览全页齐全 |

来源核对优先关注页面主张、数字、条件和图示关系；需要解释疑点时附必要短引文或位置，不要求为每句填写证据矩阵。贯穿约束不能画成事后步骤，汇总统计不能画成个体过程，规则说明不能充当稿件事实。

使用当前可用工具检查实际文字、形状、字号和几何；工具报告只覆盖其检查范围。不能用自行登记的角色值证明实际样式正确，也不能把程序零告警当成语义或审美通过。原稿逐字完整仍需检查提炼页是否改错意思。

**断行有机器判据。** 容量预检（`fitChineseTextToFrame`）算的是「它以为能排几行」，引擎排出来的是另一回事；拟合偏乐观时引擎会多分出一行，多出来的那个字或标点就独占一行。`qa/*.layout.json` 的 `element.textLayout.lines` 记的是引擎排完之后的真实行盒，所以这件事可机器判据：`auditRenderedLineBreaks`（`src/tools/audit-rendered-typography.mjs`）比对拟合行数与引擎行数，并对宽框内的孤立单字/单标点报警，已并入 `auditRenderedDeck`。逐页看图仍是必要的人工复核，但它管的是门禁看不到的语义与审美，不再需要靠肉眼去发现断行。2026-09-12 R1 的缺陷、根因与修复见 `runs/20260912-r1-thin-runner/审查记录.md`。

## 记录与返工

在 state.md 简记问题所在页、现象/证据、返回层及复核结果，链接已有工具回执即可。无须复制出独立角色报告、字号报告和几何报告全文；工具必要输出原样保存。初次最终核查仍覆盖全稿，不能只看上一轮问题清单。

内容/关系错误回内容导演；区域/容量/阅读关系错误回蓝图；导出或对象错误修复构建。区域与页数可调整，不能为保留原布局删掉条件或压成难读文字。连续同类问题无改善时改变策略；遇到实际阻塞保留候选，不假报完成。

复杂的独立审查、全面主张矩阵和批量统计可在 R1 后按真实失败优化。历史 E 的错误 APPROVE、F 的来源审查以及 H 的连线缺陷继续作为反例，不把已有审查材料变成每次任务的强制审批链。
