# 运行记录约定

每个新任务使用唯一目录。最小产物职责以[运行流程](../运行流程.md)为准，不预建复杂 Schema：

- 原稿或输入引用：保存原始内容与演示要求。
- state.json / state.md：`state.json` 是唯一机器状态真源（运行器原子写，不手工编辑）；`state.md` 由它渲染，含目标、输入、候选文件、实际发现、下一步与中断位置。检查摘要可直接记录在 state.md，不强制另写验收报告。
- content.md：一级标题为页面，实际内容块有稳定 ID 和必要来源。**由 state.json 渲染，不是可手工编辑的真源**；每项列两份正文——**上屏稿**由模型在被引用来源的基础上提炼撰写，**逐字来源**由程序按 sourceIds 从原稿回填、是保真检查的比对证据。提炼可以改写文字、调整顺序、合并拆分，但不得改变原意（[内容组织](../../rules/内容组织.md)）；机器只能查出编造的数字与引号内容，**查不了**加限定条件、弱化语气、换同义词、中文数词编造，仍需人看。
- blueprint.json：**实际被构建的那份**蓝图，引用页面与内容块，记录区域、表达、阅读关系；不复制正文。与模型的意图不一致时以它为准。
- deck.pptx 与逐页预览（`qa/slide-NN.png`、`qa/montage.webp`）：证据必须对应交付文件。
- 运行证据：`tool-events.ndjson` 与各阶段 transcript（`content-transcript.json` 等），工具回执原样保留。
- 逐页审查记录（如 `审查记录.md`）：首版/自修/外部干预分开记账，写清未解决问题。可选，但没有它时未解决问题只存在于对话里。

布局实文草稿可利用构建过程预览，不要求另交一套初模。保留失败、首版、自修与外部干预差别，不用覆盖文件制造成功。候选变化或中断前更新状态，恢复时核对实际文件。

旧 runs 保持原结构与文件名，其结论只适用于当时条件。20260910-magazine-regression 的 A–H 结果是历史参考；不自动接着它推进新重构。Git 忽略的产物需在交接时单独核对，保存文件不等于已提交或验收。

20260912-r1-thin-runner 是自建运行器的首个完整闭环样本（交付成立；首版的断行缺陷已修复并补上机器门禁），可作历史失败及修订的对照基线，不继承为现行 M1–M5 通过。

20260913-r1-content-relations 与 20260913-r1-revision 是**同一份短稿**的两次重跑，必须成对看：前者是补完内容提炼与关系表达后的**首版**（暴露出「一个区绑多条时渲染器只画第一条」的静默丢件缺陷），后者是加上方案结构闸门后的**修订版**（两条关系缺陷已修好、逐页无丢件，但新暴露一页主区空掉的基础布局问题）。修订版来自改代码，属**外部工程干预**，不计入自主修订；两版模型相同但采样不同，不能直接当作闸门有效的证据——闸门那次一次都没触发。
