# 长提示迁移核对与机制证据

本记录不替代 PPT 复验，不把推测写成根因结论。A 的旧 v3 正文为 4,128 字符；B 的主要流程、任务协议与六份规则正文合计 25,165 字符，尚不含工具文档。这是文件字符量，不是实际 token 或注意力测量。更长及更多来源是实验变量，不能直接断言“模型记不住”。

## 已执行的机制探针

`role-override-probe.mjs` 从仍可读的历史修订脚本提取原 addText 函数。它先建 roleSpec，再执行 `{...roleSpec, ...opts}`，并将合并结果登记为 roleRegistry。传入 body 与 size=30 时，实际样式和登记都变为 30；独立按规则 17 检查才发现失败。

因此，登记表适合回答“对象用了什么”，不能充当“规范允许什么”的唯一依据。检查还需要判断对象的实际文字职责，否则把正文改名为展示角色仍可能通过纯数值检查。当前规则已经要求独立对照；接下来要根据三组实际执行判断缺口在加载、工具执行还是检查落实，避免再重复增加同义句。

## 对照后的判断

- A 本轮未通过，C 保持旧正文无损分阶段也未通过。当前证据不支持“只要恢复长提示就会成功”，也不支持“拆分本身造成失败”。历史通过版本保留为质量参照。
- B 与 A 不只是文件组织不同，因此 B 的任何失败必须结合回执诊断。
- D 用独立字号检查反馈后修到数值通过，但整页仍有关系与换行失败。这是已观察到的机制改善，不能当成完整质量恢复。
- E 第一轮独立审查驱动 B 候选修订，部分关系与无依据内容得到修正，同时出现新的字号与断行问题；第二轮独立审查再次返回 REVISE。审查是持续闭环，不能只复查旧问题是否勾销。
- 主任务外部复核仍发现独立审查漏掉的来源边界问题。当前审查回执会遗漏错误，角色独立本身不足以保证真实通过。
- 每个条件只有一个独立生成样本，E为接续返工；不能计算成功率或声称跨稿稳定。下一步应针对证据不足处设计最小复验，不批量堆更多同条件样本。
- F在相同候选上发现综合审查遗漏的来源具体化；它同时改变了新上下文、专注来源的范围与显式引文方法，不能把改进全部归因于某一句提示。E第三轮对revision-02错误判通过，而实际字号工具仍有普通语句违规；这一同文件反证足以说明当前综合审查不可靠。

## 当前能定位的失效链

| 环节 | 已有证据 | 可以得出的结论 |
| --- | --- | --- |
| 规则正文 | 当前杂志风明确禁止自设字号、quote角色与逐对象覆盖 | 不能将违规归因于规则未写；是否逐项记住不能由读取日志证明 |
| 构建参数 | 历史真实函数机制探针允许 opts 覆盖 roleSpec，登记表跟着覆盖值变化 | 规范期望与实际值必须来自不同依据；自登记不是独立验收 |
| 自动检查 | 字体族检查与包完整性通过时，A/B/C仍有实际字号错误 | 工具检查范围与质量声明不匹配，零告警并非全规范通过 |
| 工具反馈 | D读取实际PPTX字号失败并自主修正至通过 | 可机器判定的硬约束应形成实际回执，而非只有反向提示 |
| 自动缩放 | autofit_probe.py 在C实际PPT发现105个文字体带 fontScale<100000；D与E revision-02未发现此类显式设置 | 设定字号与自动缩放需要分别检查；现有实验font_gate只查设定值，不能声称覆盖有效显示字号 |
| 审查与返工 | E能修掉反馈问题，也会漏检并引入新问题 | 复审需覆盖新版本全稿；独立审查本身仍须被验证 |

这些结论不要求针对本稿增加版式答案。后续候选流程要把工作要求、原稿来源、样式期望、实际产物与审查证据分清，再在新冻结条件中检验。实验报告不是第二套生产提示。
