# 中性杂志风流程复现

当前主验证问题：把已有效的长提示转成分阶段、多轮的 PPT Harness，能否保持原有完整成品效果？先验证中性杂志风，成功后固化共用流程，再接麦肯锡式。既有 M1 未关闭，但不并行扩展其他能力。

## 对照条件

| 组 | 输入变化 | 目的 |
| --- | --- | --- |
| A-long | 旧 v3 完整长提示 | 在当前工具环境重建基线，不把历史成功当本轮成功 |
| B-split | 冻结的现行 Harness 包＋共享规则＋中性杂志风配置 | 测试当前完整体系；与 A 存在新增规则、解析器及配色细节等混杂，不能把全部差异归因于拆分 |
| C-staged | 旧 v3 原字节分成六片，按策划、绘制、审查读取 | 隔离“分阶段提供上下文”的影响，拼接字节与 A 输入一致 |
| D-gated | C 的原文分阶段流程，新增只读独立 PPTX 字号门槛；页码固定13档 | 根据 C 的实际字号偏离测试“真实工具回执驱动返工”，不提供该稿页级答案 |
| E-review-cycle | B 最终候选接独立审查上下文，再将审查回执交回制作Agent | 测试通用制作—独立审查—返工机制；是有系统反馈的修订，不是新冷启动 |

共同条件：同一份“为什么做 PPagenT”原稿，13 页，gpt-5.6-luna / high，同一宿主通用制作工具。均允许自主多轮调用与修订，分别保留首版和最终 PPT、逐页渲染、自审与读取记录。13 页仅为本次对照控制，不成为产品固定页数。未向执行者提供历史成品、专稿脚本或页级修法。子 Agent 使用空历史启动，仍可能受共同宿主/技能默认影响，不宣称完全沙箱隔离。每组仅一次，不能据此计算可靠成功率；先根据证据选择必要复验。

输入冻结见 input-hashes.json；C 的 manifest 记录字节一致性。冻结后不随共享规则更新。

## 已查明与待验证

- 历史记录支持：规则加载后仍出现自设 quote 字号与不实自审。不能仅解释为规则缺失。
- 当前历史任务的构建脚本已被后续修订，`roleSpec` 后仍合并任意 opts，具备覆盖角色样式的通路；这证明机制允许覆盖，不证明每个违规对象都由此产生。旧版本原始执行快照不足时明确为未知。
- 已执行 `role-override-probe.mjs`：抽取现存历史脚本真实 addText 函数，以最小 SDK 文字接口替身调用。body 的 17 档被 opts.size=30 覆盖，函数不拒绝，登记表同步登记 30；独立对照规范 17 判失败。结果见 `role-override-result.json`。这验证构建参数与自登记的共同错误通路，不是 PPT 渲染或历史因果完整证明。下一轮改进应使检查期望值来自独立规范，同时检查文字实际用途，防止换角色名绕过。
- 现行提示强制组合解析器，旧 v3 自主决定区域；现行解析器不支持 annotate。是否损伤自然内容高度与图文协作，须看本轮行为和产物，不能先判定。
- 现行 generation 输出与 Harness 协议并非同一入口，角色 profile 也不等价；需检查实际完整读取与依赖，而非仅以配置存在判断执行成立。
