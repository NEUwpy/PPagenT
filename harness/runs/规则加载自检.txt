# 内容组织

适用范围：独立制作任务与正式内容导演。具体输出协议由当前角色决定；本文件不指定资产、坐标或风格。

1. 通读完整输入，先确定演示目的、叙事顺序以及每页职责、核心信息和支持内容。普通文档标题不天然等于幻灯片页界；遵守用户明确要求保留的内容与页序。
2. 可以改写文字、调整顺序、合并拆分，但不得改变原意。优先级为来源真实性、原稿关系与重要内容完整性、全稿叙事、正式字号下容量，最后才是现有表达能力的便利性。
3. 保留必要条件、证据限定与论证关系。产品设想仍是设想，概念分数或示例仍是比喻，不改写成测量结果或已验证指标。不得虚构事实、数据、素材、个人经历或组织背景。
4. 不为凑对称、填满容器或提高结构命中率增加节点、分点和字段。不要添加无信息英文、泛化口号。真实英文术语保留为内容。
5. 先判断内容，再选择表达。一页可以只有文字，也可以由相互配合的多个区域组成；只有关系本身承担语义时才使用结构图，不强制每页一种结构或固定页型。
6. 开场、案例、论证、方法和收束承担不同职责时合理分页；不把整章压成巨型列表，也不为增加页数重复内容。内容过多先删除冗余、重组或在任务允许范围内拆页，不能牺牲关键事实。
7. 比较维度应对应，指标与单位、解释靠近且语义完整。流程的输入、输出、调用、分支和反馈关系不能因简化被改变；箭头方向必须忠实。
8. 图片只有在输入提供或确有可靠来源需要时使用。不得为填充版面编造素材，无图稿件可以完全不用图片。图片、表格或截图中的重要证据信息不得随意丢弃。

# 页面组合

适用范围：独立制作的整页规划。Skin 提供主题与固定外壳，本文定义共享的信息组织方法，绑定的排版体系定义视觉表达。正式候选选择器仍遵守其输出 Schema，不因本文获得自由绘图权限。

## 绘制前的页面计划

先理解整稿要回答的问题、支持判断的论证及其限制，再决定页面序列、每页职责与核心命题。内容组是这一过程的结果，不把原文段落、组数或模板槽位当成页面骨架。每组保留稳定 ID 和来源映射，允许忠实提炼；主题单列。区分事实、局部解读、综合判断、边界与行动，角色随稿件而定，不要求每页凑齐这些种类。

生成一版实文结构草稿，使用拟交付页面的真实文案，呈现证据与解释如何对应、哪些共同支持结论；不能用占位词代替内容。先检查页面是否完成其职责，再检查来源保真、实际文字容量和阅读顺序。选择媒介与布局时，让信息关系变成可见的组织：同等对象才共用并列层级，顺序编号只表达真实步骤，条件与对应动作相连，边界附着于其约束的判断。表格、相邻文字或图示均可；在计划中声明关系不代表画面已表达关系。检查由执行者完成，不要求用户逐步批准。

独立试点的 `src/composition/content-stages.mjs` 提供 `prepareContentDraft` 与 `bindExpressions`：前者检查原文完整归组，后者要求针对当前内容哈希的复核记录，并把表达选择绑定到原有组。每组正文从已复核产物读取；选择结构不能吞并其他解读和边界组。其检查不等于语义或视觉通过，原文不变模式也尚未覆盖摘要改写。正式生产线没有自动接入此试点。

先写 `composition-intent.json`，再建立图表、结构和文字对象。文件格式为 `{ "pages": [{ "pageId": "P1", "compositionIntent": {...} }] }`，每个正文页记录一项；封面、目录和结束页沿用 Skin。单页字段格式见 `schemas/composition-intent.schema.json`，用 `node src/tools/check-composition-intent.mjs <文件路径>` 检查。此为独立制作的语义计划，按 pageId 对应页面；不直接塞入正式 CompositionPlan 的封闭 Schema，不替换其合法候选和槽位协议。

- `topic`：本页要让读者理解的主题或有依据的判断；`topicPlacement`：使用 Skin 的哪个现有标题角色。区分章节标题与主题句，不机械重复。
- `groups`：每组的 `id`、`role`（analysis/interpretation/context/annotation）、`message`、`sourceRefs`（原稿章节、段落或表格）、`emphasis`（primary/secondary/supporting）和 `medium`（text/table/chart/structure/image）。同等重要的比较对象可共同构成一个 primary 分析组。
- 解读组用 `relatesTo` 指向分析组。简要发现、关键数字和详细解释可组成同一解读组，不强拆成三张卡片。没有新增意义的复述不建立独立组。
- `relations`：显式记录组间逻辑，格式 `{type, from:[组ID], to:组ID, meaning}`。type 为 comparison（比较）、sequence（递进）、conjunction（同时成立）、support（支撑）、cause（有依据的因果）、decomposition（分解）、condition（条件与行动）。meaning 说明这条关系的实际含义，不用“左侧/下方”代替；关系不自动要求画箭头。每组至少参与一条关系，单组页除外。旧计划可继续做格式检查，新执行入口要求完整关联。
- `composition`：用组合树记录哪些组相邻、共享行列或附着于相关证据；`readingOrder` 写组 ID 顺序；`alignment` 写共同起线、比较基线等实际关系。
- `fitStrategy`：说明本页最长文字和主图的容量安排，哪些区域可扩展、何时更换组合。结构容量从 guide/构建接口读取，不另填猜测的最小尺寸或视觉重量数字。

计划决定信息关系，具体尺寸在实际字体、Skin 正文区和组件容量约束下求得。发现容不下时可以回到计划调整，不把第一次选定的主图位置当成不可改变的前提。

## 少量组合方法

组合树的叶子为 `{ "groupId": "分析组ID" }`，分组为 `{ "op": "row", "children": [...] }`。一个内容组只放一次，跨组关系通过 relatesTo 表达，不复制正文。

| 操作 | 适用关系 | 排列方法 |
| --- | --- | --- |
| row | 主分析与就近解读、同口径比较 | 相邻分栏，共享起线；按可读宽度分配面积，不默认等宽 |
| column | 总体与分解、阶段与证据 | 上下连续组织，组内自然高度，避免将短句拉成大空框 |
| grid | 同等重要、字段一致的对象 | 共用列与基线；网格不意味着每格必须有卡片底色 |
| annotate | 图中局部发现、节点对应说明 | 首个子项为被解释对象，其余说明就近附着，避开文字与关系线 |

方法可嵌套。先用最少的分组表达真实关系，不为使用操作而添加内容。窄侧栏和底部横带是 row/column 的一种结果，不是必备槽位；局部标注也不意味着覆盖主图。

## 逻辑组合范例

范例规定对应关系，不指定图在左右或固定比例。原稿没有相应信息时不补造槽位。

| 页面任务 | 语义组织 | 可用组合 |
| --- | --- | --- |
| 比较决策 | 同口径比较与差异解释，共同支持带条件的选择 | column(row(比较证据, column(差异解释, 选择依据)), 适用边界) |
| 过程与门槛 | 过程表达递进，门槛解释何时推进，例外对应处置 | row(column(过程, 阶段证据), column(门槛, 例外处置)) |
| 多证据论证 | 各证据先配局部解读，再共同支持综合判断 | column(row(column(证据A, 解读A), column(证据B, 解读B)), 综合判断) |

内容组的逻辑与媒介分开。比较可用表格、图表或同行文字；过程图不因有造型就自动获得最大面积。证据与解读的归属先确定，再选择视觉表达。

## 从组合计划执行

独立生成使用 `src/composition/resolve.mjs`，不继续调用 `experiments/layout-reservation-pilot/regions.mjs` 的固定图文预留函数。该入口已能执行嵌套 row/column/grid；annotate 的实际锚点解析尚未实现，调用会明确拒绝，不能假装已支持覆盖或绕排。

```js
import { resolveComposition, buildComposition } from './src/composition/resolve.mjs';
const resolved = resolveComposition({
  pageId, intent: compositionIntent, bodyFrame: skin.bodyFrame,
  contracts, // 每组 {minWidth, minHeight}，含真实文字、标签、内边距的可读容量
  style: {gap: 28, innerGap: 20}, // 本次视觉语法的间距，不是固定分区比例
});
const receipt = await buildComposition({resolved, builders});
```

每个 `builders[groupId]` 接收 `{group, frame, relations}`。结构、图表、表格和文字均从这里取得所属组 frame；结构需要组标题时，从该 frame 内扣出标题，再将子区传给构建入口。不要在 builder 外另写一套组级坐标；组内仍由相应构建器排字和绘图。保存 resolved 与 receipt，渲染后对照实际对象复核，回调本身不能保证对象不越界。

容量先自底向上计算，再自顶向下分配。row/column 可用 `weights` 分配满足最小容量后的剩余空间，逐项对应 children；不提供时均分剩余空间，不意味着媒体等权。grid 可声明 columns，各格共享尺寸；节点 gap 可覆盖视觉语法的默认间距。容量取自组件约束或本稿实际字体试排，不把猜测尺寸当成已测量结果。

`COMPOSITION_RECOMPOSE_REQUIRED` 表示当前组合不适用：返回语义计划调整分组、嵌套、媒介或允许的分页，再重新解析。不降低正文角色、不删除条件，也不在失败后绕过入口画一套固定矩形。组合入口只约束组级几何与执行顺序，事实、图内排字和视觉关系仍须看最终渲染。

例如趋势与原因共同支撑一个判断：`column(row(趋势分析,趋势解读),row(原因分析,原因解读))`。若完整比较表需要全宽，则可用 `column(比较表,决策解读)`。这两个例子规定对应关系，不规定固定比例或每页必须存在的元素数量。

## 从关系确定主表达

编排前简记：本页判断、支持依据、依据之间的关系、最直接的表达。按本稿关系选择，不按页型清单凑数量：

| 内容关系 | 排列方法 | 读者应直接看到 |
| --- | --- | --- |
| 对象比较 | 相同字段共享列、基线、单位或坐标尺度；标签紧凑、依据充分展开 | 同口径差异及其意义 |
| 条件与决策 | 条件与所需依据逐项对应，动作放在相邻位置；共用动作可合并但归属明确 | 满足与不满足分别怎样处理 |
| 责任与处置 | 角色与负责动作就近；发生分歧或失败的处置紧邻关口 | 谁确认、谁复核、例外怎么办 |
| 能力或阶段递进 | 阶段配本阶段特征及进入下一阶段所需凭据 | 阶段变化与推进条件，不只是三个名称 |
| 并列类别 | 用共同起线、自然行高组织类别及说明；数量多时采用行列 | 各项各自作用及相同地位 |
| 定量证据 | 根据比较、趋势、构成或分布选择数值编码，标明单位、口径及来源 | 支持观点的差异、变化或异常 |

趋势图共享时间轴；原因、构成或驱动分解须让类别与整体分母对应。窄色段容不下标签时外置并连回，不能缩小到难读。方案比较可从少量对象、关键维度开始，逐格按实际行数给行高；阶段或行动计划让阶段、责任、交付与进入条件同行或同列，回退指向真实返回点。评估指标与进入条件分清，数量、比例、首次响应和结案等口径不能在压缩文案时互换。

一个问题可由多个互相支持的视图回答，相关视图共享对象名称、尺度和颜色意义。先把主要依据放到连续、足够大的区域，再安排背景与解释。来源类别、背景介绍通常只需紧凑文字，不能比真正决定行动的条件占据更多视觉注意。

## 跨组对齐与整页秩序

组合树还应体现跨区域的共同轴，不能只保证每一行内部整齐。需要上下对应的两列时，优先 `row(column(A,C),column(B,D))`，使 A/C 与 B/D 共用列边界；四格需要同时共享行列边界时用 grid。`column(row(A,B),row(C,D))` 的两行独立分配宽度，只有内容确实需要错列时才使用，不能把它当作默认两列布局。

绘制前在 alignment 中写明实际对应组和边缘：哪些共享左起线、哪些共享右边缘、哪些共享文字基线。一个横贯整页的共同轴通常比每层各自居中更能组织页面。相关组有底色和无底色时，同时核对承载面的边缘与内部文字起线：上组有内边距，下组也应使用相同文字缩进，或统一调整承载面位置；只对齐外框不算文字已对齐。

组内标题、编号、条目名、说明与数字各有稳定起线；同级条目共享列宽与基线。结构原设计的内部关系由构建器保持，排版层负责它与周围内容组的边缘、文字轴和阅读关系，不通过任意拉伸源设计来凑齐。

实际复核既看每组，也看整页：遮住文字细节后，仍应看出贯穿相关区域的列边界、组间距与主辅关系。若每行单看成立，合在一起却呈现多条无意义的错位轴，应返回组合树重组，而不是逐个对象平移补丁。

## 视觉重心与有效占用

区域面积不是视觉重量。预留框中的空白、浅色薄线结构、密集深色文字和大面积承载面即使外框相等，也不能视为等重。规划时先在 `fitStrategy` 写出预期主焦点，以及主要证据、解读和辅助区如何沿阅读路径分布；不要填写未经测量的“视觉重量百分比”。

根据完整稿件预算每组实际内容高度和可读留白，再分配剩余空间。每个 builder 应让有联系的文字、图形与解读组成自然高度的组；区域是边界，不是必须顶齐、底齐或铺满的形状。共享列轴仍需保持，重心调整优先改变组合与内容组所分配的空间，避免在固定区域内任意漂移。

渲染后分两步看：先看含 Skin 外壳的整页缩略图，判断第一眼焦点与上下、左右是否明显失衡；再看正文区，区分有效内容、承载面和空白。上部密集而下部只有孤立短句、重色面集中一角、正文在中间断成大空带，均需结合信息关系判断是否重组。非对称不等于失衡，四区也不要求等重；关键是主要信息获得阅读优先级，其余内容沿清晰路径承接，而不是所有重量挤在一端。

发现失衡时先检查主次和组间关系，再调整树的嵌套、容量与剩余空间权重；必要时改变局部媒介和图文分工。密集证据与稀疏解释可改变面积配比，有联系的解释可以就近回到证据组。不能通过加空卡片、重复结论、无意义加深颜色、放大少量标签或缩小正文制造平衡。结构源设计的颜色与内部几何仍由组件维护。

## 文字周围的阅读空间

容量包含文字周围的空间：标题与正文、正文行间、段落与并列项之间、末行与承载面边缘都应计入 minHeight/minWidth。不能把“没有溢出”当作“留白足够”。组内近、组间远，间距由视觉语法提供；增加内容后重新试排容量，不把所需留白压成零。

这里的留白指文字和内容组的阅读空间，不是增大结构图内部空洞或扩大页边空白。正常中文正文不靠插入空格逐字拉开；优先调整实际行距、段距、栏距、内边距与换行，短标签必要时使用统一字距，不能破坏词组和数字单位。

## 图文共同适配

先决定完整分析需要什么表达，再检索结构或图表。结构保留源设计、主题映射和已支持的尺寸能力；其大中小是适配选项，不是页面主次。普通行列更合适时直接使用，不为调用而改变原稿关系。

执行时从计划求出每组实际区域，再创建对象；结构调用的 targetFrame 对应结构子区，正文安全区只提供外边界。渲染后核对实际区域与计划，尤其检查“计划有独立分析/解读，结构却占满正文区”的不一致。容量失败不能靠删除关键条件或把来源压成无含义单字解决。

同时预算图内标签、图外解读和必要口径。实际占用轮廓与安全净距用于避让；空白是可用空间，不是必须填字的任务。斜向结构的外接矩形不等于全部被占用，几何空隙也不自动成为合理的文本区域。

## 从渲染返回计划

逐页将真实渲染与计划并排检查：主要分析是否确实得到阅读优先级，解读能否找到对应证据，完整正文区是否得到合理利用，结构与文字是否属于同一页。

- 主次错误、证据挤窄、中央堆积而两侧无意义空白、图文割裂：标记 `recompose`，修改分组或区域组合后重新绘制。
- 换行、图标尺寸、标签距离、线条净距：标记 `local`，修正实际对象后重新渲染。
- 内容缺失或结论无依据：先回原稿修正，再检查编排。

保留首版计划/渲染与最终计划/渲染，在 review.md 中记录页码、具体发现、修正级别与复核结果。计划检查只验证格式和关联完整性，不能证明审美、事实或几何通过；实际复核按质量规则执行。连续两轮同一问题没有改善时更换该页组合并记录原因，不持续压字和缩图；仍无法解决时明确交付候选及未解决项。

# 排版

适用范围：拥有页面绘制与区域编排权限的制作任务。不授权正式候选选择器绘图；字体名称与颜色从所选 Skin 读取，字号角色、间距和页面边界从其绑定排版体系读取。

## 页面编排

按已加载的[页面组合](页面组合.md)先写主题、分析与解读的关系计划，再安排实际区域；本文件负责组内排字与几何细节。页面组合的 row/column/grid/annotate 是信息组织方法，不要求绘制容器边框，也不覆盖 Skin 或结构源设计。

- 每页先确定一个首要视觉焦点；大小、字重、颜色、深浅和留白共同服务内容。同级项目保持等权，不为了变化随机加深一项。
- 先安排区域关系与阅读顺序，再分别排字和放图。结构不必占整页，文字不必附着在每个图形内部。
- 局部关系表达按[技能选择顺序](../skills/references/selection.md)执行：项目结构技能优先，项目库不适合且属于技术图示时再用 Archify，两者都不适合则自主编排。普通文字不强行图示；具体调用和参考适配由结构 Skill 维护，所有路径仍服从本次 Skin、排版和交付要求。
- 页标题与页脚之间建立正文内容带。主要内容按自然高度组成完整视觉组，再调整整体位置与视觉重量；不靠拉长空框居中，不全部贴顶留下无解释大空白，也不把每个模块拉满整页。
- 组内距小于组间距，标题、符号和解释具有明确归属。同级项目共享列、基线和对齐轴；默认左对齐，节点标签可在所属节点内居中。
- 邻接文字区域之间保留实际间隔；长说明在所属区域换行，不跨入邻组。先确认文本框内边距与换行行为：可排字宽度是框宽减去左右内边距，不是框的外宽。编号、短标签和单行标题须按实际字体测量后容纳完整一行；不能因默认内边距把两位编号排成上下两行。有承载面或边框时，按实际换行高度加上下内边距，末行与底边保留真实净距，不能刚好贴边或漏出。
- 数字与单位紧密结合。公式作为完整组，字母、等号和主体对齐基线，分隔线在字形实际下界之外留净距。
- 连线只表达明确关系，有真实端点与方向，不悬空。先排节点和标签，再由实际边界确定起终点；箭头抵达目标边界，不只画一小段指向大片空白。避让全部非目标文字，包括灰色注释与连接标签；标签置于线旁留净距，或在标签处断开线段。流程的末端输出、退路与返回路径不能因版面宽度不足被省掉，应调整分区或换行布置整组流程。
- 内容放不下先重组、精简冗余、换分区或在允许页数内重新分页，不持续缩小正文硬塞。
- 按语义逐行安排文字，避免短标签拆成孤字、标点独占行，中英文混排不让品牌名或英文单词无意孤立。必要时调区域宽度、语义换行或忠实改写；封面引语也要检查。
- 图片保留比例和必要图注；截图、结果图的字与坐标不能为填满容器裁掉。

## 全稿组织

- 页型由页面职责决定：观点、解释、分组文字、比较、数字、关系图、图文或简洁收束均可，不是必须逐项使用的清单。
- 普通正文页的页首已说明主题时，不再追加一条大号重复标题。引导句仍按正文角色，与其解释内容组成一组；不能把原稿每节的第一句都提升为第二页标题。展示大字只服务少量核心结论；多数页让内容本身成为主体。
- 结论能在内容区讲清就不在页底再重复；不要把“大标题—结构—底部总结”当作所有页面的固定模板。
- 变化来自信息密度、区域比例、页面职责和证据类型；不为了不重复制造错误关系。保持绑定排版体系的文字角色与所选 Skin 的视觉身份一致。
- 制作方法、风格名称、试验轮次、页数等交付元信息放报告，不放进正文或封面空角落。

# 质量检查

## 整页对齐与排版留白

逐页另记录 `视觉重心`：预期第一焦点、实际第一焦点、上下/左右有效内容分布、是否存在孤立重块或割裂阅读的大空带，以及通过或 recompose 的理由。先看整页缩略图再看正文细节，不用 bbox 面积相等或对象未越界替代判断。失衡需要回到组合计划调整；留存首版和自主修订版，标明是否接受过外部逐页反馈。

除组内检查外，沿整页检查相关组的共同列边界、文字起线与标题基线。上下层各自整齐但互相错列，仍属于组合问题；有底色与无底色的区域要一起核对内边距，不能只对齐外接框。

检查标题至正文、正文行间、段间、条目间以及末行至承载面边缘的实际净距。既拒绝文字挤线、条目粘连，也检查不相关的大段空隙是否破坏阅读连续性。留白不足返回容量或组合调整，不缩字号、不随意逐字加空格。跨组轴错误记为 recompose；组内行距段距问题记为 local，均须重渲染复核。

适用范围：制作与交付阶段。程序检测和实际看图互补，不以文件存在或页边界合法代替视觉验收。

## 内容与可编辑性

- 核对页面实际呈现的命题、证据及限定，而不只核对来源ID或覆盖率。提炼前后须保留统计对象、时间口径、比较基础、估计或已验证状态、条件的同时成立或择一关系；不能把边界改成步骤、把设计动作改成已具备能力。模拟材料须让读者看出其性质。检查发现缺口时回到原稿与页面职责，自主重组，不机械补一个文本框。
- 对照原稿核对重要论点、概念限定和关系，特别是流程分支、输入输出与反馈方向。为原稿中的关键角色和关系列出对应页码，不能用“架构大体保留”掩盖角色、输出或退路缺失。没有数据的定性关系不画成貌似实测的统计图；确需概念示意时明确其性质，不暗示数值比例有证据。
- 原生文字、生成的图形、表格与关系图可独立编辑，不用整页截图冒充成品。来源照片、截图等可以保留为图片对象。
- 确认页面数、比例、对象与文件完整性；保留最终 PPTX 和全部页面预览。

## 排字预检

批量复用文字组件前，先以本稿的最长页标题、两位编号、窄栏说明和中英文混排句做小样并查看实际导出渲染。确认内边距、字体、行距和换行设置在当前工具中确实生效；不要仅凭参数名或无报错推断设置有效。正式字号下安排合理宽度和自然高度，不以自动缩字掩盖容量问题。单字尾行、行首标点、标点独占行必须通过语义换行、调宽或忠实改写修复；禁止裁切文字来隐藏它们。

预检也覆盖实际使用的表格及强调文本，检查其导出后的字号、行高和整体高度是否遵守相同文字角色，并将真实占用反馈给组合容量。不能用预设外框高度或构建参数证明表格已容纳；未验证的默认样式不进入批量复用。

## 实际视觉核验

先对照本次 `composition-intent.json` 检查真实页面。主要分析、对应解读、阅读顺序与预期不一致，或出现中央堆积、两侧空旷、图文割裂时，按页面组合规则标记 `recompose` 并重新编排；单个文字或图标的局部缺陷标记 `local`。在 review.md 中记录首版发现、修改级别与最终复核，不以计划格式检查通过替代看图。两类修正均须重新渲染，重要内容不能因调整区域而消失。

1. 先看全稿缩略图，检查气质、页面职责、密度、焦点与连续构图；再逐页看清晰的实际渲染，不只抽样。
2. 创建文字时登记“页码／对象／角色”，导出后读取实际 PPTX 文字运行的 typeface、字号和字重，与绑定排版体系角色表逐项比较（先统一设计像素与 pt）。范围包括封面、引导句、节点、数字、结论，不只页首。自行编写的角色映射仍须对照规则，不能拿脚本自己的错误数值证明自己正确。字体存在不证明角色使用正确；发现未登记角色、越档字号或错误字体时先修正。字体缺失须报告替代。章节归属与独立页码分别检查。
3. 检查中文正确性、语义换行、标题完整、短标签孤行、图片比例、可读字号、对象越界与碰撞。特别看最长说明、最密关系图、公式大字、混排句、封面引语和正文末行。
4. 绘制时登记文本所属页面和内容组，并与最终导出对象的页面归属、坐标交叉核对；不能用错误的页码登记跳过本页相交检查。检查文字是否落在所属区域、邻接文字是否相碰以及分隔线或连线是否穿字。对并列项目逐个核对编号／符号、标题和说明是否共享本组对齐轴，不能只看框之间无重叠。区分有意的背景承载文字与不允许的文字互碰、边线穿字。
5. 几何检查必须执行而非只写报告。检查文字与全部可见线段相交：包括细长矩形实现的横线／竖线、虚线和箭头，不只名为 connector 的对象。使用实际排字区域，保守程序报警须逐项区分背景、边框、文字、连接并人工复核非预期交叠。页面未越界不等于组内安全，文件校验无告警不等于画面正确。
6. 逐页记录至少三个独立判断：文字换行与短标签、线条和文字净距、内容组自然高度与纵向重心；另对照全稿检查第二大标题与页底总结是否形成重复模板。先看最终 PPTX 对应的 PNG 再填写，指出检查对象与发现的问题，不批量填同一句“无问题”。
7. 缺陷须修正并重新渲染复核；字体角色、章节编号、碰撞或溢出未解决时，不得宣称没有视觉问题。

报告单独交代输入、设计取舍、实际执行的检查和未解决限制，不把测试说明写入演示正文。

交付检查记录须可复核：保留文字角色对照结果、几何检查结果和逐页视觉记录。通用文件完整性校验不能替代这三项。若检查尚未执行或仍有上述缺陷，只能报告候选与待修项，不能给出“已完成逐页检查”的成品结论。

# 中性 Skin

适用 Skin：`neutral-editorial-001`，暂定绑定「杂志风」排版体系，由索引自动加载。本文件只维护视觉身份与颜色体系，不复制排版要求。历史资产 ID 和目录名保持不变。该 Skin 资产仍为 candidate；已接入结构 HTML 预览及共享测量转换，当前暖米色效果获用户认可。正式 CLI 仍限东北大学，不把结构预览通过等同于全稿生产迁移或资产晋升。

## 视觉身份与配置

- 纸感、编辑式、安静、精确，有清晰的教学阅读路径；不依赖组织 Logo、行业插画或装饰照片。
- 字体名称只维护在 [asset.json 的 fonts](../../assets/主题/中性编辑排版-001/asset.json)，执行时读取该字段，不另立字体 tokens 真源。具体文字角色由绑定的排版体系引用字段。

## 唯一颜色体系

2026-09-08：PPA 中性结构预览采用用户确认的单主色暖米色派生方案。唯一颜色输入为 `assets/主题/中性编辑排版-001/asset.json` 的 `mainColor`，当前 `#F5F4EF`。由 `src/runtime/skins/primary-tone-palette.mjs` 统一生成以下用途色；不得单独维护强调色或覆写各用途颜色。字体仍读取同一资产的 `fonts`。

`mainColor` 是用户设置的主调；历史组件字段 `primaryColor` 是派生后的强调用途色，仅为兼容现有组件。该字段不是第二个颜色输入。当前审美验证针对暖米色，不代表任意深色主调已通过验证。


排版体系和可换色组件按用途读取以下颜色；不能把所有对象直接染成强调色。原照片、Logo、具有固定数据含义或警告／正反语义的颜色不强行重着色。

| 用途 | 当前颜色 |
| --- | --- |
| 背景色 | 纸色 `#F5F4EF` |
| 浅承载色 | `#EEECE4` |
| 强文字色 | 炭黑 `#201F1D` |
| 正文色 | `#4D4A42` |
| 辅助色 | `#84827A` |
| 分隔线色 | `#D7D4CA` |
| 强调色 | 单一低饱和砖红 `#A35D4F` |

结构与原生图形共用此颜色体系。普通承载面应比页面纸色稍深，不能把浅色卡片直接映射为页面背景。文字仍按强文字／正文角色取色，不能随承载面一起淡化。关系线、箭头、分面保留原稿的深浅次序，映射为同一米色色系的连续色阶；透明度独立保留，不用统一降低透明度代替换色。

调用结构主题入口时，以上用途分别对应 `background / surface / dark / body / muted / line / primaryColor`。已审批的 35 个结构（包含三个保留造型样板）统一经过 `src/visual-runtime/neutral-structure-theme.mjs`：先解析原稿颜色，再按原色明度连续映射到主色派生的浅承载至深承载区间。相同用途、相同原色必须得到相同结果；原稿不同的色阶不要求最终完全相同。禁止按结构 ID、名称增加中性配色覆盖，也不再为三个样板另走配色分支。页面背景与对象填充分开处理，形状几何和字号容量沿用原实现。转换后的审美效果需检查实际 HTML，不据此宣称整页调用或 PPT 已验收。

# 杂志风

本体系可供多个 Skin 复用；当前绑定由 `rules/index.json` 确定，不允许任务绕过 Skin 任意覆盖。具体颜色与字体名称读取 Skin 配置，本文件只维护排版要求。原数值来自既有独立生成实验；分离后 Luna high 首轮未通过视觉验收，现补充执行约束，后续复现仍须实测。

## 画布、间距与文字角色

- 以下数值是 1280 × 720、16:9 画布的设计像素。换算到 13.333 × 7.5 英寸页面的 PowerPoint pt 时乘 0.75；库采用设计像素则直接使用，不混用。
- 左右边距约 56，共享列与基线；页码轻小、靠右下角。多行正文行距通常从 1.55–1.75 调整。框内末行到底边通常至少保留 16–24 设计像素净距。

展示／标题取 `fonts.display`，正文／辅助说明／页码取 `fonts.body`。

## 固定文字角色

| 角色 | 字体字段 | 设计字号／字重 |
| --- | --- | --- |
| 封面展示标题 | `fonts.display` | 58／同类一致 |
| 页首标题 | `fonts.display` | 25／bold |
| 模块标题 | `fonts.display` | 21／bold |
| 密集关系图同类节点标签 | `fonts.display` | 统一 17 档 |
| 正文与引导说明 | `fonts.body` | 17／regular |
| 辅助说明 | `fonts.body` | 15 |
| 数字或公式强调 | `fonts.display` | 可统一 48 档 |

页码与章节编号可单独设定。先把以上角色编成唯一的文字样式映射，再创建页面文字；各页使用角色，不自行追加 28／31 等近似字号来做引导句、结论或节点。封面两行展示标题同用封面角色，不因英文更短放大；强调数字也按表执行，不临时放到百位字号。遇到新文字用途先归入已有角色，不把每处差异解释成新角色。实际字体角色的核验按共享质量规则执行。

引语、页底结论不自动成为展示角色：解释性句子使用正文角色，真正的模块标题才使用模块标题角色。不得新增 `quote`／`takeaway` 等名称绕过角色表，也不得通过逐对象参数覆盖已确定的字体、字号或字重。符号与章节编号的特例不适用于普通语句。普通页不要预设固定的“第二标题—正文引导—主图—大号结论”四段骨架；先按内容职责形成自然内容组。

## 页首、符号与容器

- 正文页首为“两位章节编号＋短标题＋向右延伸细线”，稳定左上，编号和标题均完整单行。编号用 Skin 强调色，标题用 Skin 强文字色；三者共同视觉中心对齐。线的起点由标题实际排字右界加间距确定，不能给所有标题固定同一个线起点而留下参差的大断口。目录页同字号字体，编号可为 00。
- 章节编号按目录章节归属，同章各页沿用同一编号，不能随正文页逐张递增；页码另行递增。生成前建立章节与页面对应表。
- 圆形可编辑符号是设计语言亮点，例如 A、≈、◐、□、↔、●。可配细轮廓或有依据深色填充，用于分类和阅读节奏；不全部替换成中文，也不强加到每个文本框。
- 符号与模块标题相邻，通常略大于一行字；不把没有额外信息的字母放成全页最大焦点，不在封面空角落加无关符号标签。
- 用平面文字、留白与细线组织。线用于标题延伸、分组、对比边界或真实连接；关系连接可用箭头。
- 避免阴影、渐变、胶囊、厚重容器与圆角卡片墙。细框仅在确有分组／对比职责时使用；底部结论不默认套横贯全页色框。

## 可选页面表达

以下是风格偏好，不是固定页数或结构清单：

- 封面：左侧大标题、强调副标题与短说明，必要时右侧短引语，保持克制。
- 目录：连续编号、章节标题及可选短说明，横线分隔、无卡片，各行自然高度，整体视觉居中。
- 文字展开：短结论配分组解释、平面列表、双列或适合数量的网格。
- 原则与方法：圆形符号或编号、短标题与解释共享对齐轴。
- 对比：用 Skin 的低饱和强调色与灰度表达主次。
- 指标：以展示字体的大数字形成克制的视觉焦点。
- 数字与单位、短标签先组成紧凑的阅读单元，再安排单元之间的留白。单位位置依据实际数字右界与基线确定，不按一个宽数字占位框机械后移。留白主要用于区分信息组，组内仍应有清楚归属。
- 收束：一句有来源的核心结论与少量辅助内容，允许很简洁。

避免连续页面都成为“圆圈＋长横线＋三列文字”；变化依据共享排版规则，字体、配色和符号语言保持一致。

整页先确定主要阅读对象及支持说明的关系，再选形状。流程中的推进条件与贯穿规则按语义分开：真实条件分支连接到对应步骤；贯穿规则可作图旁说明，不必塞进独立形状。形状应帮助识别关系，不用扁长椭圆或孤立框把普通注释装饰成视觉焦点。强调色用于确有意义的焦点，最后一个节点不因处于末尾就自动获得最重色块。

有用户认可的视觉参考时，先比较它的文字组合、比例、线条、信息密度和整页节奏，再将适用方法转译到本稿；不要求照抄参考坐标或页型。完成后并看参考与新页，检查相近气质是否来自这些组织方法，而不只是相同背景和字体。内容增加时重排区域自然高度，避免在旧布局底部连续追加说明。
