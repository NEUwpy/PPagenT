# PPagenT 产品需求（MVP）

2026-09-30 当前需求口径。PPagenT 的最小目标是把一份稿件可靠地变成内容忠实、关系清楚、风格统一、原生可编辑的 PPT。

## 两大阶段

1. **稿件到灰稿**：理解稿件，形成页面表达共同契约，编译灰稿供建设检查。
2. **灰稿到成品**：消费同一契约，按已建设的 Skin、风格、布局和结构能力生成成品。

使用阶段只保留两类模型：语义理解模型负责理解、分页、关系和内容填充；JEV 负责在程序给出的合法候选中判断和选择。程序负责契约校验、来源、容量、参数、几何、构建和检查。Codex、视觉模型和自由绘图只服务建设阶段，不进入产品。

## MVP 交付

- 输入先以一份已展开、可可靠读取的稿件为主；格式扩展另行验收。
- 灰稿必须能检查页面目的、内容完整性、来源、主次、关系和承载；不能静默删件或编造事实。
- 成品必须保留共同契约表达，具备原生可编辑对象，并通过容量、几何、导出和预览检查。
- 无能力或证据不足时返回明确缺口，不用缩字、删稿、自由坐标或高级模型兜底。

## 验收顺序

先分别验收两大阶段，再用真实稿件验证连接。建设阶段可用模拟灰稿探索后段，但模拟输入只证明灰稿到成品；固定回放、程序测试和产物存在都不能代替语义与用户审阅。

当前实现仍在迁移：正式 gray 入口已接入 JEV 的有限布局选择，独立运行和完整成品质量尚未成立。实际状态见[项目进度](方向讨论/页面编排能力计划.md)，共同契约见[页面构成与布局规范](架构/页面构成与布局规范.md)。
