# 产品目标与路径

2026-11-16 更新讨论稿。商业动机和服务主张见[动机、痛点与商业机会](方向讨论/20261029-产品动机与价值讨论.md)；本文维护产品阶段、交付目标、范围和推进顺序。

## 产品阶段

| 阶段 | 输入与任务 | 交付重点 |
| --- | --- | --- |
| 第一阶段，已有内容的编排与美化 | 用户已有 Word、PDF、PPT 或 Markdown 等材料，对内容做最少必要改动，完成页面编排和视觉制作 | 适合常规演示、清楚得体、稳定可靠的可编辑 PPTX |
| 第二阶段，根据主题或需求制作 | 用户提出主题或要求，系统补充资料、组织和撰写内容，再调用制作能力 | 在第一阶段制作能力上扩展内容准备，具体范围后续讨论 |

第一阶段重点服务高校、国企、央企及企业的常规汇报、教学和交流。质量侧重内容承载、可读性和适当设计，发布会级创意设计留待后续评估。材料格式的具体支持范围与接入顺序仍需讨论。

## 当前责任：Markdown → PPTX

**本轮只完成 Markdown 到 PPTX 的责任。** 给定 MD 稿件、相关资源及必要要求，核心负责页内内容组织、页面表达和排版制作。

**上游将各种材料整理为 MD 时，各页内容就应适合单页承载。** MD → 灰稿在这个前提下进行编排。MD 无须提前选结构或指定版式；具体分页标记和文件组织形式随后按系统需要确定。

第一阶段的多格式材料通过上游整理适配同一制作核心。**上游“各种材料 → MD”当前暂不开展**，其范围和接入顺序后续讨论。产品阶段与眼下建设范围分别维护，分支安排见[AGENTS](../AGENTS.md#分支分工)。

本轮先以原有架构为底稿，讲清整个系统怎样编排、匹配元素、判断和选择，再由系统需要反推 Markdown 输入格式。具体流程与取舍见[架构](架构.md)，不提前定义输入字段或模板。

## 第一阶段交付目标

自动交付可编辑 PPTX。用户可以自行调整成品，不依靠人工补做才能完成交付。

- **内容忠实。** 以用户已有内容为准，保留事实、依据、数字和必要限定。仅在表达确有需要时做提炼、删重、压缩或结构化重组，形式性标题与标签应有原文含义支持。
- **编排成立。** 页面围绕要讲清的事情组织，分组、主次、关系与阅读顺序清楚，文字、图像与图示相互对应。
- **视觉得体。** 运用确定的模板、Skin、风格和复用能力，落实文字层级、对齐、间距及必要图示，整套协调、清楚可读。
- **可编辑交付。** 文字、图形和图表以可编辑形式制作，图片保留为可替换资源，输出 PPTX。
- **自动衔接。** 在支持范围内从输入完成交付，灰稿到成品自动交接。必要选项有默认值，用户可自行调整成品。
- **持续省事。** 换稿后质量和风格仍可预期，用户在核对和修改上的总耗时应比原有做法减少。

阶段完成需要有跨稿交付和使用效果证据，具体支持范围、质量阈值与可接受修改量待讨论。当前状态仍为目标与方案讨论。

## 内容准备的责任边界

第一阶段的材料整理服务于已有内容的准确转入和页面承载。上游负责来源读取、内容提取和适量整理，制作核心依据整理后的内容做编排与美化。

从主题出发的资料搜索、实质内容补充和撰写归入第二阶段。二者都可使用同一套制作核心。

## 本轮待明确的范围

1. 页内内容编排与表达选择的质量要求，包括分组、主次、关系和版式承载。
2. 默认要求与用户可选项，以及成品的质量边界。
3. MD 内容与资源要求、上游交接边界，以及材料不完整或含义不清时如何处理。
4. 第一阶段的支持范围、阶段完成标准，以及继续、收窄或停止投入的判断条件。

原有流程、内部表示与程序优先评估复用；只有存在明确缺口或不适用时才调整、重选。统一输入为 MD 不要求重新发明整条制作链。

## 推进路径

1. 整理商业动机与机会，形成可继续讨论的产品主张。
2. 明确产品范围、默认体验、交付标准与责任边界。
3. 盘点既有实现、资产和方案，统一到当前架构的职责划分，讨论并明确复用、调整和技术路线，详见[架构](架构.md)。
4. 充分讨论后，以 MD → 灰稿、灰稿 → PPTX 两条线同步建设，用共享编译器检查交接，随后按已明确的顺序扩展第一阶段的材料适配。
5. 根据跨稿交付、用户返工及实际使用效果判断第一阶段成果，再评估第二阶段的启动和范围。

当前在整体架构盘点与方案讨论阶段。旧进度、测试和局部产物用于核查已有能力，不作为调整后整条链已经完成的证明；实施计划在整体方案与必要调整明确后制定。
