# 产品定义与架构边界

PPagenT 面向学校、科研院所、事业单位和企业的工作型演示，把用户内容转为可靠、体面、原生可编辑的 PPTX。东北大学是第一正式场景，不是最终产品边界。输入与交付需求独立见[产品需求](产品需求.md)，不由某种架构倒推。

**目标产品是 PPT 专用 Harness。** 验证对象是 Codex 项目 Harness＋Luna high 与持久状态、上下文组织、工具循环、审查反馈、返工及交付机制的整体能力，不是输入一次提示词后期待单次模型响应完成制作。运行资料统一从根目录 [harness/](../harness/README.md) 进入。当前使用 Codex 项目驱动 Luna high 验证闭环，不等于项目自身运行时已实现。

结构库建设以“实际排版中容易正确调用，并与 Skin 和页面布局稳定协调”为目标；保留现有设计，只提供必要且受约束的变化能力。具体建设边界与验收标准见[结构库建设目标](架构/结构库-变与不变.md#建设目标2026-09-07-用户确认)，不得将缩放样例通过等同于整体目标达成。

## 兼容实现与已有能力

| 部分 | 当前职责与边界 |
| --- | --- |
| 现行生产线 | 内容导演输出内容；程序筛选合法候选；视觉导演选择 Composition／Structure；确定性执行与检查交付 PPTX。仍主要是一页一个主结构，不是自主 Agent 工具循环 |
| 规则层 | 根目录 `rules/` 保存唯一现行规则正文，`index.json` 按 profile／Skin 选择；Skin 唯一绑定一个可共享排版体系。每次导演入口重新读取，视觉批次共用本次入口快照，无跨阶段冻结承诺 |
| 正式角色提示 | 内容导演加载共享内容原则与其执行协议；视觉选择器加载候选选择协议。静态角色协议归规则，Schema、动态输入与修复反馈仍由代码约束，选择器不加载自由排版规则 |
| 独立制作入口 | 短任务提示词读取 `generation` 共享规则、指定 Skin 及其绑定排版体系，供有制作工具的 Agent 执行；加载命令本身不生成 PPT、不调用模型 |
| 资产与渲染 | 现行正式 CLI 限东北大学 Skin；中性 Skin 仍为 candidate，只用于独立实验／审批。规则迁移不自动晋升资产 |

当前已披露候选可开放 `text-plus-structure`；未披露则不能使用。通用 Media、多结构自由组合与新的 Harness 尚未接入正式生产线。旧 API 生产线明确使用 legacy-structure-assets.mjs；新结构入口已改为原生 Skill 构建；独立制作入口已通过共享排版规则连接结构 Skill，支持 Agent 先提取结构关系与视觉识别特征，再执行原生适配构建或多参考组合，项目库不适合时，关系图以 Archify 补充，数据图表以 Lieflat Charts 非商业试用补充；适用技能均不适合则自主编排，尚不代表整稿稳定性验收通过。四类输入与局部对话修改是产品需求，不代表现有正式入口全部支持。

## 关系表达技能的优先顺序

客户输入决定内容；Skin 与绑定排版体系提供基础视觉规范。项目自建结构技能为第一顺位；第二顺位按内容分工，Archify 处理技术关系图，Lieflat Charts 处理数据图表（当前非商业试用）。适用技能均不适合时自主编排。技能用途与许可见[技能清单表](../skills/README.md)。统一选择真源见 [技能选择顺序](../skills/references/selection.md)。基础规范不代替视觉验收；Archify 仍为 pilot，在 PPT 任务中其 HTML/SVG/JSON 仅为图示中间产物，必须继续完成原生对象适配、Skin 统一及完整页面验收；不能以独立网页替代 PPT。此次为独立制作指导及技能目录声明，正式 Harness 自动路由尚未实现。

## 规则、Skin 与版式如何分工

Skin 决定视觉身份与一个完整颜色体系，包括主题色、配套色阶、Logo 或身份装饰、字体配置。独立制作的共享页面组合规则先确定主题、分析、解读、主次与阅读关系；排版体系决定这些关系如何呈现，包括字号角色、密度、间距、正文重心、符号与容器。Skin＋共享组合方法＋风格规则共同产生本页 Layout；它不是单一固定版式。

旧独立制作试点提供可选的 `composition-intent.json` 路径，声明逻辑关联与嵌套组合；新 Harness 以轻量蓝图为起点，不强制所有任务走该解析器。选择该工具时，`src/composition/resolve.mjs` 根据组件和文字容量解析组级区域，由 buildComposition 将同一计划交给各组构建器。支持嵌套行列与网格，容量不足明确要求重组；锚点覆盖尚未实现。实际渲染若主次、重心或图文整合失败，返回计划重排。入口和字段见 [页面组合](../rules/页面组合.md)。此为独立制作的轻量组合执行层，复用现有 Skin、组件和渲染器；未扩展正式候选选择器的封闭 CompositionPlan Schema，正式线自动迁移尚需验证。

暂定一个 Skin 绑定一个排版体系，多个 Skin 可以复用同一体系：当前「中性 Skin」对应「杂志风」；大学 Skin 共用「麦肯锡式」的命名与分工已确认。大学咨询式实验已合并，见[整稿测试](../experiments/university-skin-pilot/stability-01/RESULTS.md)，现行索引已将东北大学 Skin 绑定到「麦肯锡式」，历史冻结指南不参与加载；独立制作规则绑定不等于正式 renderer 迁移或审美验收通过。历史资产 ID 和目录名不因用户可见名称改变而批量改名。

可换色组件按用途消费 Skin 配色，文字、图像与关系图仍是不同表达能力。结构的现行共享与换色方式见下节；早期蓝紫主题实验只保留为历史证据，不能代替中性转换的当前状态。

规则正文分工与读取方式只在 [rules/README.md](../rules/README.md) 维护。颜色用途取值留在 Skin；字号、间距等排版数值留在绑定体系。已有资产 `fonts` 继续是字体名称真源，规则通过声明加载该字段，不复制一套 tokens。资产描述引用规则，不再抄写整段规范。

提示词只负责本次任务、输入输出与加载入口；执行器负责可编辑对象、几何和契约校验。参考教程先成为学习笔记，再将适用且经验证的经验修订到现有规则。历史提示词保留为证据，但不作为并行版本选择。

## 结构源设计与 Skin 的共享方式（2026-09-08）

**一个结构维护一份源设计，各 Skin 共用；Skin 不复制结构库。** 源设计是资产的绘制实现及其共享依赖，保存形状、连接、内容容量和原稿色阶。原稿蓝色是转换的输入依据，不表示结构只属于东北大学。

```text
结构源设计 + 稿件内容 + 已支持的区域适配 → HTML/SVG
Skin 主色 → 派生色板 → 共享颜色转换 → 测量与渲染
```

Layout 先安排页面内容、阅读顺序和结构占区，结构服务于排版。颜色转换保持原几何；字号、尺寸和小配件适配是另一项能力，不能因换色成功就宣称全库支持任意大小。

| 修改位置 | 重新渲染后的影响 |
| --- | --- |
| 某一个结构的源形状、布局或内容契约 | 该结构在各 Skin 下的表现同步更新；其他结构不随之改变 |
| 一个 Skin 的主色 | 使用该 Skin 的结构重新派生配色；不修改结构源设计或其他 Skin |
| 全库共享绘制依赖或颜色转换规则 | 所有调用该公共实现的结构受影响，需检查代表结构 |
| 当前任务里的副本 | 只影响该任务；不会自动回写结构库 |

已生成的 PNG、PPTX 和缓存不会自行改写，需重新生成或刷新对应缓存。若某结构有多个历史入口，修改时应确认它们指向的源实现与共享依赖，避免只改一份冻结样例。

当前中性 Skin 的唯一颜色输入是资产 `mainColor`；`primary-tone-palette.mjs` 派生全部用途色，兼容字段 `primaryColor` 是派生强调色，不是第二个用户输入。35 个已审批结构，包括三个尺寸样板，都经 `compileHtmlComponentTheme` 调用同一个 `neutral-structure-theme.mjs`，不按结构名称追加颜色覆盖。程序按原色明度连续映射，保留深浅顺序和透明度；卡片承载面与页面背景区分，文字保持可读。相同用途和相同原色得到相同结果，不要求不同原稿色阶被涂成同色。具体规则只维护在[中性 Skin](../rules/skins/中性编辑排版.md)。

内置已审阅转换为中性 Skin；东北大学仍使用既有主题路径。新 Skin 现可通过登记工具接入同一结构转换程序，仍需验证，不能宣称任意主色、尤其深色或高饱和色，都已验证好看。当前大中小保真适配仍只有折角便签、简明漏斗、成熟度阶梯三个结构；35 个结构的统一换色不扩大这个范围。

用户已认可当前暖米色转换效果，代码存档为 `373fe19a`。验证记录见[统一转换预览](../experiments/structure-unified-neutral/index.html)：35 个结构的默认、较少、较多共 105 个 HTML 状态，未检测到指定文字容器裁切；21 项定向测试通过，并检查汇聚色阶、同原色漏斗及循环箭头配色。它不代表全部结构的 Luna 整页调用、任意尺寸或最终 PPT 已验收，也不自动晋升 Skin 资产状态。

## 后续目标，尚未完成迁移

目标是薄的 PPT 专用 Harness。2026-09-12 的最小架构保留内容、视觉两个专业职责，可在同一执行对话中协调；独立上下文不再是首轮前置条件。总控为状态、工具调度、恢复与交付责任，可由宿主和执行者承担，也可由仓库内的薄运行器承担（`src/runner/`，2026-09-12 建成，只拥有循环、状态落盘、工具派发、恢复这四件事）；两条路都不要求额外自主 Agent 或复杂程序状态机。职责如下：

| 角色 | 目标职责 |
| --- | --- |
| 总 Agent | 持有任务状态、预算与产物；调度两个导演，路由局部反馈、QA 与交付，不替代导演包办设计 |
| 内容导演 | 叙事、章节、分页、页面职责、来源与内容层级；按明确反馈修订受影响页面，不决定资产或绘图坐标 |
| 视觉导演 | 全稿节奏、版式、内容区域及 Text／Media／Structure 组合；在能力声明内适配，不发明事实和素材 |
| 能力执行器 | 执行已有程序与资产；声明语义、容量、不变量、适配面、示例、来源和检查方法 |
| Native QA | 检查可编辑性与可定位的几何、字体、容量等问题；不能代替全部审美判断 |

Layout 组织 Text、Media、Structure 三类表达能力。Structure 只在真实拓扑关系需要时调用，不以结构命中率或随机不重复衡量质量。信息按“能力摘要 → 表达目的／Logic → 具体实现”逐层读取，不一次装入全库，也不为每层增设 Agent。Native／QA 是公共执行层，不是第三类视觉资产库。

此前 `DeckBrief / PageBrief / PageComposition / ArtifactState` 是候选责任命名，未发布 Schema；当前采用运行流程中的 content.md、blueprint.json、state.md 最小约定，不并行建设另一套 IR。内容与来源只保留一份，其他对象引用。Harness／SDK 不绑定特定产品；并发队列、Worker 留待需求成立后处理。

区域展示文案需要绑定原稿来源（实验称 PageView），允许精炼但必须保留事实、条件、职责与关系。内容阶段决定语义与分页；视觉阶段决定区域与表达，语义改动回到内容阶段，避免绘图时悄悄删改原意。历史无图片路线保留为候选实验。当前 R1 复用宿主已有渲染和查看工具，记录实际反馈方式，不先施加无图片限制；这也不能被计作无图片产品路径验收。

## 自主编排与资产复用边界

- 正向指导说明阅读入口、层级、归属、节奏和留白怎样服务内容；边界限定事实、身份、适用文字角色、真实关系和可编辑性。具体分组、区域比例、强调与分页由 Agent 在此范围内决定，不用固定文字模板或庞大版式库作为前置条件。
- Layout 是本页实际编排结果，排版体系是跨稿复用的方法，两者分开。网格只描述空间与占用，不替代因果、顺序或归属。
- 结构跨 Skin 通用，按[技能选择顺序](../skills/references/selection.md)选择：项目结构优先调用或参考适配，Archify 补充技术图示，Lieflat Charts 补充数据图表（当前非商业试用），适用技能均不适合再自主编排。新执行入口不加载旧 Mapper、容量、最小尺寸或固定文字框；原生构建保留稿件事实、来源、条件与关系，自主安排节点、线条、尺寸与图外说明，可择取多个参考中的局部方法，不设参考数量配额、不要求先调用失败。验证本次输出并记录实际采用的参考，构建成功不等于视觉验收通过。
- 文字是正常元素，按语义角色和真实换行高度排放；图片需真实来源与必要标注。结构仅在局部关系需要时检索，不强制每页一个结构或达到调用配额。
- 运行时只改本次产物，不改核心库或长期规则。来源、条件与关系不能为整齐删掉；程序检查和视觉验收分别记录，未覆盖项不写成通过。

## 已合并实验与正式能力的区别

无图片网格原型已验证双上下文、来源绑定、局部修订与一页 Text + Structure，仍是实验路径，详见[闭环证据](../experiments/penguin-harness-v2/GRID-RESULTS.md)。正式候选选择已纳入 Text 与 Structure 同级选择；这不等于正式选择器有自由坐标权限。Codex Skill 早期有真实结构调用；后续咨询式整稿主要参考重组。三篇精选 29 页包含反馈修订，最新两次同提示独立复验为 1/2 整稿通过，尚未证明稳定性、DeepSeek 可迁移性或产品成本。

## 适配与迁移底线

- 保留现有可交付路径，已有程序与资产作为未来能力实现或通过 ID 引用，不另复制平行几何真源。
- 目标降级顺序为：精确调用 → 契约内适配 → 少量能力组合 → 重组或拆页 → 成熟文字／图文表达；不能通过虚构事实、缩字硬塞或整页图片假装成功。当前程序尚未实现整条目标阶梯。
- 运行时派生仅属于本次稿件，应留来源、差异与 QA 记录；不能覆盖核心资产或自动晋升。入库与正式调用始终分开，`PPT源/` 仍是唯一原始 PPT 来源。
- HTML 保留在资产设计、复现与审批；现行资产 HTML-to-Native 编译继续复用。目标正式线直接生成 Native 对象，但不同时维护独立 CSS 与 Builder 两套设计规则，也不一次重写全库。
- `asset-gap` 是能力缺口，`content-capacity-gap` 是内容容量不合法，不能混为一类；真实性、依赖、可编辑性与明显几何错误不能被降级掩盖。
