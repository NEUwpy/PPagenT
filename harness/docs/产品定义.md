# 产品定义与架构边界

2026-09-30 用户对齐。**PPagenT 把稿件可靠地转成内容忠实、逻辑清楚、风格合适、原生可编辑的 PPT。** 面向日常工作型演示，以前置设计和参数化能力获得可控质量与成本。

## 两大阶段

1. **稿件到灰稿。** 理解稿件、形成分页和页面表达，程序编译灰稿；以灰稿检查内容、归属、关系、主次和承载。
2. **灰稿到成品。** 消费同一页面表达，选择已建能力，按 Skin、风格和结构规则生成可编辑成品。

页面表达是共同契约，灰稿是它的可视视图；“灰稿”也可作为这份中间产物的统称。建设时直观检查灰稿，投入使用后默认直接交付成品，不要求用户逐阶段批准。契约只维护一份，见[页面构成与布局规范](架构/页面构成与布局规范.md)。

## 建设与使用

| 场景 | 参与者与职责 |
| --- | --- |
| 建设阶段（当前） | 用户与 Codex coworker 建原则、资产、程序和最小契约；Codex 看图与验证。允许分角色、分支建设前后段，阶段性合并 |
| 投入使用 | 语义理解模型负责理解、分页、保真提炼与必要关系；判断选择模型负责有限候选判断与选择；程序负责测量、样式、几何、构建和检查 |

用户当前选型为 **DeepSeek v4.1 Flash + JEV**。当前代码已接入 OpenRouter Decisions API，用 JEV 在程序确认的合法布局候选中做有限选择；完整灰稿到成品链仍未完成。产品不依赖 Codex、视觉模型、临场自由设计或更高级模型兜底。图像预览仍可由程序生成，建设审图由 Codex 完成。

Harness、Agent、Skill 是实现手段；开发协作角色不是产品模型角色。MVP 与稳定性见[产品目标与路径](产品目标与路径.md)，当前状态只在[项目进度](方向讨论/页面编排能力计划.md)维护。

## 结构源设计与 Skin 的共享方式（2026-09-08）

一个结构维护一份源设计，各 Skin 共用；Skin 给出身份和内容区，风格给出表现规则，布局与结构程序承载内容关系。变化通过已支持的参数和程序实现，不为每种数量另建固定模板。

修改结构源设计检查该结构的受影响状态；修改共享转换检查代表结构；运行中的副本不自动回写或晋升。配色迁移、尺寸适配和完整成品分别验收。历史验证见[统一转换记录](../experiments/structure-unified-neutral/index.html)，调用范围以实际资产契约为准。

## 当前实现边界

工作台 gray 入口、`gray-plan-3`、来源绑定、测量、局部布局选择、灰稿交接和原生构建可复用。纯文字映射与受限美化已有建设候选；跨组关系、多图示、重复模型判断及成品质量尚未整体验收。

旧 stage runner、legacy 双导演和自由局部排版保留兼容身份。其字段和权限按实际代码使用，不成为新生产目标。当前 PPT 引擎仍有 Codex 运行时依赖，产品独立运行未成立，见[外部依赖](../harness/外部依赖.md)。实际入口见[运行流程](../harness/运行流程.md)，旧细节见[纠偏前快照](archive/20260930纠偏前/README.md)。
