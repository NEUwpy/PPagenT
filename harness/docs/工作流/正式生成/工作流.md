# 正式生成工作流

2026-09-30 起，建设和投入使用均只按下列两段流程推进；旧流程不再调度，旧入口只保留兼容与历史证据。

## 阶段一：稿件到灰稿（main）

1. **读取与保真。** 读取原稿和要求，建立可回溯的来源 ID，保留数字、条件、程度和时间限定。
2. **分页。** 按主要目的和阅读关系形成逐页稿。一页讲清一个主要事情，必要内容完整；“不多不少”由语义完整性和后续容量一起判断。
3. **页面表达。** 每页填写共同契约：页序、目的、主题句、内容 ID、分组、主次、关系、表达类型、候选能力和必要备注。
4. **候选选择。** 建设资产预先登记一级页面版式和可选二级结构。程序给出合法候选及容量，JEV 只选择命名 ID，不给坐标。
5. **绑定与编译。** 程序把内容 ID 绑定到区域/槽位，校验数量、来源和容量，生成实文灰稿、结构占位、检查结果和日志。
6. **灰稿检查。** 用户与 Codex 检查页序、内容、关系、主次、承载和占位说明。通过后冻结契约，交给后段；不通过则回到对应责任点。

## 阶段二：灰稿到成品（home）

1. 读取冻结的共同契约和灰稿，不重新分页或改变页面意图。
2. 选择 Skin、风格规则、参数化布局和结构资产，把同一内容 ID 填入声明的槽位。
3. 按容量边界测量文字和结构，求解几何，生成原生可编辑对象。
4. 输出 PPTX、完整预览、几何/导出检查和日志；用户与 Codex 检查实际页面。
5. 若是样式或承载失败，修资产/程序或选择已登记变体；若是语义或关系失败，回写共同契约并重新编译灰稿。

## 建设与使用

建设阶段由用户与 Codex coworker 设计资产、规则、程序和检查。home 可以用模拟灰稿先建设美化，但模拟输入要记录为模拟来源；它只证明后段，不证明前段自动分页和表达。

投入使用只调用语义理解模型（当前 DeepSeek v4.1 Flash）、JEV 和确定性程序。语义模型理解和填充，JEV 在合法候选中判断和选择，程序负责契约、来源、容量、测量、几何、构建和检查。产品不调用 Codex 或视觉模型。

## 检查点

- **资产：**参数、槽位、容量、拒绝条件、程序入口和原生可编辑证据齐全。
- **分页：**一页一个主要目的，必要内容/限定完整，来源可追溯，无静默删件。
- **表达：**关系与表达类型明确，候选覆盖，JEV 选择可解释且可回放。
- **灰稿：**实文可读，页序、关系、主次、区域和槽位可检查，无未声明溢出。
- **成品：**内容和关系指纹保持，输出原生可编辑，完整预览和用户审阅通过。

## 实际入口与日志

当前工作台入口为 `src/runner/gray-agent.mjs`；它复用 `gray-plan-3`、plan/state、来源绑定、JEV 布局选择和现有测量/渲染能力。每次模拟生成都走当前生成线并写运行日志；生产工作台从日志和运行产物编译状态、输入、输出和检查视图。工作台是建设调试工具，不是产品交付界面。
