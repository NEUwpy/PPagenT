# 生产工作台

本文维护工作台的入口和日志约定。流程职责见[架构](../../架构.md)，技术取舍见[技术选型与决策](../../技术选型与决策.md)。

## 数据与实现边界

- 运行事件和阶段产物是状态来源；工作台从 `events.jsonl`、`trace/*.json` 及运行产物编译展示，不维护第二份手写状态。
- 阶段视图展示状态、输入、输出、错误与原始产物；绿色状态或可见预览不代表质量验收。
- `src/workbench/main-flow.mjs` 登记十步，当前接通原稿读取与规范化。灰稿编译步骤登记 HTML、预览、交接布局与诊断。使用既有单页契约的 A0 仍走原入口。
- 旧 gray、双导演与模型接口供追溯历史运行。固定回放与模型重新规划的证据分别记录。

结构化方案到灰稿目前通过[独立编译试验](../../../experiments/gray-compiler-20261120/README.md)运行，工作台接入待验证。

## 工作台本地检查

```powershell
npm run production:workbench
```

核对原输入、状态、各阶段产物及事件/trace。`awaiting-user-review` 是既有建设审阅状态，不据此增加产品人工放行环节。保留失败与人工干预记录，不将人工修好的单页计作自动能力。

原模型接入和两段视图见[修订前说明](../../archive/20261119灰稿职责调整前/source/docs/工作流/正式生成/生产工作台.md)，不作为当前选型依据。
