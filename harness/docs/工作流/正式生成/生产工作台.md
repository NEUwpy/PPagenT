# 生产工作台

2026-09-30 现行定义：PPA 工作台是建设阶段的**生成线调试与日志编译器**，不是面向最终用户的产品功能。它用来确认每次模拟是否真的走当前生成线，查看每个状态点的输入、输出、日志和中间产物，以便用户与 Codex 优化流程。

## 数据原则

- 每次模拟都调用当前正式入口，不能另写一条“只为预览”的捷径。
- 运行事件和阶段产物是唯一事实来源；工作台从 `events.jsonl`、`trace/*.json` 及运行产物编译展示。
- 日志更新后，工作台展示随日志更新；页面不维护第二份手写状态。
- 每个阶段至少展示：状态、开始/结束、输入摘要、输出摘要、错误/缺口和可定位的原始产物。
- 工作台可展示灰稿 PNG/PPTX 和完整日志，但展示不等于用户验收。

## 当前两段视图

| 阶段 | 主要状态点 | 重点输入 | 重点输出 |
| --- | --- | --- | --- |
| 稿件到灰稿 | 读取 → 分页/页面表达 → 候选 → JEV 选择 → 绑定/容量 → 灰稿 | 原稿、要求、来源、候选、契约 | 分页稿、页面表达、选择结果、绑定、灰稿和检查 |
| 灰稿到成品 | 读取冻结契约 → Skin/风格 → 参数化结构 → 测量/构建 → 预览/检查 | 灰稿契约、Skin、风格、结构参数 | PPTX、PNG/HTML 预览、几何/导出检查和缺口 |

当前代码首先把 gray 线和布局选择接入工作台；灰稿到成品仍按最小能力逐步接通。状态名称必须来自实际事件，不能因界面出现绿色就宣称里程碑通过。

## 建设与使用边界

建设阶段由用户与 Codex coworker 看图、审阅和调试；home 可以提交模拟灰稿探索后段美化。投入使用只保留 DeepSeek v4.1 Flash、JEV 和确定性程序，Codex 与视觉模型不进入产品。

JEV 通过 OpenRouter Decisions API 做受限候选选择；它只处理程序给出的命名候选，程序负责绑定、容量、测量和构建。OpenRouter 凭证只放在被 Git 忽略的 `config/credentials.local.md`，不写进工作台日志和仓库。

## 启动与检查

```powershell
npm run production:workbench
```

先看流程状态，再看各状态点的输入/输出和原始日志，最后检查灰稿/PPTX/PNG。`awaiting-user-review` 只表示等待建设审阅；固定计划、测试、日志完整或候选生成成功都不自动关闭里程碑。

旧 visual checkpoint、legacy 双导演和旧工作台字段只为读取历史运行保留，不作为当前 MVP 流程。
