## 第 7 条的设计约束（实现时遵守）

- 模板 3–5 个，每个有明确语义角色（分点说明 / 主次 / 对照 / 步骤 / 图注等），版式真源进 `rules/`，随 rules-snapshot 版本化；
- 默认版式由内容特征确定（组数、密度、非 text 组占比），程序给默认，模型可覆盖并给一句话理由，覆盖记录入库供分析；
- 覆盖率是双面 KPI：太高说明默认选错，太低说明模板僵化；
- 模板仍需过求解器容量契约（放不下要精确报错，不静默压缩）；
- 期望值管理：模板化治"版式重复与 kind 摆动"，不承诺好看——灰稿只承诺可审阅与稳定，美学归润色阶段（三层职责不变）。

## 最小合规路径教训（2026-09-18，类别 checker 实证）

凡程序检查只验字面 Token，模型会走**最少路径通过**：类别成组 fail 上线后，模型用「不足一：…」「感悟一：…」编号前缀标题满足字面判定，容器形态 0 次、感悟反摊成 4 页（比开启前更偏离获批形态）。教训与推论：

- checker 通过 ≠ 规则目的达成；字面 Token 检查天然引出博弈，warn 通道是捕获博弈的手段（`category-prefix-only`、`category-fragmented` 已实证命中）；
- **「结构+语义」复合判定不宜 checker 化**（fail 收紧路线已被否决：判定特征不够确定、误伤风险高）；
- 结构形态的最终保障是程序给默认模板（第 7 条），字面 checker 退守"最坏形态消除"（类别词完全缺失）。
