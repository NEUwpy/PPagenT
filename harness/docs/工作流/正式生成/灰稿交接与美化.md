# 灰稿交接与成品

灰稿与页面表达是一体两面。灰稿由共同契约编译而来；成品继续读取同一契约，不从灰稿图片反推内容，也不另维护正文。

2026-10-29 明确：main 从 Markdown 文字与图片自动形成灰稿 PPTX，显示实文与蓝色预留区；home 在冻结的页面表达内制作图形、放入来源图片并生成成品。两段自动流转，产品中途不需人工分析或批准。

## 交接内容

- 共同契约版本、页序/目的、稳定内容 ID、来源及主次/关系。
- 文字区和蓝区的所属页、位置、面积及槽位；蓝区表达用途、所承载内容与必要关系。
- 图片原始引用、对应资源、必要图注及所属蓝区；不能只交截图或丢弃资源。
- 灰稿 PPTX、完整预览、检查与运行日志、能力版本和建设审阅状态。

灰稿不制作成品结构图、不放入实际图片；home 按蓝区用途填入并检查容量、几何、内容与来源。以上是目标契约，新增媒体字段须核对 Schema 和实际消费点，不能据文档宣称已支持。

建设阶段可用模拟灰稿先建设 Skin、风格、布局、结构和程序。后段可以由 home 等建设角色推进，完成后以同一契约、输入和预览合并验证。建设时 Codex 可检查图片；产品运行不调用视觉模型。

前段改变页序、内容归属、关系或主次，必须写回共同契约。后段只在契约范围内选择能力和参数；发现表达需要改变语义时退回前段。

当前灰稿交接与受限成稿仍是局部实现。单稿自动完成只记跑通，通用通过另验；固定计划回放和人工美化不证明自动生产。失败保留证据，回所属能力修复后自动重跑与回归，不能以人工补做或仅登记缺口结束建设。完整验收见[产品需求](../../archive/20261030重新讨论前/docs/产品需求.md)。
