# 通用内容规划与灰稿验证

本入口验证永久内容规划环节：完整原稿 → 模型按区域独立规划 → 程序检查 → 另一轮模型语义检查 → 原生灰稿 → 实际审阅及反馈修订。当前只交灰稿候选，不接正式美化，也不表示 M1 或跨稿稳定性通过。

在仓库根目录运行，继续使用既有 `config/deepseek.local.json` 或 Provider 环境配置、运行器状态与 PPT 引擎：

```powershell
node src/runner/gray-draft.mjs --source 原稿.md --output 新运行目录 --width 1170 --height 492 --label 内容区域 --max-revisions 4
node src/runner/gray-draft.mjs --source 原稿.md --output 原运行目录 --width 1170 --height 492 --label 内容区域 --resume --feedback 审阅反馈.md --max-revisions 4
node src/runner/gray-draft.mjs --replay 原运行目录/state.json --output 新重编译目录
```

反复修订未收敛时，可在 `--resume` 时加 `--fresh-plan`，保留旧版本但不把旧逐页规划送回模型，重新依据原稿、区域及反馈规划。

首次输出目录必须不存在；恢复核对原稿哈希与区域尺寸。`--max-revisions` 是本次首轮后的额外修订次数。恢复保留 `revision-N` 与人工反馈；已有 PPT 存在时，新版本放在对应 revision 的 artifacts 下，当前指针见 `state.json` 的 `grayDraft.artifactDirectory`，不能只看目录根部的旧 PPT。

尺寸为真实内容区设计像素，支持宽高 240–4000；主题句在内容区外，画布宽高分别增加80与150。正文22–28px、区域标题26px、主题28px。灰区呈现实文，浅蓝区呈现表达作用、承载内容、基本关系、制作要求。四种验证尺寸无单独分支，页数由模型决定；当前单次规划保护上限100页，超出明确失败，不静默裁页。

`state.json` 是机器真源；`plan.json`、`content.md`、`state.md` 是派生视图。PPT 与预览均从其中页面内容和 regions 构建。`revision-N` 保存模型响应、usage、程序检查、语义审稿及修订；`human-feedback-N.md` 保存外部审阅依据。新调用保存系统提示快照，早期试验的提示变化在本轮报告说明。

程序检查覆盖来源引用、数字与引文的既有保真检查、区域边界/重叠、固定字号容量及原生文本完整性。语义检查对照完整原稿，检查事实、条件、逻辑、分区职责；它未看图片，也可能漏检。导出的 PPTX 会重新导入渲染，`editable-check.json` 核对原生文字，`preview.html` 提供逐页浏览。实际视觉仍须逐页审阅，任何自动通过都不能代替用户验收。

使用同一模型端点的独立审稿调用不是独立外部审查团队。当前不自动分析图像或调用结构库；蓝区表达要求就是灰稿交付内容，不能将其算作已完成图示制作。程序通过但实际灰稿失败时，通过 `--feedback` 交回模型修订，不手写逐页方案冒充模型通用能力。
