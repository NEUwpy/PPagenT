# 角色与提示入口

当前体系架构图及执行关系统一见[体系架构与运行流程](运行流程.md)，本文只维护角色职责和提示入口。

保留内容导演与视觉导演。总控是状态、预算、工具调度与交付责任，不要求增加第三个自主设计 Agent，也不固定每个角色只能单轮运行。

| 职责 | 工作及交接 |
| --- | --- |
| 总控 | 接收要求、保持任务状态、按需提供上下文与工具结果、安排审查和返工、恢复中断、核对交付 |
| 内容导演 | 论证、页面职责、提炼、来源与语义约束；结合整页容量反馈调整组织，不机械按原段落分配 |
| 视觉导演 | 宏观区域、阅读关系、媒介与原生构建；反馈容量和表达问题，不为布局篡改事实 |
| 审查职责 | 从实际产物反查原稿与规则，返回有证据的失败；可由执行者切换审查视角完成，不预设额外 Agent |

## 当前提示来源

两套视觉组合共用同一套任务与角色协议，只加载不同的 Skin 与排版体系；不分别维护完整总提示词。产品目标是可更换底层模型的 PPT 特化 Harness。当前 Luna high 是实验配置，不是能力定义；相近能力模型的迁移仍须在同一任务与验收条件下实测。

## 统一提示体系

| 层次 | 唯一职责与入口 |
| --- | --- |
| 任务输入 | `任务/新任务入口.md`：原稿、受众、用途、交付阶段、视觉组合、输出目录；模型和工具由宿主实际配置 |
| 共享执行协议 | `运行流程.md`、生成任务提示词：持久状态、双导演协作、先整页初模再局部能力、构建与返工 |
| 共享制作规则 | `rules/index.json` 的 generation：内容组织、页面组合、排字与质量要求，两条组合共同遵守 |
| 视觉配置 | 中性 Skin＋杂志风，或东北大学 Skin＋麦肯锡式；各自承担身份与视觉规范 |
| 按需能力上下文 | 已接入的私有结构库、技术图示、数据图表的调用说明、适配约束与真实工具回执；不预读全库 |
| 审查与恢复 | `产物审查.md` 和本次 runs：对实际 PPT 与渲染作判断，记录失败原因、修订及中断位置 |

角色指令统一交代六件事：**职责与边界、所需输入、需要作出的判断、可用工具、交付物与证据、失败后的返回位置**。这是提示协议的共同格式，不要求各角色输出机械 JSON 或把所有正文复制到每次调用。已有规范按其职责引用，不另建平行规则。

**模块化维护与运行时加载分开决定。** 按职责拆文件，不意味着执行者每阶段只能看到一片规则。完整设计上下文可以由适用模块合并后一次加载，再按需补充工具说明、产物反馈和状态。迁移已有有效提示时，先核对正文、顺序、任务模式和制作自由度是否等价；新增解析器、角色限制或审查要求逐项验证，不把它们与文件归类一起默认启用。宿主继续提供多轮工具循环，完整加载设计要求不等于单次API生成。

内容导演与视觉导演共同形成“页面职责＋提炼后的实文＋宏观区域和阅读关系”。结构、技术图示与图表是后续按需调用的能力，不接管页面职责和分页；调用后若容量或表达不成立，返回两位导演调整。初模已经填入真实内容，不能只是文本摘要或空占位框。

当前 `content-director`、`visual-selector` 是已有程序的角色加载入口；尤其后者仍受候选 Schema 限制。当前自主制作读取 generation 与本包执行协议，不能仅加载这两个旧 profile 就宣称完整 Harness 已启动。尚未证明跨模型稳定，也未由代码统一强制以上协议。

## 现行正文入口

- [生成任务提示词](docs/工作流/正式生成/生成任务提示词.md)：当前初模与完整制作任务协议。它是 Harness 的任务入口，不是裸 API 的完整产品实现。
- [规则索引](rules/README.md)：内容导演、视觉选择器等现行角色协议按加载入口读取；现行选择器受其 Schema 约束，不能直接当作目标自主视觉导演的完整实现。
- [运行流程](运行流程.md)：持续推进、审查返工与恢复的共享约定。

给执行者的上下文包括本次输入、当前状态、适用协议、按需能力说明及真实工具反馈。不要用越来越长的初始提示词代替这些动态信息。新增角色协议在本目录维护或迁移现有真源；不复制历史长提示词另开平行版本。

## 既有成功能力的回归

当前中性杂志风回归以用户9月11日指定的第一轮A组效果为目标，C次优、B不作为视觉基线；更早的旧v3样稿保留为历史参考。不能以“已拆分成文件”接受能力倒退，也不能用更多规则检查通过替代整体效果。维护者将旧要求逐项核对到现行责任文件，区分遗漏、冲突、未加载、未执行、工具限制和审查漏检，再修改对应机制；不是看到坏页就追加该页答案。A实际视觉效果与其所有文字规则完全合规并非同一件事，规范是否保留该效果也要验证；无依据内容和非预期遮挡等基础缺陷仍独立检查。

验证使用相同原稿、可比模型与工具环境，记录实际加载内容和版本，由执行者按现行体系重新生成并自主返工；不提供旧构建脚本或该稿逐页修法。对照实际 PPT 和渲染，先恢复既有能力，再用新稿验证迁移。若需对照运行旧 v3，作为隔离的基线实验记录，不恢复成第二个生产入口。工具/额度中断单独记录，不能计为风格失败或通过。
