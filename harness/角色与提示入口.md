# 角色与提示入口

架构与返回路径只在[运行流程](运行流程.md)维护。当前主线为 2026-09-16 确认的 M1–M5，当前聚焦 M1 内容规划，A 效果回归已转为历史参考，不再主导新任务。

| 职责 | 工作与交接 |
| --- | --- |
| 内容导演 | 原稿理解、分页、页面目的、提炼实文、来源与条件；通过当前运行器更新内容状态并派生 content.md，按容量/关系反馈调整 |
| 视觉导演 | 引用内容形成 blueprint.json，决定区域、媒介、阅读关系，结合 Skin/排版构建；需要语义变化时返回内容职责 |
| 运行责任 | 记录 state.md、调用工具、恢复任务、检查和交付；由当前宿主与执行者承担，不增加第三个设计 Agent |

两位导演是专业职责，不要求两次调用、两个进程或独立上下文。检查可由执行者切换视角完成；实际渲染与证据核对不可省略，但不预设专门 Reviewer。程序强制隔离、复杂调度与多 Agent 审查属于后续可选优化。

## 最小上下文入口

- [新任务入口](任务/新任务入口.md)：原稿、演示要求、一种视觉组合与输出目录。
- [生成任务协议](docs/工作流/正式生成/生成任务提示词.md)：最小闭环制作与交付要求。
- `rules/index.json` 的 generation：共享内容、页面组合、排版、质量与所选 Skin 的绑定风格。旧 `content-director`/`visual-selector` 只服务兼容 API 入口，不作为新 Harness 的完整启动协议。
- 已接入能力说明：需要局部结构、技术图示或数据图表时读取，不预读全库，不设调用配额。
- 本次 state.md 与实际工具回执：恢复、失败诊断和修订的依据。

共享规则按职责维护、按当前阶段和需要加载。内容职责读取内容和规划规则、相关风格条件及能力概览，不需要组件内部坐标；视觉职责读取已确认内容关系、选定 Skin/风格和实际所需结构/Skill 说明，不擅自重释稿件事实。保留必要交接上下文，不默认装入全库；当前加载器的实现范围与该组织原则分别记录。流程、模式、工具约束和输入字节的变化分别记录，避免实验混杂。

content.md 的一级标题表示一页；核心结论仅适用时填写。蓝图不复制正文、不锁死坐标；需要调整内容时更新内容真源及受影响产物。不要求另写完整角色报告或 Visual Plan。

## 历史参考的使用

A–H 留有用户偏好 A > C > B、同输入生成波动和审查漏检证据。它们可帮助判断整体效果与机制风险，但不能把 A 的旧脚本或页级答案当新稿实现。严格数值合规与用户偏好不是同一指标；来源错义、伪数据和遮挡仍必须检查。现行能力以 M1 规划、M2 制作和 M3 跨稿的各自验收为准，不能沿用旧通过声明。
