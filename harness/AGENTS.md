# PPT Harness 项目约定

现行重构基线为 `d5efa449`（2026-09-12）。先读 README.md、运行流程.md、角色与提示入口.md 和产物审查.md。以最小完整闭环为主线，旧 API 与 A–H 实验只作兼容能力和历史证据。

当前制作宿主为 Codex，制作模型由创建者实际设置 `gpt-5.6-luna / high`；不通过文字假装切换模型，不安装 Penguin，不以 DeepSeek 为当前前置条件。模型可替换是目标，跨模型效果待验证。

保留内容与视觉两个专业职责，可在同一执行对话中协调，不要求额外 Agent。分页内容 → 页面蓝图与真实内容草稿 → Skin/排版适配与原生构建 → 实际渲染和检查；按失败原因往返，不固定一次调用或逐阶段审批。

任务使用独立 runs/<任务名>/，以 content.md 保存分页实文和必要来源，blueprint.json 引用内容并记录区域/媒介/阅读关系，state.md 记录候选、问题及下一步。暂不建独立 Visual Plan 或全面 Schema。内容变更同步受影响蓝图与产物，不维护多份正文。恢复旧任务可继续原有文件名，先核对其实际状态，不批量迁移历史 runs。

默认完成一种已选风格的可编辑 PPT 和实际预览，不默认停在黑灰初模。仅用户明确要求初模时交付初模。蓝图必须考虑真实内容、基本字号与容量；区域比例、换行和局部分栏可调整，不能把第一次坐标锁死。必要时回到内容阶段，不能缩字硬塞或删掉条件。

生成后实际渲染并检查来源、关系、可编辑性和基础排版；问题简记 state.md，工具证据原样保留，不强制另建审查团队或重复报告。保存首版、自修与外部干预；未通过只能称候选。R1 未实际通过前，不扩大复杂流程、全库路由、多风格或批量基准。

规范从本包读取，工具依赖按外部依赖.md 检查。组合解析器与来源编译试点可按需使用，不作为所有任务必经关卡；选用后遵守其契约。不要默认调用父仓库 npm 入口替代 Harness。既有工具缺失时说明具体阻塞，不伪称已接入。

运行任务只改本次目录；用户要求维护 Harness 时才修改对应共享责任文件并同步。不得把专稿答案写入通用规则、覆盖失败记录或自动晋升核心资产。阶段推进、候选变化或中断前更新状态，续行前核对实际文件。
