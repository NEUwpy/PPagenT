# PPT Harness 项目约定

2026-09-16 起按现行 M1–M5 能力里程碑推进，当前只聚焦 M1 内容规划，尚未通过。先读 README.md、运行流程.md、角色与提示入口.md 和产物审查.md。Harness 是实现手段，不以自研框架完整度计进度；旧 R0–R3、旧 M1–M5 与 A–H 保留历史，旧 API 保留兼容。

多轮工具调用循环由仓库自建运行器 `src/runner/` 承担，不再依赖 Codex 宿主；制作模型按当次实际配置记录，不通过文字假装切换模型（R1 实测为 DeepSeek，密钥经 `config/deepseek.local.json` 注入且不入包）。PPT 引擎仍是 Codex 工作区内的私有包，运行环境因此仍需 Codex 运行时，见[外部依赖](外部依赖.md)。不安装 Penguin。模型可替换是目标，跨模型效果待验证。

保留内容与视觉两个专业职责，可在同一执行对话中协调，不要求额外 Agent。分页内容 → 页面蓝图与真实内容草稿 → Skin/排版适配与原生构建 → 实际渲染和检查；按失败原因往返，不固定一次调用或逐阶段审批。

规划与检查是永久生产环节，调试可交灰稿，投产后后台保留规划与检查、用户只见最终 PPT。三类设计规则为 Skin 规则、通用排版规则、风格规则；美化可微调区域位置和比例，内容分组、主次、关系或拆页变化必须返回规划。灰稿按共享 `rules/排版.md` 使用灰色实文区与浅蓝制作说明区，不把后台分析放上屏。

任务使用独立 runs/<任务名>/；当前运行器以 state.json 为机器真源，content.md 和 state.md 由其派生，不手工改写。content.md 展示分页实文和来源，blueprint.json 引用内容并记录区域/媒介/阅读关系，state.md 展示候选、问题与下一步。暂不建独立 Visual Plan 或全面 Schema。内容变更同步受影响蓝图与产物，不维护多份正文。恢复旧任务可继续原有文件名，先核对其实际状态，不批量迁移历史 runs。

M1 可单独审阅内容与页面规划，并用真实 PPT 提供反馈；不把规划通过计作完整制作通过。正常制作任务默认完成一种已选风格的可编辑 PPT 和实际预览，不默认停在黑灰初模。仅用户明确要求初模时交付初模。蓝图必须考虑真实内容、基本字号与容量；区域比例、换行和局部分栏可调整，不能把第一次坐标锁死。必要时回到内容阶段，不能缩字硬塞或删掉条件。

生成后实际渲染并检查来源、关系、可编辑性和基础排版；问题简记 state.md，工具证据原样保留，不强制另建审查团队或重复报告。保存首版、自修与外部干预；未通过只能称候选。当前不扩大复杂流程、全库路由、多风格或批量平台，只补当前验证直接需要的能力。成熟框架选型留待工作流稳定后，独立部署与商用依赖等归 M5。

规范从本包读取，工具依赖按外部依赖.md 检查。组合解析器与来源编译试点可按需使用，不作为所有任务必经关卡；选用后遵守其契约。不要默认调用父仓库 npm 入口替代 Harness。既有工具缺失时说明具体阻塞，不伪称已接入。

运行任务只改本次目录；用户要求维护 Harness 时才修改对应共享责任文件并同步。不得把专稿答案写入通用规则、覆盖失败记录或自动晋升核心资产。阶段推进、候选变化或中断前更新状态，续行前核对实际文件。
