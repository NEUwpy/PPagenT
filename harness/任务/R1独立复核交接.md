### 请重点打这几处（我认为风险最高的地方）

1. **续跑会不会抹掉上一次的失败原因。** 设计意图是 `summary.attempts[n]` 先存下 `previousStatus` / `previousError`，
   再开跑。请核验：失败→续跑→失败这条路径上，**第一次**的 error 是否还能读到。
2. **`closeInterruptedStageCalls` 必须与前端判据同构。** 模板 `production-workbench.html:107` 的函数 `stageInfo` 里，

   注意它是 **last-wins 取最后一条终态**。服务端收尾用两个 Set（running / terminal）复刻它。

3. **我写交接件时发现的一个真缺陷，已定位、未修（故意留给你复核）。**
   `stageInfo` 的 `terminal` 是 last-wins，于是「同一阶段在上一轮尝试里失败过、本轮正在重跑」时：

   `running` 判为 false → 该阶段在**正在跑的时候显示成「失败」**。
   这正是本轮新加的「继续跑」会走到的路径（续跑从停下的那个阶段接续，而它上次多半是 failed）。
   服务端 `closeInterruptedStageCalls` 用双 Set 不会误关它，**是前端显示不对**。
   我在实现时判断「用 last-wins 映射会错」，但没意识到前端本来就是 last-wins。
   我没有顺手改：本轮的批准计划里写明 `stageInfo` 不动，而且这正好是你该独立复核的东西。

### 复现 §3 A6 那四个数字的脚本

门禁只认 `slide-N.layout.json`，所以要复现 1013/766 必须自己走全仓。把下面这段存成任意 `.mjs`
（路径用绝对路径），`node` 直接跑：

```js
import fs from "node:fs/promises";
import path from "node:path";
const ROOT = "C:/PPagenT";                       // 改成你的仓库根
const SKIP = new Set(["node_modules", ".git", ".tmp"]);
const NAME = /^slide-\d+\.layout\.json$/;
const files = [];
async function walk(dir) {
  for (const e of await fs.readdir(dir, { withFileTypes: true })) {
    if (e.isDirectory()) { if (!SKIP.has(e.name)) await walk(path.join(dir, e.name)); }
    else if (e.name.endsWith(".layout.json")) files.push(path.join(dir, e.name));
  }
}
await walk(ROOT);
const acc = { gate: { files: 0, hits: 0, hitFiles: new Set() }, other: { files: 0, hits: 0, hitFiles: new Set() } };
for (const f of files) {
  const bucket = NAME.test(path.basename(f)) ? acc.gate : acc.other;
  bucket.files++;
  const layout = JSON.parse(await fs.readFile(f, "utf8"));
  for (const el of layout.elements ?? []) {
    const lines = el.textLayout?.lines;
    if (!Array.isArray(lines) || !lines.length || typeof el.text !== "string") continue;
    const fitted = el.text.split("\n").length;                       // 与门禁同一判据
    const engine = Number(el.textLayout.lineCount ?? lines.length);
    if (engine > fitted) { bucket.hits++; bucket.hitFiles.add(f); }
  }
}
for (const [k, v] of Object.entries(acc)) console.log(k, JSON.stringify({ files: v.files, hits: v.hits, filesWithHits: v.hitFiles.size }));
```

预期 `gate` 822/631/292、`other` 191/135/61，合计 1013/766/353。
把 `bucket.hits++` 那行改成按 `path.relative(ROOT, f).split(path.sep)[0]` 计数，
就得到 §3「766 处的分布」那张表（`experiments` 572 / `outputs` 174 / `harness` 16 / `output` 4）。

**这两个数字都直接读自存量 JSON**（`fittedLines` = 存下来的 `text` 里的 `\n` 个数，
`engineLines` = 存下来的 `textLayout.lineCount`），**不重新计算**——
所以字宽系数那次修改**不会**改变任何历史产物的判定，这一点请你自己确认。

**密钥**：`config/deepseek.local.json`（已 gitignore）。**不要把它的内容打进日志、报告或提交里。**
