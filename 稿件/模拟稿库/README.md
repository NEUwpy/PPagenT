# 模拟稿库

当前 M1 阶段（内容规划）专用的仿真稿件库。稿件按真实业务材料的口径撰写，与真实稿基本无差别，用于反复验证"文字 → 灰稿"链路（及后续制作段落）。库内稿件**不带"模拟资料"一类声明**，不写"本文为示例"；使用记录放在各实验目录，不在本库改写稿件。

输入类型与[产品需求](../../docs/产品需求.md#2-四类输入需求)的四类输入对应：

| 库内分类 | 对应四类输入 | 材料形态 | 首批示例 |
| --- | --- | --- | --- |
| `行政信息/` | B 材料转演示（行政文体） | 信息稿：通知、通报、规定，非第一人称 | 固定资产盘点通知 |
| `学术讲稿/` | A 讲稿转演示 | 第一人称讲稿：讲座、汇报口述稿，有叙述线索 | 焊接技术发展史讲座 |
| `学术材料/` | B 材料转演示（学术文体） | 客观成果：论文节选、科研报告，含数据与结论 | 激光焊接接头研究报告 |
| `简短需求/` | D 简短需求转演示 | 一句话或一段需求，先形成内容稿再制作 | "给我讲一个焊接历史的 PPT" |
| （预留）已有 PPT | C 已有 PPT 优化 | 待后半场建设后启用，暂不入库 | — |

## 生成与使用规则

1. **像真实材料**：真实的术语、数据、组织文风与信息密度；不使用"模拟资料""示例稿件"等字样。
2. **登记在前**：每份稿件在下方清单登记类型、主题、篇幅、考察要点与状态；未登记的稿件不入库。
3. **考察要点对齐 M1 的失败模式与能力边界**：对照、分解与构成、时间线、条件—处置、例外密集、多分支归属、长稿分页、超短稿、数字保真；不要每份都是同一结构组合。
4. **可复用不复写**：同一稿件可用于不同基线轮次，使用记录写在实验目录；发现稿件本身有问题才修订，并注明修订原因。
5. **不堆积同质稿**：新稿优先补未覆盖的领域与结构；同一领域最多两份。
