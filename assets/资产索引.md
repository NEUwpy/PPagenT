# 核心资产索引

`assets` 只保存已经进入正式调用、并将在真实稿件中持续优化的首选版式家族。资产按封面、目录、章节页、正文、尾页和结构图分类，不按来源 PPT 分类。

正式 Style Group 资产包固定包含：

- `asset.json`：来源、Skill / Style Group 身份、语义和容量边界、State 控件、Content Slot 契约、HTML 与兼容 Builder 入口；
- `review.mjs`：HTML 审美组件、共享示例内容和 State 参数解析；
- `generate.mjs` / `runtime.mjs`：正式生成入口与内容映射；HTML 单源资产从这里导出组件，旧资产仍导出 Native Builder；
- `example.pptx`：由同一正式入口按声明 State 自动生成的整个样式家族；HTML 单源资产经通用编译器生成，未迁移资产暂由旧 Builder 生成。

迁移后的一组只保存一份 HTML 布局组件，不为二项、三项、四项分别保存代码，也不再另写一份同义 Native 布局；旧 Builder 只作兼容。预览 PNG、布局检查和看板 JSON 是可重建缓存，不属于核心资产。

结构资产的正式颗粒度为 `Visual Skill → Style Group → State → Content Slots`。新式核心包在 `runtime` 中登记 `skillId`、`styleGroupId`、`stateContract`、`mediaContract`，需要二层承载时再登记 `slotContract`；旧 `familyId / variantId` 仅作为兼容字段保留。Content Slot 是父 State 求解后的真实可见区域，不是另一个整页 Composition 槽位。

全部核心资产都由正式生成线直接扫描 `assets/<分类>/<资产>/asset.json`。核心库不再保存或维护中央 `registry.json`；资产目录及其声明就是唯一真源。`html-component` 结构资产由通用编译器读取最终 DOM/CSS/SVG 后生成原生可编辑 PPTX；`legacy-builder` 是未迁移资产的临时路径。Skin 仍由各自运行入口提供。

HTML/CSS 用于复现、审美优化和 State 扩散，也是迁移后 Style Group 的唯一布局真源。正式生成在本地浏览器中求解 DOM/CSS，再机械编译为 Native 对象；不把截图放进 PPT，也不调用视觉模型。新蒸馏或重复版式原则上先进入 `备选资产`，仍需用户明确确认后才可晋升核心库。

`layoutExpansion.mode=responsive` 表示同一版式会针对当前数量重新计算布局；`fixed` 表示数量不是该资产的可扩散维度。登记范围不得超过生成代码实际支持的范围。

当前核心资产：

- 东北大学封面 001、正文 001、尾页 001：复现自东北大学模板第 1、3、4 页。
- 并列能力卡片：`parallel / parallel-cards-p135`，来源第 135 页，支持 3–7 个无先后、无高低的同级项目。
- 双向对比：以“狗哥蓝色-精美逻辑图PPT模板”第 55 页为典型来源，保留镜像双栏、独立承载面、中央关系标记和行列对齐。
- 顺序流程：蒸馏自同一来源的多页顺序结构；正式流程目前只允许基础横向卡片变体。
- 多角色泳道流程：蒸馏自同一来源的多页泳道结构；当前验证 3 角色、3 阶段和独立总结。
- 三层组织树：蒸馏自创意图文模板第 406 页；支持 2–4 个部门、每部门 1–3 人及非均衡分布，并通过东北大学 Skin 全状态验收。
- 中心辐射关系：支持 3–8 个并列外围节点，围绕同一中心主题自适应分布。
- 循环闭环：`cycle / cycle-pdca-ring-p57`，来源第 57 页，支持 3–6 个按顺时针组织的环形步骤；旧的上下孤立卡片轮廓不再作为核心实现。它是首个声明动态 `Content Slots` 的资产，槽位随 3–6 步 State 一起求解，当前默认承载普通文字；子 Skill 的正式候选与组合尚未接线。
- 时间轴与发展历程：支持 3–6 个带时点、阶段标题和说明的里程碑。
- 层级金字塔：支持 3–5 个由核心到基础逐级扩大的层级。
- 转化漏斗：支持 3–6 个逐步收窄的筛选或转化阶段。
- 鱼骨原因分析：支持 4–6 类原因、每类 1–4 条因素，共同指向一个结果问题。
- 四象限分析框架：固定承载四个同级分析象限。
- 分层架构与生态关系：支持 3–6 个来源节点、一个平台层和 3–6 个应用节点。
- 问题与改进措施：蒸馏自同一来源的问题—改进页面；当前验证左右各 2 项的现状/缺口到介入/结果表达。

进入核心库表示允许正式流程调用并接受持续优化，不表示已经完美。用户在真实稿件中指出问题后，应修复原核心资产、容量边界或参数映射；不得临时新造结构替换。

正式运行只自动发现 `status=core` 且具有完整 `runtime` 声明的资产包。备选资产、实验组件和没有蒸馏来源的视觉变体不得进入核心候选集。循环闭环、双向对比、四象限、泳道、金字塔、分层架构、组织树、问题—改进和中心辐射现已走通 `html-component` 单源正式链路；其余结构资产暂走 `legacy-builder`，后续逐项迁移，不批量自动晋升。
