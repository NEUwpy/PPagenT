# P3 实际占位：最小试验

用户同意尝试将结构像普通页面对象一样交给Layout管理，用实际占位替代整块定位矩形禁区。本轮只在本目录实现P3原型，未修改核心结构、旧实验或正式Layout。

## 做了什么

- 从真实渲染树读取图形、文字、编号、状态的边界，转换到页面坐标，含描边与旋转包围框。
- P3按每一级将说明承托面、文字、编号、踏面和连接立面聚合，保护级内留白；状态标签按测量位置归到最近的编号组。当前为明确的P3分组规则，未宣称可自动理解所有结构。
- 各组外围加14px安全距离，得到四段沿阶梯分布的保守占位。不是单一大矩形，也不是精确贴着每条曲线的轮廓。
- 给定要放文字块的宽高，用16px网格枚举可容纳位置。布局根据阅读目的从候选中选择位置；算法不会把所有剩余像素自动视为应该填满的空间，也不自动生成整页构图。
- 新harness先测量结构，再检查正文与占位的相交，随后通过真实invokeStructure生成可编辑PPTX，重导入生成PNG。

## 对照结果

| 样例 | 变化 | 结果 |
| --- | --- | --- |
| baseline | 原800×390定位框，说明放右侧 | 成功 |
| rectangle-control | 同框、同形、同字，说明进入左上空白 | 旧矩形规则拒绝 |
| occupied-fit | 与上一行完全相同，改用实际占位判断 | 成功；结构节点与原始P3逐项深比较完全一致 |
| collision-control | 故意将文字放到第一级 | 被新规则拒绝，回执指出level-1 |
| layout-fit 1 | 阶梯扩大为1168×480，重新枚举可用说明位置 | 成功生成；视觉检查发现末级说明孤字换行，保留中间稿 |
| layout-fit 2 | 区域改为1040×440，保留原文和字号 | 重新渲染后换行改善；作为完整页面候选展示 |

index.html展示原版、同框机制对照、整页候选。三个开关分别展示定位矩形、四组实际占位及14px安全距离、外部文字块。红色区域包含必要留白，所以不等同于“有色像素轮廓”。

## 验证与视觉结论

- 同框对照：原始P3所有节点（几何、文本样式和填充）完全一致，正文原文相同；只移动说明。
- 两项定向测试通过，验证级内区域保护、定位平移、旋转物件、零高度关系线以及必须按当前尺寸重新测量。
- 四份PPTX检查源文字完整、字号仅11.25/12.75/18.75pt（对应中性Skin的15/17/25px）、原生形状存在。
- 已实际查看baseline、occupied-fit、两版layout-fit的PPTX重导入PNG。占位对照解除了不必要禁区；单纯搬入说明并没有自动完成排版，所以另做整页候选并保持视觉验收边界。

结论：**实际占位与定位矩形分开，在P3上可行。**未声称已实现精确多边形绕排、任意结构自动分组、全库支持或Agent稳定整页排版。本轮由父任务执行，未重新运行Luna。

## 文件

- occupancy.mjs：保守占位、P3分组、相交判断及空区候选。
- harness.mjs：独立实验执行器，不影响旧试验。
- build.mjs：同框A/B和碰撞反向对照。
- layout-page.mjs：完整页面布局候选；参数2生成修订版。
- checks.json、pptx-checks.json：技术验证。
- gallery.mjs：检查已有PPTX并生成可开关占位叠层的页面。

已有尝试不覆盖。复跑构建应改用新目录/尝试编号；验证可直接运行 `node --test experiments/structure-occupancy-pilot/occupancy.test.mjs`，展示页可运行 `node experiments/structure-occupancy-pilot/gallery.mjs` 重建。
