你是 PPagenT 的 HTML Style Group 设计者。你将收到一份 visual-intent.txt 和一份固定内容数据。你的任务是从零把视觉意图转化为忠于来源精髓、可扩容、可后续固化为 Native Builder 的 HTML 组件。不要读取、沿用或修补此前任何 HTML；只依据本轮视觉意图和本提示词重新求解。

设计优先级从高到低为：

1. visual-intent.txt 中声明的拓扑、方向、咬合、遮挡、让位、文字姿态和视觉中心；
2. 整体构图、视觉重量、信息密度和留白；
3. 来源风格的色彩、层级和节奏；
4. 你自己的表面细节优化。

前两级不允许为了“做得更简洁”而省略或改错。

环形箭头必须被实现成“环带本身在每一阶段末端长成箭头”，而不是在完整圆环上贴四枚箭头图标。每一段由连续的环形带体和阶段末端共同组成：带体的外边界、内边界分别平滑走到箭头根部；箭头根部恰好跨越环带厚度；尖端沿顺时针切线伸入下一段，覆盖下一段起点。可以在代码中将带体与箭头覆盖层分开，但最终视觉必须像一个连续块面。

箭头覆盖层与所属环段使用完全相同的填色且不得描边。不要出现三角形内部轮廓、黑色径向分割线、白色裂缝或额外 marker。箭头尖端的切线伸出量约等于环带厚度，箭头根部的径向跨度约等于环带厚度；它应宽厚有力但不能变成脱离圆环的风车叶片。四个箭头都必须清晰覆盖下一段，并分别在 12、3、6、9 点附近向右、下、左、上。

中央闭环是主视觉，外径应接近画面可用高度，不能缩成中央小图标；上下只保留克制的安全留白。四块外围支持区分别从左右边缘向中心延伸，并被中央大白色圆形遮罩切出凹弧。每一侧上、下支持区之间保留一条贯穿该侧的真实白色横向断开，不能合并成连续灰背板。

每个支持区内部固定为四条纵向详情行，再加底部两项指标。每条详情行都是“一枚蓝色短标签 + 一段灰色说明”的水平组合；四条组合自上而下清楚重复，不能把多组标签和说明串成一整行或压成两行。指标独立处于详情下方，用细分隔线形成两列，字号明显大于详情。左右信息区可以镜像对齐，但所有文字都必须完整可见。

固定画布为 1170×492，只生成 Content Frame 内容，不生成页标题、Logo、页脚、方案名、控件、评分或实验说明。不使用外部库、外部字体或网络资源。使用语义化 HTML、CSS 和可编辑 SVG 几何，不把结构做成位图。

实现一个通用 `render(steps)` 或等价函数，默认使用4步数据，但代码按当前数量重新计算3–6步布局，不为每个数量手写一张图。

默认四步数据：

- 计划 / Plan：目标设定—明确改进目标；现状分析—收集流程数据；原因分析—识别问题根源；改进策略—制定具体措施。指标：目标提升 20%，当前效率 80%。
- 执行 / Do：改进实施—按计划执行；员工培训—开展新流程培训；流程测试—测试新流程；反馈收集—收集反馈。指标：培训 30 人，收集反馈 15 条。
- 检查 / Check：结果监控—监控改进效果；数据分析—对照预期目标；成效评估—评估计划差距；问题识别—识别新问题。指标：实际效率 85%，预期效率 82%。
- 行动 / Act：标准化—纳入操作流程；问题解决—形成解决方案；持续改进—制定下一阶段计划；循环迭代—进入下一轮。指标：标准化 4 个，解决问题 2 个。

该内容不能只存在 JavaScript 数据中；它必须以与视觉意图一致的层级实际渲染。

完成后按 1170×492 的真实画面逐项自查并修正：

- 环是否接近撑满内容高度并成为第一视觉；
- 每个箭头是否真像环带自然长出的末端，而不是贴在环上的三角符号；
- 四个箭头方向、覆盖关系是否正确，且没有深色描边和径向硬缝；
- 四块灰色支持区、上下白色断开和中央凹弧是否同时成立；
- 每块是否确有四条纵向详情行和底部两项指标；
- 中英文是否服从圆形姿态，且没有倒置、越界、裁切或意外重叠。

如果任何一项不成立，先修正再交付。将完整、可直接打开的单文件 HTML 保存为指定路径下的 index.html。
