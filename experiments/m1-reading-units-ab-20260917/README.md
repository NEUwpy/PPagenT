## 这轮补清的机制缺口

1. **提炼与表达之间没有稳定保持阅读单元。** 本轮 A 图书馆内容阶段已生成“咨询台已统一回答口径。”，表达阶段又拆回两层。因此不能把根因全归到内容模型第一步，更不能假定再加一个阶段名称就会解决。
2. **指导规则未变成可靠行为。** B 内容阶段已出现同义重复，表达阶段继续保留，还加上“已处理／待处理”。本轮两阶段都改，不能分别估计贡献。
3. **审稿漏检与误拒同时存在。** B 的重复和模拟性质遗漏被放过；A 简短稿的合法蓝区却被拒绝。审稿accepted不可当作规划正确的证据。
4. **少标签不是正确目标。** B 长稿保留“东区／西区”“服务点／物资管理员／协调员”有定位和对应价值；B 第二页虽然标签减少，标题保真却变差。

## 用于后续修订的具体阅读参照

以下由主 Agent 在看完本轮结果后整理，未发给生成模型，不是盲评标准，也不代表新一轮自动规划结果。

- 图书馆“咨询台已统一回答口径。”本身就是完整要点，无需再写一次；“预约取书提示不清”与“读者常把到馆通知理解为已完成借阅”有要点与说明分工，可以保留两层。
- 馆藏维护可共同阅读：“破损书目登记已完成；修复仍需按损坏程度排队，登记完成不等于修复完成。”是否拆为两个状态项要看比较任务，不按状态词黑名单判断。
- 文件保存可按对象组织：“个人草稿保存在本机，可离线打开。”“团队定稿保存在共享目录，需要网络连接。”共同命名要求就近附着；两种对象与各自条件无需隔栏寻找。模拟性质仍须可见。
- 东区、西区可作为并列对象标签；三类责任人可作为分工检索标签。这些不是应一律删除的“句子拆分”。

## 交付与复核边界

- `index.html`：三组 A/B，原稿、内容阶段与表达阶段实文，以及实际灰稿。
- `latest/`：四份 PPTX、14 张 PNG、六份原稿/两阶段计划/审稿原始记录。
- `reading-units.json`：逐块列出内容与表达阶段的标签、实文和来源，用来定位缺陷从哪一步出现；没有打分或自动语义判定。
- `verification.json` / `run-evidence.zip`：配置一致性、源文件快照、逐文件 SHA256、全部六次运行；outputs 被忽略也不丢证据。
- 本轮没有改生产契约、共享规则或求解器，也没有迁移 Harness 镜像。没有因为负结果启动第二轮采样。

下一步应针对这里已定位的转换做可执行验证：完整句经过表达阶段是否仍完整、真正的对象比较是否仍对应。若尝试独立单元形成步骤，需要与本轮候选另做对照，不能把本轮称为该步骤已验证或缺口已解决。

## 实验设置

问题：把完整事实拆为“状态标签＋对象残句”，再把它当成要点与说明，会制造无价值层级。此次检验在现有 blocks/text/可选 label 中补足单元形成与表达复核，暂不增加阶段、字段、评分器或求解器规则。

- A：现有内容、表达、审稿契约；布局采用已验证字段互斥的 layoutOnly，隔离布局协议错误。
- B：仅替换内容阶段的组织顺序段与表达阶段的单元检查段；其余相同。不提供任何测试稿的改写答案。
- 三稿：图书馆分类稿、东区／西区长稿、简短文件保存稿。每稿 A/B 各一次独立从原稿生成，不承接旧计划或审稿反馈，不择优重跑。
- 同一模型配置、共享规则、尺寸、字号、审稿和求解器；maxRevisions=0。保留全部请求、响应、失败与快照。
- 人工比较：完整阅读句、必要展开、分支与比较维度、限定与关系、分页和实际灰稿。导出/审核通过不是 M1 通过；三个单次配对也不是稳定收益证据。
- B 是内容＋表达两处的联合干预，不能分别归因；未固定随机种子，模型随机性仍是限制。生产默认契约暂不变。
