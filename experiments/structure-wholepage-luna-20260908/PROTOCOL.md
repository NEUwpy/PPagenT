# 整页任务验收：结构调用是中间步骤

本轮对应用户明确纠正：在应该使用结构的页面，Agent 应正常选择和调用结构，并完成整页排版。上一轮的“首轮技术成功7/12”不是此任务的通过率。

## 实验设置

模型：Luna high。固定当前中性 Skin 和首批三个保留造型结构实现，提供三份业务稿件，分别包含并列条件、逐级筛选、成熟度及下一步重点。不给坐标或预定页面模板；Agent 自己决定结构选择、内容分工、位置、区域与阅读顺序。允许使用现有输出 harness 或直接调用结构入口，禁止改变原造型和固定字体角色以凑页。

每页先记录主旨、阅读顺序及内容分配，再构建、渲染最终PPTX并检查；最多三次自主尝试。父任务检查后的修订必须与自主结果区分。已有harness仅保证技术边界，不替代视觉判断；若其矩形占区约束妨碍合理编排，记录为执行接口限制，不作为设计要求。

## 逐页验收依据

1. 内容与关系：所给事实完整、关系结构正确；P1无顺序，P2不引入虚构数量，P3保留当前2级和目标4级。
2. 整页组织：页面重点清楚，标题、结构和解释形成阅读顺序；不存在两个互不相关的图文堆。
3. 内容分工：结构承担关系表达，外部文字提供必要解释或行动；不反复复述同一段，也不把布局说明放进成品。
4. 空间与对应：相关文字靠近或明确对应对象；结构大小服务本页内容，留白分组而非由不可用内部空区制造；无重叠、裁剪、孤立标点或压线。
5. Skin与结构：沿用中性字体字号及用途色，保留原图形识别特征；不以机械缩字绕过问题。
6. 输出：真实调用记录、可编辑PPTX及最终PNG。技术成功但以上项目失败，仍判整页未通过。

由父任务逐页给出“通过候选／需修订”及证据。不以自动对象数量或模型自评充当整页视觉验收，也不以三页样本推断总体稳定性。
