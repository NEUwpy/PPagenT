# 调用结构并完成整页排版：三页复验

## 结论

按用户纠正后的完整任务标准，这轮**尚未整体通过**。Luna high 的三个首稿均成功生成，但父任务整页检查为0/3通过。收到具体反馈后，最终P3为通过候选，P1/P2仍需修订。不能将调用成功说成排版完成，也不能把通过候选视为用户已验收。

本轮没有让父任务代画失败页再计入Luna成绩。全部页面与三次稿件均由同一个Luna high执行者制作；首稿后的修订有父任务具体视觉反馈，因此最终1/3候选也不是自主首次成功率。

## 过程与对照条件

- 给出三份业务稿件、当前中性Skin、结构Skill和可用执行接口，没有指定页面坐标或左右/上下模板。
- 要求Luna先决定页面主旨、阅读顺序和内容分工，再选择结构、实际调用、导出并检查PPTX。
- 结构造型与Skin字号固定，未为试验改库内几何。Luna自行选择继续使用上轮harness，因而仍受到“结构整体矩形与外部文字不能相交”的接口限制。该限制不是用户的设计要求。
- P1另有一次icon参数无法解析的输入失败，保留于P1-invalid-input-attempt-1。每页后续各有3份已渲染稿，共9份PPTX。有效首稿的3/3技术成功不能隐去先前输入失败。
- 三份原始稿件见manuscript.json；逐页主旨与尝试计划见luna/layout-plan.json。父任务看过首稿和第三稿的实际PPTX重导入PNG，第二稿仅保留为修订证据，不宣称进行了独立视觉验收。

## 查明的限制

1. **Agent层面**：规划记录写了“阅读顺序”和“图文对应”，实际调整仍多是移动文字块与改变区域尺寸。仅增加规划说明，并没有保证落实到视觉关系。
2. **接口层面**：结构区域包含内部留白，而harness以整个矩形禁止外部文字进入。此次P1按高度缩放后，实际卡组只占所给大区域中间的一部分。调用者若仅看targetFrame，难以按真实图形边界组织页面。
3. **验收层面**：技术检查可以发现越界、字体异常和构建失败，但无法识别这种图文割裂与无意义留白。应保留最终整页人工视觉判定。

以上支持“整页排版目标尚未稳定实现”，并不能把全部原因归给结构代码，也不能说明结构Skill方案应废弃。下一步若继续实施，应优先解决实际可见占区/锚点与页面排版的协作，再用相同稿件复验；不应通过增加大量几何参数或让Agent自由重画掩盖问题。
