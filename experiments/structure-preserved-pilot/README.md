# 首批 3 个结构：保留原造型的区域适配

> 本目录保留上一阶段的 24 份字号锁定样本；当前实现已继续修正字号和小配件。最新证据见 [尺寸试点](../structure-size-pilot/README.md)。下文是上一阶段记录，重跑默认脚本会使用当前实现。

本轮按用户修正后的目标重构：沿用现有造型，放宽放大、缩小与区域适配；不让模型读特征摘要后自由重画。仅改折角便签、简明漏斗和成熟度阶梯的绘制入口，其他 32 个结构未迁移。

## 已实现

| 结构 | 保留原实现 | 本轮调整 |
| --- | --- | --- |
| 双排折角便签 | 纸面、卷页、底影的原曲线路径，标题带、图标和两排居中节奏 | 卡片、间距和标题带按同一比例变化，正文按新宽度换行；不再用固定字符上限代替实际测量 |
| 简明漏斗 | 原圆台曲面、顶部椭圆、随形渐显箭头、输入图标和外围轨道 | 以真实中心造型占区等比适配；缩小时重新安排最窄层标签宽高 |
| 成熟度阶梯 | 原踏面、立面、接缝和共同透视计算，斜向文字承托面与状态标记 | 消失点与几何一同变换；说明区按可读需求保留宽高，承托面跟随文字区变化 |

新入口为 invokeStructure 的 execution: preserved-design，调用者提供语义 content 与 targetFrame，不再重写 build。guide 中的 implementation 给出是否支持此入口。对应绘制实现仍是资产原 review.mjs，通过新增 renderAdaptiveMarkup 提供适配。

文字保留当前 Skin 的字号；无法完整排下会拒绝，不降低字号、裁掉稿件或修改造型撑满区域。HTML/DOM 仍用于测量和编译，但没有恢复要求用户填 State 或固定文字框坐标的界面。

## 实测

每种结构 8 组，共 24 份单页可编辑 PPTX，每份均已导出后重新导入、保存 PNG。index.html 并排展示 HTML 和 PPTX 重导入结果，可点击下载对应 PPTX。

- source：原实现，1170×492。
- same：新入口，同尺寸同稿件。
- large：1404×590.4，几何 1.2 倍。
- small：994.5×418.2，几何 0.85 倍。
- narrow：900×600，保持比例并居中，不横向压扁。
- wide：1350×440，保持比例并居中，不拉伸撑满。
- more：便签从 4 到 8 项，漏斗与阶梯从 4 到 6 层／级。
- content：放大区域中换稿；便签首项含超过旧 4 项状态字符上限的说明，全部保留并重新换行。

24/24 均有可编辑路径／形状、完整源文字与实际重导入 PNG，见 deliverable-checks.json。图标沿用现有 SVG 图像节点，不宣称每条图标描边均是 PowerPoint 独立形状。report.json 保持技术状态 rendered-unreviewed；父任务视觉结论另列如下，不把成功调用当视觉验收。

## 父任务视觉复核

- 已查看三张完整联系表覆盖 24 页，并放大核对便签长稿、窄区阶梯及漏斗原样与缩小结果。
- 卷页、完整底影与标题带可辨；同尺寸新旧构图一致，缩小后正文换行而字号不变。
- 曲面漏斗、外围输入和随形渐显箭头可辨。实测发现 SVG 渐变转 Native 的位置范围、方向及透明起点换算有误，已在共享编译器修复并重导出全部漏斗样本。
- 阶梯保持连续踏面／立面、统一透视、斜向承托面；窄区增加文字可用空间后不再溢出。
- 本轮结论：这些代表样本达到保留原造型、可读、内容完整的候选标准，供用户查看。尚不代表用户视觉验收，也不是全库完成。

## 代码验证与边界

新增定向测试直接比较同尺寸原实现与新入口的非文字节点几何和填充，3 个结构一致；另检查缩小后的文字字号不变、长文本超出时拒绝，以及 SVG 渐变位置与透明度的正确转换。相关运行时和 Skill 测试通过，git diff --check 无错误。

数量范围仍为便签 4–8 项、漏斗 3–6 层及 0–7 输入、阶梯 3–6 级。保持当前朝向和排布，尚不支持任意折行、任意小区域或超出范围的数量。按当前稿件和目标区实际测量；极端长稿可能拒绝。当前矩阵只验证默认 Skin，没有完成其他 Skin 的逐样例视觉复核；旧双导演 API 工作台仍独立运行。
