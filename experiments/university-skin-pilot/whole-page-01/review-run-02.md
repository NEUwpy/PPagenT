# 文字反馈后的修订：REVISE

同一 Luna/high 任务接受指南 v2、首轮评审和 pt/px 接口事实后修订，约 293 秒。父任务在完成后查看两张直接预览、最终 PPTX 再渲染的两张预览、builder、报告和实际布局。未手改执行者产物。

## 已改善

第 2 页从名词清单改为“记录什么、不能替代什么、授权问题怎样处理”的完整解释，保留了暂停与负责人处理后继续的条件。结构文字单位已纠正：节点正文实际为 20 px。错误的正负对比页本轮移除，因此没有继续出现打叉收益、打勾代价；这不证明比较选型能力已修好。

## 仍未通过

- D1：第 1 页仍使用原来的整页中心辐射，说明被插在左侧节点之间。独立文本框不代表独立且合理的阅读区域；说明的横线与段落打断结构原有轮廓，靠近下方节点且缺少阅读停顿。构建代码先调用整页结构，再在其内部 (56,468,390,84) 加文本，未完成共同分配空间。
- V2：实际文本行第 2 行以逗号开头，第 3 行仅“产生”。这一点可从 layout 的 textLayout.lines 直接发现，不需要执行者看图。零文本 bbox 重叠不能证明断行和留白合格。
- C1：“图外解释”出现在面向听众的小标题中，暴露制作标签。
- S2：报告声称已保留“清洗另存”，实际该词及相应明确表达没有进入页面。它也没有展开清洗处理与原始数据的区别，不能把字段名称视为完整保留语义。
- V1：结构 CSS 的混合对齐、阴影及中心小字限制仍存在，整页样式没有统一。第 2 页虽更完整，仍有较长的横向解释、较大的空区与重复的标题引导，需要继续改进视觉分配，不能仅凭文本增加认定审美成立。

## 当前结论和下一步

指南的研究对象已正确转向整页，但 v2 还没有形成可独立稳定执行的设计办法。结构调用与文字解释分别有进展，二者的空间组织仍未通过。输入冻结见 revision-inputs.json；本轮属于反馈修订，不能当成冷启动成功。

下一步先落实“共同分配空间”的可执行办法：根据图外解释的自然尺寸，确定图可用区域；再筛选能在其中保持自然尺寸和关系的资产。结构内部未声明的空隙不能直接当成图外说明区。有意的节点标注仍须明确指向对应节点，与任意塞字区分。同步查明实际所需资产的样式可配置性，不以继续增加提示词掩盖接口限制。

当前不再追加同一结构的局部补字试跑，不迁入正式 Skin/Harness。只观察到本轮资产的限制，不能据此断言整个库均无法适配。
