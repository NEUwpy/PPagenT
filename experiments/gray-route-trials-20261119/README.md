# Markdown → 灰稿路线试验

2026-11-19，基于当前工作区架构及基线 `acaf72e3`。三路由同项目的 GPT‑6.2 Sol 极高推理窗口独立制作。它们共读最新版文档和原稿，各自在实验目录写入。三路共用 1280×720 画布、1170×492 默认正文区、18px 正文字号下限和原稿信息保留要求。各路线对资产品种、文字分槽和排序有不同实现，比较以实际结果和代价为依据。路线建议归入[技术选型与决策](../../docs/技术选型与决策.md)。

对照的前三稿在三路最终版均通过各自灰稿门；三路都以源内全文为基准保留范围、条件与事实。人力稿中的「2017」「唯一」和「作风改进不要求立竿见影，重在持续用力」亦在可见正文。高密度稿保留原段重复，用作容量负例。路线各自保留了最初和最终测量，不以成图代替放行。C 同时检查所测对象是否进入交接树，实际 PPT 的一致性见独立探针。

- **A 值得复用的部分**是中性多维比较、短内容便签、共同条件带及一条候选就可放行的运行方式。原尺寸便签直接塞进短主区，以及将丰富的四点感悟强行塞进标题和正文均受限的便签，均有实测失败。[A 运行与失败证据](template/README.md)
- **B 的增益出现在要同时决定组宽和图示容量的页面。** 汇聚部件复用了原路径、输入和结果形状，在实验副本调整了容量和尺寸绑定。53 个候选中 16 个达到 HTML 门槛，失败能指向具体组或槽。它目前按已知稿件冻结语义和候选起点，跨稿候选生成器仍待验证。窄区纯文字余量约 2px，适合作为实际 PPT 换行验证的临界样本。[B 运行与候选证据](compose/README.md)
- **C 适合发现新表达。** 窄服务页零新增布局代码也能重排，保留这一做法有价值。自由 CSS 的视觉结果超出交接表达时，需要模型或作者提出可编译的替代。人力页反复手调、首次任意斜角无告警丢失，限制了这种自由度作为默认主线。[C 运行与编译失配](authored/README.md)

## 跨稿与运行分工

另取备件供应、汛期值班两份模拟稿及一份共同上线稿，从 Markdown 读入同一窄接口。GPT‑6.2 Sol 冻结响应的 38 条引文全部能逐字回溯，三份原稿在默认与窄区各通过一次，共六页。特意压到 770×270 时三稿均显式拒绝。源记录和组范围的结构门挡住了假引文和未知组，但漏掉了采用真实引文的否定义务反转，以及引用有效组 ID 的错误作用范围。[冻结响应、代码与失效反例](bridge/README.md)

同一窄接口接上真实模型后，三份模拟稿都自动生成了默认幅面的灰稿与布局文件。两份稿漏掉了具体执行方式，另一份因文案重复在窄区被拒。第二次审稿能补回备件执行方式、消除汛期稿重复，也出现了发现漏项后正文仍未补全的情况。几何合规和审稿回执都不能代表语义已通过。[真实调用与修订证据](bridge/README.md#真实模型调用)

同一服务稿使用现有 DeepSeek 适配，一次结构化请求能进旧语义校验。旧工具循环实跑八轮卡在提交接口，把首轮计划取出单独校验即可通过。旧布局器给对照稿生成七个几何候选，七个都无法表达正确的对照关系。JEV 两个请求返回 HTTP 401，本轮无法比较它的选择质量。原有语义标识、规则、trace 与校验有复用价值，旧循环、旧布局选择和新职责之间需要显式接口。[运行实测与受控注入](runner-reuse/README.md)

## 灰稿 → PPT 边界

汛期稿当前的布局结果直接写成 13 个可编辑原生文字框。PowerPoint 实际打开，文字完整，XML 中框坐标最大差约 0.00004 CSS px。两个文本框少了一行，PowerPoint 报告的实际文本最远约超出框右边 16px；另有一处行数相同仍超出 12px。文字框在位、同样的字号和行数都不足以放行。应输出字符范围和任一实际渲染差异，按页、组件、文字框回写。

已有汇聚整页导出含 38 个原生对象和 1 张原校标图片，三条路径可编辑。现有树的采样点近似曲线，从资产源补入三次贝塞尔指令可以保留曲线。两种路径都没有连接器联动。旧树缺少部分单边线与内联文字样式，页壳渐变也未完整还原。PptxGenJS 4.0.1 可作为首个开源候选验证已测原语，完整版式、图表、连接与部署仍待验证。[原生文件、PowerPoint 导图和审计](handoff/README.md) · [PptxGenJS 4.0.1 许可证](https://github.com/gitbrent/PptxGenJS/blob/v4.0.1/LICENSE)
