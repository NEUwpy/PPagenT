# 中性 Skin：Luna high 结构调用与布局压力实验

2026-09-08。对象为双排折角便签、简明转化漏斗、成熟度阶梯三个 preserved-design 试点。12 个案例，三组 Luna high 执行者各处理四例。

## 结果

**三个结构能在完整中性 Skin 页面中调用，受约束的原造型方案可继续使用；目前不能宣称 Luna 可稳定自主处理所有布局与压力恢复。**

- 首次技术成功 7/12：a1、a2、a3、b1、b2、c1、c2。首次失败 5/12：a4、b3、b4、c3、c4。
- Luna 后续 11/12 案例曾生成对象，但 b3 关系选错，c3/c4 改短了稿件，因此 11/12 不能作为质量通过率。
- 父任务补做四例：a4 调整相交分区、c3/c4 恢复原稿做同稿扩区、b3 纠正收敛关系。四例均成功生成。最终展示页含 8 份 Luna 输出和 4 份父任务对照／纠正输出。
- 21 份成功尝试均检查导出 PPTX 中源文字完整性、文字角色字号与可编辑对象；失败尝试也全部保留。三张联系表覆盖最终 12 页，另放大检查密集便签与六层漏斗。当前为视觉候选，尚未经用户确认。

Luna 的原报告保留在 a/b/c 下，部分结论被本审计纠正，不能单独引用为通过证据。追加复核时 Luna 遇到使用额度限制，父任务接手完成四个对照，明确标为 parent，未冒充 Luna 执行。

## 本轮实现修正

1. 中性 Skin 的角色数值是设计 px，结构 CSS 接口是 pt：17px→12.75pt，15px→11.25pt。固定字号通过 Skin 显式传入，允许遵守其合法值；默认结构字号阶梯及12pt下限未取消。不能把15px误当成15pt，也不能因默认阶梯覆盖 Skin 角色。
2. 新增三结构的中性语义样式适配，按 Skin id 启用。便签采用纸面与浅标题带，漏斗与阶梯使用浅承载、细轮廓、深色文字；图标使用少量砖红，去除无职责的组件投影。保留折页、曲面、连续透视与随形箭头。便签折页的底影属于原设计识别特征，保留低对比表达。
3. 首轮发现便签第2/3张的旧 nth-child 样式优先级覆盖中性标题带，已修正并同稿重渲染。
4. harness 处理真实结构调用、完整页面、分区相交检查、HTML测量、PPTX导出／重导入及证据保存。页首和页码单行行距已修正；部分早期 Luna 页面保留原页首基线状态，未伪装为同版重跑。

## 如何解释实验

Luna 自己读 Skill/guide、选择 assetId、映射 content、给出页面分区、调用 harness 和分析回执。父任务提供了稿件要求、三个试点范围、固定 Skin 和共享执行器。这是受控调用实验，不是全库盲选，也不是正式双导演生产线端到端验收。没有运行多随机种子或重复批次，不能从一次12例推断总体稳定性。

源文字完整性校验只保证每次传入的文字存在于 PPTX，不能识别“重试前改稿”。所以父任务另外对比初稿与重试稿，才发现 c3/c4 的对照变量改变。类似地，nativeShapeDelta 和成功回执不能发现 b3 的关系误选。

下一步应优先完善三点，而非扩大自由度：选择时明确区分筛选与成熟度；恢复时先做区域相交检查再试容量；记录重试前后的稿件差异。长说明可分到图外，但必须作为明确的内容安排变化记录。

## 文件与复现

- index.html：最终12页、所有尝试与失败原因、单页可编辑PPTX下载。
- audit.json：以父任务审计为准的结构化结果。
- a/b/c：Luna 原稿、选择记录、脚本、逐次产物与回执。
- parent：父任务同稿对照／语义纠正，不能计入 Luna 自主成功。
- harness.mjs：共享执行器；已有 attempt 编号不可覆盖。
- collect.mjs：重新检查已有产物并构建看板与联系表。
- parent-controls.mjs：父任务四例的可读执行源码；重跑需新输出目录／尝试编号，避免覆盖证据。
