# 无图片网格编排闭环：2026-09-05

## 结果与证据边界

已跑通有限能力下的正文闭环：一个逻辑 PPT Agent，独立内容/视觉上下文，通过持久化项目编排，Native 文字/网格数据反馈，局部修订后生成可编辑 PPTX。模型没有接收图片。最终人工检查了全部四页，独立 overflow 检查通过。

输入是本分支新构建的虚构[共享仪器试稿](fixtures/grid-manuscript.md)，包含目标/边界、比较、顺序与贯穿规则、检查项。稿件没有逐页版式答案。试验不是产品质量或普遍审美认证，也没有证明费用已达到产品要求。

## 实际发生的闭环

1. 内容阶段从原稿自主生成 5 页，12 个来源段落全部绑定。
2. 视觉阶段提出区域方案；三列文字中一项不能按固定字号排下。模型只修最后一页，改为三个纵向文字区，其他方案不动。
3. 第一轮 Native 结构编译因 MCP 未传递 Windows 浏览器环境而失败。修复环境传递后从项目继续；补上宿主依赖错误快速停止，防止模型重复修页面。
4. 5 页初稿里，异常规则单独成页的占用估计仅 7.6%。旧软提示允许模型以强调留白解释，未满足本轮用户要求。
5. 第二轮复用已保存内容和方案，按本轮稀疏限制重新检查。视觉 Agent 自主请求重组 `booking-flow` 与 `exception-rule`，内容阶段只合并这两页，保留全部来源。
6. 新视觉上下文自主选择“上方三步核心流程 + 下方异常规则文字条”，没有把贯穿规则误画成第四步。最终 4 页中 3 页为文字区域编排，1 页为真实 Structure + Text 混合页。
7. 其余 `pilot-scope / coordination-modes / first-round-checks` 的页面内容与 Composition 和第一轮逐字段一致。

最终混合页文字占用网格比例 31.25%，最大空矩形占正文区 16.67%；正文居中，对齐一致。其他文字页沿用统一左对齐。上述指标来自 Native 文本框与行的字形占用估计，装饰和空框不算文字密度。

## 调用与成本

第二轮是基于第一轮项目的修订实验，不是全新稿件基线。三个模型阶段合计 11 次请求、11 次工具调用；模型阶段约 265 秒，原始整轮约 270 秒。累计上下文 token 115,208，其中 cache read 70,784、cache write 17,791、output 26,633。这些不是 115,208 个新输入 token，也不是实际账单金额。

第一轮的源稿内容生成、环境失败及恢复成本另存证据，不计入上面的第二轮数字。当前 DeepSeek/Penguin 适配中，配置的 4K 输出额度仍未可靠约束返回量；去掉图片不意味着整体推理成本问题已经解决。后续应先约束模型思考/输出预算、压缩重复工具结果，再建立同稿成本基线。

## 合并与复现

当前分支只增加一个基础网格、基本文字适配器和现有 `sequence-flow-001` 的调用，不扩建正式 Layout/Structure 库。本轮新实现不修改正式 `src`、`assets`、`catalog` 或 `schemas`；工作区原先存在的修改另行保留。

公开证据位于 `evidence/grid-loop-20260905/`：最初与最终项目、阶段统计、第二轮工具记录和验证摘要。无密钥或会话私有目录。运行入口与参数见 README；可以把保存项目作为 `--seed-project`，但复现新模型决策不保证逐字相同。
