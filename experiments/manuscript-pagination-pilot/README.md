# 未预分页稿件：整稿到页面的实文组织

## 本轮问题与条件

在原稿未标页码时，能否先固定来源，再形成页面职责清楚且不丢条件的内容组织？本轮主任务编写模拟稿、选择两种分页并核对结果。没有独立执行模型、没有调用生成 API；不能当作冷启动或跨稿稳定性证据。原稿虽无分页标记，但论述顺序较清晰，尚不构成乱序、跨段指代或长稿挑战。

## 实际产物

- `manuscript.md`：新模拟稿，包含观察、估计投入、选择依据、并列门槛、回退与因果边界。
- `two-pages.md/json`、`three-pages.md/json`：两种候选，JSON 同时保留来源引用计划及编译后的真实文字。
- `verification.json`：原稿哈希、覆盖结果及故意漏掉最后一段的拒绝记录。
- 复跑：`node experiments/manuscript-pagination-pilot/run.mjs`。

## 本轮判断

选择三页方案作为下一步试排候选：P1回答为何先核对原因；P2回答为何选B及其负荷约束；P3回答如何采证以及何时扩大或暂停。三页分别为266、261、254字符（含原文标题及标点），两页方案后页为515字符。这些只是内容量记录，不是容量测量，也不能据此判两页放不下。

两页方案覆盖同样完整，但把方案选择、试点执行与扩大范围三个决策任务合在后页。三页方案更容易分别检查决策依据与进入条件；代价是读者需要跨页连接试点选择和评审。本轮未使用视觉结果证明三页优于两页，保留两者供后续验证。

逐页语义核对：

- P1：当周总预约数是两组比例的分母，保留可能重叠且不可相加；原因未知、考试周期和不能直接增容与观察同页。
- P2：两方案范围相同；准备工作量与每周维护分开，保留不含维修与估计性质。B的依据是补全故障信息，不是投入更低。1.5工作日是可投入容量，不是已达标状态；超负荷回退仍在本页。
- P3：采证、原因分支、三个同时成立的门槛、失败时保留规模及记录都保留；无对照不能证明因果仍与评估同页。

此判断为作者自审。机器输出仍保留 semanticStatus=unreviewed，未伪装独立复核；尚未经过实际 PPT 排版及视觉验收。

## 最小实现与验证

复用 `src/content/source-blocks.mjs` 获取段落 ID、文字和原文位置。新增 `prepareManuscriptDraft` 从完整原稿派生来源，检查原稿哈希、未知来源、遗漏、重复，然后从来源取回原文，调用已有 prepareContentDraft。调用方不能再提交一份删减后的单页原文来证明整稿覆盖。

故意移除 source-010（扩大范围门槛、失败动作、无对照边界）后，入口在单页编译前拒绝。16项定向测试通过，覆盖旧分组/组合行为及新入口的整页遗漏、跨页重复、未知引用、过期哈希和正文替换。

边界：这是独立制作的可调用入口，尚未接入正式 CLI；不自动分页或判断关系正确性。本轮仅支持每个来源块使用一次，不支持摘要、块内拆分和有理由的跨页复用。标题也作为来源块保留，尚未建立标题元数据豁免。新增关系 context 只用于内容分组，不能直接塞入现有 composition-intent 的封闭关系枚举；视觉计划仍须明确映射。
