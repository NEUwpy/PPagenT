# 结构检索与实际采用

按 `ppagent-structure` Skill 的要求先按内容关系检索，再核对候选契约。

## 检索结果

- `comparison-dual-verdict-001`：双对象、两侧各 3–5 条一一对应短要点，单条上限 16 字；适合对称逐项比较。
- `comparison-pros-cons-balance-005`：同一决策的收益—代价权衡，左右各 2–4 条并给出倾向结论。
- `sequence-flow-001`：3–6 个有明确先后的连续步骤，但明确不适合分支或授权门禁。
- `sequence-phase-gates-004`：3–5 个阶段及相邻门禁，容量为短阶段说明与短门禁条件。

## 实际判断

本轮没有执行 `invokeStructure`，没有把候选结构的示例事实带入页面，也没有声称直接调用成功。

- 第 2 页虽然具有比较关系，但原稿需要较长的条件、代价与“没有效率证明”边界，超过 `comparison-dual-verdict-001` 的对称短条契约；采用其“共享维度、中央结论”的关系作为参考，重组为原生双栏。
- 第 3 页包含授权变化时暂停共享的分支，`sequence-flow-001` 明确避开分支；`sequence-phase-gates-004` 的阶段/门禁容量又不足以承载四步主线和授权说明。因此参考“连续轨道 + 门禁”语义，自主用原生节点、线和箭头绘制。
- 第 1 页是五类材料共同解释一个结果，不是顺序流程或两对象比较；第 4 页同时有时间阶段、评估依据和多项停止触发条件，均不适合直接套用单一组件，采用自主原生表达。

实际采用方式：候选结构用于关系判断和容量约束；最终四页均由 artifact-tool 原生可编辑形状实现，保留事实、方向、条件和限制。
