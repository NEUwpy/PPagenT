# 设计记录

## 沟通任务

读者看完四页后，应能按四个问题理解一套拟定的结果归档与复核试点：先知道记录单元如何共同解释结果，再看到新增与历史补录的范围取舍，随后理解带授权门禁的复核主线，最后依据四周试点证据决定保留、修改或停止。

## 页面分配与理由

1. **结果记录**：把五类材料放在同一“结果可解释”中心周围，用连线表达共同解释关系；左侧单独放“完整记录 ≠ 全部开放”，把访问边界从记录内容中抽离出来。
2. **范围选择**：两栏共享同一问题维度，中央结论把“新增先行 / 历史按需”作为范围选择；底部保留“没有证明效率提升”的证据边界。
3. **受控复核**：四个编号节点沿一条横向轨道推进；授权变化用下方虚线门禁表达暂停与继续；页底界定复核范围。
4. **四周试点**：上方先锁定拟定范围，中部时间轴组织四个阶段，底部把评估依据与停止触发条件并置，最后保留“没有实测效率或完成率”。

## 视觉系统

- 画布：1280×720；背景 `#F4F8FB`，主题蓝 `#315F91`，深蓝 `#17324D`，浅蓝 `#EAF2F9`，黑灰正文与 `#B8C9D9` 结构线。
- 字体：Microsoft YaHei。页面标题 38px，主体正文 16–20px，辅助标签 14–15px；正文容器使用 `autoFit: shrinkText` 但通过 layout export 检查实际字号。
- 形状：全部为 artifact-tool 原生可编辑文本框、矩形、圆角矩形、圆形、箭头和线；没有图片、位图或不可编辑插图。
- 版式：统一顶部问题编号、标题、页码与分隔线；每页改变分析区剪影，避免四页都成为同一种卡片网格。

没有读取图片、旧实验、参考笔记、其他候选提示、旧 builder 或记忆；没有委派或 Git 操作。没有外部资产，因此没有外部资产来源块；每页 speaker notes 保留 `[Sources]`，注明唯一用户源 `source.md`。
