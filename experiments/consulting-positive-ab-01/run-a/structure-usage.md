# Structure usage

按 `ppagent-structure` Skill 的要求，先对稿件关系做检索，再决定是否直接调用组件。

## Catalog queries

查询了可用逻辑总表，以及 `containment`、`comparison`、`sequence`、`progression`、`convergence` 五类逻辑。重点检查了以下资产契约：

- `containment-consensus-field-005`：2–5 个同级主体共享一个中央共识场；适合共同交集，不适合本页五类记录要素与开放边界。
- `comparison-pros-cons-balance-005`：单一决策左右各 2–4 条收益/代价并要求综合倾向；可参考对照语义，但 Page 2 的两条路径含长段限制、建议和证据边界，超出其短要点容量。
- `sequence-phase-gates-004`：3–5 个阶段及阶段间门禁；Page 3 的四阶段主流程相近，但授权异常是独立暂停分支且每阶段正文较长，未直接调用。
- `progression-spectrum-focus-001`：3–5 个沿连续共同维度分布的区域，禁止连接线；不适合 Page 4 的真实四周时间事件与去留判断。

## Decision

本轮采用“检索后自主绘制”。没有执行 `invokeStructure`，因此没有把任何页面报告为直接调用成功。自主绘制保留了检索得到的有用关系判断：Page 2 的左右权衡、Page 3 的有序推进与异常分支、Page 4 的时间顺序；页面造型和内容容量按本稿事实重新设计。未读取候选提示、旧实验、参考图片或旧 builder。
