本轮按用户要求了解当前项目和 Git，讨论中性 Skin + 杂志风 + Luna high 的生产稳定性，并试验近背景色结构。基线为 main / adfa4640；未修改正式代码、资产或现行规则。原工作区已有两份文档修改，本轮保留。

## 实测结果

[打开三种配色对照](review.html)。调用现有 `hub-radial-001` 的 HTML 组件和共享主题编译入口，使用资产示例内容。A 是现有主色映射；B/C 是本实验 CSS 样式覆盖，分别为浅承载和同背景线框。

- 4、6、8 项共 9 张浏览器渲染；选定的根、节点、图标槽及文字组的文本和矩形位置保持一致，记录见 audit.json。
- 查看三种六项图和线框四项、八项图：浅色和线框均保持中心与外围的归属；后者更接近当前杂志风的纸色、细线与克制强调。中心层级由尺寸、同心轮廓与留白支撑。
- 现有共享运行时真实解析了三种数量的原组件，结果为 resolved-current-*.json。未执行 invokeStructure、Native 编译或 PPTX 导出；这不是直接原生调用成功，也不是 Luna high 生成证据。
- B/C 未改变内容和位置，但有去阴影、去底层填充和线框版直角化等样式变化；不以此证明所有几何、所有结构或所有样式语义均兼容。

## 当前架构的实际缺口

1. rules 已区分共享规则、Skin 和排版体系，但当前中性 Skin 仍为 candidate；正式 CLI 限东北大学。用户本阶段优先中性 Skin，不应在旧大学 Shell 上继续扩场景。
2. 新合并的结构主题入口支持 primaryColor，历史报告验证 35 个核心结构的蓝紫代表状态。其机制按原颜色饱和度、亮度归类，不按对象的文字、填充、轮廓职责归类。
3. 本次将中性完整配色传给 resolveStructureTheme 后，background #F5F4EF 与 surface #EEECE5 实际变为 #FFFFFF；line #D8D5CC 实际变为 #DEC5C0。前者来自严格中性色筛选，后者来自显式主色强制派生。见 audit.json 和 src/visual-runtime/html-component-theme.mjs。
4. 现行独立制作任务提示词与工作流仍明确“不接结构库”；合并代码不意味着中性制作入口已接通。
5. Luna high 的中性拆分规则首轮未通过；大学实验最新同条件复验为 1/2 整稿通过。它们不能证明跨稿稳定性。具体记录分别见 docs/PPT制作规则参考/中性编辑排版-提示词复现/复现记录.md 与 experiments/university-skin-pilot/stability-01/RESULTS.md。本轮未复跑或实时核验其他制作任务状态。

## 建议的推进范围（尚未实施）

先以现有 Codex Agent 验证方法与能力，再决定 Harness 迁移。不复制学校专用结构库，不新增一套平行规则。

1. **主题适配**：Skin 明确提供背景、承载面、正文、强调、装饰分隔线与关系线角色；执行器尊重显式值。填充允许浅承载或同背景；文字、图标、连接与语义状态分别处理。仅给主色不能完成中性化。
2. **排版与执行**：杂志风继续负责整页阅读、字体角色、密度和留白；共享执行能力落实字体单位换算、文本测量、节点包围盒和从真实边界派生连接线，减少 Luna 临时重写底层几何。
3. **结构接入**：沿现有规则/任务入口增加按需读取结构 Skill。直接调用必须满足原组件尺寸和容量；参考重组单独记来源，不能把样式适配理解为获得任意缩放能力。普通文字、媒体和结构都由页面内容需要决定。
4. **独立验收**：实际指定 gpt-5.6-luna / high，冻结本轮输入，分别覆盖叙事长文、流程条件、比较权衡、真实数据和有图稿件；记录首轮、工具自修、人工反馈后的结果。最终检查来源覆盖、关系、真实文字/连线、可编辑性和整稿视觉节奏。有限样本通过只说明覆盖范围内可用。

线框结构可以补足无照片页的关系表达与视觉变化；照片、截图、实物图的证据职责仍需媒体能力承担。这个样例没有验证图文生产。
