# 纯内容 JSON → 自动编排灰稿

[打开对照首页](index.html) · [实际检查](output/verification.json) · [公共输入契约](../content-to-expression-20261120/inputs/README.md)

四份公共样本在 1280 × 720 都通过两条路线。分带路线让留出样本的三个金额档位横向对齐，也让 **720 × 800 的汛期值班**在旧路线超容时排进一页。竖幅正文仍为至少 18 CSS px，正文底部余量为 6.5 px。两种上线方案的整页结果相同。

## 输入如何变为灰稿

| 层 | 本次实现 |
| --- | --- |
| 内容 | 公共 `page-content@1` 只写页题、主旨、实文、阅读顺序、真实的组内关系和局部边、条件范围、引文与讲述备注。幅面通过 CLI 独立给定。直接复用公共 Schema 与引用校验。 |
| 内部表达 | 从有据的三至六路单结果选库内汇聚图，从有据的无分叉单链选局部流程，对象和值可以形成短项条。同组比较保持等权。按关系及容器选择，页面 ID 与标题只用于标识与显示。两条路线读取相同的内部表达，转换后逐项核对全部上屏文字与来源绑定。 |
| 排版输出 | 两条路线用同一灰稿页壳、字体与组件。浏览器实际量出组宽、换行、字号、图形与连接、作用域与读取次序。每个候选的实测或拒绝原因均可打开。 |

**A · 旧编译器**直接执行上一轮 CLI。按文字量、最低宽度和实测在整页并排、整页堆叠中选择。**B · 测量分带**枚举连续组的分带组合，每行分配等宽或按内容加权的列宽。同组纯文字项有足够空间时可在组内流入多列。保留既有库图、比较区、范围说明和阅读顺序。对有效候选按实测额外换行、短尾行、同带高度差、占用和密度排序。跨级别规则在 B 中有独立上沿，布局数据绑定其所覆盖的处置情形。A 的列表保留原句与内部作用域记录，页面上沿用普通条目样式。

目检依据是固定画幅浏览器灰稿。已检查关系方向、条件位置、分组与扫描顺序。18 CSS px 是本次浏览器下限，文字清晰度还依赖演示环境。公共样本的内容整理来自人工。未调用模型，未从 Markdown 自动提取页面关系，也未验证 PowerPoint 的字体重排、原生制作或主题迁移。局部表达超出已支持的关系会显式拒绝。样本所给组别没有重要度，程序保留同级标题，通过版面和作用域表达主次。

## 复跑

在仓库根目录运行。使用项目已安装的 Node 依赖和本机 Chromium 浏览器，可通过 `BROWSER_EXECUTABLE_PATH` 指定浏览器。最后一个参数给一个新的输出目录。

```powershell
node experiments/semantic-auto-layout-20261120/run-suite.mjs experiments/semantic-auto-layout-20261120/replay
```

单页可分别运行 `--route baseline` 或 `--route bands`，默认同时运行两条。单页回执中任一路拒绝会返回非零退出码，仍保留另一路结果。套件会检查预期拒绝与其诊断产物。

```powershell
node experiments/semantic-auto-layout-20261120/compile.mjs experiments/content-to-expression-20261120/inputs/duty.json --width 720 --height 800 --route bands --out experiments/semantic-auto-layout-20261120/replay-duty-tall
```

每个用例保留逐字相同的 `content.json`、内部 `expression.json`、各路线的 `report.json` 和可重放 HTML 及截图。通过时另有 `layout.json`，拒绝时有可重放的诊断。套件逐页校对实文与来源、作用域、局部边、库图端点、阅读顺序、字号下限和幅面，另检查拒绝六类设计字段、拒绝跨层引用，并验证换掉页面 ID、打乱局部链节点和边的顺序仍能得到同一表达。
