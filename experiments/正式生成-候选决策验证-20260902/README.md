## 样本一：为什么做 PPagenT

- 输入：`稿件/为什么做PPagenT-v1.md`；
- 有效输出：`为什么做PPagenT/为什么做PPagenT-候选决策验证-r2.pptx`；
- 正文 10 页，9 页使用 Structure Group，1 页使用确定性正文 fallback；
- 使用 5 种 Structure 资产；3 页存在多个合法候选并由视觉导演选择；
- 顺序 Logic 的 3 页都只有 `sequence-flow-001` 一个合法候选，属于已确认的资产覆盖缺口；
- 确定性溢出检查通过，13 张渲染图已逐页目视检查，未见遮挡、裁切或不可读文字。

运行中确认并修复：普通 Markdown 章节的一一顺序原文绑定、可选 `points` 空值规范化，以及 CLI 溢出工具必须使用真实可执行文件路径。

## 样本二：让六地红

- 输入：`稿件/让六地红-v1.md`；
- 有效复放输出：`让六地红/让六地红-候选决策验证-replay-r2b.pptx`；
- 该文件复用 `run-r2` 已完成的内容导演与视觉导演结果，只用当前代码重新执行候选复核、渲染和质量门禁，没有新增模型调用；
- 正文 6 页，4 页使用 Structure Group，1 页使用确定性正文 fallback，1 页为普通 editorial；
- 只使用 2 种 Structure 资产；`parallel-equal-cards-001` 连续用于 3 页；
- 第 4、5 页各有两个合法并列候选，但视觉导演仍连续选择等权卡片，属于已确认的视觉选择坍缩；
- 第 3 页的 `1+3+N` 被内容导演识别为普通 `parallel`，没有保留组合系统的嵌套关系，属于已确认的内容结构识别不足；
- 第 2 页需要承载两个标题与正文的通用 comparison Structure Group，当前资产不足，使用正文 fallback；
- 确定性质量审计与溢出检查通过，9 张渲染图已逐页目视检查，未见遮挡、裁切或不可读文字。

运行中确认并修复：结构线索读取器不能把句末“必须”前的并列地名误判成行动清单；语义图标查询必须只引用候选 `mediaContract` 指定的来源，不能把普通 `items` 冒充 `structuredData.inputs`。

## 已确认的下一步

1. 内容导演提示词与结构线索：重点区分“复合系统／分组层级”和“平铺并列”，先用 `1+3+N` 回归，不扩写视觉职责。
2. 视觉导演节奏：当相邻页面存在不同合法 Structure Group 时，披露明确轮廓与此前使用信息；重复选择必须给出内容适配理由，不以硬配额禁止必要复用。
3. API 恢复：实现整次运行共享一次恢复预算和阶段断点复放，非法字段只做定向修复，避免整篇重新调用两个导演。
4. 资产建设：补第二种通用顺序 Structure Group，以及可承载“两项标题＋正文”的通用 comparison Structure Group。

本实验不能证明当前生成线已经解决结构单一问题；它证明候选层能暴露并记录问题，也把问题进一步分成内容识别、视觉选择和资产覆盖三类。

最终验证边界：完整测试 224 项中 219 项通过、5 项为既有资产／快照／旧循环断言失败；公共资产审计通过。
