## 这两次怎么做

上一版由 Agent 逐稿提炼上屏文案、手写 HTML/CSS 底稿，用 CSS Grid 分组，实际调用库内多路汇聚结构的 HTML 入口，由 Chromium 生成和检查画面。主题页首、组件配色已上过样式，构图和语义写在单页实现里。它是带基础样式的排版样张。详细讲述仍可查原稿。[上一版 HTML](../talk-slide/review.html) · [讲述备注](../talk-slide/讲述备注.md)

旧灰稿在组边界、同起同收和后段可读的分组／来源／图意计划上更清楚。它的蓝色结构区保留制作说明。本次样张延续旧灰对占位和归属的表达，放入实际图形和上一版的讲述要点。分区改为左略窄、右略宽，组顶和组底对齐，降低结果框高度，明确左下四个同口径短项与右侧四个连续的独立读点。[旧灰预览](../../home-gray-magazine-20260919/input/gray.png) · [旧状态](../../home-gray-magazine-20260919/input/gray-state.json)

## 从 AI 生图抽出的验收条件

参考的是用户在 2026-09-20 留存的 Image-2.5 图。文件 SHA-256 与当时的原图相同。用户记录强调正文的网格、编号、平行结构、克制色阶和连续阅读，并要求学习风格、延续 Skin 与结构库。[用户原记录](../../../docs/方向讨论/20260920.md) · [参照原图](../../html-library-reuse-20261119/assets/generated-reference.png)

| 在灰稿里确定 | 在样式版里表达 |
| --- | --- |
| 两组的阅读顺序、边界和共用对齐轴；页首主旨、图示占位与实际文案 | 用间距和细分隔让两组归属可辨，保持页首层级 |
| 左侧三项原因汇聚一个结果，合规另列；四个短项用同一对象和状态口径 | 图沿用库内三路曲线，结果框收紧；合规用一行轻浅底面托住对应短项 |
| 四点是独立讲述锚点；真实业务流程只在第一项内部 | 圆形编号、无箭头细线和浅承载面给出阅读节奏，斜切用于收边 |
| 固定文字、字号、行框和图形几何后出样 | 主题色浅阶、细分隔和已有主色渲染；参考图的校标及标题条属其原主题页壳 |

共用风格原则以[麦肯锡式规则](../../../rules/排版体系/麦肯锡式.md#正文的视觉秩序)为准。左右比例、分组条数和元素高度是这页的试作参数，换稿应按实际关系和容量重排。原图补写的组织共识、数据协同、激励等说明缺少原文支撑，本页沿用来源受控的讲述内容。

## 验证

同一份模板 HTML 和布局 CSS 生成两页，样式变量负责底色、线色与强调。实际 Chromium 渲染核对了主体、组件、逐段文字和字号行框，两版几何一致。导出的 `layout.json` 记录来源、阅读序、关系、对象和汇聚曲线，作为试验性交接证据。原生制作、跨稿泛化及共享编译仍待接通。初次渲染发现渐变定义位置漏掉了选择器，右侧底面成为黑色，最终已按实际截图校正并增加停色检查。
