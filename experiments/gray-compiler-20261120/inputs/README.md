# 结构化页面方案怎么写

`page` 记录这页要表达的内容，`sources` 记录支持这些判断的原稿片段。页面、分组、条目和说明各有稳定的 ID，编译时用这些 ID 核对来源、归属和适用对象。字段定义见[输入 Schema](../page-plan.schema.json)。

| 层级 | 填写内容 |
| --- | --- |
| 页面 | 页题、页首主旨、按阅读先后排列的内容组。演讲时才用的解释放在 `notes`。 |
| 分组 | 标题、组内关系和条目。关系可以是独立、并列、比较或顺序。 |
| 条目 | 上屏标题、正文及可选组件。给出组件的语义类型和节点文字，程序决定实际占位。 |
| 适用范围 | 共同条件用 `scopeNotes` 写一次，用 `appliesTo` 列出适用对象。页级说明引用组，组级说明引用条目。 |
| 来源 | 每处文字有 `sourceIds`。对应来源登记仓库内原稿路径与可逐字找到的引文。主旨或概括可以同时引用多条。 |

以下是[不足与感悟](hr.json)中第一点感悟的真实条目。该条目在内部承载三个有顺序的节点，所在的「四点感悟」分组仍是并列关系。

```json
{
  "id": "alignment",
  "title": {"text": "用 BLM 统一语言、目标和策略", "sourceIds": ["s-blm"]},
  "component": {
    "kind": "sequence",
    "steps": [
      {"text": "业务战略", "sourceIds": ["s-blm-flow"]},
      {"text": "人力资源战略规划", "sourceIds": ["s-blm-flow"]},
      {"text": "落地方案", "sourceIds": ["s-blm-flow"]}
    ]
  }
}
```

另外两份输入可查看不同层次的适用范围。

- [两种上线方案](options.json)用比较关系排列两个方案，并将回退演练绑定到两者。
- [汛期值班](duty.json)将适用日期绑定到全页三个组，并在对应条目中保留「或」「无论级别」及时间门槛。
