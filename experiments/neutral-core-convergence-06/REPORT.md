# 汇聚核心试验结果

## 本轮结果

同一份 `core.mjs` 已用于 Luna High 编排的 3 页：1156×410 全宽短稿、700×400 局部短稿与侧栏、820×460 长稿与侧栏。三个调用均首次返回可用；参数见 `cases.json`。主 Agent 没有代写页面 builder。

重新导入最终 PPTX 后逐页目视复核：上下流线在接近结果时逐渐变平并汇合，恢复了上轮适配版缺失的平滑汇流。框体高度随文字量变化，局部结构可以与说明共存。最终文件中未见文字裁切。美观是否符合用户期待仍由用户比较预览判断。

第一轮审阅发现：第 2 页侧栏句号孤行、第 3 页结果正文“发生”被拆开。反馈后由 Luna 修正；后者采用语义换行，说明当前预排尚不能自动保证断行质量。

## 已完成的拆分

- core.mjs：只处理连接锚点、汇流几何和空间不足判断，无稿件、Skin 或 PPT API。
- adapter.mjs：根据稿件估算换行及节点高度，分配局部节点位置，再调用核心。
- builder.mjs：Luna 负责整页稿件与布局、样式和原生对象绘制，直接使用核心路径。

这验证了“核心不变、参数和外围可变”的一个结构原型。没有修改正式资产或把试验推广到全库。

## 检查

核心检查：3 种宽度的末端方向、近终点汇聚带宽、路径向前延伸；过窄/过矮区域返回失败；长稿需要更高节点。

最终 PPTX：3 页，原生对象分别 21 / 35 / 31 个，图片均为 0；画布越界均为 0。包完整性、声明字体、版面检查以及 Artifact Tool 导入通过；已经用最终文件重新导入渲染。未在 PowerPoint/WPS 原生程序内实测。

## 下一步仍需解决

1. 当前测字是字符宽度估算，尚未接入字体引擎；词语与标点断行需要完善。
2. 页面先给区域，节点宽度由编排指定；自动寻找区域、与侧栏共同重排还没有实现。builder 的重试只能扩大区域，本轮未触发，不能当作通用页面协商能力。
3. 汇流最小空间是试验阈值，需增加稿件和尺寸样例校准；本轮只交付了三输入案例。
4. 本轮给了 Luna 明确接口和示例范围，证明的是指定核心后的调用和排版。还没有验证它从全库自行选择、发现并调用核心的稳定性。

建议先由用户确认这三页是否保住了结构精髓，再以此确定核心契约，随后完善实际测字与页面空间协商；暂不批量拆全库。
