# P1：排版先行，结构承接

本轮落实用户纠正：页面先有四项并列表达需求，结构让这种表达更好看，并适应页面的编排。不能围绕完整结构样例安排剩余文字。

## 实验

`layout-plan.json` 在生成任何一版之前保存了短稿、常规稿的页面区域、文字角色、四个项目区域。短稿采用左侧主张和右侧四项条件；常规稿采用页首主张与横向展开的两列两行。四项仍是无顺序的并列关系。

同一计划分别生成普通色块版与折角便签版。两者共享完全相同的稿件、文字坐标、断行、字号和项目区域。普通版保留同样的标题与图标作为控制，只移除便签纸面／折角设计；因此本实验隔离的是结构外观的作用，不是两套模型独立排版能力的比较。

常规稿沿用上一轮新增的 98 字说明，没有再次扩写，仅调整语义换行。短稿保留四项原文和主张含义。

## 最小边界

- Layout 输出项目区域；结构适配器接受这些区域，不能重新居中、缩小整组或增加原样例外围留白。
- 适配器复用原 `review.mjs` 的文字、图标和折角曲线路径。纸面按区域展开，折角固定在右下，图标保持 20px，标题带保持 36px。折角在两个不同宽度中尺寸一致。
- 本轮仅验证四项、两排的 P1。`adapter.mjs` 是本次任务的实现，未注册为全库通用接口。原版造型仍可回看。
- 便签版真实通过 `invokeStructure` 的自定义 build 执行，记录为 `layout-led-pilot`；不是已登记的 `preserved-design` 模式。普通版直接构建对照对象，不冒充结构调用。
- 扫描仍用于碰撞复核，不负责产生本页构图。

## 纠正与验证

第一轮发现常规稿的解释成为长单行，已统一改为条件与解释两行；普通色块意外被主题编译映射为浅红，已改用语义 surface 变量；常规便签版第一轮因说明框与安全留白相差 0.5px 被拒绝，已调整说明框净高并重渲染。旧尝试保留在 `renders/`，最终默认第二轮。

已逐一查看第二轮四张由实际 PPTX 重新导入渲染的 PNG。`checks.json` 验证文字完整、字号档位、项目边界、普通／便签版全部文字坐标与样式一致、不同宽度折角尺寸不变。便签的主体与文字为原生对象，图标为 SVG 图像及 PNG 回退。

本轮结果证明这两套具体 P1 排版可以被结构承接，页面不再由原样例的居中空白决定。视觉审阅认为相较上一轮横向布局明确，常规稿的两侧空白已减少。这是父任务设计并执行的局部验证，不能用来宣称 Luna 自动规划或其他结构已稳定适配。
