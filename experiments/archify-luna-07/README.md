# Archify × Luna High 试用

任务：验证开源技术图示 Skill 的实际使用效果，并为未来 Harness 建立项目技能库。本轮不是结构库尺寸改造，也不交付原生 PPT 转换器。

上游：tt-a1i/archify v2.16.0，commit `c826e6c3a7abad19c0f3cd1ca57207d54b1ad8de`，MIT。安装位置 `skills/vendor/archify`。发现、加载及版本核验见 [项目技能库](../../skills/README.md)。

## 测试稿件

制作中文未来目标流程图：稿件进入编排器，查询结构库，判断当前空间是否适配；适配时调用结构核心，生成可编辑 PPT，渲染检查，通过后交付。不适配时调整页面区域，回到适配判断；检查失败回到编排器。此为目标流程，不表示当前项目已经全部实现。

必须保留两种回流、分支条件和唯一交付出口。不得删除关系只为通过几何检查。

## 分工与检查边界

- Luna High 编写候选 JSON、执行 Archify CLI、根据诊断修改并生成 HTML。
- 主 Agent 安装固定包、建立技能库、检查真实浏览器截图与结果。主 Agent 不代写候选来冒充 Luna 成功。
- 首个执行者停止后，仅保留 v1/v2 JSON；没有可审计的首轮执行回执。因此不能推断它此前验证通过。
- 接续执行者从 v2 开始真实验证。每次状态以本目录实际回执和最终报告为准。

入口：[交付 HTML](archify-luna-07.html)、[浏览器截图对照](archify-luna-07.visual-check.html)、[浏览器检查 JSON](archify-luna-07.visual-check.json)。这些文件存在不等于最终验收通过，尤其要核对 visual-check 的 ok/status。

## 已观察到的问题

v2 四泳道布局在 1440×900 窗口中 scrollHeight=2217，主 Agent 查看 light 截图确认只能看到上部图示。结构校验与浏览器容纳是不同检查，确定性交付通过也不能作为完整视觉通过。后续修正版及最终结论由报告记录。

未做无 Skill 对照试验，不能声称该 Skill 相比原生 Luna 提升了多少；本轮只能验证实际可用路径与暴露的问题。

## 本轮收束

Luna 将 v2 四泳道重排为 v3 单泳道，全部 8 节点、9 关系及语义标签保留。主 Agent 独立重新运行 showcase 校验通过，并确认最终 HTML 哈希与浏览器检查回执一致。自动浏览器检查通过，但人工视觉仍判为需修改：1440 light 截图标题顶部疑似裁切、图标和中文标题拥挤、正文偏小。进一步应用内浏览器复核被 URL 安全策略阻止，未绕过。

结论：完成固定版本安装、项目技能库建立及真实 Luna 试用，Archify 保留 pilot 状态，不晋升直接可用于 PPT 的生产能力。详见 [Luna 报告](REPORT.md) 和 [主 Agent 核验](parent-audit.json)。
