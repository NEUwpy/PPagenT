# 通用规则改写实验：修改前后与副作用

本轮找到了值得继续验证的局部规则写法，但没有找到可以直接替换当前规则、同时保证其他效果不退步的整套提示词。生产入口和共享规则均未修改；实验通过 provider 包装层替换系统提示，原版、失败及候选全部保留。

## 做了什么实验

基线为上一轮八份模拟稿及其实际输出。保持同一模型配置 deepseek-v4-flash、thinking disabled、18000输出token上限、原稿、尺寸、固定字号和求解器。每稿一次内容规划，保留原有排版尝试，没有人工逐页修正文案。测试重点没有传给模型。

第一轮比较原版重跑、精简正向版、正向加反向约束版，共24次运行。第二轮用同八稿比较局部替换版和进一步精简版，共16次。最后对预先编写、未参与规则调试的四份新稿做原版与两个候选对照，共12次。合计52次本轮生成运行；历史八份只作已有证据，不算新运行。另有32次审稿对照、16次固定内容的排版选择，均不混入端到端结果。

模型不保证确定性。历史原版仅长稿导出，原版重跑却是分类与事实推测稿导出、长稿失败。因此不同稿的结果变化不能全部归因于规则。整套提示一起替换的结果只能评价整套候选，不能把每个改善归功于其中某一句；只有固定内容的排版对照隔离了排版提示这个变量。

## 为解决共性问题，具体替换了什么

### 1. 把混合字段示例改为互斥的合法输出形状

原版用一个示例同时出现 `type:"single|row|column|grid",weights:[2,1],columns:2`，再用正文解释哪些字段可用。新写法分别列出 single、row、column、grid；只有 row 可有逐组正数 weights，只有 grid 可有 columns。新增的操作是“只填写所选形状适用字段”，其余页序、组序与固定文字要求保留。没有放宽程序检查。

固定四份历史模型内容计划，每种提示各选两次布局：原版8次中5次字段非法、1次容量失败、2次求解通过；新写法8次中1次字段非法、4次容量失败、3次求解通过。它主要减少了契约错误，不能说容量问题已经解决。历史分类计划在新写法第二次选择中可以原文不动地排成一页；六页长稿两次都能继续求解通过。两份可渲染的第二次选择已重放成PPT，明确标为“固定内容回放”，不计作自主规划成功。

### 2. 把“保持引用”改成可执行的取值操作

新规则要求每个 block 的 sourceIds 从绑定组已有来源的并集中原样复制，数字、单位和引文沿用来源写法；明确 JSON 字符串需转义。第二轮还利用已有接口：只改媒介不改文案时可省略 blocks，让程序沿用原块；重写时才完整填写 text 和 sourceIds。没有新增解析器、自动补引用或修复模型答案。

历史数据稿因中文数字转为阿拉伯数字被拦，正向版生成了两页，数字口径在图中保留；但它漏掉模拟声明。局部替换版在原数据稿仍被数字检查拦住，四份新稿中的混合数字稿则导出一页；新稿并行案例仍出现表达输出错误。因此这是通用操作写法的候选，不是保真或引用问题全部解决的证据。当前字面数字检查的局限也没有被提示词修复。

### 3. 按本轮可见证据审稿，区分内容与成品

将审稿规则改写为：claim、heading、body会显示，灰区实文和蓝区承载内容都可以作为证据；deckBrief、requirements与后台叙述不能补足可见缺失。蓝区说明用于审阅图示计划，不代表图已经制作，也不能仅因它是蓝区拒绝实际承载内容。

第一轮正向版在六个受控审稿对照中均按预期判断；加反向约束版却放行了一份删掉必要条件的蓝区内容。第二轮审稿在合法蓝区上通过、对四种错误关系/条件保持拒绝，但仍放行“原稿为模拟，页面未说明模拟”的反例。它甚至解释模拟性质可以从页面外的来源理解，违反该规则。真实生成中同类漏检也重复出现。故这条重写澄清了契约，但审稿可靠性尚未成立，不能据此放宽或取消人工核对。

### 4. 以信息归属和阅读任务压缩重复，而不是增加案例禁令

精简版把内容组织浓缩为：先按读者问题确定各页范围，主题覆盖全部主体；每项信息有一个主要展开位置；短条件随对应动作就近阅读，标题定位、正文展开。它替换了原版相应长段，没有加入图书馆、报名工具或仓库的专稿答案。

第一版精简遗漏了原规则中“约二十字”的主题长度提示，比较、并行及长稿出现主题溢出；第二版恢复这一通用容量提醒并明确后台字段不上屏。第二版比较与并行稿均导出两页，但分类稿拆成三页，其中一页只放一句工单安排，主分支归属也弱化。四份新稿中的混合数字稿拆成三页，局部替换版则为一页。说明“按页面目的规划”这类原则仍不足以约束分区和疏密。

### 5. 正反向写法的对照没有支持继续堆禁止句

反向版在正向版末尾增加了四组短约束：不按段落或角色数分栏、不让声明独占区域、不遗漏/混用引用、不将蓝区当未上屏、不跨组合携带字段等。它在八稿中仅两份导出，正向版四份；还出现审稿放过条件缺失。单次实验不能断言反向提示普遍更差，但没有证据支持采纳这批附加禁令。

## 修改前后结果

下面只统计生成了实际PPT的稿件数，不是内容正确率或验收通过率。

|版本|原八稿导出|四份新稿导出|四阶段契约总字符数|
|---|---:|---:|---:|
|历史原版|1/8|未运行|3955|
|本轮原版|2/8|1/4|3955|
|精简正向版|4/8|未运行|3187|
|正向加反向版|2/8|未运行|3416|
|局部替换版|4/8|2/4|3896|
|进一步精简版|4/8|3/4|3381|

字符数是四阶段固定契约合计，不是token数；共享规则全文保持不变，输入稿件、动态内容和失败反馈另计。最短版本比原版少约19%，局部替换版仅少约1.5%。因此不能说完整系统提示缩短了19%。

原八稿的所有已导出正向版和反向版均在可见文本计划中缺少模拟声明；本轮原版导出的两份也缺少。局部替换版的事实推测与长稿含模拟说明，但分类与条件稿缺少。进一步精简版的原八稿四份导出均缺少。可见文本计划检索只帮助发现缺项，不等于像素或全面语义验收。

## 实际看图后的收益与退步

- **同内容排版回放**：六页长稿文案和表达不变，第三页右栏变宽后，用户反馈文字不再挤在窄栏；原来主题只概括左侧物资的问题仍保留。说明几何调整可以改善局部阅读，但修不了内容主题。
- **局部替换版长稿**：恢复导出为八页，物资与反馈分开后各页主题更对应内容；但部分单句限定仍被分成大区域，短内容页增多。第六页主题“先统一记录再择一试行”新增了原稿没有的先后依赖，是需要退回的语义问题。
- **进一步精简版比较与并行稿**：主要取值、并行安排、彩排前提和返修内容可以读出；仍有模拟性质遗漏、短内容占大栏。并行稿将“审核完成且联调通过”概括为“均通过”，需要核对是否强化原条件，不能只凭自动审稿放行。
- **新稿混合数字**：局部替换版一页、精简版三页，后者有明显稀疏和重复展开。局部替换版主题把30份与十五份称为“接近”，原稿没有这一评价依据。两者都不应仅凭导出计为成功。
- **新稿普通文字**：三个版本都没有增加页数，但共同文件命名要求仍独占大栏。精简版可见文本计划及原生文字包含“模拟资料”，实际重导入预览标题开头的“模拟”未显示，暴露文本检查与像素之间的差异。
- **新稿无汇合门槛的并行**：精简版生成一页，海报制作无需等前两项、发布仅需文案确认、设备异常不暂停志愿者确认以及模拟范围均可见。这是局部正面样本，不代表所有并行稿都稳定。

## 本轮采纳结论

不替换生产规则，不宣称“不影响其他效果”已经做到。保留完整候选及其失败，便于继续实验。

较值得保留的通用写法是“用互斥合法形状表达输出契约”，因为固定内容对照支持它减少无效字段。内容提炼和审稿的整体替换仍不具备验收依据；尤其应防止用“导出更多”掩盖声明遗漏、标题新增关系和过度分页。提示词继续增长也不能替代确定性契约约束、容量反馈和真实图像检查。

交互对照页提供逐稿左右选择、独立翻页、原稿、精确规则全文、失败原因与实际PPT链接。图像是实际PPTX重导入结果，失败案例没有伪造修改前页面。所有PPT仍是待审实验产物。

实验实际发给模型的消息保存在每次运行的 `NN-stage.messages.json`，这是变体提示的证据。运行器自身生成的 `system-prompt.txt` 等文件仍写原常量，不得把它们当作变体实际发送内容。代码、规则哈希和快照随每批运行保存，生成结束时已核对未变。未改生产代码，未提交或推送。
