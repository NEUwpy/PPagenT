## 场景与结果

| 场景 | 页面先确定的需求 | 结构承接方式 |
| --- | --- | --- |
| 四层漏斗 | 左侧收敛、右侧四行依据、上方来源 | 原漏斗层级对齐四个行中心，逐层引线对应依据 |
| 五层漏斗 | 左侧判断主张、中间五层、右侧准入条件 | 原漏斗适配五个行中心与更紧的列宽 |
| 四级阶梯 | 上方行动说明、横向展开的四级递进 | 原阶梯主体统一变换到等级位置，文字和编号单独保持字号及尺寸 |
| 三级阶梯 | 左侧解释、右下三等级递进 | 原阶梯跟随右下区域，当前为第 1 级、目标为第 3 级 |

五层漏斗与三级阶梯使用新编业务稿，分别测试层数变化与不同页面分工。四层与四级沿用之前稿件事实。每页各有简洁版与结构版，最终共 8 份 PPTX。所有最终 PNG 均来自 PPTX 的重新导入渲染，父任务已逐一目视检查。

修正后的四个场景具备完整内容、清楚的层级／依据归属和无孤字断行的文字，作为本轮待用户查看的成稿。**这证明这些具体布局可以由结构承接，不等于 Luna 独立生成的稳定性已通过。** 本轮由父任务直接规划并执行，没有调用 Luna。

## 具体实现

`plan.mjs` 先写出页面主张、内容分工、文本区、阶段／等级中心，再由 `build.mjs` 应用两种外观。两种外观共享内容、字号和全部文字坐标；简洁版也保留来源图标／等级编号，避免借删信息让结构版显得更好。

`adapter.mjs` 调用现有原实现并适配：

- 漏斗复用原曲线路径、层盖、内嵌箭头和外围曲线。共同轴、渐窄趋势不变，映射到等距行中心；图标圆圈单独保持尺寸。简洁版以递减矩形表示同一层级。
- 阶梯对主体执行同一个横纵坐标变换，保留连接关系与共同透视；等级文字、编号和状态分别定位，不让字号或圆圈随主体拉伸。简洁版用上升连线与文字面表示同一关系。
- 接口只在本实验接受有规律的阶段／等级位置，拒绝反向或破坏节奏的位置；不支持任意拖散这些连续结构。
- 结构版经过真实 `invokeStructure` 自定义 build，记录 `layout-led-pilot`。不是已登记的 `preserved-design` 构建模式。没有修改原资产或正式生产线。
- 扫描用于碰撞复核。新增实际轮廓必须位于正文区的检查，避免定位框合法而图形越界。

## 实际纠正

1. 第一轮：五层漏斗外圈侵入左侧主张安全留白；四级阶梯实际左缘超出正文区；三级阶梯重复的辅助状态说明与第一等级保护区相撞。保留拒绝和旧稿，调整区域／位置并删去重复状态句。
2. 第二轮：五层漏斗底部文字过贴边；阶梯状态未对准编号圆心。第三轮增加漏斗横向容量、设置状态居中后重渲染，未通过缩字号解决。
3. 最终 `checks.json` 检查 8 份 PPTX 的文本完整、语义字号、实际边界、指定阶段／等级位置、编号圆形、状态居中，以及简洁版和结构版所有文字几何与样式完全相同。

首轮 8 次尝试中有 2 次被检查拒绝，第二、第三轮各生成 8 份。看板锁定第三轮，其余产物保留，不将生成成功直接写为视觉验收通过。

## 使用

- `index.html`：四页对照，切换简洁表达／结构版，下载可编辑 PPTX。
- `layout-plan.json`：当前布局，前两轮分别保存在带 round 后缀的文件中。
- `gallery.mjs`：核对第三轮并生成看板。
- `renders/invocations.ndjson`：真实结构调用记录。

仍需将这种职责分工收敛成正式接口并复验模型使用。此次仅验证两种关系结构的受约束承接，不扩大到全部结构，也不宣称任意非矩形排版已实现。
