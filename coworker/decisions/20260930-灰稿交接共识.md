## 核心定义

灰稿不是第二份内容，也不是手工布局文件。它是页面表达契约的确定性编译视图，用于检查内容、关系、承载和阅读顺序。

```text
gray-plan-3 内容真源
  + 冻结的版式/结构/槽位绑定
  → 灰稿编译产物（实文、轮廓、占位、检查回执）
  → home 消费同一契约生成成品
```

表单、灰稿和成品都引用同一组 `pageId/groupId/blockId`；不维护第二份正文，也不从 PNG/PPT 反推契约。

## 交接包分层

### A：内容与页面表达

沿用 `gray-plan-3`，冻结：

- `origin`、`contractId`、`revision`、来源和内容指纹；
- 页序、`pageId`、`title`、`claim`、`pagePurpose`、`narrative`；
- 组的 `id/role/heading/importance/kind` 及顺序；
- 块的 `id/label/text/sourceIds`，限定词保留在实际上屏文字中；
- 已有 `relations` 原样保留。没有关系字段时，不凭空新增语义；能力不足就拒绝或记录缺口。

### B：冻结的承载绑定

main 生成并冻结：

- 稳定版式候选 ID、`family/direction/allocation`、`layoutProgramVersion` 或注册表版本；
- 区域拓扑：`regionId → groupId`、顺序和作用；
- 表达 `kind`、`sourceLocation`、`contentRefs`；
- `programId/assetId/variantId`、`slotBindings`、`capacityRef`；
- `bindingSha256`。

版式 ID 直接采用当前 main 实测候选的稳定 ID，例如 `cards-horizontal-measured`、`cards-support-band`、`album-horizontal-...`。旧 `category-container` 只做显式 legacy 映射，不作为新入口的合法候选。

### C：灰稿与回执

灰稿、PNG/PPTX、几何、容量、编译和审阅信息都是 A+B 的派生产物。实测 `regions`、`contentMinimums`、`fontSize` 进入 receipt，供复核和 home 参考；不回写为第二套布局真源。

## 双方职责

**main**：原稿读取、分页、页面表达、候选选择、结构版本选择、槽位绑定、灰稿编译和回执生成。  
**home**：读取已验收的 A+B，选择 Skin/风格 token，在冻结版式、结构和槽位边界内测量、求解和生成原生可编辑成品。

home 不重新分页、改 `claim`/关系、重选表达或重选结构。内容和关系问题回 main；容量、渲染和资产问题回 home/资产建设。

## 三套状态与入口门禁

状态必须分开记录：

1. `contract`：`draft → frozen`，只表示 Schema、引用、指纹和候选合法。
2. `gray`：`not-run → compiled → awaiting-review → accepted`，表示实文可读、页序/关系/区域/槽位/容量可检查，并有 Codex/用户审阅证据。
3. `final`：`not-run → compiled → accepted`，表示成品、原生可编辑性、导出/几何/完整预览和用户审阅通过。

home 正式成稿入口必须验证：

- 同一 `contractId/revision`；
- `gray.status = accepted`；
- gray artifact/receipt 的 `contentSha256`、`bindingSha256` 与冻结 A+B 一致；
- 编译器和资产版本有记录。

否则只允许 dry-run，或返回 `gray-not-accepted`。`freeze=frozen` 不能代替灰稿验收。

## 修订规则

内容、关系、分页、版式、结构、槽位或容量声明变化时升 `revision`，重新计算指纹并清空旧 gray/final receipt；不把旧回执附到新契约。
