# 关系表达技能选择

用户稿件决定信息与关系；Skin 与绑定排版体系决定基础视觉。规则提供设计依据，仍须渲染验收，不能保证每次生成自动好看。

1. 普通文字无需强行图示。需要关系表达时，先检索项目 ppagent-structure，核对语义、数量、文字、空间与交付形式。有适配结构优先调用；已有结构可保留核心而适配时优先适配。参考改写须说明采用的核心特征，不冒充直接调用。
2. 项目结构不适合时，按内容分工选择第二顺位：架构、流程、时序、数据流或状态图使用 Archify；数值比较、趋势、构成或分布使用 Lieflat Charts（当前非商业试用，详见其接入说明）。二者是不同能力，不要求数据图先经过 Archify。用具体候选契约或检索记录说明原因，无需故意制造一次失败，不为优先级强套不合适的结构。
3. 项目结构和适用的补充技能都不适合时，自主原生编排。无需设使用配额；用户明确指定技能时遵循任务要求。

选择按每个需要图示的页面区域独立进行。其他页已命中项目库，不构成本区域跳过适用补充技能的理由。若本区域选择自主编排，简记项目库与适用补充技能各自不适合的原因；实际调用受阻则记录阻碍，不能写成内容不适合。

Archify 当前为 pilot 第二顺位。在 PPT 任务中，它接受页面所需关系、目标区域和样式要求，HTML/SVG/JSON 仅为中间产物；必须继续完成本页原生可编辑对象转换或重建、Skin 适配和最终 PPT 渲染。独立 HTML 不能替代 PPT 交付，不能以截图嵌入冒充可编辑结构。只有用户独立请求技术图 HTML 时才以 HTML 为终点。

所有路径都检查事实、关系、可读性与最终产物。记录 contentRelation、projectCandidates、fitReason、selectedSkill、actualInvocation、outputKind、nativeEditablePptx、unresolved。这些是简短证据字段，不要求为每页新增冗长报告。

本文件为独立制作及未来 Harness 的选择真源；registry 的 selectionPriority 是发现顺序提示，不是已实施的自动路由器。
