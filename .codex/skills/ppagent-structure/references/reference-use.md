# 将结构用作设计参考

先检索真实目录，再执行 `node .codex/skills/ppagent-structure/scripts/catalog.mjs reference <assetId>`。它给出来源、语义、视觉意图及实现路径；需要理解某个局部形状或连接时再读相应源码。图像输入不是必要条件。

从参考中提取对这页有用的方法，例如“阶段间的门禁表示推进条件”“对称对象沿共享比较轴排放”。然后按本稿的内容量和目标区域重新安排原生节点、线条和文字。可以改变宽高、朝向、节点位置、图内外文字分工，简化空间隐喻，或组合多个参考；让连接、分隔与归属在新布局中仍然清楚。

源组件的 minimumFrame、stateFootprints、固定坐标和字符容量约束其既有执行代码，不自动约束新编写的表达。新的表达需要核对自己的文字容量、对齐、边界与连接，不能用“原资产已通过”代替检查。直接导入并执行原组件时，仍按 invocation.md 的真实接口与容量执行。

主题取自本次 Theme，整页组织取自 LayoutGuide；源实现的颜色和装饰不是必须继承的边界。保留稿件关系和证据，不把真实顺序变成平级卡片，不把条件、回流或极性省去；参考本身只承载部分关系时，在图外补足对应说明。

本次输出保留一条简短记录即可：`mode: reference`、`referenceAssetIds`、吸收的设计方法、为本页改变了什么、关系与实际输出的检查结果。没有直接调用就不生成 success 调用事件，也不伪造原资产不变量检查。新表达只保存在这次构建脚本中；是否后来积累为核心能力是另一项工作。

## 当前原生连接执行提示

本项目 artifact-tool 的 `slide.shapes.connect(source, target, options)` 使用 `fromSide` / `toSide` 选择连接点；当前已验证的单向箭头在目标端设置 `tail: { type: "triangle" }`，不要因英文直觉把 `head` 当作目的端。`head` 会在源端出现箭头。这只是当前工具 API 的执行细节，不是对流程方向或朝向的设计限制。

导出后核对实际 proto 中 `fromElementId`、`toElementId`、连接点和 `lineStyle.tail`，并检查路径是否穿过文字。文案“通过后进入下一步”必须和箭头尖端一致。当前证据见 university-skin-pilot/reference-01/run-04；API升级时重新核对。

图内保留关系所需的对象、连接和简短条件，记录内容、责任与解释可以放在图旁的对应文字列。重组的目标是让结构参与整页论证，不是换一种方式复制满页结构。最终修改 PPTX 后重新渲染；保存最终文件哈希，不能用旧 PNG 为新版背书。
