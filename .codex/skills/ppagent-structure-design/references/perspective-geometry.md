# 透视形状生成法

本参考用于箭头、道路、箭带、轨道、平台、漏斗式通道等需要明显前后关系的几何主体。目标不是复制某组坐标，而是从投影关系生成可编辑 SVG／DOM 轮廓。

## 当前能力边界

透视不是单一模板。当前只实现并验证了以下模型：

- **模型 A：单消失方向的直线收缩带＋直立节点**。主体在页面中正视呈现，沿一条斜向纵深轴收束；节点以底部接触锚点落在带面中轴，尺寸和间距共享一维射影函数。本文件第二、第五和第七节中的现有公式与审计脚本目前只对模型 A 作确定性保证。

以下模型尚未形成已验证的生成器与独立审计，不得套用模型 A 后宣称透视正确：

- 双消失点或三消失点体块；
- 俯视／仰视平台、台阶和多层空间；
- 弯曲道路、空间曲线与旋转截面；
- 等轴测、斜投影等不以近远收缩为主要规则的表达；
- 圆柱、球体、复杂立体及其真实投影轮廓。

遇到新类型时，先辨认投影类别、相机／消失点、空间轴和可见面，再为该类型补充独立参数化模型、参考实例和审计不变量。不得为了复用现有脚本，把所有“有立体感”的图都降格成直线箭带。

## 一、先定义空间，不先画轮廓

把页面视角与形状方向分开：页面可以保持正视，形状自身仍可沿左下近景到右上远景、正下近景到中央远景或其他纵深轴展开。先明确：

- 近端位于画面哪里，远端与消失方向在哪里；
- 主体是直行、弯曲还是抬升；
- 观察者看到的是顶面、侧面，还是二者同时可见；
- 方向感主要来自截面收缩、面与面共边、遮挡还是明暗。

若这些关系不能用一句话说明，先画纯几何草图，不添加文字、节点、图标和说明块。

## 二、模型 A：用纵深轴和截面生成直线收缩带

设投影后的中心线为 `p(t)`，`t=0` 是近端、`t=1` 是远端；设屏幕中的法向为 `n(t)`，可见宽度为 `w(t)`。两侧边界由同一组参数生成：

```text
left(t)  = p(t) - n(t) * w(t) / 2
right(t) = p(t) + n(t) * w(t) / 2
```

这里的屏幕参数 `t` 不是节点在真实纵深中的等距序号。若节点在世界空间中的等距参数为 `u∈[0,1]`，直接令 `t=u` 会得到屏幕等距，只是仿射排版，不是完整透视。直线纵深上的节点使用一维射影变换：

```text
r = apparentScaleNear / apparentScaleFar,  r > 1
q(u) = r*u / (1 + (r-1)*u)
t(u) = tNear + (tFar-tNear)*q(u)
apparentScale(u) = apparentScaleNear / (1 + (r-1)*u)
```

`q(u)` 是保持端点不变的单应映射。等距 `u` 投影后，相邻屏幕距离必须从近到远逐段缩短；节点尺寸和间距由同一个 `r` 驱动，不能分别凭感觉调整。语义上确实不等距时，先明确世界参数 `u`，再统一投影，仍不能直接手填屏幕坐标。

- 直行主体使用直线中心轴；弯曲或抬升主体才使用分段线或曲线，不能为了制造“立体感”随意增加折点。
- 透视收缩通过 `w(t)` 从近到远单调减小体现。收缩强度按最终缩略图是否能立即读出近远关系决定，不固定为某个角度或比例。
- 采用仿射／斜投影且直行中心轴使用恒定屏幕法向时，近端截面、远端截面和箭头接缝必须互相平行；只能改变截面宽度，不能让远端接缝自行旋转。曲线路径或完整投影模型允许 `n(t)` 变化，但变化必须由同一投影求解，不能手工扭动某一条截面。
- 箭头从远端截面自然生长：箭身远端的左右端点同时属于箭头颈部，箭身和箭头只有一条共享接缝。
- 需要厚度时，再定义统一的投影厚度向量 `d(t)`，用同一条顶面边界生成侧面；不能复制整个形状并偏移成阴影来假装侧面。
- 明暗和渐变必须沿纵深轴或真实分面变化，只强化已经成立的几何，不能替代透视收缩。

## 三、有参考图时提炼参数，不只抄坐标

优先读取来源对象、路径或像素边界，提取以下归一化关系：

- 纵深轴的画面方向；
- 近端宽度与远端宽度的关系；
- 主体在 Content Frame 中的占位比例；
- 箭头宽度、长度与箭身远端截面的关系；
- 共享接缝、可见分面和明暗方向。

测量用于验证理解并得到视觉语法。最终实现应把这些关系转成相对坐标、中心轴、截面函数和共边规则，使画布或数量变化时仍能重新求解；不要把来源页的绝对坐标当成通用能力。

## 四、没有参考图时从语义生成

1. 根据阅读方向选择近端与远端，先确定中心轴在画面中的起止位置。
2. 选择能在缩略图中明确区分近远的截面收缩；先看剪影，不先加色彩效果。
3. 按中心轴和截面函数生成主体，再从远端共享截面生成箭头或终点结构。
4. 若需要体块，按同一投影视角补顶面、侧面和遮挡关系。
5. 只有空间关系仍难以用二维草图判断时，才可用生图模型生成概念母版；母版只用于确认相机与空间关系，最终仍转换为可编辑几何。

## 五、先审主体，再加内容

透视主体先以无文字状态在真实 Content Frame 和看板缩略图中审批。至少回答：

1. 一眼能否看出近端、远端和前进方向；
2. 两侧轮廓是否由同一截面系统收束，而不是等宽图形旋转；
3. 箭头、侧面和其他分面是否共边，有没有双缝或断裂；
4. 去掉渐变、阴影和节点后，剪影是否仍然成立。

主体通过后，先定义附属体与主体接触的投影锚点，再把锚点按 `t(u)` 放到同一中心轴上，并让节点尺度随 `w(t)` 或同一透视函数变化；文字默认保持页面坐标系中的正立可读。不要让内容单元各自模拟一套透视。

- 当视觉意图要求节点位于带状主体“中间”时，先明确它属于整条复合带、顶面、前半面还是侧面，并为该目标面命名左右边界；再在同一个 `t` 上求边界交点并取中点。不能先对整条复合带求中点，再把这个结果误当成某个子面的中点，也不能凭最终画面手动平移节点。
- 圆盘、球体等直立附属体若通过底部椭圆与平面接触，落在透视轴上的应是椭圆中心／接触锚点，不一定是主体圆心。先把椭圆中心放到目标面近远截面中点的连线上，再让直立主体与椭圆共享同一竖直中心线；主体圆心相对接触锚点的抬升量由自身尺度统一计算。不能把圆心先放到轴上，再把椭圆作为局部装饰向下偏移。
- 节点尺寸由同一 `w(t)` 驱动后，还要检查最终缩略图中的尺度级差是否可辨认。仅在数值上微小递减但肉眼近似等大，不算建立了透视；代表状态应同时验证圆心的截面中点误差和节点尺寸由近到远严格递减。

## 六、常见错误

- 把等宽二维箭头整体旋转，误当成透视箭带；
- 参考图沿斜向纵深展开，却擅自改成画面中央的跑道；
- 用侧视的“先平后折”折线替代正视页面中的纵深收缩；
- 在主体剪影尚未成立时先加阴影、节点和说明卡；
- 箭身与箭头分别绘制但没有共享接缝；
- 通过多个对象各自倾斜来拼凑空间感，导致投影视角不一致。

## 七、含节点透视结构的三道门

当圆盘、球、平台、标签或其他附属体需要跟随箭带纵深时，不直接画成品，按三道门推进：

1. **纯几何门**：只显示主体轮廓、纵深轴、代表性横截面和消失方向；隐藏文字、图标、渐变与说明块。先确认近远、收束、共边和剪影。
2. **绑定门**：为每个附属体声明世界参数 `u`，用同一射影函数求屏幕参数 `t(u)`，再从同一 `t` 的左右边界计算接触锚点、局部带宽与尺度。临时显示横截面、目标面中轴、椭圆中心、主体中心和实际中心；不得手动平移某个节点修图。
3. **成品门**：移除辅助线后再添加图标、文字和配色，在真实画布及看板缩略图中检查透视级差是否仍然可辨认；同时查看黄金态、较少态和较多态。

绑定门使用 `scripts/audit-perspective-layout.mjs` 做独立检查。审计 JSON 至少提供画布、左右边界的近远端、节点的世界参数 `worldT`、屏幕参数 `t`、接触锚点 `node.x / node.y` 与 `size`；若接触锚点属于整个梯形中轴，`centerRatio` 使用 `0.5`。直立主体另提供 `visualCenter` 和 `anchorOffsetRatio`，用于检查主体与椭圆同轴及统一抬升。等距世界节点设置 `requireSpacingCompression: true`；需要明显近大远小时，再按缩略图设定 `minAdjacentScaleDropRatio`，不要只检查“后一个数值略小”。临时审计数据不进入资产包。

```powershell
node .codex/skills/ppagent-structure-design/scripts/audit-perspective-layout.mjs <audit.json>
```

脚本会拒绝：接触锚点偏离目标横截面／中轴、主体与椭圆不同轴、世界或屏幕采样顺序错误、等距节点的画面间距未向远端压缩、局部带宽未收缩、节点尺寸未递减、尺度级差低于设定阈值，以及圆盘或椭圆托底等可见外轮廓越界。审计通过仍不能代替最终像素检查。
