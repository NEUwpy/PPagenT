# 现行规则

这里是生成时使用的规则正文唯一目录。加载清单由 [index.json](index.json) 管理；每类只维护一个现行文件，变更历史交给 Git，不发布并行 v1/v2/v3。

| 入口 | 用途 |
| --- | --- |
| `generation` | 独立制作任务：内容组织、排版、质量检查；可附加指定 Skin，自动加载其唯一绑定的风格规则 |
| `content-director` | 现行内容导演：共享内容原则与该角色执行协议 |
| `visual-selector` | 现行视觉选择器：只在合法候选内选择，不获得自由绘制权限 |
| `skins/` | 各 Skin 的视觉身份与唯一颜色体系；资产目录只引用，不复制正文 |
| `排版体系/` | 可由多个 Skin 共享的字号角色、间距、符号、容器和页面表达规则 |
| `页面组合.md` | 独立制作共用的主题、分析、解读关系计划与组合方法；先规划再绘制 |

```powershell
npm run rules:load -- --profile generation --skin neutral-editorial-001
```

命令输出实际规则正文及加载清单，不启动 PPT 生成。正式独立任务入口见 [生成任务提示词](../docs/工作流/正式生成/生成任务提示词.md)，架构见 [产品定义](../docs/产品定义.md)。

暂定每个 Skin 在索引声明一组 `rules` 与一个 `layout` ID；`layouts` 将该 ID 映射到唯一现行规则清单。中性 Skin（保留资产 ID `neutral-editorial-001`）绑定「杂志风」（`magazine`）。不同 Skin 可共享同一体系，不能从 CLI 单独覆盖排版。东北大学 Skin（`northeastern-university-001`）绑定「麦肯锡式」（`mckinsey`），加载现行分析排版规则；字体与主题直接来自既有运行时契约。此处是独立制作规则绑定，不改正式 renderer。独立制作的共享排版规则提供结构 Skill 入口，Agent 按需读取通用结构或参考方法，加载器不预读全库。

## 分层与加载原则

### 四类规则（2026-09-16）

- **内容结构规则**：先确定页面目的、信息职责、关系和内部层级，见 `内容结构.md`；`页面组合.md` 提供关系与空间表达方法。
- **Skin 规则**：视觉身份及内容区域等基础约束。
- **排版规则**：所有风格共用的区域安排、网格、对齐、留白和文字层次，以 `排版.md` 为维护入口；分页或关系变化返回内容结构规划。
- **风格规则**：美化已有规划结果。历史目录 `排版体系/` 和索引 `layout` / `layouts` 保留兼容名称，其风格职责不再称“风格排版规则”。

规划与检查是永久生产环节，灰稿是调试展示。美化可以微调区域位置和比例，改变内容分组、主次、关系或需要拆页时必须返回规划。灰／浅蓝展示约定见 [排版](排版.md#永久规划与灰稿)。下面的加载结构是文件与工具职责，不另立一套与四类规则竞争的设计分类。

规则按职责组织为：**内容规则 → 页面规划规则 → 视觉风格规则 → 结构选择规则 → Skill 调用规则 → 制作约束 → 检查规则**。这是责任划分，不要求新建七套文件或七个 Agent；优先维护已有真源。

内容与规划分别由 `内容组织.md`、`页面组合.md` 承担；身份与风格由 `skins/`、`排版体系/` 承担；结构和 Skill 选择复用 [选择规则](../skills/references/selection.md) 与对应能力说明；制作约束和检查使用已有排版、执行及质量文件。

按阶段和本页需要加载：规划读取内容原则、相关风格条件与能力概览；确定表达需求后再读取具体结构或 Skill；构建与检查读取对应约束。保留必要上下文，不默认把全库装入一个提示词。当前 `generation` 等 profile 的实际加载范围仍由 index.json 与运行器决定，本次说明不代表已实现新的自动路由。

## 维护方法

- 独立制作采用内容结构＋Skin＋共享页面组合＋绑定风格规则：`内容结构.md` 维护页面职责、归属与必要关系，`页面组合.md` 维护已确定关系的空间组织，`排版.md` 维护组内文字与几何，风格文件维护美化。基础排版不另建语义识别体系。新 Harness 以引用 content.md 的 blueprint.json 为轻量计划；`composition-intent.json` 及 `src/tools/check-composition-intent.mjs`、`src/composition/resolve.mjs` 是可选执行工具，选用时由蓝图派生输入并遵守其契约，不强制新增一套计划；不等同于正式候选协议中的 CompositionPlan。根目录灰稿另以 `gray-plan-3` 和四种基础组合调用共享求解器，尚未迁移 Harness 镜像；正式选择器也未加载此自由编排规则。

- 共享逻辑组织维护于 `页面组合.md`，麦肯锡视觉表达唯一维护于 `排版体系/麦肯锡式.md`；任务入口只要求加载和核对，不复制原则正文。聊天记忆不参与运行时加载，实验快照也不是现行规则。大学独立生成读取该文件；`content-director`、`visual-selector` 当前不读取 Skin 绑定规则，不能把前者加载成功宣称为后两者已生效。加载证据与成品遵守证据分别报告。

- 通用原则归共享文件；身份与颜色体系归 Skin；具体字号角色、间距、符号与页面表达归绑定的风格规则；机器角色契约归 `执行/`。字体名称仍只维护于既有资产 `fonts` 或大学运行时 Skin 契约，排版体系引用字体字段。同一要求只改所属文件，其他位置引用。
- 新 Skin 复用风格规则与结构源设计，不复制结构库。中性 Skin 由一个 mainColor 派生颜色，35 个已审批结构共用连续映射，保留色阶与透明度、区分背景和承载面；禁止逐结构配色补丁。规则取值见中性 Skin 文件，能力和变更影响见产品定义。新 Skin 接入及任意主色效果仍需验证。
- 新经验先进入 [PPT 制作规则参考](../docs/PPT制作规则参考/README.md)。用户明确要求可直接提炼；教程中的建议先判断适用条件、与现行规则的冲突，并用必要小样验证。
- 能修订已有规则就不新增文件。尚未验证的图文、结构经验留在笔记，不预建空规则，也不把全部资料默认加载。
- 新增可消费规则时更新索引与相关测试。检查适用 profile，不能把自由编排指令注入候选选择器。
- 旧实验提示词是历史证据，不再继续同步规则。索引、规则或依赖缺失应明确失败，不能默默退回旧提示词。
- 规则拆分先审计原约束、字体和数值无损，再用无历史上下文的完整样稿检验视觉效果；加载测试通过不等于审美验收通过，不以重新调用旧构建脚本冒充复现。
