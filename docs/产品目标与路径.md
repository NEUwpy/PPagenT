# 产品目标与实现路径

2026-09-28 路线纠偏。本文维护建设方向、技术取舍和重复生成口径；产品边界见[产品定义](产品定义.md)，资产与计划接口见[页面构成与布局规范](架构/页面构成与布局规范.md)，验收进度见[项目台账](方向讨论/页面编排能力计划.md)。本次更新规范，不宣称运行器已完成迁移。

## 建设方向

**把专业制作能力前置建设为可调用资产、参数、约束和生成程序；运行时模型主要承担语义理解、逻辑分析、判断、有限候选选择和内容填充。** 目标是在可验证的覆盖范围内，以较低的重复生成成本、较快速度和高度一致的结果交付原生可编辑 PPT。

前期可投入强模型与人工设计审阅，把逻辑表达、布局、组件、风格和调用方法做好。生产时消费这些能力；不把逐稿编写布局代码或让模型临场设计作为常规路径。重资产的价值是跨稿、跨模型复用的执行能力和验证证据，不以资产数量、提示词长度或检查器数量计进度。

保留“文稿 → 分页稿 → 灰稿 → 美化成稿”两段生产流程。灰稿对应可追溯的内容与空间计划，便于分别验收前半段的规划和后半段的实现。原 main/Home 的分工现作为同一系统中的职责边界，不再要求在两个分支重复建设。

## 建设工作与生产工作的分工

| 环节 | 主要工作 | 完成依据 |
| --- | --- | --- |
| 建设 | 定义适用关系与输入契约，设计可变布局和组件，落实风格参数及生成代码，验证容量和失败返回 | 不同内容、边界数量、长短文及反例下的原生 PPT、实际预览与审阅证据；可调用实现与版本 |
| 生产 | 理解与保真提炼，形成分页及必要关系，从合法能力中选择并绑定内容，调用程序构建 | 计划、选择、实际产物相互一致，来源和关系保留，最终质量通过 |
| 维护 | 对失败定位到理解、映射、候选覆盖、容量、风格或渲染；修复所属能力 | 同类新稿有效且原有场景不退化；保留原失败与修订条件 |

建设阶段可以试验新的视觉方案；生产阶段的自由度应来自已实现、已验证的参数和变体。已有参考重组或自由坐标接口保留兼容与研发价值，不因此成为新生产主线的默认兜底。无合适候选时如实记录缺口；只使用保持关系且已验证的降级方案，必要时返回规划。

## 实现取舍

- Harness 继续承担状态、版本、工具调用、预算、检查、有限返工及回放；优先复用现有运行器，不以框架迁移为本轮目标。
- 复用 Skin、风格、布局、逻辑与结构图四类资产及已有 Logic 分类。语义角色、关系和来源是选择依据，字段按实际决策需要补齐；外部建议中的 PageContentGraph、GreyPagePlan 和六层命名属于参考，不直接立项为新系统或新文件格式。
- 布局先满足真实关系，再比较已登记家族、变体和参数。块数只用于容量判断，不单凭块数推出并列卡片、流程或矩阵。几何、字体角色和装饰实现逐步由可调用程序承担，模型不能靠任意坐标补偿能力缺口。
- 风格经验继续保留文字说明，并逐步落实到现有配置、组件及渲染规则。相同要求保持一份真源，不另建同义 token、求解器或正文副本。
- 用户当前计划以 DeepSeek v4.1 Flash 承担理解、分析及暂时的选择/填充，后续考虑 Jev 类模型承担部分有限判断。这里记录选型意向，不改配置，不证明实际可用性或效果；运行记录必须使用服务实际返回的模型标识。不同职责分别验证准确性、延迟、成本与稳定性。
- 商用依赖和许可在选资产时记录，产品化验收纳入 M5。现有私有 PPT 引擎及外部 Skill 的限制不因路线调整消失。

## 稳定性与版本

**相同有效输入和固定执行条件应得到一致的计划选择与内容布局。** 这是当前建设目标，替代此前“不要求每次重新规划选择相同结构”的口径；尚未实现完整保证。

分别验证三件事：新调用的语义理解与选择是否一致；既定计划在固定资产、规则、字体、引擎及环境下是否确定地生成相同内容和几何；同一任务是否能复用已验收计划或成品。缓存只证明复用，不能用它证明模型重复判断准确或稳定。

计划需关联输入、演示要求、选择理由、能力版本及运行条件；缺失的版本信息先明确记录，不能假装已有完整冻结机制。缓存与规范化输入是待验证实现选项：来源或要求变化必须失效，规范化不能抹掉有意义的差异，失败或未审候选不得作为已通过结果复用。PPT 文件字节一致还涉及时间戳和内部 ID，须与内容/几何一致分别测试。

规划经验证后成为构建依据。改变事实、关系、分页或视觉承载约束时建立新版本并重验受影响产物；不能悄悄改正文、继承旧验收或为了保持第一次布局而删掉必要条件。

## 验证与纠偏

先用人工核对的计划验证资产和程序，再让模型完成同一输入契约，最后检验完整原稿流程与未参与建设的新稿。三个层面的结果分别记账，不用手写计划成功代替自动规划成功。

范例用于明确质量目标和暴露通用缺口。修复需说明适用关系，并验证不同措辞、不同内容量和相似外观但不同关系的反例；不写稿名、页码或样稿专属答案。出现卡片堆叠时，先区分关系识别、内容映射、候选不足与选择错误，不能预设一律缺少新结构。

程序检查覆盖可计算的来源映射、容量、溢出、碰撞和版本等约束；语义检查核对原意、条件和逻辑；视觉审阅核对真实成品。三者互补，不因资产化取消语义或最终视觉验收。反复发生的设计缺陷优先修资产及实现，不无限添加逐稿提示词。

#### 历史：一、目标（已确认）

**用最少的设计，让任意内容都能得到逻辑完整、原生可编辑的 PPT。**

| 维度 | 判据 |
| --- | --- |
| 可靠 | 三关依次全过：① 单稿跑通 → ② **同稿重复，每页结构选择一致** → ③ 新稿冷启动通过 |
| 覆盖 | 结构库相对**生成器能发出的逻辑**完备即可；不要求每页调用结构 |
| 设计前移 | 决策提前：区域、结构、主次、阅读顺序在动手前定下，后续阶段只执行、不重选 |
| 复用 | 四层全要：① Skin 换标换色 ② 结构一份源设计多 Skin 共用 ③ 整页版式复用 ④ 跨稿复用内容结构 |

#### 历史：二、实测现状（2026-09-12）

| 层 | 实际状态 |
| --- | --- |
| 逻辑覆盖 | 生成器可发 **18 类**结构类逻辑，**18/18 有结构可用**；5 类只有单点；`logic-map` 的 journey/spatial 是生成器发不出的僵尸条目 |

#### 历史：三、路径（由目标反推）

**0. 清障（已授权）。** 修 2 个真缺陷与审计工具的 kind 守卫；12 项过期断言对齐真源。测试不可信则后续改动无保险。

**1. 决策固化 —— 兑现「设计前移」与「结构选择一致」。**
blueprint 显式记录每页选中的结构 assetId 与版式 id；构建阶段只消费、不重选。这是"同稿重复一致"唯一可行的机制，不依赖模型自觉。

**2. R1 实跑 —— 兑现「单稿跑通」。**
一份短稿走完全部生产阶段，同时**记录缺口**：内容里出现、却没有合适结构可用的逻辑关系。

**3. 版式统一 —— 兑现「整页版式复用」。**
把 35 个结构从单槽位扩到多版式槽位，结构页与文字页共用一套 skin-normalized 坐标系。同时把 32 个只有裸声明的资产补成已登记的 `planned` 契约（`enabled:false` 起步，与已有 3 个一致）——否则「一份源设计多 Skin 共用」没有可核实的承载物。

补契约不是只改清单：这 32 个 `runtime.mjs` 都还没导出 `resolveSpatialRequirement`，而清单登记了 `spatialResolverExport` 就必须真的导出（否则 `loadCoreAssetPackage()` 运行期抛错）。`src/tools/migrate-structure-adaptation-contracts.mjs` 现在带写入前闸门，会把这 32 个全部拦下并逐条报告——入口模块要和清单一起改。

**4. 按真实缺口补库 —— 兑现「库完备」。**
补什么由第 2 步的缺口记录决定，不预先补。
