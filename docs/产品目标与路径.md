# 产品目标与实现路径

2026-09-30 用户确认。定位见[产品定义](产品定义.md)，共同契约见[页面构成与布局规范](架构/页面构成与布局规范.md)，进度唯一见[项目台账](方向讨论/页面编排能力计划.md)。

## 当前目标：MVP

以最小实现达到两个大里程碑：**稿件到灰稿成立；灰稿到成品成立。** 每段可拆小交付，先用已展开稿件、所需少量关系能力及一组 Skin/风格验证；不先覆盖所有输入、全部结构或建设新框架。

前段形成同源页面表达并编译灰稿；后段按固定规则和已建资产生成成品。先核对实际可调用能力，缺什么补什么；不默认增加长提示词、自由绘图或为样稿写特化分支。

## 建设与使用分开

当前用户与 Codex coworker 建设、看图和验收。前后段可分角色推进；home 可用模拟灰稿探索美化原则，落实受限程序并给出成品预览，再阶段性合并。具体安排见[建设分工](分支分工.md)。

使用阶段只有语义理解模型（当前选型 DeepSeek v4.1 Flash）和判断选择模型（JEV）。程序提供合法候选、计算参数并执行，模型不承担逐稿编写坐标或制作代码。Codex 及其视觉能力仅用于建设；产品模型不需要图像输入或视觉理解。

## 六条设计原则

固定要求资产化；可复用设计组件化；内容变化参数化；确定计算交程序；开放生成尽量转为选择和填充；复杂度沉淀在系统实现中。规则、Skin、布局和结构优先复用同一真源，能力不足明确返回，不换标签凑成功。

## 稳定性目标

用户希望同一稿件多次生成的结果基本一致，“十次有九次基本一样”表达这一目标，尚非测得的成功率。

相近的语义理解、受限选择和固定程序有利于减少波动；但主次/分组的小变化可能跨过分页、容量或候选边界，引起明显差异。参数化只限制变化范围，不自动保证结果相同。

分别验证：

- **新理解与选择：**固定稿件及要求，多次重新调用模型，对照页序、内容、关系和能力选择。
- **程序执行：**固定契约、能力、字体及环境，比较内容和几何。
- **跨稿闭环：**用未参与建设的稿件，检查两段连接和完整质量。

缓存复用和程序回放不能代替第一项。先记录实际模型标识、输入、契约、规则及能力版本；当前不建缓存平台或完整版本冻结系统。

## 实现顺序与底线

先用模拟/人工核对的共同契约验证程序，再让使用模型产生/选择同一契约，最后连接原稿到成品。模拟美化不证明前段自动规划，单段通过不证明整稿通过。

内容或关系变化写回契约，重新编译受影响视图和成品；容量失败返回相应规划/能力。保留失败和用户审阅，程序检查不代替语义与实际成品判断。

复用现有运行器、`gray-plan-3` 和测量构建链，具体字段按实际工具；本次只纠偏说明，不改变代码、配置或 Schema。投入使用前须解决独立运行及依赖条件，见[外部依赖](../harness/外部依赖.md)；不把建设机器可运行记为产品可部署。
