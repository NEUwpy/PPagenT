# 产品目标与路径

2026-11-16 讨论稿。商业依据见[动机与机会](方向讨论/20261029-产品动机与价值讨论.md)，系统分工见[架构](架构.md)，技术取舍见[技术选型与决策](技术选型与决策.md)。

## 产品阶段

| 阶段 | 任务 | 交付 |
| --- | --- | --- |
| 第一阶段：已有内容的编排与美化 | 将 Word、PDF、PPT、Markdown 等已有材料做最少必要整理，完成页面表达与制作；具体格式支持顺序待定 | 适合常规演示、清楚得体、稳定可靠的可编辑 PPTX |
| 第二阶段：根据主题或需求制作 | 补充资料、组织和撰写内容，再调用第一阶段的制作能力 | 范围与启动条件后续讨论 |

## 当前责任：Markdown → PPTX

本轮建设核心为 **MD → 灰稿 → PPTX**，负责页内组织、表达选择和排版制作；上游“各种材料 → MD”暂不开展。

上游整理后的每页内容应已适合单页承载，MD 不必指定版式或结构资产。先明确系统怎样编排、匹配与制作，再反推 MD 的分页、资源和文件约定。

## 第一阶段交付目标

- **忠实：** 保留事实、数字、依据、关系和必要限定；只做表达所需的提炼、删重、压缩与重组，新增标题和标签须有原文含义支持。
- **清楚得体：** 分组、主次、关系和阅读顺序成立；整套文字层级、对齐、间距与风格协调。优先做好日常演示，创意设计范围另议。
- **可编辑：** 文字、图形、图表可编辑，图片可替换，交付 PPTX。
- **省事：** 支持范围内自动衔接并完成交付，不依靠人工补做。提交材料即可发起制作，必要选项有默认值，不采用聊天框式多轮对话。
- **可复用：** 换稿后质量仍可预期，用户核对和修改的总耗时减少。

支持范围、质量阈值、可接受修改量及材料缺失或含义不清时的处理仍待确定。跨稿交付与实际使用效果用于判断阶段完成，局部产物和测试不等于产品验收。

## 内容准备的责任边界

第一阶段上游负责读取、提取已有内容并整理到单页容量；制作核心据此编排和美化。从主题出发的搜索、实质补充和撰写归入第二阶段。

## 推进路径

1. 对齐产品范围，盘点既有流程、设计资产及外部成熟实践。
2. 围绕明确疑问讨论并做必要探索，比较设计效果、建设成本和跨稿复用，确定整体方案与技术路线。
3. 路线明确后，按 MD → 灰稿、灰稿 → PPTX 两条线建设，以共享编译器检查交接；再按确定的顺序扩展材料适配。
4. 根据跨稿交付、用户返工和持续使用判断成果，决定继续、收窄或停止，再评估第二阶段。

当前处于第 1—2 步，尚未进入正式实现；具体分支与维护约定见[AGENTS](../AGENTS.md)。
