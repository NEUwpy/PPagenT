# 产品目标与实现路径

2026-09-30 现行口径。定位见[产品定义](产品定义.md)，共同契约见[页面构成与布局规范](架构/页面构成与布局规范.md)，进度唯一见[项目台账](方向讨论/页面编排能力计划.md)。建设和投入使用都只采用本文的新流程；旧流程只在[纠偏前快照](archive/20260930纠偏前/README.md)中作为历史证据。

## 当前目标：MVP

用最小实现跑通两个大里程碑：**稿件到灰稿；灰稿到成品。** 不先扩全输入、全结构、全 Skin 或新调度框架；每个大里程碑拆成能拿真实产物验收的小交付。

## 一份契约、两段编译

页面表达数据是前后段共同契约，灰稿是这份契约的编译视图。表单可以作为契约的编辑、检查和调试投影，但不能成为第二份正文或第二个状态源。

```text
原稿与要求
  → 语义理解、分页与页面计划
  → 页面表达契约（页序、目的、内容 ID、关系、表达需求）
  → 表达/版式/结构候选与槽位绑定
  → 灰稿编译（建设检查点）
  → Skin、风格与结构程序编译
  → 原生可编辑成品
```

前段把“这一页讲什么、哪些内容一起读、需要什么表达”固定下来；后段只在这个边界内选择和填充。灰稿冻结内容、关系、页序、表达、区域和槽位，后段不得重新解释页面意图。

## 建设阶段与投入使用阶段

| 阶段 | 参与者 | 职责 |
| --- | --- | --- |
| 建设阶段（当前） | 用户与 Codex coworker；可分前段、后段和 home 角色 | 建立参数化结构、版式与 Skin，写规则和程序，使用模拟灰稿检查页面与成品，阶段性合并 |
| 投入使用 | 语义理解模型（当前 DeepSeek v4.1 Flash）、JEV、确定性程序 | 语义理解、分页、有限判断选择和填充；程序负责校验、候选、容量、测量、几何、构建与检查 |

Codex 的视觉能力只属于建设阶段，用于查看建设产物和发现问题；Codex、视觉模型和自由绘图不进入产品。home 可以先用人工或模拟灰稿探索美化原则，但模拟输入必须标记来源，不能代替原稿到灰稿的自动验收。

## 新流程的具体职责

### main：稿件到灰稿

1. 读取原稿，保留来源和必要限定。
2. 分页：一页围绕一个主要目的或判断组织，既不漏掉必要内容，也不把无关内容硬塞在一起。
3. 形成逐页内容和页面表达契约：页序、主题句、内容 ID、分组/主次/关系、表达类型和所需承载能力。
4. 从已建设的表达候选中选择页面级版式；必要时再选择版式内部的结构变体。模型只能选择候选 ID，程序校验合法性、容量和绑定。
5. 把内容 ID 绑定到区域/槽位，编译灰稿。灰稿显示真实文字、占位结构、页序和阅读关系，供 Codex 与用户检查。

### home：灰稿到成品

1. 接收冻结的页面表达契约和灰稿，不重新规划页面。
2. 选择 Skin、风格规则、参数化布局和结构资产；把同一内容 ID 填入已声明槽位。
3. 在容量和样式边界内测量、求解和渲染原生可编辑对象。
4. 输出完整预览、PPTX、几何/导出检查和问题证据；发现内容或关系错误时回写契约，发现承载错误时修资产或程序。

## “十次有九次相近”的正确表述

这是工程目标，不是已测得的成功率。相近的语义理解、有限候选和固定规则会把波动限制在候选边界内；分页、主次或容量一旦跨过边界，结果仍可能改变。要分别比较模型重新理解、固定契约回放和最终闭环，不能用缓存或重复回放冒充稳定性。

## 实现底线

- 固定要求资产化，变化内容参数化，确定计算交给程序。
- JEV 只在程序提供的合法候选中选择 `layoutId`、`variantId`、`structureGroupId` 等命名选项，不写自由坐标或制作代码。
- 页面“内容不多不少”由语义完整性、主要目的和程序容量共同判断，不用单一字数阈值。
- 无适用能力、缺必要关系或超出容量时明确返回缺口；不静默删稿、缩字、自由绘图或编造结构。
- 固定计划回放、模型独立判断、模拟美化和未参与建设的新稿闭环分别验收。

当前优先复用 `gray-plan-3`、现有 plan/state、来源绑定、测量和原生构建；新增字段先核对真实调用点。完整灰稿到成品链、独立运行和跨关系能力仍按项目台账逐项验收。
