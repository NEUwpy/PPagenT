# 运行配置信息

> 状态：当前正式运行配置契约。本文只记录 Provider、密钥和入口，不决定未来使用哪一种 Agent Harness。

本文记录 PPagenT 正式生成工作流的模型接入方式。真实 API Key 只保存在本机 Git 忽略文件或 GitHub Secrets 中，不进入代码、Markdown、示例 JSON 或 Git 历史。

## DeepSeek DirectorProvider

当前默认配置：

| 项目 | 值 |
| --- | --- |
| Provider | `src/agent/deepseek-provider-from-env.mjs` |
| API 格式 | OpenAI-compatible Chat Completions |
| Base URL | `https://api.deepseek.com` |
| 请求路径 | `/chat/completions` |
| 内容导演 Model | `deepseek-v4-flash` |
| 视觉导演 Model | `deepseek-v4-flash-vision-exp` |
| JSON 输出 | `response_format: {"type":"json_object"}` |
| 思考模式 | 正式调用的内容导演与视觉路由为 `enabled + low` |
| 正式命令 | `npm run agent:run:deepseek -- ...` |

模型名和接口依据 DeepSeek 官方文档：[Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)、[Vision](https://api-docs.deepseek.com/guides/vision/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode)。

## 本地 JSON

本机真实配置位于：

```text
config/deepseek.local.json
```

该路径已由 `.gitignore` 排除。可以从受 Git 跟踪的 `config/deepseek.example.json` 复制字段结构：

```json
{
  "apiKey": "replace-with-local-secret",
  "model": "deepseek-v4-flash",
  "baseUrl": "https://api.deepseek.com",
  "roles": {
    "content": { "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 16384 },
    "structure": { "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 4096 },
    "visualIntent": { "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 8192 },
    "visualComposition": { "model": "deepseek-v4-flash-vision-exp", "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 8192 },
    "reviewer": { "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 8192 }
  }
}
```

`chat/completions` 是 DeepSeek 的标准推理协议，不表示使用闲聊模型。当前正式路径使用低等级 thinking：内容导演一次生成完整 Markdown 内容稿与机器元数据；程序编译内容表单并生成内部 PageIntent；视觉导演使用独立的视觉模型，读取逐页内容、合法能力卡及候选 Structure 的已登记预览，输出紧凑 Skill 选择表与 `rhythmPlan`。`structure / visualIntent / reviewer` 配置仍为研发兼容字段，正式生产不调用。

Provider 优先读取环境变量，其次读取本地 JSON。可用环境变量为：

- `DEEPSEEK_API_KEY`
- `PPAGENT_DEEPSEEK_MODEL`
- `PPAGENT_DEEPSEEK_ENDPOINT`
- `PPAGENT_DEEPSEEK_BASE_URL`
- `PPAGENT_DEEPSEEK_THINKING`
- `PPAGENT_DEEPSEEK_REASONING_EFFORT`
- `PPAGENT_DEEPSEEK_MAX_TOKENS`

角色级环境变量使用 `PPAGENT_DEEPSEEK_CONTENT_*`、`PPAGENT_DEEPSEEK_STRUCTURE_*`、`PPAGENT_DEEPSEEK_VISUAL_INTENT_*`、`PPAGENT_DEEPSEEK_VISUAL_COMPOSITION_*` 和 `PPAGENT_DEEPSEEK_REVIEWER_*`。每个角色可分别覆盖 `API_KEY`、`MODEL`、`BASE_URL`、`ENDPOINT`、`THINKING`、`REASONING_EFFORT` 与 `MAX_TOKENS`。例如视觉导演可使用 `PPAGENT_DEEPSEEK_VISUAL_COMPOSITION_API_KEY` 和 `PPAGENT_DEEPSEEK_VISUAL_COMPOSITION_MODEL`，而不改变内容导演。公开运行配置只显示角色是否已配置，不返回 Key。正式生产只读取 content 与 visualComposition 角色发起模型连接；其余字段只为研发兼容保留。

## 运行命令

```powershell
npm run agent:run:deepseek -- `
  --input <稿件.md> `
  --output <输出.pptx> `
  --run-dir <运行记录目录>
```

生产模式只调用内容导演和视觉导演，然后进入核心资产选择、确定性渲染与质量门禁。视觉导演的首轮调用会按图片顺序读取合法候选 Structure 的核心预览；资产未保存现成 PNG 时，程序从其 `example.pptx` 按需生成 `.tmp/visual-director-candidate-previews/` 缓存。若研发模式存在上一轮渲染证据，后续视觉调用优先读取整套 montage 或逐页 PNG。图片使用 OpenAI-compatible Chat Completions 的 `image_url` 内容块，运行日志只保留图片类型与顺序，不保存 base64。研发模式的渲染后视觉审查复用已配置的 visualComposition 视觉模型。

也可以运行 `npm run production:workbench`，或双击项目根目录的 `PPA生产工作台.exe`。EXE 动态读取当前项目源码，并通过运行版本指纹避免在源码更新后继续复用旧后台服务；正在计算的任务不会被强制中断。本地页面读取同一份 `config/deepseek.local.json`，展示模型、Endpoint 和非敏感运行版本信息，但不会显示或写出 API Key。

## GitHub

如果以后在 GitHub Actions 中运行，不上传 `config/deepseek.local.json`。在仓库设置中创建名为 `DEEPSEEK_API_KEY` 的 Actions Secret，并把它映射为同名环境变量。模型、Endpoint 和非敏感参数可以写进 workflow，真实 Key 不能出现在仓库文件、Issue、日志或提交历史中。

## 密钥轮换

密钥一旦出现在聊天、终端历史、截图或误提交中，应在 DeepSeek 控制台撤销并生成新 Key，然后只更新本地忽略 JSON或 GitHub Secret。
