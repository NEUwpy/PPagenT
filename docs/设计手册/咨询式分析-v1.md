# 咨询式分析 · 设计手册 v1

这是一套用于研究讨论、方案论证与决策汇报的独立视觉体系。它由用户提供的咨询报告参考蒸馏而来，核心气质是冷静、精确、紧凑、有依据。读者先理解判断，再查看支撑判断的材料，最后找到适用条件。整页是一张组织好的分析，不是标题下面散落的几句话。

本手册可以直接作为演示设计 Agent 的设计输入；不依赖学校模板、现有代码、结构库或预制页面。来源与取舍记录放在文末，数值比例是本手册的设计选择，不冒充任何机构的官方标准。

## 一、第一眼的样子

白色纸面，深蓝判断标题，黑灰正文，少量蓝色强调。页面上方是紧凑的标题区，下面的主要空间属于分析材料。无大面积标题色带，无大字号口号，无装饰背景。边缘整齐，内容组相互咬合，空白把不同职责分开。

远看能看出一个明确的主体，以及支持它的其他区域；近看有足够的事实、解释和条件可供追问。专业感来自信息安排的准确性、重复关系的秩序和细节的统一。

视觉强弱按职责分配：判断标题最先被读到；主分析获得最连续的面积；组标题给阅读入口；正文可以连续阅读；条件贴近其限制的内容；来源退到边缘。不要让校名、页码、边框或背景成为视觉主体。

## 二、标题与正文构成论证

每页围绕一个可说清楚的问题。标题给出已有依据支持的回答；答案未知时，准确写出待判断的问题。正文用事实、比较、推理、限制或行动安排展开它。用具体词语写判断，不用“赋能、升级、全面提升”等空话占据标题。

标题可以跨两行，按意义断开，同套保持相同字体与字号。不要为了强塞一行缩小字号，也不要在正文另立一个近义的大标题。标题下面只有在交代对象、时间、口径时才设简短副标题。

删掉重复说法，留下能支持判断的细节。一页一观点，不等于一页只有一个句子；一组相关的证据、条件和结论可以共同回答一个问题。稿件很短时合并重复页面，不制造目录页、口号页和总结页凑数量。

## 三、先找到分析单位，再安排版面

先判断哪些内容必须一起读，形成不可拆散的分析单位，例如一个判断及其依据、两个对象在同一维度上的差异、一项动作及其责任和产出。然后将这些单位组织为主区、支撑区或共同轴线。分区名称准确概括组内内容，不把材料、原因和结论混成一个同级列表。

### 1. 判断—依据：窄入口，宽解释

当页面回答“为什么这样判断”时，用短判断作为扫描入口，旁边放完整依据。重复的论证行共享左边界和内部间距，读者既可纵向扫结论，也可横向追问理由。行高由依据自然决定，各行不需要同高。

以下为虚构方法示例，不是待制作页面或可复制事实：

```text
判断标题：现场指导适合处理例外，操作手册承担重复问题

重复操作        步骤固定、答案一致，操作手册可以保留完整细节。
                更新后使用同一版本，减少重复讲解。

情境例外        条件变化会影响判断，现场指导可以追问背景。
                人员时间有限，预约范围需要提前说明。
```

这里的设计来自论证行、窄标签和宽解释；不需要给每行做卡片。关键词加粗就能成为入口，线条只在分组仍不清楚时表达组界。

### 2. 对应比较：让差异出现在同一个位置

先确认比较对象和稿件提供的共同维度。对象统领列，维度统领行，对应项沿同一基线展开。标签只出现一次；限制紧贴受限的方案。比较结果可以成为标题，正文仍完整展示判断的依据。

```text
                  集中讲解                自助手册
适用问题          需要追问的例外          答案稳定的重复操作
投入方式          占用讲解者时间          先编写，再持续维护
尚未解决          无法随时响应            无法判断新情境
```

这是共享口径产生的行列关系，不是所有文字页的默认表格。没有共同维度时，采用各自职责明确的主区与支撑区，不为了整齐伪造可比性。

### 3. 主分析—解释：面积随信息职责分配

当一组材料承担核心论证，另一组仅交代假设、范围或行动含义时，核心材料形成一个宽而连续的主区，补充占较窄侧区。主区内还能细分出对应的子组。侧区可以较短，不必与主区填到同样高度。

```text
判断标题
┌────────── 主分析：数据、事实或对照 ──────────┐  适用范围
│  分析单位 A          分析单位 B            │  影响解释的条件
│  证据与必要标注      对应证据与标注        │
└───────────────────────────────────────────┘  行动含义
                                               有依据的下一步
```

框线仅在这里说明区域关系，成稿不需要画框。主辅关系由面积、位置、间距与文字层级建立。

### 4. 组成、顺序与条件：让视觉关系准确

共同组成一个对象的材料，用共享标题、并列标签或成组的文字行呈现；不能因为条目多就编号成流程。真实先后可以使用步骤行，动作、责任人与产出靠近。条件、例外、暂停、回流依附其作用范围，与正常步骤使用不同编码，不加入正常顺序的连续编号。

多个组共同受一个条件限制，就让条件位于整组相邻的共同说明区；只作用于局部的条件放在局部。位置、编号和线条同样在表达事实，不能与原稿关系矛盾。

### 5. 图表与图片：主体必须有分析职责

数据图先确定要读出的差异、趋势或组成，再选表达方式。直接标出关键数值和对象，统一量纲、时间与比较口径；用灰色承载背景，用蓝色指向本页关心的证据。保留必要的坐标、单位与来源，移除不参与阅读的网格和图例。证据的解释贴近证据，不另做一个遥远的“总结卡”。

照片用于展示对象、现场或现象，裁切围绕被讨论内容；说明交代读者该观察什么。没有合适的数据或图像时，使用充分的文字分析，不编造图表、不用配图占空。

## 四、网格、密度与留白

用同一套外边距和隐形列网格建立秩序。页面左右边界相等；标题、主分析与页脚共享外侧基线。整套选择一个列网格，内容区可以跨列组合，网格不是可见装饰。

需要严格对照的区域共享宽度、起点与顺序；不同职责按实际信息量分配宽度。先根据正文尺度估计自然行长和高度，再分配区域。窄区容纳短标签和少量条件，宽区容纳解释、图表和相互对应的材料。

正文构图由完整分析单位组成：组内紧密，组间有通道，页边有保护。若一条正文的行距为一个节拍，组内标签与说明距离小于组间通道；组间通道至少能明显区分新的阅读单元。重复单元沿用同一节奏。

信息密度指一眼能分清多少有意义的材料，不是填满多少像素。证据充分的页可以较密；同一组仍要有清晰入口。内容较少时，合并相关论证或形成集中构图。不能把三个短句拉开占满整页，也不能把全部内容挤在左上方，让大片空白失去作用。

每条线、每块浅底承担一个职责：分组、范围、比较轴或强调。不重复包围同一组，不给每段自动加框，不给每页固定增加总结条。浅底可组织共同条件，深蓝实心块只用于需要强强调的局部，不能将普通文字拆成一墙色块。

## 五、字体与颜色成为稳定的识别系统

使用一种清楚的无衬线字体，中文与数字保持协调。以正文大小 B 为尺度，在整套开始时选择一组适合画幅和阅读距离的字号，此后固定角色。页标题约为 1.5B，组标题约为 1.1B，正文为 B，注释约为 0.8B；这是构建层级的比例，实际取值在整套内锁定。重要条件与判据属于正文，不能为了塞下而降为注释。

正文常规字重，组标题加粗，页标题深蓝加粗。局部关键词可以加粗，整段粗体会破坏层级。标题与正文使用一致的无衬线语言，不混入书法体、装饰衬线或为字体而设的文字模板。

每页选择一种正文文字对齐方向并贯彻；此体系的分析正文采用左对齐。数据列可以按数量级右对齐，数字序号与页码作为独立标记处理。整套同角色行距一致；长句在完整词组之间断行，孤立标点和句尾单字需要调整。

本体系的色彩角色：深蓝 #163E6C 用于标题和关键识别；分析蓝 #3677BD 用于证据强调；正文 #252B33；辅助灰 #65707D；细线 #CDD5DE；浅底 #EEF3F8；纸面白色。两个蓝色属于一个主题色系，不能随页轮换含义。黑灰承载大部分内容，蓝色的节制让强调有效。不新增彩虹分类、渐变、投影和透视。

## 六、整套节奏与大学身份

先用标题连读出整套论证，再看页面构图。比较页、解释页和执行页的结构来自各自任务；不规定每套必须出现几种版式。相邻页面沿用字体、外边距与颜色，信息组织可以变化。一个可靠的设计体系既能做密集分析页，也能做简洁的开场和决策页。

封面清楚交代主题、讨论对象与场合，结尾落在实际要决定或理解的内容。短汇报不强制目录，不以“谢谢”替代决策。大学身份作为轻量品牌层：校名或真实 Logo 位于固定边缘位置，页码和来源保持安静。校徽、学校名称不代表材料已获学校认可；虚构案例保持明确的方案讨论口径。

加入大学身份时保留这套分析语言，不恢复大面积标题带、装饰性校景背景或书法大字。已有学校 PPT 可以提供真实标识，不能自动决定整个新 Skin 的版式。

## 七、设计成立的边界

原稿事实、关系、否定、条件和不确定性完整保留。影响启动、继续、停止和解释结果的条件进入可见页面；只在备注出现不算交代给听众。不会为了风格编造数据、效果或来源。

字体角色统一，文字完整可读，内容在承载区域内；关键字词不被难读断行。对齐、位置、编号及图形连接符合真实关系。没有遮挡、越界或无意义空容器。

完成时从实际成稿核对三件事：标题是否有正文支持；主要区域之间是否能直接完成比较、解释或检查；样式是否帮助识别主次。几何检查只证明能放下，设计评审还要判断阅读是否清楚、视觉重心是否合理。没有图片输入的 Agent 也要读回实际文本、文字行、角色与坐标，不能用计划代替成稿证据。
