## 为什么调整

现有 Structure Group 已能稳定表达逻辑关系，但部分资产把标题、正文、分点、数值和说明的位置写死在结构代码中。同一结构因此只能适配少数文字组合，继续增加相似 Structure Group 又会造成资产膨胀。

本任务要把“页面逻辑结构”和“区域内部文字排版”分开：优先提高现有结构的适用范围，而不是为每种文字差异增加新结构。

## 已确认的目标模型

```text
Structure Group
└── TextRegion
    └── TextBinding
        ├── Text Layout（组合排版）
        │   └── Text Primitive（基础文字组件）
        ├── 本次文字内容
        └── 对齐、间距、留白等受控参数
```

- Structure Group 只负责逻辑关系、固定图形和文字区域几何。
- TextRegion 表示稿件文字可以进入的连续区域；不连续区域不能强行合并。
- TextRegion 的几何表示扣除边框、图标、连线和固定装饰后的实际安全书写 box，而不是视觉外框；看板、容量计算和正式渲染共同读取这一份几何事实。
- Text Layout 只能在安全 box 内排版；紧凑、标准、宽松密度可以增加内部留白，但不得突破安全边界。
- TextRegion 的用途只作为视觉导演选择 Text Layout 时的候选排序提示，不作硬性排除；硬条件包括区域尺寸、最低字号、内容字段、实际溢出结果和已确认的最小可读尺寸。DOM 未报告溢出不等于视觉可用。
- 文字排版库分为两级：基础文字组件与组合排版。
- Text Primitive 是可复用的基础文字组件，例如标题、正文、分点、数字指标和注释；它负责语义角色与基础样式，不负责页面结构几何。
- Text Layout 是区域内部的组合排版，负责排列一个或多个 Text Primitive，例如标题正文、标题分点、数字指标说明。
- 同一 Text Layout 可服务所有尺寸与内容相容的 TextRegion。
- 标题有无、正文有无和内容长短不再对应新的 Structure Group。
- 仅标题、仅正文、标题正文和标题分点等，在视觉层级与布局算法相同时，作为同一 Text Layout Family 的内容状态；空字段自动折叠，不保留空位。
- 只有视觉语法或布局算法确实不同，才建立新的 Text Layout，而不是为字段有无复制排版。
- 文字排版不追求数量；先建立可扩充、可筛选、可机械编译的机制。
- 首批排版库不采用只能验证机制的极小集合，而要覆盖固定场景中常见的文字表达；覆盖通过复用基础文字组件和组合排版家族实现，不枚举每一种字段排列。
- 正式生成中的 Text Layout 由视觉导演选择，不提供用户手动选择步骤。
- 正式生成时，视觉导演只能选择已登记的组合排版及其离散状态，不临时自由拼装 Text Primitive；基础文字组件用于建设和复用组合排版。
- 现有组合排版无法满足真实需求时，在测试或入库流程中形成新的候选组合，经确认后再进入正式调用范围，不在正式生成过程中现场创造。
- 内容导演输出与具体版式无关的页面语义，包括页面目标、核心结论、语义条目、指标、证据和强调关系，不直接填写某个 Text Layout 的字段。
- 视觉导演选择 Structure Group 与 Text Layout，不复制正文，也不输出内部坐标。程序读取字段契约，把页面语义绑定为标题、正文、分点、数字等 Text Primitive，形成结构化 TextBinding。
- 内容措辞由内容导演在 PageContent 阶段确定；Typography Matcher 只做有限候选匹配和绑定展开，不理解或改写内容，也不是第三个 Agent。
- 同一 Structure Group 中地位相同的重复 TextRegion，默认统一使用同一 Text Layout Family、密度和对齐状态，以保持对称和秩序。
- 同级区域可以因字段缺失而呈现不同内容状态；只有 Structure Group 明确声明区域语义不同，才允许混用不同的组合排版。
- 每个 TextRegion 登记一个默认 Text Layout 和一组兼容 Text Layout；默认值用于资产预览、稳定展示和无歧义回退，正式生成时视觉导演可以在兼容集合中改选。
- 看板中的排版切换只产生临时预览，不直接修改资产；只有在入库维护中明确保存并重新生成证据后，才能变更默认绑定。
- 视觉导演只选择 Text Layout 暴露的离散状态：横向左、中、右对齐，纵向上、中、下对齐，以及紧凑、标准、宽松密度；不直接给出字号、间距、内边距或坐标数值。
- Text Layout 与 Skin 把离散状态解析为字体档位、行高、间距和内边距，程序再按真实容器完成适配与溢出判定。
- Structure Group 内部文字统一使用 Skin 字号阶梯 `25 / 23 / 21 / 19 / 17 / 15 pt`；Text Primitive 声明默认档位与允许范围，程序从大到小选择能完整容纳的最大规范字号，不生成连续缩放的临时字号。
- 正文默认 17 pt、必要时最低 15 pt；小标题和数字指标按各自角色使用字号阶梯的受控子集。封面、页标题等 Shell 字体规范保持独立。
- 文字适配以真实 TextRegion box 为事实来源：结合内容、字体度量、Skin 字号档位和组合排版规则求解，不以简单字符数代替实际排版。
- 入库时为每个可调用组合保存由真实 Region 和浏览器排版派生的轻量容量摘要；不维护手写字数矩阵。视觉导演据此快速筛选，最终是否容纳以同一 HTML 排版器为准。
- 正式渲染只对已选候选执行一次确定性的真实溢出检查；失败时换排版、压缩内容、换结构或拆页，不突破最低规范字号。
- 正式生成的固定退让顺序为：无事实损失的措辞压缩 → 组合排版的紧凑状态或更小规范字号 → 同一 Logic 下其他 Structure Group → 拆页 → 已登记的通用纯文字结构 → 明确失败。
- 退让过程中不得硬套不相容结构、突破 15 pt、临时创造结构或补写原稿没有的事实。
- Text Layout 可以自动换行并折叠空字段，但不得静默截断、添加省略号或隐藏已绑定内容；TextBinding 必须完整呈现，否则判定不适配并进入退让链。
- 测试流程单独记录未覆盖的真实需求，供用户决定是否建设新 Structure Group 或 Text Layout；该反馈环不进入正式生产流程。
- 现有按字符数登记或估算的容量规则纳入迁移范围，统一改为由 box 与真实排版规则派生；字符数仅保留为便于导演理解的摘要。

## 实现参考原则

PPagenT 可以设计适合 PPT 的排版机制，但不从头发明底层布局算法。实现优先参考前端已有的 Flexbox、Grid、Box Alignment、Intrinsic Sizing、Container Queries 和 CSS Text 等成熟经验，复用其容器驱动、内在尺寸、对齐、换行和间距模型，再针对固定画布、Skin 字号规范与 Native PPT 编译进行取舍和适配，而不是照搬浏览器接口。

HTML 浏览器布局结果是文字排版的唯一事实来源。Native 编译器读取真实 DOM 的坐标、字号、行高、对齐和显式换行后机械写入 PPT，不得再次缩字、重新分配区域或调用第二套容量算法。候选入库时只对代表状态进行一次 HTML—Native 对照；正式生成只运行轻量溢出检查，不逐页截图复查。若两者不一致，修复公共编译器，不给单个资产添加补丁。

## 首批文字排版库

基础文字组件：

- `Heading`：标题；
- `Body`：连续正文；
- `List`：列表，无序、有序和无标记作为离散状态；
- `Metric`：突出数值与单位；
- `Label`：短标签；
- `Annotation`：注释、来源或补充说明；
- `Quote`：引语；
- `Emphasis`：关键词或强调语。

组合排版家族：

- 单段陈述；
- 标题内容；
- 标签内容；
- 结构化列表；
- 数值说明；
- 多指标组；
- 键值信息；
- 引语来源；
- 标题指标正文；
- 摘要信息组。

同一组合家族通过字段缺省、对齐、密度和字号阶梯覆盖内容状态，不把每种字段排列分别登记为新排版。

## 后续扩展规则

真实稿件无法由现有排版表达时，按以下顺序判断缺口：

1. 现有组合排版的内容状态或离散参数是否已经能够覆盖；
2. 是否只需用现有 Text Primitive 新增一种组合排版；
3. 是否确实缺少一种新的基础文字组件；
4. 只有逻辑关系或区域几何也发生变化时，才考虑新增 Structure Group。

任何新 Text Primitive 或 Text Layout 都必须同步更新排版库目录、字段契约、容量包络、看板说明和正式生成线的渐进披露信息，不能只增加实现代码。稳定架构文档与入库工作流文档在本次重构落地时同步更新，确保后续工作流延续本规则。

新 Text Layout 先进入候选状态，正式生成线不可见。看板从“最小可用框”开始展示该排版家族的 HTML、Native PPT 和字段缺省状态，不展示低于可读下限的实验小框；用户按排版家族一次审批，通过后才登记为正式可调用。该审批不要求全库重跑、SHA 校验或多轮重复验证。

## 验收条件

- 新增一种 Text Layout 时，无需修改兼容 Structure Group 的结构几何代码。
- 看板能从真实代码读取 TextRegion，并显示当前及兼容的 Text Layout。
- 用户可在看板切换排版和受控参数，HTML 与 Native PPT 保持一致。
- 正式生成时，导演只选择 Structure Group 与兼容排版，不生成坐标、复制正文或创造临时结构。
- 不兼容组合有明确原因，不通过缩小到规范字号以下强行容纳。
- 三个首轮验证对象覆盖分离区域、重复区域和开放大区三种情况。
- 其余核心资产逐项审计；无需迁移的资产保留明确理由，不机械全改。
