# 系统架构

2026-11-17 讨论稿。本文维护职责、资源与技术取舍；[目标与路径](产品目标与路径.md)维护产品范围。库存沿用 10 月 30 日只读核查；既有生产链未重跑，同页方法实验另见下文。

## 已确认的骨架

```mermaid
flowchart LR
    A[MD 与资源] --> B[前段：页内编排]
    B --> C[灰稿页面表达]
    C --> D[共享编译器]
    D --> E[灰稿预览]
    D -->|同一份合规表达| F[后段：视觉制作]
    F --> G[可编辑 PPTX 与成品检查]
```

| 环节 | 责任 |
| --- | --- |
| MD → 灰稿 | 确定页内分组、主次、关系、阅读顺序和区域，绑定内容 |
| 共享编译器 | 检查引用、绑定、几何与交接完整性，生成灰稿预览和诊断 |
| 灰稿 → 成品 | 在既定区域选择结构图、放入图片、制作文字与图形，应用样式并检查 PPTX |

灰稿固定内容归属、整页位置和面积。文字区保留实文与层级；蓝区保留图示内容描述、关系与要求，**不选具体结构资产或绑定其内部槽位**。后段选择资产并完成区域内部制作，保持内容与关系；图片区域保留资源和放置要求。

结构化页面表达是交接源，预览是编译视图。两段读取同一份表达；后段不重新分页，也不从预览图识别布局。分支安排见[AGENTS](../AGENTS.md#分支分工)。

## 设计能力与检查

前段调用页面分区和图文组织能力，后段调用标题、文字、图像、结构图和图表的区域制作能力，共享 Skin、风格与运行基础。模型承担内容理解和受限判断，程序承担测量、几何、绑定、调用与编译；具体组合待定。

共享编译器检查元素和资源引用、内容绑定、区域边界及必要避让、文字层级和蓝区描述完整性。语义忠实与表达质量另行审查；后段检查结构匹配、实际原生对象和导出结果。编译器的具体检查深度待定。

正式建设时，两条线按同一规范推进，后段可先消费合规的模拟灰稿，再接入前段产物。

## 本次重议的依据

[9 月 20 日样例](../experiments/home-mckinsey-style-20260920/README.md)以用户生图为视觉参照，在固定灰稿上经多轮规则和代码调整生成原生 PPTX；具体过程见[当时记录](方向讨论/20260920.md)。它说明局部可以复现，跨稿自动交付仍未证实。

此前枚举组件、调灰稿与看图修改消耗较大。此次需同时判断：组件怎样组成好的整页设计，调整是否进入实际制作能力，迭代能否带来可复用的改进。设计效果、建设成本和复用收益都影响路线选择。

## 外部实践：待比较，未选型

早期对谈已提过 [CSS Grid](方向讨论/PPagenT第二次对谈GPT-260811.md)及 [SeaSlides／HTML／Typst](方向讨论/PPagenT第三次对谈GPT-260812.md)，尚缺针对当前边界的系统比较。

| 可借鉴实践 | 对应问题与边界 |
| --- | --- |
| [CSS Grid](https://www.w3.org/TR/css-grid-2/)／[Yoga](https://www.yogalayout.dev/docs/about-yoga) | 规则化矩形分区、尺寸与对齐；Yoga 可接外部文字测量，不负责语义或绘制 |
| [Cassowary／Kiwi](https://github.com/nucleic/kiwi/blob/main/docs/source/basis/basic_systems.rst) | 用必需／软约束表达对齐、最小尺寸与优先级；表达意图和候选仍由上层提供 |
| [Typst 测量与排版](https://typst.app/docs/reference/layout/measure/) | 根据可用区域与样式测量内容；可编辑 PPTX 的衔接须另核查 |
| [ELK](https://eclipse.dev/elk/documentation.html) | 结构图节点、连线与内部布局；需保留项目设计特征，仍由渲染层制作 |
| [SeaSlides](https://arxiv.org/abs/2608.03298) | 语义描述、复用组件与模板分工，最接近整体链路；当前代码、导出可编辑性及许可须核查 |

比较重点：固定幻灯片容量、真实文字测量、既有设计适配、原生可编辑输出及部署许可。项目已有布局和浏览器测量程序，应比较直接复用、接入和自研的成本，避免平行重建。

2026-11-17 已完成[首轮同页五法对照](../experiments/layout-methods-20261116/README.md)，保留图像、作者适配工作与导出差异，作为继续讨论的依据，尚未选型。

## 尚待决定

- 整页设计如何形成，页面版式与区域组件怎样组合；Skin、文字测量和组件容量何时参与编排。
- 内容关系、表达方式、候选筛选与选择分别交给哪些模型或程序，是否沿用现有调度和 JEV。
- 以哪份内部表示为底稿统一灰稿，哪些检查进入共享编译器。
- 哪些成熟方案值得接入，哪些能力保留自研，以及 PPT 引擎和部署方式。
