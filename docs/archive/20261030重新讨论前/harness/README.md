# PPT Harness 使用入口

2026-09-30 当前口径：生成线只有两段——稿件到灰稿、灰稿到成品。页面表达是共同契约，灰稿是编译视图。Harness 负责状态、调用、检查、有限返工、日志和产物留存；它是建设手段，不是产品定位。

建设阶段由用户与 Codex coworker 使用，Codex 可看图。投入使用阶段只调用语义理解模型、JEV 和确定性程序，Codex 与视觉模型不进入产品。

当前工作台默认进入 main（`src/workbench/main-flow.mjs`），只接入原稿读取与规范化；A0 只调试已有单页契约到灰稿。旧 gray-agent/runner/legacy 入口保留历史或兼容身份，不代跑新主线。日志由 `events.jsonl` 与 `trace/*.json` 编译，实际入口见[运行流程](运行流程.md)。

2026-10-29 明确的输入与验收口径见[产品需求](docs/产品需求.md)：Markdown 文字与图片、全自动生成、灰稿蓝区预留、单稿先跑通；失败回建设修复后重跑。

```powershell
npm run production:workbench
```
