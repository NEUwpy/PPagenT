# 两大阶段的最小审查

2026-10-29 当前口径。建设阶段由用户与 Codex 对照 Markdown 原稿及图片资源看完整灰稿和成品；投入使用只调用语义理解模型、JEV 和确定性程序，中途不需人工分析、补做或批准。程序检查、固定回放和候选状态不代替质量验收。

| 对象 | 检查重点 |
| --- | --- |
| 稿件到灰稿 | 页序、页面目的、实文与来源、归属、必要条件、主次、关系、表达候选、槽位和承载；结构图/图表/图片以蓝区预留，位置/面积/用途和媒体绑定完整；main 不提前制作或放入成品 |
| 灰稿到成品 | 同一契约被正确实现，内容/关系/页序/槽位保持；蓝区正确填入图形或原始图片与必要图注，Skin/风格一致，文字可读，原生对象可编辑，预览覆盖全稿 |
| 程序证据 | Schema、候选、绑定、容量、几何、实际字号/行盒、导出和版本；只报告工具实际覆盖的范围 |

关系是否正确看页面是否忠实表达原稿，不能以是否调用结构组件判断。无溢出、文件可编辑和程序零告警不证明语义或审美通过。

内容/关系问题修契约；候选覆盖回资产；绑定问题修映射；容量/几何问题修能力或返回规划；导出问题修构建。修改后重编译受影响页并检查最终完整预览，保留首版、失败、修订来源和用户反馈。

**当前先验单稿自动跑通：**从原始稿件到灰稿或成品完整自动运行，内容与编排正常；人工预分页、补契约或修页面的结果只记建设干预。**通用通过另验：**用不同且未参与建设的稿件持续检验，不能从一版稿件或有限样本推出所有稿件均通过。完整口径见[产品需求](docs/产品需求.md)。

失败返回责任点后，建设工作继续修复并自动重跑与回归到问题不再复现；返回缺口不等于建设结束。人工审阅用于建设验收，不是产品每次生成的中途放行步骤。

模拟输入、固定计划、模型独立判断和实稿闭环分别记录。检查证据必须对应当前契约与最新产物，旧验收不能自动继承。旧审查说明已[归档](../docs/archive/20260930纠偏前/harness/产物审查.md)。
