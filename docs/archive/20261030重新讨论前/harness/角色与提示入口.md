# 角色与提示入口

## 产品运行角色

产品运行只定义两类模型：

- **语义理解模型：**稿件理解、分页、页面目的、内容归属、必要关系和内容填充。
- **判断选择模型（JEV）：**只从程序给出的合法版式/结构候选中判断和选择，不写自由坐标、不生成制作代码。

程序负责契约校验、来源、候选合法性、容量、槽位绑定、参数、几何、原生构建、检查和日志。产品不调用视觉模型或 Codex。

基础输入先支持 Markdown 文字与图片，Word、PDF 及转换以后扩展。main 自动编排 PE 契约并输出实文与蓝区灰稿；home 按蓝区用途制作图形、放入图片并输出成品。产品中途不需要人分析、补做或批准，见[产品需求](docs/产品需求.md)。

## 建设角色

用户与 Codex coworker 是建设协作者。main 建设稿件到灰稿，home 建设灰稿到成品；可分支开发并阶段性合并。home 可用模拟灰稿探索后段美化，模拟来源必须记录。

建设角色不等于产品运行角色。协作协议见[ppagent-coworker](../.agents/skills/ppagent-coworker/SKILL.md)；planner/reviewer 与 executor 是协作协议角色，前段/后段是任务范围，不能混称为模型角色。

建设审阅与资产审批只用于改进和登记能力。当前先取得单稿自动跑通证据，通用通过另验；失败回所属能力修复后自动重跑与回归，不以人工改好当前稿件代替。

## 当前代码边界

工作台默认 main 目前只接入读取与规范化；A0 是已有单页契约到灰稿的局部调试。旧 gray-agent 的语义规划与 JEV 布局选择属于可复用局部代码，不代表主线已连通。旧视觉导演、视觉表单和自由局部排版仅作兼容或建设证据。实际入口见[运行流程](运行流程.md)，规则和提示正文以消费点为准。
