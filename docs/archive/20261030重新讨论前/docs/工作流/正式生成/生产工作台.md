# 生产工作台

2026-10-29 对齐：PPA 工作台是建设阶段的**生成线调试与日志编译器**，不是面向最终用户的产品功能。它用于查看输入、状态、输出、日志和中间产物，帮助用户与 Codex 修复能力。产品目标是 Markdown 图文稿件自动生成 PPT，中途不需人工接力，见[产品需求](../../产品需求.md)。

## 数据原则

- 整稿验证调用新 main；A0 等局部调试须标明固定输入和覆盖范围，不用旧 Agent 代跑待建设节点。
- 运行事件和阶段产物是唯一事实来源；工作台从 `events.jsonl`、`trace/*.json` 及运行产物编译展示。
- 日志更新后，工作台展示随日志更新；页面不维护第二份手写状态。
- 每个阶段至少展示：状态、开始/结束、输入摘要、输出摘要、错误/缺口和可定位的原始产物。
- 工作台可展示灰稿 PNG/PPTX 和完整日志，但展示不等于用户验收。

## 目标两段视图

| 阶段 | 主要状态点 | 重点输入 | 重点输出 |
| --- | --- | --- | --- |
| 稿件到灰稿 | 读取 → 分页/页面表达 → 候选 → JEV 选择 → 绑定/容量 → 灰稿 | Markdown、图片引用与资源、要求、来源、候选、契约 | 分页稿、页面表达、选择/绑定、实文与蓝区灰稿 PPTX、完整预览和检查 |
| 灰稿到成品 | 读取冻结契约 → Skin/风格 → 图形/媒体填充 → 测量/构建 → 预览/检查 | 灰稿契约、Skin、风格、结构参数、来源图片 | 成品 PPTX、完整预览、几何/导出检查和缺口 |

上表是目标，不表示全部节点可运行。当前默认入口是 `src/workbench/main-flow.mjs`，十个步骤仅“原稿读取与规范化”接入；A0（`src/workbench/segment-runner.mjs`）只编译已有单页契约。旧 gray 运行仍可查看，不作为新主线。状态名称来自实际事件，界面绿色不等于单稿跑通或通用通过。

## 建设与使用边界

建设阶段由用户与 Codex coworker 看图、审阅和调试；home 可以提交模拟灰稿探索后段美化。投入使用只保留 DeepSeek v4.1 Flash、JEV 和确定性程序，Codex 与视觉模型不进入产品。

JEV 通过 OpenRouter Decisions API 做受限候选选择；它只处理程序给出的命名候选，程序负责绑定、容量、测量和构建。OpenRouter 凭证只放在被 Git 忽略的 `config/credentials.local.md`，不写进工作台日志和仓库。

## 启动与检查

```powershell
npm run production:workbench
```

先看流程状态，再看各状态点的输入/输出和原始日志，最后检查灰稿/PPTX/PNG。`awaiting-user-review` 只表示等待建设审阅，不能要求产品每次生成中途由人放行。固定计划、测试、日志完整或候选存在不等于主线单稿自动跑通，跨稿通用能力另验。

失败保留原输入、错误、产物和修订来源，回建设修复后自动重跑与回归。人工改好当前稿件不能作为自动能力证据，只登记缺口也不结束建设。

旧 visual checkpoint、legacy 双导演和旧工作台字段只为读取历史运行保留，不作为当前 MVP 流程。
