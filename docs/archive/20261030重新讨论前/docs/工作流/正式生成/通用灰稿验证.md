# 灰稿验证

2026-10-29 口径。灰稿是页面表达（PE）共同契约的编译视图。它必须显示真实文字、内容归属、主次、必要关系和空间承载，页面目的可从契约核对；结构图、图表及图片用蓝区预留，记录用途、位置、面积与内容/媒体来源。main 不提前制作成品结构图或放入实际图片。

基础输入是 Markdown 文字、图片引用与资源。当前优先用一份真实稿件接通 main 的自动读取、分页、页面表达、候选选择、绑定和灰稿 PPTX；中途不人工预分页、补契约或批准。Codex/用户在建设验收时看完整产物，不成为产品每次运行的人工节点。

## 验证口径

- **单稿跑通：**同一真实输入完整自动生成灰稿，内容/限定/来源不丢不乱，页序与编排正常，文字可读，蓝区和媒体绑定完整，输出可编辑 PPTX 与完整预览，建设审阅核对质量。
- **通用通过：**换不同稿件仍能正常转换的目标，须用未参与建设的稿件持续检验；一稿、有限测试或同稿反复成功不能证明所有稿件均通过。
- **局部证据：**模拟契约、A0 编译、固定回放、程序检查和旧 Agent 运行分别记录，不能替代新 main 自动跑通。模型重理解与固定契约回放也分别比较。
- **失败修复：**回到语义/分页、来源/媒体、候选、绑定、容量或渲染所属能力，保留失败、修复后自动重跑与回归到问题不再复现；不人工补做当前稿件、不删条件或静默降质。
