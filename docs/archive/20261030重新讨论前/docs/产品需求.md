# PPagenT 产品需求（MVP）

2026-10-29 用户明确。PPagenT 的目标是输入一份稿件，自动输出内容忠实、关系清楚、风格统一、原生可编辑的 PPT；中途不需要人分析、分页、选择结构、填充或批准。

## 基础输入

- 当前只以 **Markdown 稿件**为基础，包含文字和图片引用及对应资源。
- Word、PDF 等其他格式及其到 Markdown 的转换以后再加，已有转换代码不扩大当前验收范围。
- 稿件不要求人工预先分页或整理为页面契约；这些工作属于系统。

## 两大阶段

1. **main：稿件到灰稿**。自动理解和分页，形成页面表达（PE）共同契约，编译灰稿 PPTX。
2. **home：灰稿到成品**。消费同一契约，按已建设的 Skin、风格、布局和结构能力生成成品。

两段是内部职责划分，产品使用中不要求用户在中间接力。建设阶段可以分段检查和看图验收。

使用阶段只保留两类模型：语义理解模型负责理解、分页、关系和内容填充；JEV 负责在程序给出的合法候选中判断和选择。程序负责契约校验、来源、容量、参数、几何、构建和检查。Codex、视觉模型和自由绘图只服务建设阶段，不进入产品。

## MVP 交付

- 灰稿落实页面表达编排：页序、页面目的、真实文字、分组、主次、关系和区域；结构图、图表及图片的位置和面积以蓝色预留区表示，此时不制作成品结构图、不放入实际图片。
- 蓝区须能追溯所承载的内容、关系或图片资源，并说明后段需要填入什么；不能只剩无含义的空框。
- 灰稿必须能检查内容完整性、来源、主次、关系和承载；不能静默删件或编造事实。
- 成品必须保留共同契约表达，具备原生可编辑对象，并通过容量、几何、导出和预览检查。
- 无能力或证据不足时返回明确缺口，不用缩字、删稿、自由坐标或高级模型兜底。

## 跑通、通过与失败

- **当前先追求跑通。** 一份真实 Markdown 稿件未经人工中途接力，自动输出内容和编排正常的灰稿，只算 main 单稿跑通；同样自动走到成品才算全线单稿跑通。
- **通过是通用能力目标。** 要做到换来不同稿件也能正常转换，不能凭一版稿件、固定回放或有限测试宣称“无论什么稿件都通过”。后续用未参与建设的稿件持续检验，逐项记录失败与覆盖范围。
- **失败回建设。** 保留失败稿件和证据，定位所属能力，修复规则、资产或程序，再自动重跑与回归，直到该问题不再复现；不能以人工代做当前稿件、静默降质或只返回缺口结束建设。
- 建设阶段的人工审阅用于判断质量与修复能力，不成为产品流程中的必经步骤。模拟灰稿只证明后段，程序通过、产物存在和等待审阅都不能代替质量验收。

以上是目标与验收口径，不表示已实现。实际状态见[项目进度](方向讨论/页面编排能力计划.md)，共同契约见[页面构成与布局规范](架构/页面构成与布局规范.md)。
