# 建设角色分工与阶段性合并

2026-09-30 确立分工，2026-10-29 对齐目标。当前是建设阶段，用户与 Codex coworker 一起开发和看图。角色、分支用于建设协作，不属于产品运行架构，也不要求此刻启动协作或创建分支。

| 建设职责 | 范围与交付 |
| --- | --- |
| 前段（main） | Markdown 图文稿件自动分页与页面表达编排，输出实文灰稿及蓝色预留区，保留内容/关系/媒体来源；当前先交付单稿自动跑通证据 |
| 后段（home） | 消费冻结契约，在蓝区填入结构图、图表及图片，落实 Skin/风格/参数化资产和程序，输出成品与完整预览；可用模拟灰稿先建设 |

home 是建设角色称呼，不表示当前已切换到某个分支。模拟输入标明来源，只证明后段。建设时 Codex 可看图；产品运行时仅有语义理解与判断选择模型。

产品从输入到成品不中途等待人工分析、补做或批准。建设分段审阅不成为运行时人工节点。输入、跑通与通用通过的口径见[产品需求](产品需求.md)。

## 最小合并约定

- 共用[页面表达契约](架构/页面构成与布局规范.md)、稳定内容 ID 和来源；后段不再生成另一份正文。
- 交接保留图片引用与资源、蓝区用途/位置/面积及对应内容，main 不提前制作结构图或放入实际图片。
- 后段可按能力调整样式及几何，内容归属、关系、页序和主次变更写回契约。
- 阶段交付包括代码/配置变更、契约范围、输入及 PPT/完整预览、问题与验收状态；报告从简。
- 合并保留双方工作、模拟/自动来源与失败证据；解决接口差异后用同一契约验证，再连实稿闭环。单段验收和 Git 合并不代表全产品通过。
- 失败分配回所属能力，修复后自动重跑并回归到问题不再复现；不能以某一稿人工补齐或仅登记缺口结束建设。

需要邮箱协作时用[项目协作技能](../.agents/skills/ppagent-coworker/SKILL.md)；planner/reviewer 与 executor 是协作协议角色，前段/后段是建设任务范围，两者不混用。不自动发送任务或修改既有邮箱记录。
