## 当前目标与状态口径

- **先跑通 main：**一份真实 Markdown 稿件自动完成读取、分页、页面表达、候选选择、绑定和多页灰稿 PPTX；无人工预分页、补契约或中途批准。灰稿呈现实文，以蓝区预留结构图、图表及图片，不要求 main 制作这些成品。
- **单稿跑通与通用通过分开：**一份稿件成功只记跑通；“通过”面向不同稿件均能正常转换的通用目标，须以跨稿证据持续检验，不能从有限样本推定所有稿件都已通过。完整成品闭环按同一口径另验。
- **失败继续建设：**保留失败证据，修复所属能力后自动重跑并做回归，直到该问题不再复现。返回缺口不等于建设结束，人工补做不算自动跑通。
- **当前未跑通：**主线只接入原稿读取与规范化；后续九步尚未接入。A0 是已有单页契约到灰稿的局部调试。此次目标澄清不改变既有实现或验收结论。

输入与验收的完整要求见[产品需求](../产品需求.md)。

**MVP 当前下一交付：**以一份真实 Markdown 稿件（文字与图片）为输入，先核对读取、媒体引用与资源留存，再建设“长稿件 → 分页稿”，随后依次接通 A2–A4，最终取得 main 单稿自动跑通证据。分段审阅属于建设，不在产品中加入人工接力；未建设步骤不得跳跑或用旧灰稿线代替。

## 建设和投入使用

建设阶段由用户与 Codex coworker 建资产、规则、程序和检查；main 负责 A1–A4，home 负责 B1–B3，阶段性合并后做 C1。Codex 的视觉能力仅用于建设审阅。

投入使用只包含 DeepSeek v4.1 Flash、JEV 和确定性程序。语义模型负责理解和填充，JEV 在合法候选中判断和选择，程序负责契约、来源、容量、测量、几何、构建和日志。产品不调用 Codex 或视觉模型。

## 稳定性验收

“十次有九次相近”是目标，不是当前结论。按三个比较分开记录：

1. **模型重理解：**固定原稿和要求，多次调用，比较页序、内容、关系和候选。
2. **契约回放：**固定契约、资产和环境，比较绑定、几何、PPTX 和预览。
3. **跨稿闭环：**用未参与建设的新稿检查两段连接和完整质量。

如果分页、主次或容量跨过候选边界，结果可能明显改变；不能用缓存或重复回放代替模型稳定性。
