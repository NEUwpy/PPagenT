# 前半段建设计划：稿件到灰稿

> 2026-09-30 建立，2026-10-29 按用户明确的目标更新。当前状态唯一见[项目台账](页面编排能力计划.md)；下方 2026-10-01 状态保留为历史快照。

## 目标

当前先让一篇真实 Markdown 图文稿件自动编译为内容和编排正常的灰稿 PPTX，中途无需人工分析、预分页、补契约或批准：

`Markdown 文字与图片 → 分页稿 → 页面表达（PE）契约 → 候选选择与确定性绑定 → 实文与蓝区灰稿 PPTX`

灰稿是页面表达契约的编译结果，也是建设阶段的直观检查点。结构图、图表和图片只预留蓝区，记录位置、面积、内容/关系或媒体来源，由 home 填入成品。日志与工作台读取同一轮产物，表单不维护第二套正文。输入和验收口径见[产品需求](../产品需求.md)。

## 范围

本计划只做第一大阶段：**稿件到灰稿**。

基础输入先支持 Markdown 文字、图片引用和对应资源；Word、PDF 及转换以后扩展。一稿自动成功只记“跑通”，不能宣称通用通过。

- DeepSeek v4.1 Flash：语义理解、分页、页面表达规划。
- JEV（OpenRouter `~typesafe/jev-latest`）：在程序测量出的合法候选中做窄选择。
- 程序：内容 ID、候选容量、槽位绑定、关系校验、灰稿编译、日志记录。
- Codex 的视觉能力：只用于建设和验收，不进入产品运行时。

第二大阶段“灰稿到成品”的 Skin 美化、图形制作、图片填充及成品导出只保留接口边界，不在本计划实现；灰稿 PPTX 和完整预览属于 main 交付。

## 共同契约

优先复用 `gray-plan-3`，不另造一套表单正文。契约至少固定：

- 页：`pageId`、标题、主张、`pagePurpose`、叙事、`sourceIds`、内容组。
- 组：`id`、`role`、`heading`、重要性、`kind`、内容块、表达类型、关系、生产约束。
- 块：稳定 `id`、文本、`sourceIds`、作用域。
- 媒体：图片引用、资源来源、必要图注及其所属页/蓝区。字段和消费链须核对实际实现，不能假定现有 Schema 已支持。
- 结构候选：适用关系、输入与槽位、数量和文字容量、合法参数、拒绝条件、可调用实现及验证证据。

页面顺序、页面目的、内容关系、内容 ID、区域和槽位在灰稿检查点冻结；Skin 只处理后半段的风格渲染。

## 里程碑

### A0｜候选资产可调用

**产物**：首批可参数化的版式/结构候选及其容量和适用关系说明。

**检查条件**：候选能被程序测量和调用；不适用、超容量或缺实现时返回明确拒绝，回建设修复，不让模型自由补画。A0 只验证局部能力，不代替主线跑通。

**边界**：宏观页面版式优先；微观结构可选，不强制两级嵌套。

### A1｜分页稿成立

**产物**：由系统自动生成的一篇完整 Markdown 图文稿件的分页稿。

**检查条件**：每页只有一个主目的；页内内容足以说清该目的但不过载；保留原文的条件、程度、否定、时态和来源，图片资源有归属。未解决的内容遗漏或资源丢失算失败，不以“已登记缺口”通过本步骤。

**判断方式**：以语义完整性和候选容量为准，不用统一字数切页。

### A2｜页面表达契约成立

**产物**：每页的 `gray-plan-3` 页面表达：内容组、内容块 ID、主次关系、表达 `kind`、关系、候选要求和选择理由。

**检查条件**：契约可同时投影为表单和灰稿输入，文字和蓝区均有内容/来源绑定；区域位置与面积由受限程序求解，不由模型写自由坐标，不提前制作结构图或放入图片。

### A3｜候选选择与绑定成立

**产物**：每页一个经过测量的候选 ID、关系选择和确定性槽位绑定。

**检查条件**：

- JEV 只回答候选 ID、关系等窄问题，输出是合法枚举或明确拒绝。
- 程序按内容 ID 绑定到槽位，校验顺序、关系、容量、区域和来源。
- 不以换小字体、删内容或任意改关系消除超容量。
- JEV 选不出合法候选时，生成线停在可解释的阻塞状态。

### A4｜main 单稿自动跑通

**产物**：含真实文本与蓝色预留区的灰稿 PPTX、完整逐页预览、同源契约和日志。

**跑通条件**：真实 Markdown 从读取到灰稿全程自动；页序、页面目的、内容关系、来源、蓝区用途/位置/面积、媒体绑定和容量可复核，文本可读。建设阶段对照原稿看完整灰稿确认质量；程序输出文件或等待审阅不自动算跑通。PPA 工作台只从日志和产物展示状态。

## 贯穿检查点

1. **同线检查**：整稿运行调用新 main；A0 等局部回放标明固定输入及覆盖范围，旧 Agent 不代跑未建设步骤。
2. **日志检查**：每个状态点记录输入、输出、状态、错误和产物路径；运行时事件的真实阶段名不得被工作台统一覆盖。
3. **稳定性检查**：单稿跑通后，分别比较模型重新理解和固定契约回放，再用未参与建设的稿件检验。稳定性是目标，不把“十次九次一样”或有限样本成功写成通用结论。
4. **模型边界检查**：语义模型负责理解与规划，JEV 负责窄选择；容量、几何、绑定和拒绝由程序负责。
5. **建设审阅**：查看完整灰稿，核对内容、关系、蓝区、空白和可读性；审阅发生在建设验收中，不成为产品每次生成的必经步骤。

## 建设顺序

1. **核对基础输入**：选一篇真实 Markdown 图文稿件，保留原文、图片引用与资源，检查读取及来源留存。
2. **建设 A1**：从规范化原稿自动产生分页稿及来源、限定、重复/遗漏检查。
3. **接 A2**：生成页面表达及文字/蓝区归属，复用既有契约与校验，补齐实际缺失的媒体绑定。
4. **接 A3**：复用已有候选测量、JEV 选择和确定性绑定；A0 作为回归，只补当前暴露的通用能力缺口，不先扩全资产库。
5. **落 A4**：自动编译完整灰稿 PPTX 与预览，日志如实记录全部节点；建设审阅判断是否取得单稿跑通证据。
6. **修复与复验**：失败回所属能力修复，重新自动生成并回归；单稿跑通后再扩大跨稿验证，单稿结果不晋升为通用通过。

## 失败与交付边界

当前先取得 A4 单稿自动跑通及建设审阅证据。语义无法确认、来源缺失、无合法候选、容量不足、JEV 返回非法选择、绑定失败或产物不可读时，该次运行如实记失败并留存证据；随后回到所属能力建设，修复、自动重跑与回归，直到问题不再复现。返回缺口不结束建设，人工补做页面不算自动跑通。

不在本轮做 Skin 美化、视觉模型产品化、成稿导出、独立部署或旧流程恢复；历史文档和失败证据继续保留为历史资料。
