## 已确认的方向变化

正式生成线第一阶段已经在当前本地工作区完成：候选能力卡、就绪度、单组锁定、确定性 fallback、选择来源和改进日志已接入。提交 `2dbacf3a` 保存了2+3架构改造前的完整工作区基线。完整决策见[正式生成线架构决策](../工作流/正式生成/生成线架构决策.md)。

两份历史真实稿件的最小验证已经完成。`为什么做 PPagenT` 的 10 页正文中 9 页使用结构、覆盖 5 种资产；`让六地红` 的 6 页正文中只有 4 页使用结构、只覆盖 2 种资产，并出现三个已区分的问题：`1+3+N` 被压成普通并列、两个多候选页面仍连续选择同一等权卡片、comparison 与 sequence 存在明确资产缺口。实验记录见 `experiments/正式生成-候选决策验证-20260902/README.md`。

问题已经从“继续加长提示词”升级为内容契约与表达模型共同不足。当前本地工作区已把内容导演主契约收敛为一个页面边界：`contentMarkdown` 中每个 H1 就是一页，H2 是页内主节点，H3 只表示节点内小标题；整套标题、核心结论和叙事弧保存在轻量 `deckMetadata`，pageId 由程序按 H1 顺序生成。程序立即编译为现有 `DeckPlan / PageContent`。视觉侧已有2+3运行时原型，但 2026-09-03 的真实 HTML 目视检查未通过：原型绕过视觉导演已选的登记资产，把正文页统一替换为低保真网格，因此已经退出自动正式路径。2+3仍是确认方向，但不能写成已经完成正式接入。已确认采用2+3架构：

- 页面由 Structure、Text、Media 三种表达组合；
- 一级 Structure 可以承载二级 Structure、Text 或 Media，二级 Structure 不得继续嵌套 Structure；
- 页面级与结构内文字共用同一套 TextRegion／受控 Markdown／Renderer；
- 内容导演输出核心信息、多个内容块、块间关系和块内 Logic；
- 视觉导演规划三种表达、两层嵌套、内容绑定与可追溯展示性派生；
- 程序负责候选过滤、区域求解、State、坐标、字号、边界与遮挡验证。

PPA 文字库已从十种字段组合 Text Layout 收敛为两个 Markdown Renderer：`markdown-flow` 负责传统连续文档流，`markdown-zoned` 用同一份 Markdown Token 流形成 lead／body 命名区域复杂排版。受控语法目前覆盖三级标题、段落、无序／有序列表、引语、行内强调和分隔线；禁用图片、表格、代码、链接、原始 HTML 与多层列表。两个模式各用较少、代表性和较多内容进行 PPA HTML 前置渲染，共 6 个状态通过 15pt 最低字号、越界、裁切和整体溢出门禁，并完成截图目视检查。颜色、字体和主题身份读取当前 Skin。旧十种渲染器仍隐藏保留，避免改变已审批 Structure Group；这两个视觉 Renderer 候选仍为 `awaiting-user-review`。它们与本轮已经接入内容导演的“层级 Markdown 内容稿”职责不同，不能混写成文字视觉样式已经正式入库。

PPA 资产看板已按四个能力域重组：Structure 按 `Logic → Structure Group → State` 展示，不再区分“基础、常用、补充”；Text 管理统一文字能力；Media 保持空白并如实标记尚未建设；Layout 汇总 Skin、Shell、Content Frame、Composition 与 Surface。全部资产与数据目录降为默认折叠的技术记录，资产审批队列默认折叠；正式生成、API 调用、运行日志和结果继续由 PPA 生产工作台负责。

第一版2+3契约和运行原型已经存在。`PageContentBlocks 0.1` 从逐页稿投影核心信息、内容块、块间关系、块内 Logic、受控 Markdown 与来源片段；`PageExpressionPlan 0.1` 保存 Composition、Structure／Text／Media 表达、内容引用和最多两层 Structure。当前本地正式线已受控开放第一种真实 `text-plus-structure`：页面必须恰有两个 H2 内容块，其中一个内容块有明确分点和块内 Logic；程序必须找到能按登记自然占用尺寸放入子区域的核心 Structure Group，另一个块才可进入独立文字区。组件保持原字号，不允许先按整页解析再缩小。未命中上述条件的页面继续使用既有整页 Structure 或正文兜底；`multi-structure`、Structure 内嵌 Structure 和 Media 仍未进入自动交付。

PPA 生产工作台按步骤展示输入、真实提示词或程序规则、输出和后续程序。正常路径完成一次内容导演文本调用、一次视觉导演多模态调用和确定性解析；内容或视觉确定性复核未通过时，最多使用既有恢复预算定向重答。视觉复核失败时先把原始失败页与错误交回下一次视觉调用，不提前改写其他已通过页面；恢复预算耗尽后才只对仍失败的页面使用确定性正文兜底。视觉导演使用独立 `deepseek-v4-flash-vision-exp` 配置，首轮读取合法候选 Structure 的核心预览，长稿分批时把此前页面的职责、疏密、重心与 Composition Family 传给后续批次。可选“调试时暂停表单”允许用户在合法候选内更换 Structure Group／Variant。程序随后在真实 Skin 模板上直接排版暂存 Native PPTX，并从该文件导出逐页图片；用户确认后只复制同一份 PPTX 到交付目录，不重新选结构、排版或编译。整套 HTML 已退出正式生成，只保留在单个资产建设与入库验证中。历史记录删除同时清理输入副本、事件、中间产物、预览和交付目录。

当前 `VisualPlan` 已加入完整 `rhythmPlan`。每页明确记录独立于 Logic 的 `pageRole`、`densityTarget`、`visualWeight` 和实际 `compositionFamily`；视觉导演从合法 `compositionOptions` 选择具体 Composition，程序重新核对 Family。确定性审计报告连续三页同构、家族占比过高、密度全平、缺少锚点与卡片化占比过高，并把结果写入生产统计。它借鉴优秀生成项目的功能页、密度节奏和构图家族实践，但仍保持 PPagenT 的核心资产、固定 Skin 与 Native PPT 事实源边界。

离线回放最新真实导演结果曾生成 10 页 HTML 与 PPTX，12pt 最小字号和几何门禁通过，但用户与浏览器原始尺寸目视检查均判定视觉失败：左侧主旨成为狭长文字墙，右侧是重复空白卡框，`1+3+N` 退化为 2×2 内容网格，七个正文页形成同一种低保真轮廓。该结果只能证明技术链可编译，不能作为2+3可用证据；相关自动接入已经撤回。

此前尝试把“HTML 先看再转 Native”接入正式生成线，但真实结果证明它重建了 Skin 和页面壳，形成第二套渲染事实并引入标题重复、字体和对齐差异。该路径已经撤回。正式检查点现在位于暂存 Native PPTX 生成之后，展示该 PPTX 的逐页渲染图。
