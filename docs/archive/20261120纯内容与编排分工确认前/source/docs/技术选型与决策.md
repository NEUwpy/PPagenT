本文在讨论期维护技术取舍、依据与待选项，随讨论调整；现行职责统一见[架构](架构.md)，文档定稿与归档约定见[AGENTS](../AGENTS.md#文档维护)。变更保留日期和原因；实验通过与用户验收分别记录。

## 当前选型：HTML 编排灰稿，PPT 原生制作

2026-11-19，用户确认。

- **方向。** 用 HTML/CSS 与浏览器编排和测量实文、组件，输出灰稿布局结果与预览。PPT 端消费同一结果完成原生制作，可简化灰稿主题页壳。
- **依据：** 优先复用成熟的测量和布局能力，减少自建排版计算；[同页实验](../experiments/layout-methods-20261116/README.md)已显示字体与换行转换误差，须保留成品检查。
- **评估要求：** 用现有结构库接入真实内容后的整页效果判断路线；临时绘制的通用框图只作基础对照。分别核查设计保留、内容容量、区域适配与原生 PPTX 差异。
- **后续：** 有需要和条件时，再评估迁移到直接原生排版或独立排版器；当前不并行建设。内容组织、灰稿契约与排版实现保持分工，为后续替换留空间。

整页布局须考虑真实组件占位，职责见[架构](架构.md)。HTML 是否减少相对于直接原生排版的调试及维护成本，仍待跨内容密度对照。

## 2026-11-20 独立编译试验

先把结构化页面方案编译为灰稿，再验证稿件如何形成方案。试验以 `gray-page-plan@1` 表示单页实文、来源、分组、局部关系和限定范围。用现有 Node 和 Ajv 检查契约和引用，用 CSS Grid/Flex 和 Chromium 排实际文字和组件。程序按内容量、画幅和最小组件尺寸生成候选，以实测结果选定布局，给出失败位置。整个编译无需模型请求。输入实例、运行命令、实际产物和支持范围见[试验记录](../experiments/gray-compiler-20261120/README.md)。

三份 1280 × 720 单页试编通过，覆盖并列组、比较、局部顺序与库内汇聚结构。不足与感悟、汛期值班两页在 1020 × 720 尺寸下重排通过，不足与感悟在 720 × 420 压力试验中被拒绝并返回容量诊断。结果支持继续用浏览器完成单页候选测量。跨稿视觉质量、多页、不同主题约束和 PowerPoint 交接仍需验证。[试验记录](../experiments/gray-compiler-20261120/README.md)

## 候选与证据

以下实践处于不同层次，保留作复用和后续迁移参考，不代表整套采用。

| 参考 | 可借鉴能力与边界 |

| [CSS Grid](https://www.w3.org/TR/css-grid-2/)／[Yoga](https://www.yogalayout.dev/docs/about-yoga) | 矩形分区、尺寸与对齐；Yoga 外接文字测量，不负责语义或绘制 |

## 2026-11-19 HTML 文字编排探索

用户对上一轮整页效果不满意，并要求以 HTML 前端文字排版继续探索，撤回[固定模板起步的建议](archive/20261119固定模板建议/README.md)。此前实测的来源校验遗漏与 PowerPoint 换行偏差继续作为技术证据。[首轮试验](../experiments/gray-route-trials-20261119/README.md)

本轮已实跑 Pretext、Paged.js、BudouX、Grid System 与 Quoin，并用 GitHub 实现的思路和原生 CSS 重做真实稿件。当前值得深入的是按内容关系组织页面，浏览器在组内流动分栏、用子网格对齐对应事实，文字测量辅助分配宽度和切换标题形态。中文断行与末行调整需要结合实际字体、行框与页面目检。试验页面可换幅面重排，分组与强调经过人工解释，跨稿自动编排及原生交接仍待验证。[预览与试验](../experiments/html-typesetting-20261119/README.md)
