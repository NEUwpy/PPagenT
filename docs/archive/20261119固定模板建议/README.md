## 2026-11-19 路线试验后的建设建议

现行架构的关键接口在单页原型上可行。实测从 Markdown 生成带来源的上屏语义，经过浏览器排版得到可消费的布局，原生端直接使用该布局写出可编辑文本。后续主线采用 **固定布局语法起步，按实文测量挑选有限变体**。固定模板沉淀为候选，模型编写新结构和新排版仅用于探索；进入主线的表达需具备组件契约和原生对应。结论、失败样本与可重跑程序见[三路试验](../../../experiments/gray-route-trials-20261119/README.md)。

### 先做一条单页链路

1. **读稿与语义。** 复用现有规范化和来源切分。以已按单页承载整理的 Markdown 为输入，交给模型一次生成带出处的标题、上屏文案、组、关系、主次和条件范围。为出处绑定段落 ID、原文跨度及版本。程序验证字段、来源和引用范围，审稿针对数字、义务、否定、前置条件、范围与关系核对原文。发现问题时定点重做一次并重新验证。语义结果通过再进入排版。
2. **组件和页面一起量。** 起步覆盖中性对照、并列项和有共同说明的普通文本组，以及一个已证明能凸显局部关系的汇聚组件。组件登记适用关系、必要槽位、节点数、字号和尺寸边界、设计必须保留的部分及原生原语。优先测语义最合适的一个结构版和一个普通文字版，必要时尝试改变横纵布局或区域比例。用现有 Node 模块、CSS Grid／Flex、HTML 组件排实文，由 Playwright 驱动 Chromium 检查插槽、正文边界、裁切和必要避让。中性对照字段可一一对应时优先对齐行。候选通过后先按表达质量与阅读顺序选择，再考虑余量。固定模板足够时直接放行。
3. **冻结同一布局。** 定一个版本化结构化格式，先包含画布、主题排版约束、原文与显示文案、分组关系、阅读序、组件 ID／版本及槽位、区域与对象几何、字体和样式角色、资源引用及放置。预览和原生端读取同一份通过共享校验的结果。文字保留逻辑段落和显式换行，另存浏览器行框和字符范围用于核对；图示保留锚点、曲线指令和连接语义。共享编译器按原生原语白名单拦截未支持效果，并统一字号、单位和坐标基准。组件越界先换合法变体，所有候选失效就返回失败位置和所属阶段，是否能精简原文由语义层回写并重新检查。
4. **并行验证原生消费。** 优先用 PptxGenJS 4.0.1 验证原生文本、基础形状、曲线、图片。保留已有编译和资产中可复用的节点、路径与接口；将浏览器测量与专有评估引擎解耦。先核对同一结果在 PowerPoint 中的实文、按字符比对的自然换行、字形边界、编辑行为和原生连接。用测试逐项决定边线、内联样式、曲线和页壳支持范围，再决定产品引擎和部署。
5. **再接工作台。** 独立 CLI 串通读取、语义、有限候选、冻结布局、预览和诊断，验证陌生已分页稿与两种内容区域，保留语义反转与超容的负例。用跨稿复跑和人工整页审查决定支持范围。契约和失败回执稳定后，再依据新职责更新 main 工作台步骤及 Home 消费接口。

**调度与模型。** 采用程序推进阶段、模型交付有明确定义的响应。旧运行器的来源校验、状态、日志和审阅证据可复用，工具循环仅作为原有能力。首轮将现有 DeepSeek 结构化接口接入试点，用 GPT‑6.2 Sol 的独立结果作为对照，按事实覆盖、范围正确、上屏组织、失败重做和调用代价选型。单次结构响应已有语义遗漏反例，二次审稿的修订结果还需重新对照漏项。JEV 作为候选排序对照，先评估规则排序与实际整页效果。本轮 JEV 端点回了 401，仍缺模型选择证据。

**放行边界。** 单页链路同时检查语义、整页与交接。高密度及内容区变窄时允许明确拒绝。图表、图文媒体、复杂嵌套、真实多页连续性与商业部署按组件和任务扩展。三路实验只支持当前样本的路线判断，用户验收与生产实装另有验证。
