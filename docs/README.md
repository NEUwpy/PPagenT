## 权威顺序

发生冲突时按以下顺序判断：

1. 实际代码、Schema、资产声明与可重复的轻量检查；
2. 契约和当前工作流文档；
3. 产品定义与本阶段方向校正；
4. 更新日志中的历史记录；
5. 方向讨论、实验记录和归档文档。

“目标架构”不等于“当前能力”。每份涉及未来方案的文档必须明确标记 `已实施`、`候选` 或 `待验证`。

## 归档

`docs/archive/` 中的文件已经被当前文档取代，只保留历史背景。旧文件中的数量、测试结果、下一步和架构名称都可能过期，不得作为当前开发入口。当前状态不再维护单独的 `当前阶段.md`，而是放在[更新日志](更新日志.md)顶部。
