# 大学 Skin＋麦肯锡式：结构调用

当前独立制作使用此组合；先运行 `npm run rules:load -- --profile generation --skin northeastern-university-001`。固定角色与分区排版只从 `rules/排版体系/麦肯锡式.md` 读取。

## 配置从哪里读取

以 `e383c18` 合入的共享源设计与换色方法为基础。调用方只选择 Skin、稿件与区域，不另建大学结构库，也不从历史实验复制颜色常量。

| 配置 | 唯一入口或来源 |
| --- | --- |
| Skin 与排版绑定 | `rules/index.json`：`northeastern-university-001` → `mckinsey` |
| 固定模板与目录基线 | `assets/主题/东北大学-001/style-baseline.json` 及其中登记的模板、目录实现和预览 |
| 正文安全区、展示与正文字体 | `src/runtime/skins/northeastern-university-contract.mjs` |
| 大学用途色与共享主色 | `src/runtime/skins/northeastern-university-theme.mjs`；主色引用共享 `defaultStructurePrimaryColor` |
| 独立制作字号与结构主题 | `src/runtime/skins/university-mckinsey.mjs` 的 `universityMckinseyTypography`、`universityMckinseySkin` |
| 结构造型、内容字段及适配能力 | 所选结构的 `structure-skill.json` 与 `review.mjs`；先用 catalog 的 `guide <assetId>` 查询 |

规则加载器已将 `fonts`、`theme`、`pageTypographyPx` 和 `structureSkin` 附在输出中。页外壳沿用模板；正文文字读取 `pageTypographyPx` 与 Skin 用途色；结构调用由专用入口自动传入 `structureSkin`。`theme.typography` 是既有组件基准，不能替代独立制作入口已换算的结构字号。

35 个已审批结构共用源设计，大学保留源设计蓝色层次，通过共享主题编译适配大学主色。中性 Skin 的统一暖米色转换是同一源设计的另一条呈现路径，不应套到大学结构上。修改某个结构的源设计会影响它在各 Skin 下的呈现；修改共享换色程序才可能影响整库。

## 先建模板页，再调用结构

页面必须先通过 `createNortheasternUniversityStarter`（`src/runtime/skins/northeastern-university.mjs`）复用现行大学模板及目录配方，再在返回的正文页安全区内编排。不得使用空白页重画页眉、校徽、标题带和底线。结构保留库内原有蓝色表现，不套用中性 Skin 的语义去填充样式。

先确定整页判断与图文分工，再检索结构 guide。结构外内容须提供独有依据、条件或行动，并与结构对应。以下入口复用中性试点已验证的原造型适配，不让制作模型重新画结构。

```javascript
import { invokeUniversityStructure, universityMckinseySkin, universityMckinseyTypography, closeStructureRuntime }
  from '<仓库>/src/runtime/invoke-university-structure.mjs';
try {
  await invokeUniversityStructure({
    root, slide, assetId, content, targetFrame,
    evidencePath, pageId, regionId, reason,
  });
} finally {
  await closeStructureRuntime();
}
```

`content` 采用所选结构 guide 对应的语义字段。`targetFrame` 使用设计像素，须位于 `universityMckinseySkin.bodyFrame`，并为图外说明预留实际空间。页级字样使用 `pageTypographyPx`；结构字号在入口中一次换算为 pt，不再次乘0.75。不额外填写 skin、execution、references 或 build。

同一入口导出的 `universityMckinseyTypography` 就是规则加载器的 `pageTypographyPx`：图外文字直接读取其 `heading/body/meta`，字体和文字颜色读取 `universityMckinseySkin.fonts` 及 `dark/body/muted/primaryColor`。需要共享派生浅色或线色时调用 `resolveStructureTheme(universityMckinseySkin)`，不从试验脚本拷贝十六进制常量。这样结构内与页外编排共用已配置的主题和文字角色。

支持范围由登记实现决定。首批三结构能保留原造型并按区域调整，中间尺寸也使用同一实现；这不意味着任意小区域或任意数量都可用。未登记结构、超容量与非法区域均明确失败；不以另画相似卡片绕过失败。

| 当前可调用结构 | assetId | 内容字段与现有数量范围 |
| --- | --- | --- |
| 折角便签 | `parallel-folded-notes-grid-002` | `items`，4–8 项 |
| 简明漏斗 | `convergence-simple-funnel-001` | `inputs`，0–7 项；`steps`，3–6 层 |
| 成熟度阶梯 | `progression-maturity-steps-002` | `levels`，3–6 级；可选状态 |

完整正文区域为 `1170 × 492`，位置 `(55, 166)`。原尺寸、85%、70% 是尺寸试点的代表样例，不是调用者必须选择的三个固定档位，也不是大学长文可用的容量承诺。对任意中间区域仍重新测量；大学显式字号优先，容纳不下时扩大结构区域、调整图文分区或拆页。其他结构已完成共享换色，不等于已经登记小尺寸保真执行；后续迁移应补原实现适配及大学整页证据后再开放入口。

## 验证配置与最终页面

配置或共享调用改动后，运行相关检查：

```powershell
node --test --test-concurrency=1 tests/rules-loader.test.mjs tests/structure-theme.test.mjs tests/neutral-structure-theme.test.mjs tests/preserved-structure-build.test.mjs
```

上述检查覆盖规则绑定、共享颜色转换、大学三结构字体角色、尺寸测量和溢出拒绝。模板文件、目录实现及基准预览另按 `style-baseline.json` 核对 SHA256（源码按 Git 中的 LF 换行核对，二进制按原字节核对）。检查通过只证明配置和已有执行路径成立，不替代本次稿件的整页验收。

保存实际调用日志、最终PPT和逐页渲染，核对原稿、结构不变项、文字角色与整页阅读顺序。中性样例的测试结果不能代替本稿大学页面验收。

2026-09-08 接入验证：Luna High 使用上述入口完成折角便签、简明漏斗、成熟度阶梯三张大学正文页，结构内外均读取现行配置。首轮有拆字、标签字号和图文分工问题，经父任务反馈后修订；最终逐页渲染、实际字号与几何检查已完成。见[本轮结果](../../../experiments/neu-shared-entry-20260908/SELF-CHECK.md)及其首轮对照。这证明三种结构的整页接入可用，不代表首轮自主排版已稳定，也未扩大其余结构的尺寸适配范围。
