# 正式生成工作流

2026-09-30 确立两段流程，2026-10-29 明确：基础输入为 Markdown 文字与图片，产品从稿件到成品全程自动，中途无需人工分析、补做或批准。旧流程不再调度，旧入口只保留兼容与历史证据。完整口径见[产品需求](../../archive/20261030重新讨论前/docs/产品需求.md)。

## 阶段一：稿件到灰稿（main）

1. **读取与保真。** 读取 Markdown 与要求，保留图片引用和对应资源，建立可回溯来源 ID，保留数字、条件、程度和时间限定。Word、PDF 及转换以后扩展。
2. **分页。** 按主要目的和阅读关系形成逐页稿。一页讲清一个主要事情，必要内容完整；“不多不少”由语义完整性和后续容量一起判断。
3. **页面表达。** 每页填写共同契约：页序、目的、主题句、内容 ID、分组、主次、关系、表达类型、候选能力和必要备注。
4. **候选选择。** 建设资产预先登记一级页面版式和可选二级结构。程序给出合法候选及容量，JEV 只选择命名 ID，不给坐标。
5. **绑定与编译。** 程序把内容 ID 绑定到区域/槽位，校验数量、来源和容量，生成实文灰稿 PPTX、完整预览、检查结果和日志。结构图、图表及图片只用蓝区预留位置和面积，绑定内容、关系或媒体来源。
6. **检查与流转。** 程序检查后冻结契约并自动进入后段。建设时用户与 Codex 对照原稿审阅页序、内容、关系、主次、承载和蓝区；失败回到责任点修复，不在产品中设置人工放行。

## 阶段二：灰稿到成品（home）

1. 读取冻结的共同契约和灰稿，不重新分页或改变页面意图。
2. 选择 Skin、风格规则、参数化布局和结构资产，把同一内容 ID 填入槽位；按蓝区用途生成图形、放入来源图片与必要图注。
3. 按容量边界测量文字和结构，求解几何，生成原生可编辑对象。
4. 自动输出 PPTX、完整预览、几何/导出检查和日志；用户与 Codex 在建设验收时检查实际页面。
5. 若是样式或承载失败，修资产/程序或选择已登记变体；若是语义或关系失败，回写共同契约并重新编译灰稿。

## 建设与使用

建设阶段由用户与 Codex coworker 设计资产、规则、程序和检查。home 可以用模拟灰稿先建设美化，但模拟输入要记录为模拟来源；它只证明后段，不证明前段自动分页和表达。

投入使用只调用语义理解模型（当前 DeepSeek v4.1 Flash）、JEV 和确定性程序。语义模型理解和填充，JEV 在合法候选中判断和选择，程序负责契约、来源、容量、测量、几何、构建和检查。产品不调用 Codex 或视觉模型。

## 检查点

- **资产：**参数、槽位、容量、拒绝条件、程序入口和原生可编辑证据齐全。
- **分页：**一页一个主要目的，必要内容/限定完整，来源可追溯，无静默删件。
- **表达：**关系与表达类型明确，候选覆盖，JEV 选择可解释且可回放。
- **灰稿：**实文可读，页序、关系、主次、区域和槽位可检查，无未声明溢出。
- **蓝区：**结构图、图表及图片的用途、位置、面积、内容与来源可追溯，main 不提前制作或填入成品。
- **成品：**内容和关系指纹保持，输出原生可编辑，完整预览和用户审阅通过。

这些是建设检查点，产品运行不逐步等待人工。当前先验证一份真实稿件自动跑通；不同稿件均能正常转换的通用目标另用跨稿证据检验。失败保留证据、修复所属能力后自动重跑和回归，不能靠人工补做或只返回缺口结束建设。
