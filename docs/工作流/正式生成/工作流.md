# 生成入口与兼容工作流

2026-09-16 起按 M1–M5 能力里程碑推进，当前聚焦 M1 内容规划。新任务从 [项目入口](../../../README.md) 进入，制作检查点与返工只在运行流程维护；进度唯一见仓库维护资料 `docs/方向讨论/页面编排能力计划.md`，不作为包内运行依赖。本文保留旧 API 命令与入口边界，不建立第二份架构。

## 当前制作入口：Harness

读取包内 AGENTS、运行流程和[生成任务协议](生成任务提示词.md)。默认完成分页内容、蓝图、风格构建、实际渲染与修正，交付可编辑 PPT 与预览；只有明确要求初模时才以初模结束。当前制作配置为仓库自建运行器（`src/runner/`）＋当次实际配置的模型，不安装 Penguin。

从 harness 目录加载一种选定风格，例如：

```powershell
node src/tools/load-rules.mjs --profile generation --skin neutral-editorial-001
```

东北大学可选 `northeastern-university-001`，须具备模板、字体及调用入口。Skin 自动绑定风格规则。加载器只读取规则，不生成 PPT、不预读全库。中性资产仍为 candidate，独立制作不等于晋升或旧正式 renderer 迁移。

新任务使用 content.md、blueprint.json、state.md 轻量约定；现有组合解析器和来源编译试点可选，不是必经审批。选用旧解析器时遵守其 Schema 和真实容量契约。实际渲染失败返回内容、蓝图或构建；中间计划通过不能代替成品验收。

### 复现与监督边界

M1 先验证内容与页面规划，并用真实 PPT 提供反馈；M2 用一种 Skin＋一种风格验收完整制作；M3 验证未调试新稿与新上下文的自主完成。M5 再系统验收部署与恢复等工程能力，已有恢复工具继续复用。启动时记录实际模型、工具、输入与规则版本；不转交其他模型冒充指定模型。主任务可维护通用机制与验收，不提供专稿脚本或页级答案后宣称独立复现。首版、自修、外部反馈、额度/工具恢复分开留存；运行中改变规则则另记条件。

不强制建立新任务、多个 Agent 或独立审查流程来执行一个生产阶段。详细问题放本次 runs，项目进度只保留状态与证据引用。旧 A–H、大学精选和无图片实验只作参考，不能继承为现行 M1–M5 通过。

## 旧 API 生产线：兼容保留

原稿 → 内容导演 → contentMarkdown／元数据 → PageContent／Logic → 合法候选 → 视觉选择 → State／RenderPayload → Native 编译 → 检查与 PPTX。它有中间对象和有限修复，但仍由封闭请求/候选协议驱动，不等于新的自主 Harness。

旧 CLI 仍限东北大学 Skin。候选披露时支持 text-plus-structure，不开放任意坐标、多结构或通用 Media。保留现有模板、资产、fallback 和人工检查点，不在文档重构中改写程序行为。

在仓库根目录启动兼容工作台：

```powershell
npm run production:workbench
```

底层旧入口示例（会实际调用配置的 Provider）：

```powershell
npm run agent:run:deepseek -- --input <稿件.md> --output <输出.pptx> --run-dir <运行目录>
```

这不是 R1 默认入口；保留命令不等于当前要求安装/使用 DeepSeek。配置见[运行配置](../../契约/运行配置信息.md)，检查点见[生产工作台](生产工作台.md)。

旧 `content-director`/`visual-selector` profile 分别加载其协议，选择器不获得自由绘图权限；每次入口重读规则，同次视觉批次共享快照，不承诺旧链路跨阶段冻结。

## 检查与追溯

`npm run validate:contracts`、`npm run test:selection`、`npm run audit` 是代码/资产检查，不是 PPT 视觉验收。旧工作台运行证据位于 `.tmp/production-workbench/runs/<runId>`，新 Harness 任务在 harness/runs。历史大学整稿见 experiments/university-skin-pilot/stability-01/RESULTS.md，无图片原型见 experiments/penguin-harness-v2；这些成功与失败不自动迁移到新主线。
