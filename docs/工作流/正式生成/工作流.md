# 正式生成工作流

2026-09-30 当前流程只有两大阶段：

1. **稿件到灰稿：**语义理解稿件，形成页面表达共同契约，程序编译灰稿并检查内容、关系、主次和承载。
2. **灰稿到成品：**读取同一契约，有限选择合法能力，程序应用 Skin、风格、布局和结构资产，生成原生可编辑 PPT。

灰稿是建设阶段的中间检查视图；投入使用默认直接交付成品，不要求用户逐阶段审批。灰稿和页面表达不维护两份正文。

建设阶段可由用户与 Codex coworker 分角色推进；home 可用模拟灰稿建设后段美化。模拟输入只证明后段。投入使用不调用 Codex 或视觉模型。

当前正式入口仍以实际代码和 Schema 为准：工作台 gray 使用 src/runner/gray-agent.mjs、gray-plan-3、JEV 有限选择和现有测量/渲染能力；容错语义编译和完整受限成稿尚未接入。旧入口保留兼容，不是新 MVP 目标。

遇到问题按责任返回：语义/关系回页面表达，映射回绑定，容量回布局程序，导出回构建。保留首版、失败、修订和用户审阅；程序通过不等于灰稿或成品通过。
