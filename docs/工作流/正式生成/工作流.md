# 正式生成工作流

本文只描述当前可执行入口；目标架构统一见[产品定义](../../产品定义.md)。内容与视觉两角色仍由受 Schema 约束的模型请求驱动，不是自主工具循环。

## 现行生产线

原稿 → 内容导演 → contentMarkdown／元数据 → 程序编译 PageContent／Logic → 合法候选 → 视觉导演选择 → State／RenderPayload → 模板及资产 Native 编译 → 检查与预览 → 可编辑 PPTX。

当前正式 CLI 只支持东北大学 Skin；保留真实模板和既有资产运行路径。不兼容结构时记录 `asset-gap` 并使用已登记正文 fallback。仅候选明确披露时允许 `text-plus-structure`；不开放自由坐标、多结构或通用 Media 组合。

启动工作台：

```powershell
npm run production:workbench
```

底层生成入口示例（需配置 Provider；会调用模型）：

```powershell
npm run agent:run:deepseek -- `
  --input <稿件.md> `
  --output <输出.pptx> `
  --run-dir <运行记录目录>
```

Codex 与工作台调用同一正式入口并保留运行目录。工作台的人工检查点和产物查看方式见[生产工作台](生产工作台.md)，模型与密钥见[运行配置](../../契约/运行配置信息.md)。产品“默认直接交付、之后局部对话修改”的需求不代表现行工作台已去掉所有确认步骤。

## 规则加载

`rules/index.json` 声明实际加载集合：

- 内容导演读取 `content-director`：共享内容原则与角色执行协议。
- 视觉导演读取 `visual-selector`：候选选择协议，正文进入真实模型请求。
- 每次导演入口重读文件；同次视觉分批共享本次快照。修改规则影响下一次入口读取，不承诺整个跨阶段任务冻结同一版本。

正文只有根目录 [rules/](../../../rules/README.md) 一份；Schema、动态任务输入与修复反馈仍在代码侧。缺失、空正文、非法路径或未知入口显式失败，不回退旧长提示词。规则修改不能突破合法候选与资产权限。

## 独立制作任务，不是正式 CLI 的新 renderer

使用[生成任务提示词](生成任务提示词.md)向有文件、PPT 生成及渲染工具的 Agent 提交稿件。该入口不依赖历史聊天，先读取以下命令的完整输出：

```powershell
npm run rules:load -- --profile generation --skin neutral-editorial-001
```

命令只输出共享内容、排版、质量规则、指定 Skin 的规则／字体配置和其唯一绑定的排版体系，不启动模型或生成 PPT。当前中性 Skin 自动加载「杂志风」，无需且不允许另传排版覆盖参数；多 Skin 可复用同一体系。中性 Skin 资产仍为 candidate；独立生成不等于资产晋升或正式生产接入。本轮不通过该入口连接结构库，也不改变另一远端分支的大学 Skin／麦肯锡式实现。

原完整提示词 v3 已在一份稿件上完成独立复现；拆分加载后的完整视觉复现、图文复合页、长稿与跨模型稳定性尚待验证，不把加载测试当作成品质量验收。

### Luna high 复现验收

当前指定执行配置为 **`gpt-5.6-luna` + `high`**，必须在创建独立对话时实际设置并核对；只在提示词中写“你是 Luna”不算。主任务与制作任务职责分开：

- 主任务负责归纳用户要求，维护短提示词、唯一现行规则与说明文档，启动实验，核对事实和可编辑性，逐页评审视觉结果；不替执行者写专稿构建脚本、编排坐标或修改 PPT 成品。
- Luna high 在没有原聊天上下文的新对话中，只接收短任务提示词、规则加载入口、原稿与页数等必要任务条件，以及通用制作工具／技能说明；独立组织内容、制作、渲染、自检和修正。不提供旧样稿、截图、旧脚本或隐藏的逐页设计指导，不转交其他模型制作。
- 每轮在独立输出目录保留实际读取的提示词／规则快照或可核对的哈希、原稿、任务 ID、模型与推理设置、完整 PPTX／逐页预览和自检报告。运行中不暗改设计规则；额度或工具中断后可恢复本轮，须记录恢复与额外反馈，不冒充新的冷启动。
- 结果不达标时，主任务先把问题定位到具体页面和规则缺口，再修改所属的唯一现行规则或任务入口，不新增重复规则、不把该稿坐标固化成通用要求。之后仍由 Luna high 执行验证；直接向原制作对话反馈所得的修订稿只算反馈修订，证明新规则可复制时要重新开启无历史上下文的 Luna high 对话。
- 验收依据是内容忠实、字号与字体角色、视觉编排、关系表达、整套节奏、原生可编辑性及完整渲染检查。主任务或其他模型做出的好样稿只能作内部参考，不能替代 Luna high 的验收结果；测试通过、规则加载成功或一次同稿通过，也不能证明长稿、图文复合页和所有输入已稳定。

杂志风实验结果追加到[复现记录](../../PPT制作规则参考/中性编辑排版-提示词复现/复现记录.md)；已合并的大学咨询式实验继续在其[现有记录](../../../experiments/university-skin-pilot/stability-01/RESULTS.md)追溯。两者使用相同的首轮／反馈修订区分，模型是否看图、是否调用结构、页数与输入须分别披露，不将不同实验条件混成成功率。不另建一套架构或规则说明。

## 验证与诊断

大学咨询式独立实验已从原分支合并，入口与结果在[整稿测试记录](../../../experiments/university-skin-pilot/stability-01/RESULTS.md)，包含结构 Skill 直接调用的早期试验与后续参考重组试验；各自事实以运行记录为准。这些冻结实验不改变上面的中性 Skin 规则入口及其结构调用范围，也不自动迁移正式 CLI。原分支的无图片 Harness 原型见 `experiments/penguin-harness-v2/`。

`npm run validate:contracts` 检查机器契约；`npm run test:selection` 执行程序测试；`npm run audit` 审计公开资产。具体已有失败与本轮结果见[更新日志](../../更新日志.md)，不能只因定向测试通过就声称全库全绿。

正式运行证据在指定 run-dir（工作台默认 `.tmp/production-workbench/runs/<runId>`）。检查实际内容、候选／拒绝原因、渲染载荷、QA 与预览；失败应定位页面与字段，不能把 fallback 或部分产物当作审美验收通过。逐页视觉检查按当前任务加载的质量规则执行。
