## 灰稿定位（用户拍板 2026-09-19）

> 灰稿的本质：打草稿，把每一个地方要放什么内容、占多大地盘，都规划好。灰稿＝终稿与稿件之间的位置规划形态：文字放哪、图（结构图/流程图）放哪，全部排定。（用户原话，2026-09-19 拍板）

本入口验证永久内容规划环节：完整原稿 → 信息提炼与页面职责 → 表达选择与文案重组 → 内容检查 → 基础排版选择 → 实文测量与区域求解 → 原生灰稿 → 实际审阅及反馈修订。M1 检验页面级信息架构，目标是得到无需人工重新组织的可读灰稿；当前只交灰稿候选，不接正式美化，也不表示 M1 或跨稿稳定性通过。

2026-09-16 用户指定的过程范本见 [原稿到页面：不足与感悟](../../PPT制作规则参考/内容提取/原稿到页面-不足与感悟-20260916/笔记.md)。学习顺序为：原稿提炼 → 按归属分支 → 各分支的条目要点与实文说明 → 按局部关系选择表达 → 实文容量与空间调整。先形成实文提纲，不代表先冻结坐标；选择表达后仍可修订文案与容量。范本中的两个类别、各 2／4 项是示例，不能写成页型或固定模板，也不能把两个类别误称为有证明关系的两个观点。

与代码对应：`groups` 承载本页的分支职责，`blocks` 承载分支内条目，`label / text` 区分要点与展开。原先只有组级 `kind`，使某条目需要图示时容易整组蓝化或被拆成无归属的独立区域。本次在文字组的 block 上复用可选 `kind / expression / relationship / production`，不设新角色或任意深度树；block 缺省为文字，局部非文字块显示原有四项浅蓝制作说明。实际显示投影、审稿输入、容量测量和原生渲染共用这些内容，包含局部蓝区内边距。此承载能力的验证不代表模型已能自动稳定完成信息组织；也未迁移到 Harness 镜像包。

2026-09-16 接续修订：完整不是逐字搬运。原稿保留为事实依据，规划可以提炼、合并重复信息、长句改短语，并按表达需要重组实文；重要事实、条件、否定及关系必须保留。已有 role、claim、kind 继续使用，不另建页型枚举或自报密度等级。表达选择使用 `content-stages.mjs` 的组引用绑定：原内容组恰好引用一次，可以共同进入一个表达，重写文案只可引用被绑定组的来源；随后仍进行来源保真及实际可见内容审稿。进入几何阶段后才冻结内容。旧逐字分组试点 `prepareContentDraft/bindExpressions` 的契约保持原样。

审稿输入由与测量、渲染相同的 `grayDisplayBlocks` 派生，明确区分灰色实文、浅蓝制作说明及后台职责。后台叙述不能充当上屏证据。模型审稿仍可能误判，尤其不能用 accepted 代替视觉验收。主题句按28px单行测量。灰稿同排主体栏共用上下边界；栏内按已有 blocks 划分子区，文字区为灰色，制作说明为浅蓝色，不绘制蓝区内部节点。块内按实文测量最小高度与内边距，剩余高度按各块所需高度分配，固定块间距。不能仅拉长外框、把文字全部堆在上方，也不能按条目数量机械决定两栏比例。这是空间组织约束，不代表已经完成视觉验收或自动权重判断。

运行目录与实验名称不属于稿件内容。`area.label` 只用于状态及预览标识，规划、表达、审稿与排版输入只接收区域宽高，避免将“范本页”“原退回案例迁移”等后台标签写入上屏标题。预览也不统一添加“模拟内容”；原稿含模拟性质时仍由实际主题或正文明确承载。

2026-09-16 局部试验从 `gray-draft-2` 简化到 `gray-draft-3`。内容计划使用 `gray-plan-3`：保留目的、主题句、组职责、实际文案与必要关系的一句话说明，不再要求逐句关系边；组与条目的数组顺序就是阅读顺序，条目标签可省略。每组必须选择 kind，但普通文字不要求调用结构库。

排版调用只返回每页的 `single/row/column/grid`、可选横向宽度权重或网格列数，禁止返回坐标、正文或新分组。`src/runner/gray-layout.mjs` 使用同一文字测量逻辑计算容量，再调用现有 `src/composition/resolve.mjs` 的 `resolveLayoutTree` 求区域；无需为了使用几何工具补造逻辑关系。正文区分配与文字最小容量分开，栏内子区同样复用该求解器；不新增语义分类或几何引擎。几何失败先在同一内容计划下尝试其他组合（最多三次排版调用），仍失败才返回规划。旧版候选仍可重放，续跑会采用新规划契约。

四类规则为内容结构、Skin、通用排版、风格。该入口实际加载根目录 `rules/内容结构.md`、`rules/页面组合.md`、`rules/排版.md`；没有将语义契约自动迁移到其他正式导演入口或 Harness 镜像包。

同一流程也可从生产工作台（`启动PPA生产工作台.cmd`）运行：上传稿件、给定宽高与标签后停在等待审阅；每一步的提示词、规则快照、模型响应与程序检查按轮在步骤阅读器里查看，「对比运行」可并排两条运行逐步对照。工作台不改变本入口的检查与记账方式，产物目录结构一致；工作台发起的运行会在工作台内续跑（等价 `--resume`），人工反馈注入仍走 `--feedback` 文件。

反复修订未收敛时，可在 `--resume` 时加 `--fresh-plan`，保留旧版本但不把旧逐页规划送回模型，重新依据原稿、区域及反馈规划。

首次输出目录必须不存在（工作台运行的输出目录由其预先建立并含 `input/`，调用时显式传入 `existingOutput`；CLI 默认行为不变）；恢复核对原稿哈希与区域尺寸。`--max-revisions` 是本次首轮后的额外修订次数。恢复保留 `revision-N` 与人工反馈；已有 PPT 存在时，新版本放在对应 revision 的 artifacts 下，当前指针见 `state.json` 的 `grayDraft.artifactDirectory`，不能只看目录根部的旧 PPT。

尺寸为真实内容区设计像素，支持宽高 240–4000；主题句在内容区外，画布宽高分别增加80与150。正文22–28px、区域标题26px、主题28px。灰区呈现实文，浅蓝区呈现表达作用、承载内容、基本关系、制作要求。四种验证尺寸无单独分支，页数由模型决定；当前单次规划保护上限100页，超出明确失败，不静默裁页。

`state.json` 是机器真源；`plan.json`、`content.md`、`state.md` 是派生视图。PPT 与预览均从其中页面内容和 regions 构建。`revision-N` 保存模型响应、usage、程序检查、语义审稿及修订；`human-feedback-N.md` 保存外部审阅依据。新调用保存系统提示快照，早期试验的提示变化在本轮报告说明。

## 2026-09-17 成本与质检定位修正（用户反馈后的四项改动）

用户反馈：单稿 136 秒、7 次渲染不可接受；"用表格组织"是另一种机械（该用文字条目的内容被做成了表格）；质检-打回循环不应放进正常生成线——质检是开发侧工具，根据它去改提示词/规则，让常规生成一次做对。据此四项改动：

1. **视觉质检退出生成线**：`render_draft` 不再"质检通过才算交付"；视觉评审改为可选诊断开关（`runGrayAgent({visualReview})` / CLI `--visual-review`，默认关、不打回、只落 `visual-review.json`），供开发侧收集模式问题用。
2. **表格边界收紧**（契约与 Agent 提示词同步）：行式表格只用于多个对象按共同维度互相对照；单个对象的一组规则、要求、背景说明用文字条目，不做成表格；同一页不要所有组都用同一种表达，同一稿件不同页避免重复同一组合。
3. **公文元信息不上屏**：文件标题、发文字号、主送称谓（"各部门："）、落款日期是流转信息，不上屏，也不得改写成"通知依据/背景"条目（A01 曾把《…通知》——各部门：做进版面）。
4. **页数服从内容量**：每页要有实质展开；短内容并入相邻页；全稿组数少时控制在两页内；一页放不下就分页，不要反复精简文字硬塞一页。容量报错文案同步（不再引导"精简文字"），并附"修订后直接重试、别再空转"。

配套**稀疏页帧收缩**：`resolveLayoutTree` 返回实测最小尺寸；组合自然高度 < 55% 正文区时按内容高度求解，不再把少量内容拉满整页（空框根因）。`gray-layout` 测试含新增"稀疏不收满/丰实仍铺满"。

**协议兜底**：模型偶尔忘在正文重写完整计划 JSON（协议失误）——`resolvePlan` 改用上一轮已解析计划并在回执标注 `planSource: fallback-previous-turn`，不白烧一轮；缺计划且无历史可兜时，错误消息给出修复动作。`maxTurns` 20→24（留恢复余量）。

A01（固定资产盘点通知）同日对照：135853ms/7 渲染 → 26641ms 交付（中间两次失败为几何与检查自纠，含一次 fallback 兜底）；表格与公文元信息在最终版消除；三页版式相似（单组三块堆叠）仍在观察，属规划判断的稳定性问题，不当作通过。

## 2026-09-17 流转信息来源标记（评审共识 B：覆盖死结在数据层消解）

- 上屏机械禁止（2026-09-20 评审 #111 调整）：曾以 `flow-source-onscreen` 硬拦流转段原文出现在任何上屏字段；契约三分后降为**非阻塞提示**（记录出现位置），展示价值交独立审稿按内容贡献判断，不再由格式规则硬拦；落款整段逐字与「正文单独日期不误伤」的判定逻辑不变（评审 B-2 的窄模式保留）。

## 2026-09-20 审稿版本绑定＋可见内容复核＋组级共同说明（评审 #119，tip `8ff2a45c`）

第 6 轮换措辞样本暴露的层级缺陷＋评审误判：交付版把「共同前提」由渲染器自动编号成与三项同级的「四 共同前提」，而通过结论绑定的是改动前的旧版内容、交付版本从未获得有效审稿——通过状态跨内容改动被继承。按评审 #119 三项机制修复（不动角色/覆盖/展示契约）：
