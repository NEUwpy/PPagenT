# Skin：主题与排版指南的组合

2026-09-06 用户确认方向。当前分支实施主题统一并试验结构参考重组；本文描述目标与接口职责，不宣称正式 Harness 已迁移。

## 职责

| 对象 | 决定什么 | 不承担什么 |
| --- | --- | --- |
| Theme（主题） | 一个主题主色、由它推导的深浅/透明色阶、中性色、字体与组织身份素材 | 不决定页面必须分几栏、放几个结构 |
| LayoutGuide（排版指南） | 结论与证据怎样组成页面，文字层级、对齐、密度、留白、图文对应及可读性边界 | 不写死学校蓝或紫，不固定逐页坐标模板 |
| Skin（皮肤） | 选择 Theme 与 LayoutGuide；需要时附带组织 Logo、封面/页脚配置 | 不为每个学校复制一套布局引擎或结构库 |
| Structure（结构能力） | 关系表达、设计参考与可选确定性组件；当前以纯文字结构为主 | 不接管整页，不独立决定学校配色 |
| PageComposition（本稿编排结果） | 把实际内容、主题、排版方法和结构参考组织为原生可编辑页面 | 不自动晋升为核心资产或新规则 |

东北大学可组合蓝色主题与“科研／咨询式论证排版”；其他大学可以用紫色等主题共享同一排版指南。这里的排版名称是项目场景定义，不将麦肯锡式表达等同于所有科研报告的唯一形式。用户提供的参考仍是该指南的主要视觉目标。

## 单主色

使用 `primaryColor` 作为共享主题入口；主题层统一推导深色强调、次级色、浅背景、边线及透明态。结构内部选择色彩角色和层级，不各自写一个独立蓝色。黑灰白可用于正文、边界和背景。更换主色后，图表、结构和主题强调都应跟随；正负和类别还需借助标签、位置或符号可辨。

阶段门禁流程的核心蓝 `#315F91` 作为本轮默认色依据。主题化实现与代表蓝紫验证见 experiments/structure-theme-01；实际完成状态以该目录报告为准。旧独立 accent 系列字段需要兼容，但显式 primaryColor 应优先统一派生，避免混色。旧主题文件或历史 PPT 不因新接口存在就自动重生成。

## 结构的两种使用方式

**直接调用**继续读取真实参数/尺寸契约，复用运行实现。原实现的最小区域不是可以随意绕过的校验。

**参考重组**通过结构 Skill 读取语义、视觉意图和实现，提取有用的表达方法，再按当前页面空间重新绘制。可以改变节点位置、几何、方向、图内外文字安排和内容容量；源图的满页尺寸不约束这个新表达。必须保留稿件关系、条件与证据，用实际输出检查新布局。

记录 `mode: reference`、参考资产 ID、吸收的方法和变化即可；它不是 `invokeStructure` 成功，不用旧组件的审批或几何不变量为新图背书。新表达留在本稿，后续是否积累为核心能力另行决定。

## 本轮顺序

1. Sol/medium 统一存量结构主题入口与色阶，验证蓝紫切换和原生结果，保持几何不动。
2. 父任务梳理指南与 Skill，空白 Luna/high 试验参考重组，检查整页是否摆脱满幅结构限制。
3. 根据试做结果决定哪些重复重组值得沉淀为响应式组件。暂不对35个结构逐一硬改缩放契约，也不提前迁移 Harness。

正向提示词指导论证与视觉组织；边界保护事实、关系、主题和可读性。执行工具承担确定性的文字测量与实际样式检查；模型不必看图，父任务可看最终成品迭代指南。
