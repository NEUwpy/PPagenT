# 正式生成工作台

正式生成工作台是现有生成线的本地操作入口，不是另一套工作流。稿件进入后，网站直接调用仓库中的提示词、Logic 目录、核心 Structure Group、东北大学 Skin 和 Renderer；Codex 不是日常生成依赖。

## 使用

- 启动开发服务：`npm run production:workbench`
- 双击启动：项目根目录中的 `PPA生产工作台.exe`
- 支持稿件：`.docx`、`.md`、`.markdown`、`.txt`
- 旧版 `.doc` 不做不可靠的静默转换，需要先另存为 `.docx`

工作台使用本机 `127.0.0.1`，启动后由系统默认浏览器打开。EXE 是仓库启动器，仍需与项目、`node_modules`、`PPT源/` 和本地 DeepSeek 配置放在同一台电脑上。

稿件有两个等价入口：用户在网页上传，或 Codex 把用户指定的本地文件提交给工作台接口。两者必须生成相同的运行记录并执行相同的正式流程。用户要求 Codex“用正式工作流生成”时，Codex 不手工拆稿、不直接扮演两个导演，只负责提交、监控和调试。

网页上传不会暴露原文件在电脑上的绝对路径，但工作台会把完整输入副本保存到本次运行的 `input/` 目录；Codex 读取该副本即可复现和诊断。由 Codex 代为提交时，它同时知道用户指定的原始路径和运行目录中的输入副本。

## 调试信息

页面显示真实运行中的稿件规范化、内容导演、Shell、候选发现、视觉导演、确定性解析和渲染交付。每个阶段可以查看输入、提示词、模型与 Endpoint、输出、耗时、重试和 Token 用量；API Key 不进入记录。

本地记录位于 `.tmp/production-workbench/runs/`。`events.jsonl` 只保存事件索引，完整上下文按事件分开存放，最终 PPT、逐页预览和中间 JSON 仍来自同一次正式运行。

需要 Codex 协助调试时，让它先读取固定入口 `.tmp/production-workbench/current-run.json`。该文件指向当前或最近一次运行的摘要、事件索引、逐次调用详情、规范化稿件、工作流中间产物和交付目录。Codex 与网页读取同一份记录；Codex 可以按需分析和修改系统，但不参与日常生成，也不是生产线依赖。

首版一次只运行一个任务，不增加数据库、账号、WebSocket 或额外审查 Agent。
