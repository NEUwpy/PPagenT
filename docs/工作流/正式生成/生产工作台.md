# 正式生成工作台

正式生成工作台是现有生成线的本地操作入口，不是另一套工作流。稿件进入后，网站直接调用仓库中的提示词、Logic 目录、核心 Structure Group、东北大学 Skin 和 Renderer；Codex 不是日常生成依赖。

## 使用

- 启动开发服务：`npm run production:workbench`
- Git 克隆后双击启动：项目根目录中的 `启动PPA生产工作台.cmd`
- 本机可选启动器：`PPA生产工作台.exe`；未随 Git 发布，可用 `npm run production:workbench:exe` 重建
- 支持稿件：`.docx`、`.md`、`.markdown`、`.txt`
- 旧版 `.doc` 不做不可靠的静默转换，需要先另存为 `.docx`

工作台使用本机 `127.0.0.1`，启动后由系统默认浏览器打开。源码启动器首次运行会执行 `npm ci` 和 `npm run setup:workspace`；后者连接 Codex 工作区自带的 `@oai/artifact-tool`。正式生成所需的东北大学最小运行模板已随仓库发布，因此全新克隆不再依赖 `PPT源/`。`PPT源/` 只用于继续蒸馏、来源审查和未打包主题。DeepSeek 配置可选；没有配置或模型暂时不可用时，工作流会记录原因并使用确定性兜底交付。

稿件有两个等价入口：用户在网页上传，或 Codex 把用户指定的本地文件提交给工作台接口。两者必须生成相同的运行记录并执行相同的正式流程。用户要求 Codex“用正式工作流生成”时，Codex 不手工拆稿、不直接扮演两个导演，只负责提交、监控和调试。

网页上传不会暴露原文件在电脑上的绝对路径，但工作台会把完整输入副本保存到本次运行的 `input/` 目录；Codex 读取该副本即可复现和诊断。由 Codex 代为提交时，它同时知道用户指定的原始路径和运行目录中的输入副本。

## 调试信息

页面按正式生成顺序显示稿件规范化、内容导演、Shell、候选发现、视觉导演、确定性解析、PPT 排版预览和 PPT 交付。点击任一步骤，工作台直接把该步骤的“进入内容、使用的提示词或程序规则、实际输出、下一程序去向”并排整理出来；内容导演阶段同时保存并展示人类可读的 `content-draft.md`、轻量机器元数据和程序编译后的旧表单。原始逐事件记录默认折叠，仍可查看 Endpoint、耗时、重试和 Token 用量。API Key 不进入记录。

发生程序接管时，运行仍显示为成功交付，但 `deliveryStatus` 为 `delivered-with-fallback`，并增加“鲁棒性与兜底报告”。报告逐项记录内容导演、候选、视觉导演、视觉复核或渲染阶段的触发原因和受影响页面，不把降级伪装成最佳路径。

工作台轮询使用运行状态与事件签名增量刷新。没有新记录时不重建阶段阅读器；确需更新时保存三栏滚动位置、展开状态、表单输入、焦点和文本选区。可选表单调试暂停正在编辑时，Reader DOM 完全冻结，只更新外围运行状态，避免自动刷新把用户推回顶部或丢掉尚未提交的修改。

新建运行默认连续完成“内容导演文本调用 → 视觉导演文本调用 → 确定性解析 → 直接排版暂存 PPTX”，不要求图片输入或视觉模型。需要调试时可勾选“调试时暂停表单”：视觉导演返回后、输出进入确定性解析器前，工作台展示逐页内容稿、合法候选和已经填写的 `VisualPlan / CompositionPlan`。用户可以在该页合法候选内更换 Structure Group／Variant；程序会重新填写与新结构配套的计划，避免沿用旧字段。这一暂停可选，不创建手动生成线，也不再次调用导演 API。未经视觉验收的2+3表达仍只保留在研发实验中，不进入自动正式线。

确定性解析完成后，程序直接复制真实模板页、填写动态 Skin 文字、Composition 和登记 Structure，生成暂存 Native PPTX，并从这份 PPTX 导出整套预览图。工作台进入“等待确认 PPT 预览”；用户看到的就是将要交付文件的渲染结果。点击确认后，同一个 `runWorkflowCli` 只把暂存 PPTX 复制到交付目录，不重新选择 Structure、Composition，不重新排版，也不再编译。

如果暂存 PPT 排版发现某个组件超出安全区域，程序只对失败页执行合法正文兜底，再重新生成暂存 PPTX 与逐页图片；其他已经合法的页面保持原方案。早期失败事件仍保留在日志中，但后续兜底成功后，阶段最终状态显示为成功，不把一次已恢复的尝试误标为整条生成失败。

这个检查点当前编辑的是正式生成线已经使用的 `VisualPlan / CompositionPlan`。候选2+3架构的 `PageExpressionPlan` 尚未接入正式双导演；以后接入时应复用这个检查点和页面位置，而不是再建第二个实验台。

本地记录位于 `.tmp/production-workbench/runs/`。`events.jsonl` 只保存事件索引，完整上下文按事件分开存放，最终 PPT、逐页预览和中间 JSON 仍来自同一次正式运行。

左侧固定提供“新建任务”按钮，用于退出当前历史或等待确认页面并回到稿件上传入口。工作台只把正在规范化、计算或交付的任务视为占用生成名额；视觉表单和 PPT 预览进入等待确认后释放名额，可以继续新建另一任务。

左侧“最近运行”中的每条非活跃或等待确认记录都提供勾选框和单条删除按钮，并提供三种批量操作：全选当前显示的最近记录、删除所选、清空后端全部可删记录。后者遍历完整运行目录，不受左侧最多显示最近 30 条的限制，并在确认框显示实际可删总数。

任何删除都必须二次确认；确认后后端删除对应运行的整个目录，因此输入稿件副本、API 事件、提示词与响应、中间 JSON、PNG 页面预览、暂存 PPTX 和交付文件会一起永久删除。正在规范化、计算或交付的任务仍禁止删除；等待视觉表单或 PPT 预览确认的任务会先取消其暂停调用、释放后台状态，再删除完整目录。若被删记录正是 `current-run.json` 指向的记录，工作台会改指向剩余记录中最新的一条；没有剩余记录时删除该指针。

需要 Codex 协助调试时，让它先读取固定入口 `.tmp/production-workbench/current-run.json`。该文件指向当前或最近一次运行的摘要、事件索引、逐次调用详情、规范化稿件、工作流中间产物和交付目录。Codex 与网页读取同一份记录；Codex 可以按需分析和修改系统，但不参与日常生成，也不是生产线依赖。

同一时刻仍只计算或交付一个任务，但等待用户确认不再占用计算名额；不增加数据库、账号、WebSocket 或额外审查 Agent。若另一个任务正在计算，等待任务暂时不能恢复执行，完成后即可继续。视觉表单暂停和 PPT 预览确认都依赖当前工作台进程；暂停期间重启服务会保留检查点文件，但不能恢复已经中断的运行 Promise，可以删除旧记录后重新发起生成。
