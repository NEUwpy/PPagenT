# 正式生成工作台

正式生成工作台是现有生成线的本地操作入口，不是另一套工作流。稿件进入后，网站直接调用仓库中的提示词、Logic 目录、核心 Structure Group、东北大学 Skin 和 Renderer；Codex 不是日常生成依赖。

## 使用

- 启动开发服务：`npm run production:workbench`
- 双击启动：项目根目录中的 `PPA生产工作台.exe`
- 支持稿件：`.docx`、`.md`、`.markdown`、`.txt`
- 旧版 `.doc` 不做不可靠的静默转换，需要先另存为 `.docx`

工作台使用本机 `127.0.0.1`，启动后由系统默认浏览器打开。EXE 是仓库启动器，仍需与项目、`node_modules`、`PPT源/` 和本地 DeepSeek 配置放在同一台电脑上。

稿件有两个等价入口：用户在网页上传，或 Codex 把用户指定的本地文件提交给工作台接口。两者必须生成相同的运行记录并执行相同的正式流程。用户要求 Codex“用正式工作流生成”时，Codex 不手工拆稿、不直接扮演两个导演，只负责提交、监控和调试。

网页上传不会暴露原文件在电脑上的绝对路径，但工作台会把完整输入副本保存到本次运行的 `input/` 目录；Codex 读取该副本即可复现和诊断。由 Codex 代为提交时，它同时知道用户指定的原始路径和运行目录中的输入副本。

## 调试信息

页面按正式生成顺序显示稿件规范化、内容导演、Shell、候选发现、视觉导演、确定性解析和渲染交付。点击任一步骤，工作台直接把该步骤的“进入内容、使用的提示词或程序规则、实际输出、下一程序去向”并排整理出来；内容导演阶段同时保存并展示人类可读的 `content-draft.md`、轻量机器元数据和程序编译后的旧表单。原始逐事件记录默认折叠，仍可查看 Endpoint、耗时、重试和 Token 用量。API Key 不进入记录。

发生程序接管时，运行仍显示为成功交付，但 `deliveryStatus` 为 `delivered-with-fallback`，并增加“鲁棒性与兜底报告”。报告逐项记录内容导演、候选、视觉导演、视觉复核或渲染阶段的触发原因和受影响页面，不把降级伪装成最佳路径。

工作台轮询使用运行状态与事件签名增量刷新。没有新记录时不重建阶段阅读器；确需更新时保存三栏滚动位置、展开状态、表单输入、焦点和文本选区。可选表单调试暂停正在编辑时，Reader DOM 完全冻结，只更新外围运行状态，避免自动刷新把用户推回顶部或丢掉尚未提交的修改。

新建运行默认自动连续执行“内容导演文本调用 → 视觉导演文本调用 → 确定性解析与渲染”，不要求图片输入或视觉模型。需要调试时可勾选“调试时暂停表单”：视觉导演返回后、输出进入确定性解析器前，工作台展示逐页内容稿、合法候选和已经填写的 `VisualPlan / CompositionPlan`。用户可以在该页合法候选内更换 Structure Group／Variant；程序会使用现有路由器重新填写与新结构配套的完整 `CompositionPlan`，避免沿用旧结构字段。完整 JSON 仍可展开检查和高级编辑。确认后同一个 `runWorkflowCli` 继续执行现有校验、State／内容绑定、Native Renderer 和质量门禁，不创建手动生成线，也不再次调用导演 API。

这个检查点当前编辑的是正式生成线已经使用的 `VisualPlan / CompositionPlan`。候选2+3架构的 `PageExpressionPlan` 尚未接入正式双导演；以后接入时应复用这个检查点和页面位置，而不是再建第二个实验台。

本地记录位于 `.tmp/production-workbench/runs/`。`events.jsonl` 只保存事件索引，完整上下文按事件分开存放，最终 PPT、逐页预览和中间 JSON 仍来自同一次正式运行。

左侧“最近运行”中的每条非活跃记录都提供勾选框和单条删除按钮，并提供三种批量操作：全选当前显示的最近记录、删除所选、清空后端全部可删记录。后者遍历完整运行目录，不受左侧最多显示最近 30 条的限制，并在确认框显示实际可删总数。

任何删除都必须二次确认；确认后后端删除对应运行的整个目录，因此输入稿件副本、API 事件、提示词与响应、中间 JSON、页面预览、PPTX 和交付文件会一起永久删除。批量删除会先完整校验所有目标，选中项只要包含正在规范化、生成或等待表单确认的任务，整批就在删除前拒绝；“清空全部可删记录”则自动保留这些活跃任务。若被删记录正是 `current-run.json` 指向的记录，工作台会改指向剩余记录中最新的一条；没有剩余记录时删除该指针。

需要 Codex 协助调试时，让它先读取固定入口 `.tmp/production-workbench/current-run.json`。该文件指向当前或最近一次运行的摘要、事件索引、逐次调用详情、规范化稿件、工作流中间产物和交付目录。Codex 与网页读取同一份记录；Codex 可以按需分析和修改系统，但不参与日常生成，也不是生产线依赖。

首版一次只运行一个任务，不增加数据库、账号、WebSocket 或额外审查 Agent。可选表单暂停依赖当前工作台进程；暂停期间重启服务会保留检查点文件，但不能恢复已经中断的运行 Promise，需要重新发起生成。
