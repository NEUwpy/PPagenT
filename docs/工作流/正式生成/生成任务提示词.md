# 独立生成任务提示词

把下面任务段落交给能读取本仓库、制作并渲染 PPTX 的 Agent；填入原稿、输出位置和必要演示要求。不需要复制历史聊天或旧设计长提示词。没有相应工具时应说明缺失，不把规则加载成功当作生成成功。

当前复现验收由主任务实际启动 `gpt-5.6-luna`、`high` 的无历史上下文新对话执行；主任务负责提示词／规则维护与验收，不代做成品。该模型设置不是下方提示词能自行切换的。完整分工、输入隔离与失败后再验证流程见[工作流](工作流.md#luna-high-复现验收)。

## 内容与整页编排初模（当前M1验证）

用户要求先看页面初模时，使用下面任务，不执行后面的完整视觉美化流程。初模已经确定整页布局和媒介，尚未做品牌与审美润色；不是提炼文字的展示容器。

> 根据未经页面化的原稿，独立生成一个可编辑PPT前后对照：前部连续放置完整原文，后部为已填入真实内容的整页初模。内容提炼、媒介选择和整页布局共同完成：根据页面要说明的判断决定哪些内容重要、分别放在哪个区域、彼此怎样对应，再据此调整措辞、容量和分页；不要先定一份文字摘要再把它纵向堆进幻灯片。原文能清晰放一页时不人为拆页，初模页数由论证需要决定。

> 为每页选择适合本页关系的宏观骨架，例如同口径比较、主证据配解读、过程或条件分支、多个依据共同支持判断；这些是参考，不是必须凑齐的页型。确定标题、主表达、解释及约束各自的位置、面积和阅读顺序，使用真实内容填满该骨架。适合比较的数据可成为原生表格或简单图表，关系可用基本形状与连接表达；采用何种媒介由内容决定，不设图表配额。初模中的表、图、关系和文字必须已经可读、可编辑，不用“此处放图表”或空框代替，不添加方法论说明页代替实际稿件。

> 使用白底、黑灰文字和最少的功能性线条或形状，保证文字层级与必要净距。允许承载关系的分区、表格线、节点和连接；不加无语义装饰色条、品牌外壳或装饰图标。后续美化可改变视觉语言，不能等到美化阶段才决定这页哪个地方放什么。

自主多轮审查原稿与实际PPT。语义审查主动用原稿反证提炼后的标题，核对统计口径、判断范围、信息角色及条件逻辑；整页审查判断读者能否从空间布局看出主要信息、依据归属及关系，而不是只能逐段读完文字才理解。逐页查看实际渲染，发现问题后自己选择重组、换媒介、精简或调整容量，再渲染复核；不等待外部逐页修法。保留首版与自主修订、来源映射和简短审查证据，最终交付前后对照PPT和全页预览。无越界、文字覆盖完整或计划写有关系，都不能代替初模成立。

**基础硬门槛：禁止非预期重叠和遮挡。** 布局时为文字真实换行、表格行高、图表标签、节点和连接线留足空间。导出后逐页检查整页与组内：文字不能互盖，图表/形状不能侵入相邻内容区，边线/连线不能穿字，内容不能被裁切或挤出页面；有意的背景承载文字不属于错误。不能以容器不相交、代码坐标合法或自动检查无报错代替实际渲染核验。发现冲突必须调整组合、区域容量、连接路径或必要分页，不能靠压小到难读的字号隐藏；修订后重渲染全部受影响页。任何未解决遮挡都只能标为失败候选，不能作为通过版本。

图形也是论证：自审时把图表、连接、顺序和分区表达的含义还原成一句话，与原稿核对。坐标轴与表头须保留统计对象、时间窗口、单位和聚合层级；不能把汇总量当个体过程、把并列备选画成顺序、把未知关系画成因果。主标题也不能扩大证据范围。若一种骨架需要额外假设才能成立，换骨架，不用文末注释抵消主图造成的误读。

## 完整视觉制作模式

以下流程在进入完整成品制作时使用；不能以它替代M1内容草稿实验。

---

请根据我提供的原稿和演示要求，独立完成内容编排、原生可编辑 PPTX、完整逐页预览与必要修正。原稿路径、输出目录、受众、页数或时长以本次任务提供的信息为准；保留用户明确限定的改动范围。

在 PPagenT 仓库根目录按用户选择的 Skin 运行并完整读取输出。当前默认大学 Skin＋麦肯锡式，使用下方命令；用户明确选择中性 Skin 时将 ID 替换为 `neutral-editorial-001`：

```powershell
npm run rules:load -- --profile generation --skin northeastern-university-001
```

这会加载共享规则与所选 Skin 的颜色／字体配置：中性 Skin 绑定「杂志风」，东北大学 Skin 绑定「麦肯锡式」分析方法、文字角色与容量规则；具体颜色按 Skin 用途取值，文字角色和布局按排版体系执行。不要改用历史 v1/v2/v3 提示词，不默认读取全库，不改写规则或资产。若指定其他 Skin，先确认 `rules/index.json` 有相应 ID；排版体系由 Skin 自动选择，不能单独覆盖。加载失败时停止制作并报告具体原因。

按已加载规则推进；输入足够时直接交付，不默认等待逐页或大纲审批。遇到影响事实、任务方向或改动权限的关键缺失才澄清。局部关系需要结构时，按共享排版规则读取结构 Skill，按共享规则的技能选择顺序，项目结构技能优先；项目库不适合且属于技术图示时转用 Archify，两者均不适合再自主编排；不设调用或参考数量配额。此次为独立制作，不通过正式 CLI 冒充中性 Skin 已接入。

按以下顺序执行，关卡是你的内部自检，不需要用户逐步审批：

0. 先理解整稿论证，再自主决定页面序列、每页职责和核心命题，说明合并、拆分或调整顺序的理由。随后建立每页的信息角色、关系、层级和阅读路径，才选择媒介与几何组织。不能由原文块数、段落次序或现有组件槽位主导分页；“两组文字所以双栏”不是充分依据。区分事实、解释、必要条件、行动及推断边界，不把不同决策对象合并，不把必要条件写成充分条件。保存简短策划与实文内容映射作为证据，但直接完成PPT，不停在文字材料等待批准。允许忠实提炼并留来源，关键数字、口径、条件和例外必须在页面可见；保真校验是底座，不代表策划正确。原文保留试点接口可选，不为满足整块一次分配限制合理的信息组织。

1. 每轮实验开始时加载现行规则并冻结快照；本轮生成与自主修订使用同一版本。下轮实验重新加载，不沿用旧快照。按页面组合规则写出并检查 `composition-intent.json`，包括内容组、逻辑 relations 与嵌套组合。使用 `src/composition/resolve.mjs` 的 resolveComposition 计算区域，再由 buildComposition 将同一计划中的 frame 交给各组文字、结构、图表构建器；保存解析结果与执行回执。不另写固定 visual/narrative 分区或绕开计划手写组级坐标。容量失败返回计划重组。首版与修正后的计划分别保存，不要凭整体印象另配字号或套用默认模板。
   东北大学页面先按 Skin 规则用 `createNortheasternUniversityStarter` 建立模板页，再在其正文安全区内完成图文分工；需要结构时使用 `invokeUniversityStructure`，由入口继承已配置的大学配色和麦肯锡字号。结构内承载关系与节点信息，图外说明承担对应依据、条件或行动，二者共同完成本页判断；不得只完成结构调用便交付。
2. 批量制作前，用本稿真实的最长标题、两位编号、窄栏说明和多行混排文字测试共享文字组件，导出并实际查看排字结果；按质量规则的排字预检修正后再复用组件。这些测试不计入交付页数。
3. 生成与审查形成你自主执行的多轮闭环，不要求一次生成即成功，也不等待外部逐页修改指令。保留首版后，切换到审查视角，从原稿和实际PPT重新判断：页面命题是否有依据，信息角色与关系能否直接读出，限定是否忠实，以及排字和整页视觉是否成立。不要把策划中的自我描述作为通过证据。依据质量规则记录“现象—证据—失败层—修正选择”，由你决定回到内容策划、信息结构、媒介、组件或排版哪一层，重新导出并复核；共享问题检查全部受影响页面。允许多轮工具调用或对话推进；后续通用续行指令也只要求按这套机制继续，不提供该稿页面答案。连续修订未改善时重新诊断上游选择，不重复表面调整。记录每轮实际发现与未解决项。
4. 所有未解决项清零且检查证据对应最终文件后才交付。通用文件校验不能替代角色、几何和逐页视觉检查；无法完成时明确交付为候选及其阻塞，不以“已自检”概括未执行的检查。

最终给出可编辑 PPTX、完整预览的位置、已完成的检查和仍未解决的问题。修改已有成品时，以本次指定页面为范围，不无故改变其他已认可页面。
