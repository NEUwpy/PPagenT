# Harness 最小制作任务协议

2026-09-16 对齐新的 M1–M5 能力主线。本文由维护源同步到 Harness 包；运行时从包内读取。正常制作默认执行两个检查点和完整交付；明确指定 M1 规划验证时可以单独审阅规划，并用真实 PPT 提供反馈，不把规划通过计作 M2 制作通过。旧 R1、黑灰初模实验和 A 回归保留历史。

> 根据原稿、演示要求和选定的一种 Skin＋绑定风格规则，独立完成分页内容、页面蓝图、原生 PPT 构建、实际渲染、检查和必要修正。保留内容与视觉两种职责，不固定单次调用，不等待逐页批准。
>
> 形成 content.md：一级标题为页面，记录页面目的、真实内容、稳定内容 ID、归属、主次、关系和必要来源。核心结论按需填写，不为目录/过渡页添加结论；检查无意义重复、关系误判与重要遗漏。当前运行器通过工具更新 state.json，再派生 content.md 和 state.md，不手工编辑派生文件；蓝图与构建引用同一内容状态，不维护多份正文真源。
>
> 保存 blueprint.json：引用内容，说明区域、表达方式和阅读关系。使用真实内容与基本字号测量容量；无数据不编造统计图，空占位框不算布局成立。蓝图字段从本次实际需要出发，不强制完整 Schema 或固定布局名称。
>
> 结合选定 Skin 和排版规则调用已有制作工具。允许调整区域比例、换行、间距和局部分栏；如需提炼或拆页返回内容阶段，不锁死初次布局、不缩字硬塞、不删必要条件。局部关系需要时按技能选择顺序调用，不设结构配额。
>
> 导出可编辑 PPT 并实际渲染。核对原意、图示关系、编辑性和明显排版问题；按问题返回内容、蓝图或构建阶段，修订后重新渲染。保留首版、修订与最终对应预览，state.md 简记候选、检查发现、下一步及外部干预，不增加重复报告。
>
> 默认交付完整 PPT 与逐页预览；未解决的问题明确标为候选限制，不能宣称通过。仅当用户明确要求初模时以实文黑灰初模为交付终点；不默认附加原稿对照页。

## 规则和工具

在 harness 目录执行并完整读取选定规则，例如中性风格：

```powershell
node src/tools/load-rules.mjs --profile generation --skin neutral-editorial-001
```

东北大学使用 `northeastern-university-001` 并检查模板/字体/专用入口实际可用。风格规则由 Skin 绑定，不在首轮同时验证两套。规则加载不生成 PPT，不能代替工具接入检查。

现有 `composition-intent.json`、resolver 和来源编译入口可按需复用，非所有新任务的必经步骤。若选择 resolver 路径，按原 Schema 转换蓝图并消费其 frame，失败时遵守契约返回；不伪装它支持任意绕排。不选用时由构建代码落实蓝图并测量/检查实际区域，不需要为绕过旧试点复制一套 Schema。

生成模型由实际运行方配置：仓库内运行器（`src/runner/`）读 `config/deepseek.local.json` 里的 OpenAI 兼容端点，模型名以该配置为准、不写进本协议——写死过一版（“当前为 Codex 项目＋Luna high”），模型一换就成了假话。本协议不自动切换模型、不安装 Penguin。运行过程冻结本次实际读取版本，修改共享规则后另记新实验条件。不得把旧成品脚本或该稿页级答案注入独立复现，再声称通用能力通过。

当前 M1 聚焦分页与页面内容规划，M2 验收一种 Skin＋一种风格的完整制作，M3 验证跨稿稳定；现阶段不要求独立 Visual Plan、多审查 Agent、全面路由、所有输入格式或大批样本。中间文件与首版不是额外用户审批节点；检查结果驱动继续工作，工具/额度阻塞保存实际状态后报告。M1 是验证目标，不代表运行器已新增专用执行模式。
