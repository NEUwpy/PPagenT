# 独立生成任务提示词

把下面任务段落交给能读取本仓库、制作并渲染 PPTX 的 Agent；填入原稿、输出位置和必要演示要求。不需要复制历史聊天或旧设计长提示词。没有相应工具时应说明缺失，不把规则加载成功当作生成成功。

当前复现验收由主任务实际启动 `gpt-5.6-luna`、`high` 的无历史上下文新对话执行；主任务负责提示词／规则维护与验收，不代做成品。该模型设置不是下方提示词能自行切换的。完整分工、输入隔离与失败后再验证流程见[工作流](工作流.md#luna-high-复现验收)。

---

请根据我提供的原稿和演示要求，独立完成内容编排、原生可编辑 PPTX、完整逐页预览与必要修正。原稿路径、输出目录、受众、页数或时长以本次任务提供的信息为准；保留用户明确限定的改动范围。

在 PPagenT 仓库根目录按用户选择的 Skin 运行并完整读取输出。当前默认大学 Skin＋麦肯锡式，使用下方命令；用户明确选择中性 Skin 时将 ID 替换为 `neutral-editorial-001`：

```powershell
npm run rules:load -- --profile generation --skin northeastern-university-001
```

这会加载共享规则与所选 Skin 的颜色／字体配置：中性 Skin 绑定「杂志风」，东北大学 Skin 绑定「麦肯锡式」分析方法、文字角色与容量规则；具体颜色按 Skin 用途取值，文字角色和布局按排版体系执行。不要改用历史 v1/v2/v3 提示词，不默认读取全库，不改写规则或资产。若指定其他 Skin，先确认 `rules/index.json` 有相应 ID；排版体系由 Skin 自动选择，不能单独覆盖。加载失败时停止制作并报告具体原因。

按已加载规则推进；输入足够时直接交付，不默认等待逐页或大纲审批。遇到影响事实、任务方向或改动权限的关键缺失才澄清。局部关系需要结构时，按共享排版规则读取结构 Skill，按共享规则的技能选择顺序，项目结构技能优先；项目库不适合且属于技术图示时转用 Archify，两者均不适合再自主编排；不设调用或参考数量配额。此次为独立制作，不通过正式 CLI 冒充中性 Skin 已接入。

按以下顺序执行，关卡是你的内部自检，不需要用户逐步审批：

0. 先理解整稿论证，再自主决定页面序列、每页职责和核心命题，说明合并、拆分或调整顺序的理由。随后建立每页的信息角色、关系、层级和阅读路径，才选择媒介与几何组织。不能由原文块数、段落次序或现有组件槽位主导分页；“两组文字所以双栏”不是充分依据。区分事实、解释、必要条件、行动及推断边界，不把不同决策对象合并，不把必要条件写成充分条件。保存简短策划与实文内容映射作为证据，但直接完成PPT，不停在文字材料等待批准。允许忠实提炼并留来源，关键数字、口径、条件和例外必须在页面可见；保真校验是底座，不代表策划正确。原文保留试点接口可选，不为满足整块一次分配限制合理的信息组织。

1. 每次制作或修改前重新加载现行规则，快照仅用于记录本次输入，不作为下次规则来源。按页面组合规则写出并检查 `composition-intent.json`，包括内容组、逻辑 relations 与嵌套组合。使用 `src/composition/resolve.mjs` 的 resolveComposition 计算区域，再由 buildComposition 将同一计划中的 frame 交给各组文字、结构、图表构建器；保存解析结果与执行回执。不另写固定 visual/narrative 分区或绕开计划手写组级坐标。容量失败返回计划重组。首版与修正后的计划分别保存，不要凭整体印象另配字号或套用默认模板。
   东北大学页面先按 Skin 规则用 `createNortheasternUniversityStarter` 建立模板页，再在其正文安全区内完成图文分工；需要结构时使用 `invokeUniversityStructure`，由入口继承已配置的大学配色和麦肯锡字号。结构内承载关系与节点信息，图外说明承担对应依据、条件或行动，二者共同完成本页判断；不得只完成结构调用便交付。
2. 批量制作前，用本稿真实的最长标题、两位编号、窄栏说明和多行混排文字测试共享文字组件，导出并实际查看排字结果；按质量规则的排字预检修正后再复用组件。这些测试不计入交付页数。
3. 完成全稿后，按绑定排版体系的内容原则和质量规则检查实际导出的文字、对象和全部页面渲染，而非仅检查构建脚本的登记值。在交付报告中给出排版体系要求的逐页核对证据。记录具体失败项，由你修正并重新导出；共享组件修正后复查全部受影响页面。
4. 所有未解决项清零且检查证据对应最终文件后才交付。通用文件校验不能替代角色、几何和逐页视觉检查；无法完成时明确交付为候选及其阻塞，不以“已自检”概括未执行的检查。

最终给出可编辑 PPTX、完整预览的位置、已完成的检查和仍未解决的问题。修改已有成品时，以本次指定页面为范围，不无故改变其他已认可页面。
