# 生成任务协议

当前 MVP 只描述两大阶段：稿件到灰稿、灰稿到成品。页面表达是共同契约，灰稿是编译和建设检查视图。

2026-10-29 目标：输入含文字与图片的 Markdown，自动输出 PPT，中间无需人工分析、分页、选结构、补做或批准。main 输出实文与蓝色预留区的灰稿 PPTX；home 在同一契约内制作图形、放入图片并生成成品。Word、PDF 及转换以后扩展。

建设任务由用户与 Codex coworker 执行：main 负责前段契约/灰稿，home 负责后段模拟灰稿/成品；保留输入、契约、规则/代码、PPT/PNG、日志、问题和验收状态。模拟成品只证明后段。

投入使用只允许两类模型职责：语义理解模型负责稿件理解、分页、关系和内容填充；JEV 负责从合法版式/结构候选中判断选择。程序负责来源、Schema、候选合法性、槽位绑定、容量、参数、几何、原生构建、检查与日志。不得让模型写自由坐标、制作代码或虚构能力；产品不调用视觉模型或 Codex。

保留 Markdown 原稿、媒体引用与资源、同源页面表达、灰稿/成品、完整预览和运行记录。当前先取得一稿自动跑通证据；通用通过须用不同稿件持续检验。失败如实返回并回建设修复，随后自动重跑与回归，不能靠人工代做当前稿件或仅登记缺口收尾。

目标不等于接口已实现：默认 main 目前只接入读取与规范化，A0 只回放已有单页契约。实际入口见[运行流程](../../archive/20261030重新讨论前/harness/运行流程.md)，实现与验收状态唯一见[项目台账](../../archive/20261030重新讨论前/docs/方向讨论/页面编排能力计划.md)。
