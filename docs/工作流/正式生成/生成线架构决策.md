# 正式生成线架构决策：受控视觉语法与三路径运行

> 状态：目标架构，尚未接入正式生产<br>
> 决策日期：2026-09-03

本文定义结构资产建设里程碑之后的目标生成架构。当前已经运行的流程以[正式生成工作流](工作流.md)为准；本文不得被引用为“已经实现”的证据。

## 核心决策

PPagenT 不再把“为每页选择一个完整 Structure Group”作为最终形态。Structure 降为拓扑语义明确时使用的高级 Macro；多数普通页面由 Composition + Text／Media 构成；只有少数复合页面进入有预算的有限代理编排。

AI 获得的是受控行动空间，不是自由绘图权。它通过 PPagenT Domain Action 修改页面状态，程序在每一步验证引用、容量、空间和权限，最终仍由同一 HTML Renderer、Native Compiler 与 Quality Gate 交付原生可编辑 PPTX。

## 稳定内核

目标架构保持四层稳定对象：

1. **Skin／Shell**：主题身份、标题区、页脚和 Content Frame；
2. **Composition**：Stack、Split、Grid、Rail、Hero、受限 Overlay 等空间运算；
3. **Expression**：Text、Media、Structure Macro；
4. **Primitive／Compiler**：文字、形状、线、图像、SVG、HTML 计算和 Native PPT 对象。

Structure Group 沿用现有 `Logic → Structure Group → State` 资产契约，但不再承担所有页面。Content Frame 内的普通表达也必须有容量、最小尺寸和失败边界，不能让“非结构页”成为无规则自由排版区。

## 三条运行路径

### Direct Path

适用于核心观点、普通段落、弱关系枚举、大数字和简单图文。程序从少量合法 Composition 中选择或接受一个小参数决策，直接求解 Text／Media 布局。原则上不启动页面级视觉循环。

### Macro Path

适用于流程、层级、因果、循环、矩阵、分支、网络等拓扑本身承载语义的页面。程序先按 Logic、字段、数量、媒体条件和容量过滤 Structure Macro；唯一候选锁定，多候选只允许在等价合法范围内选择。没有合法 Macro 时退回 Direct Path 并记录缺口，不跨 Logic 硬套。

### Agentic Path

适用于同页包含多个表达、媒体与文字相互制约、一级 Structure 内需放置子表达，或一次选择不能确定合理布局的页面。代理只能调用小型 Domain Action，最多少量动作、预渲染和一次修复；达到预算后必须完成或退回 Direct Path。

三条路径的实际比例尚未知，应由代表性真实稿件统计得出。路径路由本身先采用可解释规则，不增加一个“路由 Agent”。

## 内容导演

内容导演继续一次读取整稿，负责叙事、拆页、页面职责、来源证据和版式中立的内容层级。它不为提高结构命中率改变关系，也不选择 Structure Group、Composition、坐标或样式。

目标内容状态应能表达：

- 页面核心信息；
- 多个内容块及来源引用；
- 块间弱关系或强拓扑关系；
- 块内可选 Logic；
- 媒体引用及其真实性约束。

现有 `contentMarkdown + deckMetadata + pageMetadata` 和候选 `PageContentBlocks 0.1` 都是演进基础，不在一次实验中另造平行内容真源。

## PageExpressionPlan 是状态，不是巨型答案

目标 `PageExpressionPlan` 由运行时维护。初始状态包含未解析的内容块；Direct／Macro 决策或 Agentic Action 逐步写入 Composition、Region、Expression 与内容绑定。每个动作通过后才能成为新状态。

模型不需要一次输出所有嵌套对象、坐标、字号和资产合同。程序也不能在模型之后静默重写语义。若需要展示性压缩、合并或短标签，必须保存来源引用、派生类型和结果。

## 最小 Domain Action

首轮实验只需要 6–8 个窄工具，名称可以在实现时调整，语义不得膨胀：

- 查看页面内容与当前状态；
- 列出当前合法 Composition；
- 应用或替换 Composition；
- 在 Region 放置 Text 或 Media；
- 对内容引用应用一个合法 Structure Macro；
- 请求 HTML 预渲染；
- 读取确定性校验结果；
- 完成页面或选择 Direct fallback。

工具参数只接受程序提供的 ID、受控枚举和小型字段。坐标、CSS、SVG、PPT 代码、任意 HTML 和资产晋升都不属于 Agent Action。

## Harness 边界

Harness 负责模型调用、工具循环、上下文和预算，但只是可替换适配层。自研轻量 Loop、PenguinHarness、Claude Agent SDK 或其他方案均不得渗入 PPagenT 领域对象。

首轮先用最小自研 Loop 证明 Domain Action 是否有效，再决定是否比较第三方 Harness。不能为了采用某个框架而增加语言栈、状态层或治理层。

## HTML 与 Native 边界

HTML/CSS/SVG 是受控布局真源和预渲染层。浏览器计算最终几何，Native Compiler 无发挥地转换相同结果；如果 HTML 与 PPT 不一致，应修公共编译能力或受控组件，而不是在 PPT 端另写同义布局。

正式系统不接受任意网页，不把截图当作可编辑交付，也不允许 Agent 在运行时生成自由 HTML。新增视觉原语必须先在建设期完成 HTML／Native 对照并由用户确认。

## 预算与失败

具体数字由最小实验确认，原则先固定：

- Direct／Macro 不承担页面级循环成本；
- Agentic 每页有动作上限、预渲染上限和最多一次修复；
- Schema／引用错误由工具边界和确定性校验就地拒绝，不靠长提示词或整稿重试；
- 内容真实性失败不能由视觉 fallback 掩盖；
- 视觉编排失败可以退回合法 Direct Composition，并记录 `delivered-with-fallback`；
- 操作系统、模板、编译依赖或最终硬门禁失败不得伪造交付成功。

## 验证方式

首轮采用小型代表集，而不是立即重构完整2+3：

- 普通文字／弱关系页；
- 明确拓扑的 Structure Macro 页；
- 截图 + 解释 + 结论；
- 核心观点 + 多项支撑；
- 一个一级结构内包含子表达的复合页。

对照当前单次视觉决策与候选有限代理，至少记录最终合法率、fallback、人工偏好、动作数、模型调用、token、耗时、页面重复和 Structure 使用。没有证据前不预设 Fast／Macro／Agentic 比例，也不以 Structure 命中率越高越好。

## 分阶段实施

1. 定义少量 Composition Operator 及其 Region、容量和失败契约；
2. 让 Text／Media／Structure Macro 能进入同一受控 Region；
3. 把候选 `PageExpressionPlan 0.1` 收敛为可逐步修改的运行时状态；
4. 在正式代码旁建立最小 Domain Action Loop，只服务代表页实验；
5. 证明收益后，再决定是否接入正式视觉流程和是否引入第三方 Harness；
6. 最后才考虑一级 Structure 内的二级表达和可选视觉观察。

每一步都应能单独删除，不得把候选实验写进正式路径后再靠兼容层维持。

## 当前实施边界

已实施：Markdown 内容导演主契约、旧 `DeckPlan / PageContent` 编译、候选过滤、核心 Structure Group、简单正文 fallback、HTML Structure 求解、Native 编译、生产工作台与确定性质量门禁。

候选但未正式接入：`PageContentBlocks 0.1`、`PageExpressionPlan 0.1`、固定内容2+3 HTML 原型、内容覆盖与最大结构深度验证。

尚未实施：三路径路由、通用 ExpressionRegion、多表达区域求解、Domain Action、有限 Agent Loop、Agentic 页面视觉观察以及 Harness 适配层。

这一边界以代码和[更新日志](../../更新日志.md)为准。任何后续文档不得把目标架构写成当前生产事实。
