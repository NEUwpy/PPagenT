# 正式生成线下一阶段探索边界

> 状态：探索方案，不是当前生产契约
> 更新日期：2026-09-04

当前生产行为以[正式生成工作流](工作流.md)为准。本文只说明下一阶段为什么需要实验、哪些方向已经确定、哪些仍不能确定。

## 当前能力

正式生成线已经具备内容拆页、主 Logic 判断、核心 Structure Group 候选、视觉选择、正文 fallback、HTML 布局、Native PPTX 编译和确定性质量门禁。

候选 `PageContentBlocks 0.1`、`PageExpressionPlan 0.1` 和固定内容多表达 HTML 原型已经存在，但尚未接入正式双导演，也不能代表多表达生成已经完成。

## 需要解决的问题

当前视觉流程要求一页尽量归入一个主 Logic 和 Structure Group。它适合明确拓扑页，却不能自然覆盖大量普通文字、图文和复合页面。

视觉导演目前一次性输出选择结果。Schema 即使合法，也不能保证编排合理；通过继续加字段、重试和兜底解决，会增加复杂度而不一定改善画面。

## 已确定的改进边界

- Structure 调整为明确拓扑页面使用的 Macro。
- 普通页面优先由 Composition + Text／Media 表达。
- HTML 继续提供唯一布局结果，Native Compiler 不另做设计。
- 新能力必须复用现有内容、资产、Renderer、质量门禁和生产工作台。
- 新方案先旁路验证，不直接替换当前可交付流程。
- 任何视觉失败都必须能退回合法正文排版；内容真实性不能降级。

## 最小探索

先选择少量普通页、明确拓扑页和复合页，完成两步验证：

1. 不调用模型，用固定内容和固定动作证明 Text／Media／Structure 能进入同一受控 Composition，并生成合法 HTML。
2. 在相同内容、资产和 Renderer 下，对比“一次性视觉输出”和“有限反馈调整”两种方式。

比较内容完整性、视觉结果、硬门禁、调用次数、Token、耗时和 fallback。没有必要先覆盖完整稿件，也不先实现多层嵌套。

## 尚未确定

- 是否需要 Agent Harness，还是轻量程序循环已经足够；
- 反馈循环应在哪些页面触发；
- 是否需要视觉模型查看截图；
- `PageExpressionPlan` 是否适合作为最终运行状态；
- Composition 和 Region 的最终对象形式；
- 模型调用、动作和修复预算。

这些问题必须由同一组小样本实验回答，不能在文档中先写成既定架构。
