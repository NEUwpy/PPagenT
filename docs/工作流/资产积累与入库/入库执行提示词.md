# 资产入库执行提示词

> 仅用于建设阶段的单项资产任务。入库必须有用户确认；投入使用阶段不创建资产。

## 目标

把明确的逻辑表达缺口变成一个可调用、可参数化、可拒绝超限的资产。先扩展已有 Structure Group 的 State、数量、容量或字段；只有现有拓扑、阅读路径、内容角色或媒体条件不能承载时才新增。只写一条覆盖增量，不因颜色、圆角、阴影或样例领域新增资产。

## 执行顺序

1. 写清 `logicId`、覆盖增量、适用/排除条件和普通稿件可提供的字段。
2. 选择来源页，记录来源作用；用 Codex 的视觉能力和人工观察提炼逻辑骨架、阅读路径、主次、留白、比例和可变项，保存为 `visual-intent.md`。不调用视觉模型，不把截图直接交给产品模型。
3. 用 Codex/人工按 `visual-intent.md` 建一个 HTML/CSS/SVG 黄金状态；组件只负责 Content Frame，不复制 Skin Shell、来源 Logo 或调试控件。
4. 把数量、文字量和媒体变成参数，按当前输入重新求解布局；不要从最大状态删除节点，不要为每个数量写独立页面。
5. 从最终 DOM/SVG 读取真实 TextRegion/ExpressionRegion、槽位、最小尺寸、容量和媒体要求；超限时明确拒绝。
6. 用通用编译器生成原生可编辑 PPTX，等比例放入 Skin 的 Content Frame；Native 不另写一套布局。
7. 用代表状态做轻量程序检查和 Codex/用户目视检查，记录 HTML、Native、Skin、容量和未覆盖范围。
8. 用户确认后才登记 `status=core`、运行入口和可达性见证；未确认保持候选或待审。

## 不变量

- 拓扑、阅读路径、视觉中心、层级、连接、负空间和内容角色保持。
- 内容字段可从普通稿件获得，不临时发明评分、坐标、责任代码或装饰性短语。
- 文字遵循 Skin 语义令牌和可读性下限；不靠裁切、无限缩字或压扁通过。
- 一份源组件服务多个 State；失败回资产或契约，不在正式运行中临时自由绘制。

资产具体字段以[页面构成与布局规范](../../架构/页面构成与布局规范.md)和实际调用点为准，不在单个资产里发明私有 Schema。
