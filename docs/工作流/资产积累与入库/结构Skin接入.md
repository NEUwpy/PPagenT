# 结构 Skin 接入与能力登记

本流程接入结构配色与 PPA 预览，复用一份结构源设计；不创建第二套结构几何，也不自动绑定正式生产。当前模式 `continuous-tone-v1` 支持浅色纸调与深色品牌主色：浅色沿用纸色背景，深色派生浅底结构色阶。清华紫示例 `#660099` 的便签、漏斗、汇聚三个预览及新 Skin 迁移能力已于 2026-09-08 获用户认可；其他颜色效果仍需按流程审阅。

## 1. 登记

在仓库根目录运行：

```powershell
node src/tools/register-structure-skin.mjs --id warm-paper --name 暖纸Skin --main-color '#EFE4D2'
```

可用 `--body-font`、`--display-font` 指定字体。命令在 `catalog/structure-skins/` 新建 JSON，已有文件拒绝覆盖。主色是唯一颜色输入；全部结构用途色由共享程序派生。字体和结构字号暂沿用中性样板的角色配置，不能据此认为已接好该 Skin 的整页排版体系。

登记默认 `candidate`。看板刷新自动出现选项，无需修改 HTML 或为新 ID 添加转换分支。中性和东北大学为内置选项，仍读取各自既有主题来源，不能用新配置覆盖它们。

## 2. 检查与预览

```powershell
node src/tools/serve-logic-dashboard.mjs --port 4192
```

另一个终端执行：

```powershell
node src/tools/check-structure-skin.mjs --skin warm-paper --base http://127.0.0.1:4192
```

结果保存在 `experiments/skin-onboarding-warm-paper/`。检查覆盖便签、漏斗、汇聚、冰山和循环五个代表结构的默认状态，检查 HTTP、根节点与指定文字容器裁切，生成截图与报告。它不会自动判定审美或批准 Skin。

人工查看：卡片能否与背景区分；文字是否清楚；汇聚和分面色阶是否保留；轮廓及连接是否过重或过淡。发现共性问题修共享转换；若原设计有问题则修源设计，不为某个 Skin 添加逐结构颜色补丁。需要扩展验证时继续使用结构审阅工作流，不把五个样例等同于全库完成。

## 3. 确认与生效边界

得到用户对样例的明确认可后，在该 JSON 将 `status` 改为 `reviewed`，填入 `reviewedAt` 日期和 `evidence` 仓库内预览相对路径。加载器验证证据存在；该字段表示人工登记，不是系统推断批准。技术检查报告保持 `visualApproval: pending`，作为当次检查原始记录，不伪造用户审批。

看板对这类 Skin 显示“Skin 样例已审阅；全库另验”。修改主色、转换模式或字体后应改回 `candidate` 并重新审阅，历史截图不会自动更新。若要用于正式制作，还需登记 Skin 资产、规则索引、绑定排版体系及生产入口，按现有流程验收；本工具不自动完成这些步骤。

## 能力状态的含义

看板每个结构分别显示换色、尺寸、整页调用和 PPT 状态，数据入口为 `src/tools/structure-capability-status.mjs`：

- 中性换色的 35 个已审批结构沿用已认可结果；新 Skin 默认待审。
- 折角便签、简明漏斗、成熟度阶梯有大中小样例；其余仅原尺寸。样例不保证任意稿件均能容纳。
- 整页调用未建立逐结构完整验收记录，明确显示“未逐项登记验收”，不是断言历史实验从未通过。
- 原设计 PPT 审批不能代替当前 Skin 与本次排版结果的验证。

后续补齐尺寸或逐项整页证据时更新该状态入口并链接证据，不根据“预览能打开”自动升级。本轮不扩展结构中小尺寸能力。
