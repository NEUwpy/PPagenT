# 资产覆盖清单

这份清单用于回答两个问题：当前有哪些资产，以及下一批优先补什么。它只管理覆盖顺序，不替代资产元数据、质量报告或入库流程。

覆盖百分比是阶段性建设目标，不是已经由真实稿件统计出的命中率。待积累足够多的真实稿件后，再用实际调用与缺口数据修正阶段划分。

## 使用规则

- `[x]` 表示资产已经是可调用核心资产包，或仍通过旧兼容目录调用；`[ ]` 表示仍在备选区。
- 每项资产后的隐藏标识用于和注册表自动核对，不要删除或重复。
- 调整资产阶段可以直接移动整行；新式资产晋升后运行一次 `npm run assets:discover`，无需为登记而跑全库测试。
- 核心与备选状态不一致、漏列、重复或多列资产时，`npm run audit:coverage` 会失败。
- 阶段是否完成，最终看真实稿件缺口是否已明显收敛，不以资产数量凑满为准。

## 第四阶段：目标覆盖 95–99%

这一阶段主要补“同一关系只有一种画法”和“内容一变化就退化”的问题，不以继续堆积新名字为目标。

- [ ] 根据真实调用记录，为高频关系补充轮廓明显不同的视觉变体。
- [ ] 为高频资产补齐最小、常规、最大容量和超限退化状态。
- [ ] 补齐图文混排、数据与结构并置、不同 Skin 安全区适配。
- [ ] 用真实稿件统计重新校准前面三个阶段，不再只靠经验判断优先级。

## 长尾：99% 以后

- [ ] 只记录真实稿件中反复出现、现有家族无法表达的缺口。
- [ ] 单次出现的特殊结构先保留在结构样本池，不立即开发运行时资产。
- [ ] 同类缺口重复出现后，再决定扩展现有家族还是建立新家族。
- [ ] 每次新增后复查是否提高实际覆盖，避免为了“资产很多”而积累不可调用的个例。

## 当前边界

当前清单只能说明资产库存和建议建设顺序，不能证明已经达到 80% 覆盖。第一阶段的真正完成条件是：连续一批具有代表性的真实稿件中，大多数页面能自然匹配核心资产，未匹配页面主要落入已知的第二阶段，而不是依赖临时自创结构。
