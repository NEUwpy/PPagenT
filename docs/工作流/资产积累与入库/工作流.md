# 资产积累与入库工作流

2026-09-30 当前建设流程。资产建设只服务两段生成线：稿件到灰稿需要页面表达、版式和灰稿编译能力；灰稿到成品需要 Skin、风格、布局、结构和原生构建能力。Codex 是建设 coworker，可看图、实现和验证；投入使用只调用语义理解模型、JEV 和已登记程序/资产。

## 入库闭环

1. **确认缺口。** 写清逻辑关系、`logicId`、覆盖增量和普通稿件可提供的字段。能扩展现有 State/容量/参数就不新增；只换皮肤不新增。
2. **提炼契约。** 选择来源页；由用户/Codex 提炼 `visual-intent.md`，记录阅读路径、拓扑、主次、留白、可变量、容量和拒绝条件。
3. **实现资产。** 用一份参数化 HTML/CSS/SVG 组件实现黄金状态和少/多数量状态；数据、布局求解和绘制分开，按当前输入重新求解，不删除最大状态节点凑数量。
4. **登记槽位。** 从最终 DOM/SVG 读取真实 TextRegion、ExpressionRegion、媒体要求、最小尺寸和容量；同一代码拒绝超限输入。一级结构可承载二级结构，二级不再嵌套结构。
5. **原生编译。** 通用编译器把同一布局转换为可编辑 PPTX；组件等比例放入 Skin Content Frame，Native 不维护第二套几何。
6. **建设检查。** 程序检查范围、边界、重叠、字号、连接和可编辑性；Codex/用户并排查看 HTML、Native、Skin 和代表状态，记录未覆盖范围。
7. **用户确认与登记。** 用户确认后才写审批证据、运行入口、候选可达性和 `status=core`。未确认资产只保留候选/待审，不进入生产自动发现。

## 资产最小契约

| 资产 | 必须声明 |
| --- | --- |
| Skin | 字体、字号层级、色彩、页壳、Content Frame |
| 风格 | 文字层级、承载面、间距、强调和允许的视觉 token |
| 页面版式 | 整页分区、比例、区域和槽位 |
| Structure Group | 逻辑拓扑、字段、State、容量、参数、拒绝条件和运行入口 |
| ExpressionRegion | 稳定 ID、父绑定、边界、允许 `Structure/Text/Media` 类型、最小尺寸和叠加策略 |

## 维护原则

- 生产模型只选择已登记候选并填充内容；JEV 不写坐标、HTML 或制作代码。
- 参数化是同一组件的数量/文字/媒体变化，不是为每个稿件特化分支。
- 内容、关系或分页变化回共同契约；槽位/容量问题回资产；几何/导出问题回程序/环境。
- 资产代码通过、模型选择通过、单页审阅和整稿闭环分别记录。
- 旧冻结范围、旧角色和历史实验不作为当前建设调度；证据保留在历史文件。
