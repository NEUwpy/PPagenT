# 建设角色分工与阶段性合并

2026-09-30 用户对齐。当前是建设阶段，用户与 Codex coworker 一起开发和看图。角色、分支用于建设协作，不属于产品运行架构，也不要求此刻启动协作或创建分支。

| 建设职责 | 范围与交付 |
| --- | --- |
| 前段 | 稿件到页面表达共同契约，编译灰稿，核对内容/关系/承载；提供可复用契约和实际灰稿 |
| 后段（可由 home 承担） | 用同契约的模拟灰稿尝试定义美化原则，落实规则/参数化资产及程序，提供成品预览；具体分工由当次任务确定 |

home 是建设角色称呼，不表示当前已切换到某个分支。模拟输入标明来源，只证明后段。建设时 Codex 可看图；产品运行时仅有语义理解与判断选择模型。

## 最小合并约定

- 共用[页面表达契约](架构/页面构成与布局规范.md)、稳定内容 ID 和来源；后段不再生成另一份正文。
- 后段可按能力调整样式及几何，内容归属、关系、页序和主次变更写回契约。
- 阶段交付包括代码/配置变更、契约范围、输入及 PPT/完整预览、问题与验收状态；报告从简。
- 合并保留双方工作、模拟/自动来源与失败证据；解决接口差异后用同一契约验证，再连实稿闭环。单段验收和 Git 合并不代表全产品通过。

需要邮箱协作时用[项目协作技能](../.agents/skills/ppagent-coworker/SKILL.md)；planner/reviewer 与 executor 是协作协议角色，前段/后段是建设任务范围，两者不混用。不自动发送任务或修改既有邮箱记录。
