# 更新日志

本文只记录 PPagenT 生成能力版本及其真实输出，不重复产品定义或技术设计。

## 版本规则

- 生成文件统一命名为 `稿件名-v主版本.次版本.修订版本.pptx`。
- 新增生成能力、版式家族或规则能力时，至少增加次版本号。
- 不改变能力边界的错误修复增加修订版本号。
- 不兼容的输入、契约或运行链路变更增加主版本号。
- 未经用户确认的实验草稿可以删除并在原版本号下重跑。
- 一个版本正式确认后不得覆盖；再次生成必须使用新版本号并保留旧文件。
- 仓库 `package.json`、生成文件名和本日志中的生成能力版本保持一致。

## v0.3.0 — 2026-08-10

第一份真实稿件《为什么做 PPagenT》首次从原稿和 Skin 完整运行，系统内部审查通过，等待用户复核。

- 产品入口只接收原稿与 Skin；人工 `pages` 和中间 JSON 不再是业务输入。
- 内容导演生成整套 `DeckPlan` 与版式中立的 `PageContent`，独立内容审查在第 6 轮关闭全部实质问题。
- 视觉导演先判断表达关系，再从程序给出的合法候选中安排整套家族、变体和节奏；相邻页面无轮廓重复。
- 新增角色接力、因果链、三种顺序流程和加权对比等可渲染变体，并用等比例 `contain` 嵌入东北大学 Skin。
- 渲染前后视觉审查在第 8 轮通过；九页逐张检查，无未关闭的容量、断行、碰撞、越界或畸变问题。
- 新增按组件容量进行的中文词语感知均衡换行，修复行首标点、词语拆分和孤立句号。
- 最终导演产物使用原稿、产物和九张页面哈希锁定后通过正式入口回放；运行清单记录 Provider 身份、PPT 哈希与溢出检测结果，状态为 `internally-approved-awaiting-user-review`。
- 新增可执行的实时 OpenAI DirectorProvider，为四类调用传入输出 Schema，并把逐页 PNG 作为渲染后审查输入；本次正式证据仍明确标记为冻结回放。

## v0.2.0 — 2026-08-09

第一份真实稿件首次通过结构化输入之后的统一生产线生成，用户复核未通过。

- 逐页保存并校验 `PageContent`、`PageIntent`、`LayoutDecision` 和 `RenderPayload`。
- 正文由匹配器选择中心辐射、双向对比、顺序流程、分层架构和循环闭环，再嵌入东北大学 Skin。
- 10 页全部形成唯一资产选择；规则测试、资产审计和页面溢出检查通过。
- 新增首份真实稿件回归测试，防止后续再次绕过核心链路。
- 本版没有从原始稿件自动生成 `DeckPlan` 和逐页内容，视觉选择仍以单页为中心。
- 用户复核发现第 9 页几何畸变，以及同类结构多次出现导致整套视觉死板；本版不触发候选资产晋升。

## v0.1.0 — 2026-08-09

第一份真实稿件《为什么做 PPagenT》的实验版本，当前未通过。

### 流程修正

- 删除了从空白演示和通用主题生成的被否决草稿。
- 将用户提供的东北大学 PPT 设为唯一视觉源。
- 生成分成两步：先按映射复制源模板页面形成 starter，再编辑继承对象。
- 封面、目录、正文和尾页分别继承源模板第 1、2、3、4 页；结构内容不得覆盖校标、标题条和页脚。
- 多段落文本采用整体写入，单段文本继续精确替换。

### 本轮结果

- 生成 10 页原生可编辑 PowerPoint。
- 模板母版、校标、研究所名称、字体、蓝色标题条和底部线条均保留。
- 逐页视觉检查、模板继承检查和页面溢出检查均通过。
- 但生成器直接写死了拆页、内容和页面映射，绕过 `PageContent → PageIntent → LayoutDecision → RenderPayload` 核心链路。
- 因此这份输出只能证明模板继承可行，不能证明 PPagenT Agent 已经跑通。

### 当前限制

- 尚无真实稿件端到端运行入口。
- `RenderPayload` 只有 schema，尚无通用映射器。
- 结构资产选择和 Skin 组合尚未进入同一运行时。
- 当前 PPT 不进入通过回归集，也不触发任何资产晋升。
