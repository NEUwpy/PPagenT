## 2026-09-04：确定 PPT 专用 Harness 与 Skills 方向

- 明确目标架构为“总 Agent → 内容导演／视觉导演两个子 Agent → 分层 Skills → Native PPTX → QA”。
- 当前双导演仍是两次受 Schema 约束的 API 调用，不能把目标架构写成已经实现。
- 现有程序和核心资产不废弃，而是封装或引用为 Skills；程序负责可靠执行，Agent 负责选择、组合和契约内适配。
- 能力按 `Deck / Text / Media / Structure / Native-QA` 分域，Structure 再按“能力域 → Logic → 具体 Style Group”渐进披露；分层 Skill 不等于分层 Agent。
- HTML 保留用于资产入库、设计实验与看板审核；目标正式线直接生成 Native PowerPoint，迁移期继续复用已有 HTML-to-Native 能力。
- 下一步只做一个小型真实纵向切片，不全面迁移、不预先决定 Harness SDK，也不让运行时派生结果自动晋升核心库。

## 2026-09-02：内容导演改为 Markdown 唯一层级内容稿

- 内容导演不再直接生成一套与人类内容稿平行的 `DeckPlan + PageContent` 正文树；单次调用改为输出 `contentMarkdown + deckMetadata + pageMetadata`。Markdown 固定使用 H1 整套、H2 章节、H3 页面、H4 主节点和列表支撑点，程序立即编译回现有表单以兼容视觉候选与 Renderer。
- 普通输入稿的最浅 Markdown 标题不再决定 PPT 页数；只有显式完整行“第 X 页”保持硬页面边界。《青春不怕远征难》此前因单 H2 被限制为最多两页并被整节时间序列覆盖的问题从契约层移除，不增加稿件专用提示。
- 正式内容路径不再调用模型式结构读取，也不再使用 `applyStructuralHints` 静默覆盖 Markdown 编译结果；生产默认关闭直接修改 `PageContent` 的局部语义细化。
- 复杂 Logic 使用 `relationBindings` 引用 Markdown 的 page/item/title/body/point，并只补 ID、枚举、布尔、数值和邻接矩阵等机器常量；程序生成旧 `structuredData`，元数据不得复制人类正文。
- 每页一至两个逐字来源锚点按顺序定位最小连续 `sourceText`，重复、缺失、逆序或 Logic 证据落在范围外均明确失败。
- 正常生成仍为一次内容导演加一次视觉导演。正式默认最多两次内容尝试、一次视觉尝试；只有 Markdown 语法、元数据对齐和内容容量错误可以使用唯一一次内容兜底，其他语义或来源错误失败关闭。
- 每次内容尝试新增保存 `content-draft.md` 与 `content-metadata.json`，同时保留编译后的 `deck-plan.json / page-contents.json`。生产工作台轮询改为签名驱动增量刷新，人工检查点编辑时冻结 Reader DOM，并保护滚动、展开、输入、焦点和选区。

## 版本规则

- 生成文件统一命名为 `稿件名-v主版本.次版本.修订版本.pptx`。
- 新增生成能力、版式家族或规则能力时，至少增加次版本号。
- 不改变能力边界的错误修复增加修订版本号。
- 不兼容的输入、契约或运行链路变更增加主版本号。
- 未经用户确认的实验草稿可以删除并在原版本号下重跑。
- 一个版本正式确认后不得覆盖；再次生成必须使用新版本号并保留旧文件。
- 仓库 `package.json`、生成文件名和本日志中的生成能力版本保持一致。
