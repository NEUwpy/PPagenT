# 页面表达共同契约与编译

2026-09-30 用户确认。两大阶段仍为**稿件到灰稿、灰稿到成品**。本文只维护共同契约及能力边界；状态见[项目台账](../方向讨论/页面编排能力计划.md)，执行入口见[运行流程](../../harness/运行流程.md)。

## 页面表达与灰稿是一体两面

**页面表达数据（也可呈现为表单）是共同契约，灰稿是它的编译视图。** 前段写契约并编译灰稿，后段读取契约生成成品；不通过识别灰稿图片恢复内容，也不维护另一份美化正文。

```mermaid
flowchart LR
    A[稿件与要求] --> B[页面表达共同契约]
    B --> C[灰稿编译与建设检查]
    B --> D[受限选择与规则执行]
    D --> E[原生可编辑成品]
    C -->|修改写回同一契约| B
```

表单是数据的编辑/检查形式，不要求用户在产品中手填。当前先复用 `gray-plan-3`、现有 plan/state 及稳定 ID；需要时补必要字段，不另建平行 PageContent 或完整语义图。逻辑上同源，不表示已有文件已统一成一个新格式。

## 最小共同契约

| 必要信息 | 职责 |
| --- | --- |
| 页序、页面目的、主题句 | 一页讲明白什么；主题句可引出、概括、总结或表达有依据的判断 |
| 实际内容与来源 ID | 保真提炼后的上屏文字、归属、附注及必要条件 |
| 分组、主次与必要关系 | 共同阅读、对照、先后、支撑和作用范围；不靠块数推断逻辑 |
| 表达需求与内容绑定 | 文字或结构等媒介、制作要求；空间映射引用原 ID，不复制正文 |
| 布局能力及参数/区域依据 | 为灰稿编译和后段选择提供可实现的承载边界，具体记录按现有接口 |

灰稿中的逻辑分区、归属、主次和阅读顺序约束后段；文字尺寸、间距和最终几何由所选程序在边界内求解。灰稿蓝区的制作说明占地不等于最终图形的自然尺寸，不锁死第一次坐标。改变语义、分页或必要阅读关系，必须写回契约并重新检查。

灰色区显示实文；浅蓝区表示未完成的结构/图表等制作要求，不冒充成稿。灰稿必须足以直观审查内容与组织，同时后段仍有能力和样式选择空间。

## 两段职责

**稿件到灰稿：**语义模型理解、提炼和分页；程序校验、规范化、测量并提供有限布局候选；判断选择模型选择合法方案，程序编译灰稿。必要字段缺失可局部修补，语义缺口仍交模型判断；程序不能凭空推断因果。

**灰稿到成品：**判断选择模型从已实现能力中选择并绑定同一内容；程序应用 Skin、风格、参数化布局和结构资产，测量、构建并检查。无适用能力返回缺口，不以自由绘制或高级模型补救。

以上是目标职责，不固定调用次数。当前规划仍要求完整 `gray-plan-3` JSON；布局选择已分出 JEV provider，容错修补和完整成品链仍待最小交付。

## 一、四类资产

| 资产 | 负责什么 |
| --- | --- |
| Skin | 标志、身份、字体色彩来源、页壳与内容区 |
| 风格 | 文字层级、承载面、间距、强调和表现规则 |
| 布局 | 按内容关系和实文测量分配空间的参数化程序 |
| 逻辑与结构图 | 关系适用条件及其可调用表达实现 |

结构参数化支持已声明的数量、文本量和区域；超范围返回失败。每项用于当前 MVP 的能力只需讲清适用条件、输入绑定、容量/合法参数、执行入口和验证证据。沿用原资产工作流，不批量晋升或先扩全库。

## 建设、修订与已接入范围

建设时用模拟共同契约及 Codex 看图检查，可以独立推进后段；投入使用仅有 DeepSeek 类语义模型与 JEV 类选择模型，无视觉模型。图片预览由程序生成，不进入模型输入。

内容/关系问题修契约；绑定问题修映射；容量/几何问题修能力或返回规划；导出问题修构建。变更使受影响检查和产物失效，首版和失败留存。

`visualMapping` 已支持同一纯文字组内横纵分块及一条全宽共同说明，引用原 group/block ID；跨组范围、比较/条件分支、含局部图示的拆分仍未覆盖。纯文字 `source-text-v1` 为受限美化建设候选，图示仍有自由局部排版兼容路径；当前 v5 引擎缺实际字号/行盒证据，自动交付未通过。见[20260929 实施证据](../../experiments/visual-block-mapping-20260929/README.md)。

JEV 适配和凭证读取已接入 gray 布局选择；其余历史接口和详细盘点见[能力快照](现有能力盘点与首批建设.md)，新增调用须核对实际消费点。
