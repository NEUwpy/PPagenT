# 结构库尺寸适配改造目标

建立日期：2026-09-06。状态：目标已确认，汇聚原型获用户认可，全库改造未完成。

本文是跨任务持续维护的目标与交接档案，不是现行生成规则，也不表示下述能力已经全部实现。后续任务在本文件更新进度、证据和下一步，避免重复建立平行计划。

## 目标与动机

让结构库中的结构便于改变大小，根据稿件和页面可用空间重新安排内部元素，在保留核心视觉特征及内容关系的前提下，与文字、图片或其他结构共同编排。

成功标准是结构更好地服务页面表达。汇聚结构只是证明方向的一个例证，不应把整个改造限定为汇聚曲线，也不要求每页都使用结构。

原先组件偏向独占较大区域，尺寸与整块布局绑定。直接缩放容易让文字过小；完全放开参考又容易失去原结构辨识度。需要保留已有代码积累，同时分开核心形态与可变布局。

## 已确认的原则

- 每种结构明确少量必须保留的核心元素或视觉特征，兼顾内容关系和可识别形态。仅检查节点数、连线数或拓扑关系不够。
- 核心可以接受尺寸、位置等参数并重新计算，不固定原始坐标，也不依赖整体等比缩小。
- 核心以外的框体、间距、样式等允许随内容与页面调整，仍须遵守稿件事实、Skin 和可读性边界。部分结构的框体本身可能就是核心，不能统一剥离。
- 最小可用尺寸由文字、字体、节点与结构形态共同决定；空间不足要反馈具体原因，不能靠强行缩小字号或丢失内容解决。
- 优先复用可适配的现成结构；相关结构不能直接适配时参考或受控改写；没有合适结构时自主编排。保留真实调用与参考改写的区别。
- 渐进迁移，旧组件继续可用；新结构采用经过验证的新方法，旧结构按使用频率及需求迁移。

## 原型验证与用户结论

1. [原结构调用批次](../../experiments/neutral-structure-luna-batch-04/REPORT.md)：现成组件能调用，但较大、容易独占页面。
2. [自由适配改写](../../experiments/neutral-adaptive-rewrite-05/REPORT.md)：结构可以缩小并与侧栏共存；用户指出平滑汇流的精髓丢失，变成斜线碰到同一点。
3. [核心拆分试验 06](../../experiments/neutral-core-convergence-06/REPORT.md)：同一份核心由 Luna High 用于全宽、局部加侧栏、长文字三页。用户明确反馈“这回可以了”，认可此次视觉方向。

## 候选架构分工

| 层次 | 职责 | 边界 |
| --- | --- | --- |
| 结构核心 | 根据连接位置等参数生成保留辨识特征的形态，判断必要的几何空间 | 不承担整页布局；不内置示例稿件和特定 Skin |
| 公共适配能力 | 测字、换行、节点尺寸、样式及局部布局，向核心提供实际连接位置 | 不擅自改变核心特征或压缩必要内容 |
| 页面 Agent | 根据稿件选择结构、分配区域，与其他内容共同编排，处理不足反馈 | 日常优先调用核心，避免每页重写关键几何 |
| 验证 | 内容完整、尺寸与边界、核心视觉特征、最终 PPT 渲染 | 程序通过不能代替视觉检查 |

这是后续验证方向，不要求所有结构立刻使用相同接口。先通过不同类型样例寻找公共部分，保留各结构的特殊约束。

### 2026-09-06 正式结构盘点与资产侧契约迁移

本轮以 `discoverCoreAssetPackages()` 的实际结果为正式范围：35 个 `html-component` Structure Group，覆盖 18 个 Logic。目录中的 93 份 `asset.json` 仍包含待审批、撤回和替代资产，不能计入正式迁移。35 个正式资产原先全部只有 `component-full`，均声明 `1170×492` 的 natural 空间契约；其中 9 个有按数量登记的 `stateFootprints`，其余 26 个没有可用于局部组合的状态占用记录。

本轮已完成资产侧的公共入口与登记字段，尚未宣称视觉适配完成：

- 新增 `src/runtime/structure-adaptation.mjs`，为正式资产逐项绑定形态 profile。profile 保留各类结构的方向、拓扑、层级、中心锚点、泳道、象限、网格或连续路径等核心特征，不把资产归并为同一张卡片。
