# 产品定义

## 核心工程取舍

PPagenT 不让 AI 在每次任务中从头绘制页面，而是由 AI 理解内容、整理结构并选择资产，再由参数化代码完成确定性绘制。

这条路线的优势是减少重复生成消耗，使布局、视觉规范和最终 PowerPoint 更稳定、更可验证。它的代价是必须在资产建设阶段提前处理真实 PPT 中可能出现的数量、层级、密度、状态和表达目的变化。

项目需要始终面对这一矛盾：

> 模板有时尽，现状无穷多。

因此，资产建设的目标不是收集足够多的静态页面，而是把有限的视觉规律整理成能够应对变化的生成能力。

## 两条工作流

PPagenT 必须长期区分两条职责不同、不能互相旁路的工作流：

- **入的工作流（积累）**：用户与维护者共同选择来源页，保存证据，忠实蒸馏，参数化数量与容量，生成边界样例，放入真实 Skin 正文区检查，再由用户确认是否进入核心资产库。它负责把优秀 PPT 逐步转成可靠能力。
- **出的工作流（生成）**：用户只提交原始稿件并选择 Skin。内容导演按固定 JSON Schema 填写 `DeckPlan` 与 `PageContent`，视觉导演继续填写 `PageIntent`、`CompositionPlan` 与 `VisualPlan`，程序只从合法核心资产中形成 `LayoutDecision` 和 `RenderPayload`，最后确定性渲染并通过程序质量门禁。

两条工作流通过核心资产库连接，但不能在一次生成任务里混成一条：输出时缺少合适资产，应失败关闭并回到入的工作流，不能现场自创结构。积累更多经过验证、语义边界清楚且不重复的资产会扩大输出能力；未经验证的数量堆积反而会污染选择，不能简单理解为“入得越多，出得越好”。

两位导演之间传递的是版本化、可校验的结构化对象，可以由表单呈现，但机器接口以 JSON Schema 为准，不传自由散文，也不要求下一位导演猜测上一位的意思。字段只根据真实稿件暴露的问题逐步增加，不为追求理论完整而提前虚构。

## 产品输入与自动流程

用户只需要提供原始稿件并选择 Skin；测试阶段默认东北大学 Skin。正式产品工作流固定为：

> 原始稿件 → 选择 Skin → 内容导演 → 视觉导演 → 确定性渲染 → 确定性质量门禁 → 交付

视觉导演不能把“选择一个结构图”当作整页设计。它必须先形成 `CompositionPlan`，说明正文安全区如何分成文字、结构组件和图像槽位，再从程序给出的合法候选中选择核心资产。页面遵循“整页布局 → 槽位 → 组件”三层关系；结构图只是页面中的一种组件，可以占满正文区，也可以与文字并置，或在不需要时完全不出现。没有原稿图片证据时不得自行补图。

内容导演负责整篇稿件如何成为一场汇报，视觉导演负责整套 PPT 如何从核心资产库中选择清楚且不重复的表达。渲染后的字号、越界、容器内收和重叠由程序门禁检查，不交给 Agent 判断。审查者和反复复核只用于当前研发阶段校准工作流、系统提示词和资产，不属于产品每次运行的固定步骤。

## 最终系统形态

PPagenT 的目标形态由三部分组成：

- API 接口：接收原稿和 Skin，并返回结构化导演结果与最终 PPT。
- 系统提示词：约束内容导演和视觉导演，把自然语言稿件转换为稳定、可校验的规范字段。
- 核心资产库：保存有来源、有参数、有容量边界和确定性生成代码的正式版式。

API 负责理解和填写字段，代码负责调用资产并绘制；模型不得绕开资产库临时设计结构图。当前真实稿件的价值是暴露这三部分的问题并持续优化，而不是借助一次性的 Agent 能力尽快得到一份 PPT。

## 模板与组件的建立方式

PPagenT 不让 AI 每次重新设计页面，而是先把经过确认的 PPT 样式转换成可重复调用的参数化资产。

用户提供并认可一个页面样式后，需要从中明确：

- 固定部分：Logo、配色、字体、边距、装饰和元素位置等不随内容变化的视觉规范。
- 可变参数：标题、正文、日期、节点数量和强调项等允许替换的内容。
- 容量规则：页面能够容纳的文字数量、节点数量和其他内容边界。
- 退化规则：内容超出容量时，应当换布局、拆页还是停止生成并提示用户。
- 生成代码：根据已声明的参数生成原生可编辑的 PowerPoint 页面。
- 测试样例：使用不同长度和数量的内容检查正常情况与边界情况。

## 确认流程

1. 用户提供一个认可的 PPT 页面样式。
2. PPagenT 提取固定部分、可变参数、容量规则和退化规则。
3. 根据这些规则编写参数化生成代码，并生成测试结果。
4. 用户检查视觉效果、参数范围和变化规则。
5. 有明确复现或蒸馏来源、完整生成入口且当前工作流确实需要的样式，可以进入核心资产库接受真实稿件检验。
6. 用户指出问题后，应直接修复该核心资产及其边界，直到它足以长期保留；不得临时换成一个新造结构掩盖问题。
7. 核心资产入库前必须通过确定性单页质量审计；示例、生成器或共享运行时代码变化后，旧审计自动过期。
8. 未经来源支持的字段、变化方式和视觉规则不得自行加入。

视觉蒸馏不能先把多页概括成一个“平均版式”。必须先选定一张典型来源页，按原文完成忠实复现，再用不同文案验证参数化；同时记录承载面、对齐轴、对称关系、视觉重量、间距、层次、字体和强调方式。只有在 Skin 和真实稿件中仍然成立，才允许晋升或改写核心资产。视觉相似但语义结构不同的页面必须拆成不同候选，不能只因“都有两个圆”就归为同一表达家族。

## 真实稿件回归

项目通过真实稿件逐步扩大能力边界，而不是先假定一套完整规则：

1. 用当前流程生成一份真实稿件。
2. 记录用户指出的内容、版式或流程问题。
3. 修改生成流程、规则或资产后，用同一稿件重新生成。
4. 通过的稿件进入回归集合；加入新稿件后，既验证新稿件，也复查已经跑通的旧稿件。

未通过用户确认的输出只是实验草稿，可以被删除和重跑；确认后的版本必须冻结，并通过新版本号继续迭代。

建设期每次正式链路生成后，维护者还必须在链路外逐页检查导演产物和最终画面。发现问题时，要判断它属于系统提示词、核心资产、Skin 还是规则层，修复系统后再从原稿和 Skin 重跑同一条链路；在没有明显未关闭问题前，不把用户当作第一轮视觉检查者。这个闭环只用于研发校准，不增加未来产品的常驻审查 Agent。

## Skin 的规范职责

Skin 不只提供 Logo、颜色和母版，还必须声明正文安全区、字体层级、最小可读字号和表面对比规则。组件只能消费这些规范，不能依靠自动缩字把内容塞进页面；低于最小字号时，应回到内容压缩、换版或拆页，而不是交付“没有越界但看不清”的页面。

## 资产分类

- 资产库按用途分类：封面、目录、章节页、正文、尾页和结构图。
- 用途分类只负责浏览；真正用于选择的功能应继续细分，例如顺序流程、循环闭环、双向对比和章节过渡。
- 来源模板不是资产分类。来源学校、真实文件名和页码作为资产元数据保留，用于追溯蒸馏依据。

页面模板的建立称为“模板复现”，目标是保留完整页面及学校视觉规范。组件的建立称为“组件蒸馏”，目标是从案例中提取可复用的信息结构和布局规则，而不是照搬整页。

## 表达家族与视觉变体

资产需要区分三层，避免把表达关系、视觉轮廓和数量适配混在一起：

- 表达家族：内容所需的基本语法，例如中心辐射、顺序流程或双向对比。
- 视觉变体：同一表达家族的不同画面轮廓，例如环绕式、左右分支式或中心配外围卡片式。
- 适配状态：同一视觉变体针对数量、层级、文字密度和重点状态的参数变化。

例如，中心主题和四个同级要点可以使用多种视觉变体；其中每个变体再适配 3、4、5 或 6 个节点。一次实际生成只是参数化实例，不作为新资产重复入库。

核心资产库可以为一个细分功能保留多个经过验证、轮廓确实不同的视觉变体，以支持整套 PPT 的节奏变化；但不能把仅有颜色或细节差异的相似页面当成独立能力堆积。

来源模板不等于版式家族。同一来源可以蒸馏出多个家族；不同来源中规则一致的页面也可以归入同一家族。来源文件和页码只负责追溯。

## 结构样本、备选资产与核心资产

为避免优秀页面在尚未完成蒸馏时被遗漏，原始模板中的有价值页面先进入 `结构样本池`。样本池采用宽进原则，允许保留相似页面和暂未归类页面，并保存单页源 PPT、预览图及来源页码；它不是运行时可调用资产。

新复现或蒸馏的结果原则上先进入 `备选资产` 接受比较。真实稿件已经需要、来源和代码完整的资产可以由维护者晋升核心库并进入持续优化；“进入核心库”表示允许正式流程调用，不表示已经完美或结束迭代。

备选资产审核后只有几种处理方式：

- 与现有视觉变体骨架一致：提取为新的适配状态。
- 对尚无核心版式的细分功能提供了合适样式：确认后晋升为核心资产。
- 与核心资产属于同一表达家族但轮廓不同：经真实稿件验证确有节奏价值后，可以成为新的视觉变体。
- 尚不能确定适用边界：继续留在备选区测试。

备选区按功能分类，不按来源 PPT 建立专属资产包；来源信息保留在每项资产的 `asset.json` 中。

## 面向应用的资产要求

资产不能只声明能够生成什么，还需要通过实际测试逐步确认：

- 适用和不适用的内容结构。
- 支持的数量、层级和文字容量。
- 内容如何映射到参数。
- 可用的视觉变体、数量适配和语义状态。
- 内容超限或不适配时的换版式、拆页或停止规则。

具体边界不得在缺少样例时凭空补齐。应当通过真实内容生成、用户反馈和后续回归逐步写入资产说明。

运行时先由内容导演形成整套结构，再由视觉导演筛选表达家族，并结合整套页面节奏选择视觉变体和适配状态，最后调用代码生成。AI 可以在已验证范围内选择，但不能为了变化而改变原文关系。

稿件结构化与资产合法性筛选使用 `PageIntent` 和 `AssetContract` 两个机器可读对象，具体字段、分类和当前验证边界见[规则层设计](规则层设计.md)。

## 资产存储规则

- `assets` 是核心资产入口，只保存已进入正式调用、可在真实稿件中持续优化的版式家族。
- `结构样本池` 保存所有值得继续观察的来源页面，不要求已有生成代码。
- `备选资产` 保存新蒸馏、重复版式、替代方案和边界尚未确认的资产。
- 每项资产使用独立目录，固定包含案例 PPT、生成代码和资产说明，保持一一对应。
- 共用绘制能力放在 `src/asset-runtime`，但具体资产必须保留自己的调用入口。
- 工作区只用于原始模板归档和临时处理；形成参数化候选后，先进入备选区。
- 新页面入库前，必须先判断它是已有家族的新变体、新状态，还是确实具有不同视觉骨架或表达逻辑的新家族。

## 调用规则

正式资产通过结构化参数调用。AI 只能选择 `assets/registry.json` 中登记的核心页面模板或组件，并填写已声明的参数；具体绘制由确定性的程序完成。

如果核心库没有适配当前内容的资产，正式流程必须停止或退回资产建设，不得现场自创结构图、借用实验 builder，或把临时结构伪装成已有资产的视觉变体。需要增加参数、改变视觉或调整容量规则时，应当回到原资产的蒸馏来源和协作优化流程。
