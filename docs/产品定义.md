# 产品定义与架构边界

**PPagenT 是一个面向可编辑演示文稿的 AI 制作系统：将用户稿件和演示要求转化为经过内容规划与视觉编排的原生可编辑 PPT，并通过检查—返工闭环保证内容忠实、表达清楚和视觉合理。**

2026-09-28 路线纠偏：专业设计前置建设，模型驱动决策，资产与程序执行。工作型演示是当前主场景；东北大学是首个场景，不是产品边界。产品沉淀可调用的设计资产、参数化布局、风格实现、生成程序及质量证据。建设阶段投入设计与验证，生产阶段模型主要理解语义、分析逻辑、选择合法能力并填充内容，程序计算与执行；目标是降低重复生成成本并提高一致性。Harness、Agent、Skill 是实现手段，不以其建设完整度衡量产品进度。输入和交付见[产品需求](产品需求.md)。

## 资产体系与制作主线

资产分为 **Skin、风格、布局、逻辑与结构图**：Skin 给出身份与页面边界；风格给出视觉表现方法；布局将空间要求落实为可变化的区域；逻辑与结构图提供关系分类、表达方法及实现。文字和媒体是内容/表达媒介，测量与渲染是执行能力，不再混作顶层资产分类。一个结构维护一份源设计，各 Skin 共用。

内容规划与检查是永久生产环节，调试展示灰稿，投产后只向用户展示最终 PPT。设计规范分为 **内容结构规则、Skin 规则、通用排版规则、风格指引**：分别决定页面目的与信息关系、视觉身份与内容区、关系的空间表达与文字层次、美化规划结果。美化的职责边界分三层：内容与归属只有规划能改；表达媒介（文字与并置、时序、表格之间）由规划初选，美化阶段可按同一套内容关系判定复核调整并写回计划；位置、比例、留白与视觉呈现由已选能力及其合法参数落实，必要的选择由美化阶段完成。改变内容分组、主次、关系或拆页必须返回规划。麦肯锡式与杂志风是风格体系，其规则称为风格指引；历史 `排版体系` 目录与 `layout` 字段保留兼容，不表示规划随风格更换而取消。

**稿件理解与初步分页 → 页面构成规划 → 空间要求与布局候选 → 测量求解与灰稿 → 检查修订 → 风格美化与最终制作。** 这是目标职责链，不是已完成的正式线，也不要求每阶段独立模型或人工批准。统一接口与迁移边界见[页面构成与布局规范](架构/页面构成与布局规范.md)。

分页坚持一页讲明白一件事，综合表述结构和实际承载能力；主题句可以引出、概括、总结或表达有依据的判断。构成规划确定共同阅读的内容、必要关系、主次、媒介及阅读路径，布局据此分区。语义重要性与空间需求分开；不用块数推断逻辑，不把示例作为模板上限。

规划和检查是永久生产环节。灰稿已确定具有逻辑含义的区域组织与阅读关系，美化不能重新决定这些内容；可在保持关系及可读性的前提下调整细节、复核媒介并写回计划，若改变内容归属、主次、关系或分页则返回规划。调试展示灰稿，正常产品任务默认交付最终可编辑 PPT 与预览。

## 当前实现边界

工作台默认灰稿入口实际调用 `src/runner/gray-agent.mjs`，由模型通过规划检查、语义复核、布局渲染和交付工具形成闭环。旧 `gray-draft.mjs` 阶段链、通用运行器与兼容 API 各自保留；续跑能力按入口分别核对，不能互相继承。

现有 `gray-plan-3`、实文测量、来源检查、原生 PPT 与完整预览继续复用。看板同源的测量与布局选择已局部接入 gray-agent；通用 runner 已有灰稿交接和模型提交局部视觉方案。完整逻辑约束、资产覆盖及可重复生产质量仍待建设和验收。旧按组数选择默认组合的代码尚在，本次文档没有改变其行为。

灰稿文字区呈现灰色实文，非文字区呈现浅蓝制作说明，不能称为已完成图表或结构图。M1 未通过；运行器、试排和代码检查不能代替真实稿件与用户验收。流程见[运行流程](../harness/运行流程.md)，实际入口见[通用灰稿验证](工作流/正式生成/通用灰稿验证.md)。

结构库建设目标仍是“实际排版中容易正确调用，并与 Skin 和布局稳定协调”，具体适配边界见[结构库建设目标](架构/结构库-变与不变.md#建设目标2026-09-07-用户确认)。

## 关系表达技能的优先顺序

客户输入决定内容；Skin 与绑定风格规则提供基础视觉规范。项目自建结构技能为第一顺位；第二顺位按内容分工，Archify 处理技术关系图，Lieflat Charts 处理数据图表（当前非商业试用）。生产模式无合适能力时报告缺口，采用经验证的保真降级或返回规划；建设实验可进行参考重组并单独验收。技能用途与许可见[技能清单表](../skills/README.md)。统一选择真源见 [技能选择顺序](../skills/references/selection.md)。基础规范不代替视觉验收；Archify 仍为 pilot，在 PPT 任务中其 HTML/SVG/JSON 仅为图示中间产物，必须继续完成原生对象适配、Skin 统一及完整页面验收；不能以独立网页替代 PPT。此次为独立制作指导及技能目录声明，正式 Harness 自动路由尚未实现。

## 资产与运行规则的分工

四类资产的定义与相互接口唯一维护于[页面构成与布局规范](架构/页面构成与布局规范.md#一四类资产)。运行规则按内容理解、页面构成、空间与文字排版、风格应用及检查来组织；规则文件分类不等于资产分类。

| 能力层 | 职责与边界 |
| --- | --- |
| 内容结构规则 | 页面目的、信息职责、组间关系和组内层级；按区域重组与分页，不能按原稿段落直接切块 |
| Skin | 视觉身份：字体、颜色、页眉页脚、Logo、背景与基础组件样式；不决定内容关系 |
| 排版规则 | 所有风格共用的分区、网格、对齐、留白与文字层次；按语义计划落实空间表达，改关系或分页时返回规划 |
| 风格指引 | 美化规划结果，例如麦肯锡式或杂志风；可微调位置与比例、复核表达媒介（写回计划再渲染），内容分组、主次、关系和拆页变化返回规划 |
| 结构库 | 语义关系的视觉表达：比较、递进、并列、流程、矩阵等；不是整页模板，不反过来决定内容 |
| 图表/框图 Skill | 专业表达工具：有数据关系时用图表，有系统或技术关系时用框图，不为丰富页面强行调用 |

布局规范是可调用的区域组织能力，本稿 Layout 是应用规范后形成的结果。逻辑由内容规划判定，局部结构图按实际契约使用；基础几何不另建一套因果/流程识别系统。字号、颜色、间距继续引用现有资产和规则真源，不复制另一套数值。

**固定的是专业原则、能力边界和接口，不是最终页面。** 空间安排同时考虑真实关系、内容体量和视觉主次；程序算得出不代表阅读合格。

旧独立制作试点提供可选的 `composition-intent.json` 路径，声明逻辑关联与嵌套组合；新 Harness 以轻量蓝图为起点，不强制所有任务走该解析器。选择该工具时，`src/composition/resolve.mjs` 根据组件和文字容量解析组级区域，由 buildComposition 将同一计划交给各组构建器。支持嵌套行列与网格，容量不足明确要求重组；锚点覆盖尚未实现。实际渲染若主次、重心或图文整合失败，返回计划重排。入口和字段见 [页面组合](../rules/页面组合.md)。此为独立制作的轻量组合执行层，复用现有 Skin、组件和渲染器；未扩展正式候选选择器的封闭 CompositionPlan Schema，正式线自动迁移尚需验证。

暂定一个 Skin 绑定一套风格规则，多个 Skin 可以复用同一体系：当前「中性 Skin」对应「杂志风」；大学 Skin 共用「麦肯锡式」的命名与分工已确认。大学咨询式实验已合并，见[整稿测试](../experiments/university-skin-pilot/stability-01/RESULTS.md)，现行索引已将东北大学 Skin 绑定到「麦肯锡式」，历史冻结指南不参与加载；独立制作规则绑定不等于正式 renderer 迁移或审美验收通过。历史资产 ID 和目录名不因用户可见名称改变而批量改名。

可换色组件按用途消费 Skin 配色，文字、图像与关系图仍是不同表达能力。结构的现行共享与换色方式见下节；早期蓝紫主题实验只保留为历史证据，不能代替中性转换的当前状态。

规则正文分工与读取方式只在 [rules/README.md](../rules/README.md) 维护。颜色用途取值留在 Skin；具体字号角色、间距等风格化数值留在绑定风格指引。已有资产 `fonts` 继续是字体名称真源，规则通过声明加载该字段，不复制一套 tokens。资产描述引用规则，不再抄写整段规范。

提示词只负责本次任务、输入输出与加载入口；执行器负责可编辑对象、几何和契约校验。参考教程先成为学习笔记，再将适用且经验证的经验修订到现有规则。历史提示词保留为证据，但不作为并行版本选择。

## 结构源设计与 Skin 的共享方式（2026-09-08）

**一个结构维护一份源设计，各 Skin 共用；Skin 不复制结构库。** 源设计是资产的绘制实现及其共享依赖，保存形状、连接、内容容量和原稿色阶。原稿蓝色是转换的输入依据，不表示结构只属于东北大学。

```text
结构源设计 + 稿件内容 + 已支持的区域适配 → HTML/SVG
Skin 主色 → 派生色板 → 共享颜色转换 → 测量与渲染
```

Layout 先安排页面内容、阅读顺序和结构占区，结构服务于排版。颜色转换保持原几何；字号、尺寸和小配件适配是另一项能力，不能因换色成功就宣称全库支持任意大小。

| 修改位置 | 重新渲染后的影响 |
| --- | --- |
| 某一个结构的源形状、布局或内容契约 | 该结构在各 Skin 下的表现同步更新；其他结构不随之改变 |
| 一个 Skin 的主色 | 使用该 Skin 的结构重新派生配色；不修改结构源设计或其他 Skin |
| 全库共享绘制依赖或颜色转换规则 | 所有调用该公共实现的结构受影响，需检查代表结构 |
| 当前任务里的副本 | 只影响该任务；不会自动回写结构库 |

已生成的 PNG、PPTX 和缓存不会自行改写，需重新生成或刷新对应缓存。若某结构有多个历史入口，修改时应确认它们指向的源实现与共享依赖，避免只改一份冻结样例。

当前中性 Skin 的唯一颜色输入是资产 `mainColor`；`primary-tone-palette.mjs` 派生全部用途色，兼容字段 `primaryColor` 是派生强调色，不是第二个用户输入。35 个已审批结构，包括三个尺寸样板，都经 `compileHtmlComponentTheme` 调用同一个 `neutral-structure-theme.mjs`，不按结构名称追加颜色覆盖。程序按原色明度连续映射，保留深浅顺序和透明度；卡片承载面与页面背景区分，文字保持可读。相同用途和相同原色得到相同结果，不要求不同原稿色阶被涂成同色。具体规则只维护在[中性 Skin](../rules/skins/中性编辑排版.md)。

内置已审阅转换为中性 Skin；东北大学仍使用既有主题路径。新 Skin 现可通过登记工具接入同一结构转换程序，仍需验证，不能宣称任意主色、尤其深色或高饱和色，都已验证好看。此处记录 2026-09-08 的三个尺寸样板认可范围。Home 合入后已有进一步尺寸适配实现与实验，逐项支持以能力契约和对应证据核对；35 个结构的统一换色不自动证明全库尺寸或最终 PPT 已验收。

用户已认可当前暖米色转换效果，代码存档为 `373fe19a`。验证记录见[统一转换预览](../experiments/structure-unified-neutral/index.html)：35 个结构的默认、较少、较多共 105 个 HTML 状态，未检测到指定文字容器裁切；21 项定向测试通过，并检查汇聚色阶、同原色漏斗及循环箭头配色。它不代表全部结构的 Luna 整页调用、任意尺寸或最终 PPT 已验收，也不自动晋升 Skin 资产状态。

## 后续目标，尚未完成迁移

Harness 是制作闭环的运行手段，自研 Harness 完整度不是项目目标。2026-09-12 的最小架构保留内容、视觉两个专业职责，可在同一执行对话中协调；独立上下文不再是首轮前置条件。总控为状态、工具调度、恢复与交付责任，可由宿主和执行者承担，也可由仓库内的薄运行器承担（`src/runner/`，2026-09-12 建成，只拥有循环、状态落盘、工具派发、恢复这四件事）；两条路都不要求额外自主 Agent 或复杂程序状态机。职责如下：

| 角色 | 目标职责 |
| --- | --- |
| 总 Agent | 持有任务状态、预算与产物；调度两个导演，路由局部反馈、QA 与交付，不替代导演包办设计 |
| 内容导演 | 叙事、章节、分页、页面职责、来源与内容层级；按明确反馈修订受影响页面，不决定资产或绘图坐标 |
| 视觉导演 | 全稿节奏、版式、内容区域及 Text／Media／Structure 组合；在能力声明内适配，不发明事实和素材 |
| 能力执行器 | 执行已有程序与资产；声明语义、容量、不变量、适配面、示例、来源和检查方法 |
| Native QA | 检查可编辑性与可定位的几何、字体、容量等问题；不能代替全部审美判断 |

Layout 组织 Text、Media、Structure 三类表达能力。Structure 只在真实拓扑关系需要时调用，不以结构命中率或随机不重复衡量质量。信息按“能力摘要 → 表达目的／Logic → 具体实现”逐层读取，不一次装入全库，也不为每层增设 Agent。Native／QA 是公共执行层，不是第三类视觉资产库。

此前 `DeckBrief / PageBrief / PageComposition / ArtifactState` 是候选责任命名，未发布 Schema；当前运行器以 state.json 为机器真源，content.md 和 state.md 为派生视图，blueprint.json 引用对应内容，不并行建设另一套 IR。内容与来源不维护多份可编辑真源。Harness／SDK 不绑定特定产品；并发队列、Worker 纳入 M5 按实际需求处理。

区域展示文案需要绑定原稿来源（实验称 PageView），允许精炼但必须保留事实、条件、职责与关系。内容阶段决定语义与分页；视觉阶段决定区域与表达，语义改动回到内容阶段，避免绘图时悄悄删改原意。历史无图片路线保留为候选实验。当前规划验证复用已有渲染和查看工具，记录实际反馈方式，不先施加无图片限制；这也不能被计作无图片产品路径验收。

## 建设与生产的边界

建设阶段把参考中的设计方法做成可复用能力，补齐适用条件、内容契约、容量、参数、版本、失败返回和原生渲染证据。运行时模型在这些能力范围内完成判断与选择；坐标、文字测量、样式角色和对象生成由能力实现负责。具体规范见[页面构成与布局规范](架构/页面构成与布局规范.md)，建设步骤见[资产入库工作流](工作流/资产积累与入库/工作流.md)。

能力不足时，生产任务不能默认切到自由绘制或用并列卡片掩盖关系缺口。现有 Skill 原生重建、参考重组与模型自由局部排版保留兼容/实验价值；要纳入新生产主线，须先形成可调用契约并验证。旧接口仍按实际 schema 使用，本轮说明不会自动收紧其程序权限。

内容理解与保真提炼仍依赖语义判断，改为填表并不自动证明准确。重复一致的目标与版本条件见[产品目标与路径](产品目标与路径.md)；缓存、程序回放和模型独立判断分别验收。

## 已合并实验与正式能力的区别

无图片网格原型已验证双上下文、来源绑定、局部修订与一页 Text + Structure，仍是实验路径，详见[闭环证据](../experiments/penguin-harness-v2/GRID-RESULTS.md)。正式候选选择已纳入 Text 与 Structure 同级选择；这不等于正式选择器有自由坐标权限。Codex Skill 早期有真实结构调用；后续咨询式整稿主要参考重组。三篇精选 29 页包含反馈修订，旧轮两次同提示独立复验为 1/2 整稿通过；这是当轮验收记录，用户仍认为咨询式审美不足，不能作为目标风格已达标的依据。新一轮[审美提示对照](../experiments/university-skin-pilot/aesthetic-ab-01/README.md)独立记录结果；尚未证明稳定性、DeepSeek 可迁移性或产品成本。

## 适配与迁移底线

- 保留现有可交付路径，已有程序与资产作为未来能力实现或通过 ID 引用，不另复制平行几何真源。
- 目标降级顺序为：精确调用 → 契约内适配 → 少量能力组合 → 重组或拆页 → 成熟文字／图文表达；不能通过虚构事实、缩字硬塞或整页图片假装成功。当前程序尚未实现整条目标阶梯。
- 运行时派生仅属于本次稿件，应留来源、差异与 QA 记录；不能覆盖核心资产或自动晋升。入库与正式调用始终分开，`PPT源/` 仍是唯一原始 PPT 来源。
- HTML 保留在资产设计、复现与审批；现行资产 HTML-to-Native 编译继续复用。目标正式线直接生成 Native 对象，但不同时维护独立 CSS 与 Builder 两套设计规则，也不一次重写全库。
- `asset-gap` 是能力缺口，`content-capacity-gap` 是内容容量不合法，不能混为一类；真实性、依赖、可编辑性与明显几何错误不能被降级掩盖。

## 当前推进范围

2026-09-16 起按新的能力里程碑推进：**M1 内容规划成立 → M2 端到端制作成立 → M3 跨稿稳定 → M4 能力扩展 → M5 产品化**。状态、验收与证据唯一维护于[项目进度](方向讨论/页面编排能力计划.md)；旧 R0–R3、旧 M1–M5 与 A–H 仅作历史，不继承通过结论。

当前质量关仍为 M1，同时前置建设支撑灰稿与成稿的资产和确定性执行：页面目的、内容归属、实际内容、主次和关系成立，允许单独检查规划，同时用真实 PPT 提供反馈。M1 通过不等于完整制作或跨稿稳定；正常用户制作任务仍默认交付完整 PPT。实现路径和稳定性口径见[产品目标与路径](产品目标与路径.md)。

先复用现有运行器与可用能力，不急于迁移 Agents SDK、LangGraph 等框架。工作流稳定后再评估通用基础设施；正式框架、独立部署、商用依赖、并发与任务隔离在 M5 处理。现有 PPT 引擎仍依赖 Codex 私有运行时，模型调用独立不等于系统独立部署，具体限制见[外部依赖](../harness/外部依赖.md)。已有保存状态与恢复能力继续复用，不因列入 M5 而撤销。
