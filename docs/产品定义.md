# 产品定义与架构边界

PPagenT 面向学校、科研院所、事业单位和企业的工作型演示，把用户内容转为可靠、体面、原生可编辑的 PPTX。东北大学是第一正式场景，不是最终产品边界。输入与交付需求独立见[产品需求](产品需求.md)，不由某种架构倒推。

## 当前已实施

| 部分 | 当前职责与边界 |
| --- | --- |
| 现行生产线 | 内容导演输出内容；程序筛选合法候选；视觉导演选择 Composition／Structure；确定性执行与检查交付 PPTX。仍主要是一页一个主结构，不是自主 Agent 工具循环 |
| 规则层 | 根目录 `rules/` 保存唯一现行规则正文，`index.json` 按 profile／Skin 选择；Skin 唯一绑定一个可共享排版体系。每次导演入口重新读取，视觉批次共用本次入口快照，无跨阶段冻结承诺 |
| 正式角色提示 | 内容导演加载共享内容原则与其执行协议；视觉选择器加载候选选择协议。静态角色协议归规则，Schema、动态输入与修复反馈仍由代码约束，选择器不加载自由排版规则 |
| 独立制作入口 | 短任务提示词读取 `generation` 共享规则、指定 Skin 及其绑定排版体系，供有制作工具的 Agent 执行；加载命令本身不生成 PPT、不调用模型 |
| 资产与渲染 | 现行正式 CLI 限东北大学 Skin；中性 Skin 仍为 candidate，只用于独立实验／审批。规则迁移不自动晋升资产 |

当前已披露候选可开放 `text-plus-structure`；未披露则不能使用。通用 Media、多结构自由组合与新的 Harness 未在本轮接入。既有结构库继续由原生产线调用，独立制作入口本轮不接结构库。四类输入与局部对话修改是产品需求，不代表现有正式入口全部支持。

## 规则、Skin 与版式如何分工

Skin 决定视觉身份与一个完整颜色体系，包括主题色、配套色阶、Logo 或身份装饰、字体配置。排版体系决定内容怎么组织，包括字号角色、层级、间距、正文重心、符号、容器和页面表达；它不是单一固定版式。通用对齐、阅读顺序和质量要求继续由共享规则承担。

暂定一个 Skin 绑定一个排版体系，多个 Skin 可以复用同一体系：当前「中性 Skin」对应「杂志风」；大学 Skin 共用「麦肯锡式」的命名与分工已确认。大学咨询式实验已合并，见[整稿测试](../experiments/university-skin-pilot/stability-01/RESULTS.md)，其冻结指南尚未接入当前规则索引，不能宣称正式绑定完成。历史资产 ID 和目录名不因用户可见名称改变而批量改名。

可换色组件按强调、普通承载、正文、边线等用途消费 Skin 配色，不把所有对象直接染成主色。原图、Logo 和有固定数据或状态语义的颜色不强制重着色。已合并的结构主题入口支持显式 primaryColor：35 个核心结构的蓝紫代表状态已验证，HTML 解析、Native 与看板共享转换入口；未传主色的旧调用保留历史色。该实现不等于所有源码已令牌化，也没有修改缩放、字体或容量契约，见[主题报告](../experiments/structure-theme-01/REPORT.md)。文字、图像与关系图是不同表达能力，不因颜色统一而混为一种结构。

规则正文分工与读取方式只在 [rules/README.md](../rules/README.md) 维护。颜色用途取值留在 Skin；字号、间距等排版数值留在绑定体系。已有资产 `fonts` 继续是字体名称真源，规则通过声明加载该字段，不复制一套 tokens。资产描述引用规则，不再抄写整段规范。

提示词只负责本次任务、输入输出与加载入口；执行器负责可编辑对象、几何和契约校验。参考教程先成为学习笔记，再将适用且经验证的经验修订到现有规则。历史提示词保留为证据，但不作为并行版本选择。

## 后续目标，尚未完成迁移

目标是薄的 PPT 专用 Agent Harness，而不是持续增加孤立问答式 API 的补丁。一个逻辑 PPT Agent 分内容、视觉两个独立上下文，通过持久化项目交接；总控是程序的状态、预算与调度责任，不要求额外增加第三个自主 Agent。保留两个专业导演：

| 角色 | 目标职责 |
| --- | --- |
| 总 Agent | 持有任务状态、预算与产物；调度两个导演，路由局部反馈、QA 与交付，不替代导演包办设计 |
| 内容导演 | 叙事、章节、分页、页面职责、来源与内容层级；按明确反馈修订受影响页面，不决定资产或绘图坐标 |
| 视觉导演 | 全稿节奏、版式、内容区域及 Text／Media／Structure 组合；在能力声明内适配，不发明事实和素材 |
| 能力执行器 | 执行已有程序与资产；声明语义、容量、不变量、适配面、示例、来源和检查方法 |
| Native QA | 检查可编辑性与可定位的几何、字体、容量等问题；不能代替全部审美判断 |

Layout 组织 Text、Media、Structure 三类表达能力。Structure 只在真实拓扑关系需要时调用，不以结构命中率或随机不重复衡量质量。信息按“能力摘要 → 表达目的／Logic → 具体实现”逐层读取，不一次装入全库，也不为每层增设 Agent。Native／QA 是公共执行层，不是第三类视觉资产库。

暂以 `DeckBrief / PageBrief / PageComposition / ArtifactState` 表示全稿要求、页面内容、页面编排、产物状态四类责任。内容与来源只保留一份，其他对象引用；这不是已发布的新 Schema，不为未验证状态预建字段。Harness／SDK 不绑定特定产品，并发留在任务队列与 Worker 层解决。

区域展示文案需要绑定原稿来源（实验称 PageView），允许精炼但必须保留事实、条件、职责与关系。内容阶段决定语义与分页；视觉阶段决定区域与表达，语义改动回到内容阶段，避免绘图时悄悄删改原意。默认产品生成模型不接图片，读取文字布局、几何与网格反馈；图片审美复核可由研发或人工承担。杂志风独立制作目前允许执行者视觉自检，其结果不能直接充当无图片产品路径的验收。

## 自主编排与资产复用边界

排版体系的核心职责是审美判断与实现方法：阅读入口、文字层级、信息归属、强调强度、留白和全稿节奏。它不能退化为防溢出清单，也不将“有重心”固定翻译成一个巨型色块。文字、比较和关系本身可以形成焦点；容器承担聚合、条件边界或有依据的强调。文字组先按自然高度与阅读关系组织，再配置必要图形。程序检查是独立的执行底线，通过不等于达到目标风格。

大学麦肯锡式目前仍是排版体系的独立设计实验，尚未达到用户认可的接入门槛，不注册 Skin 绑定、不套旧大学 Shell。蓝色和字体只是对照实验的固定主题条件。先用相同稿件对照不同提示，再以其他稿件检查迁移；只将经验证且适用的审美方法归入将来的单一现行体系，不让历史试验全文同时成为生产规则。

- 正向指导说明阅读入口、层级、归属、节奏和留白怎样服务内容；边界限定事实、身份、适用文字角色、真实关系和可编辑性。具体分组、区域比例、强调与分页由 Agent 在此范围内决定，不用固定文字模板或庞大版式库作为前置条件。
- Layout 是本页实际编排结果，排版体系是跨稿复用的方法，两者分开。网格只描述空间与占用，不替代因果、顺序或归属。
- 直接调用结构时遵守已声明拓扑、容量、最小尺寸和支持参数；参考重组时可重新安排原生节点、线条、尺寸与图外说明，验证本次输出并记录来源，不能把参考重组标成原组件调用成功。
- 文字是正常元素，按语义角色和真实换行高度排放；图片需真实来源与必要标注。结构仅在局部关系需要时检索，不强制每页一个结构或达到调用配额。
- 运行时只改本次产物，不改核心库或长期规则。来源、条件与关系不能为整齐删掉；程序检查和视觉验收分别记录，未覆盖项不写成通过。

## 已合并实验与正式能力的区别

无图片网格原型已验证双上下文、来源绑定、局部修订与一页 Text + Structure，仍是实验路径，详见[闭环证据](../experiments/penguin-harness-v2/GRID-RESULTS.md)。正式候选选择已纳入 Text 与 Structure 同级选择；这不等于正式选择器有自由坐标权限。Codex Skill 早期有真实结构调用；后续咨询式整稿主要参考重组。三篇精选 29 页包含反馈修订，最新两次同提示独立复验为 1/2 整稿通过，尚未证明稳定性、DeepSeek 可迁移性或产品成本。

## 适配与迁移底线

- 保留现有可交付路径，已有程序与资产作为未来能力实现或通过 ID 引用，不另复制平行几何真源。
- 目标降级顺序为：精确调用 → 契约内适配 → 少量能力组合 → 重组或拆页 → 成熟文字／图文表达；不能通过虚构事实、缩字硬塞或整页图片假装成功。当前程序尚未实现整条目标阶梯。
- 运行时派生仅属于本次稿件，应留来源、差异与 QA 记录；不能覆盖核心资产或自动晋升。入库与正式调用始终分开，`PPT源/` 仍是唯一原始 PPT 来源。
- HTML 保留在资产设计、复现与审批；现行资产 HTML-to-Native 编译继续复用。目标正式线直接生成 Native 对象，但不同时维护独立 CSS 与 Builder 两套设计规则，也不一次重写全库。
- `asset-gap` 是能力缺口，`content-capacity-gap` 是内容容量不合法，不能混为一类；真实性、依赖、可编辑性与明显几何错误不能被降级掩盖。

## 当前推进范围

先稳定规则单源、短任务可复现与说明边界。当前明确以 **Luna high（`gpt-5.6-luna`，推理强度 `high`）**作为独立制作与复现验收的目标：主任务负责维护提示词、规则和文档、驱动实验与验收；Luna high 新对话负责制作和自检。成功标准是可复制的文件输入足以让该等级的执行者做出符合要求的 PPT，而不是主任务依靠历史上下文亲自做出好样稿。具体实验与修订流程只在[独立制作工作流](工作流/正式生成/工作流.md#luna-high-复现验收)维护。这是当前验证目标，不把未来产品架构永久绑定到某个模型。

本轮不建设新 Harness、不扩结构库、不宣称图文能力已经验证。下一步图文与复合页从少量真实稿件验证所需规则与适配面，不先堆大量模板。

后续 Harness 最小切片仍应比较普通文字、真实结构和复合页的质量、可编辑性、Token、延迟、fallback 与返工成本。只对明确页面问题反馈，先限定一次内容修订和一次视觉修正，不整稿无限循环。若主要靠专稿代码或成本增长却无稳定收益，先缩小自由度，不扩张框架。模型、SDK、缓存与截图反馈粒度均待验证。
