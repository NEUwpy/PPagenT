# 产品定义

## 一句话定义

PPagenT 是一个面向固定组织场景、通过 PPT 专用 Agent Harness 按内容与 Skin 规则编排、生成原生可编辑 PPTX 的生产系统。

Agent 可以依据规则直接组合原生文字、形状、线条和真实媒体。已经积累的结构与 Skills 提供可选的设计经验，程序工具负责测量、生成和反馈；固定版式或文字模板不是生成前提。

## 目标场景

第一目标是学校、科研院所、事业单位和企业中反复发生的工作型演示：有明确组织规范，需要快速、体面、稳定并可继续编辑，不要求每一页都进行高度定制设计。

产品追求的不是偶然生成一份最高分作品，而是提高目标场景中结果稳定达到可用标准的概率。

## 最终形态

目标运行结构是一个逻辑上的 PPT Agent、内容/视觉两个独立上下文和渐进披露的能力库。程序维护持久化 Deck Project、预算与局部反馈。内容阶段负责讲什么，视觉阶段负责整页区域、展示文案和能力绑定。

PageBrief 保存内容与来源；PageComposition 保存区域；PageView 保存实际展示与来源绑定；ArtifactState 保存产物、问题与修订。默认模型无图片输入，通过网格和实际文字/几何数据检查与修正；人工可以查看预览。具体边界以[架构决策](工作流/正式生成/生成线架构决策.md)为准。

## 视觉能力体系

视觉系统区分设计规则与具体编排结果：

- **Skin**：组织身份、颜色、字体、Logo、Shell、Content Frame，以及文字层级、间距、对齐、留白和强调方式等审美与排版规则；
- **Layout／版式**：通用编排器依据本页叙事、信息关系、展示量和 Skin 规则生成的区域、阅读顺序与主次安排。固定版式可作为参考，不是必须命中的模板库。

Layout 在 Skin 给定的 Content Frame 内组织三类表达能力：

- **Text 能力**：依据 Skin 的语义字号角色和区域尺寸测量、换行、分组与排放，支持观点、说明、分点、大数字、引语、证据和纯文字页面；不要求为每种版式建立固定文字模板；
- **Media Skill**：图片、截图、图表、图标及其标题、说明、裁切与占位规则；
- **Structure Skill**：流程、层级、因果、循环、矩阵、分支、网络等拓扑表达，是页面可调用的语义组件，保留数量、关系与尺寸契约。

内容编排先明确结论、支撑、分组、关系和优先级，再估计展示量；视觉编排先组织整页，再选择区域内的表达，随后通过实际测量调整。单页可以同时包含流程和贯穿规则等不同关系，不强制整页只使用一种结构。

`Native／QA` 是支撑所有视觉能力的执行与质量层，不与 Skin、Layout 并列成为第三套设计库。它负责生成原生对象、适配 Content Frame、检查和修复确定性错误。

直接编排时只需加载任务、Skin 规则和原生工具说明。有意复用结构时再渐进披露：从能力摘要、Logic 到具体 Structure／Style Group 的契约与执行器。能力检索是可选路径，不要求每一段文字或每个组合先命中 Skill，也不要求每层启动新的 Agent。

每个具体 Skill 至少包含：适用语义、容量与内容区域契约、可变参数、允许适配的范围、Native 执行脚本、参考与示例、质量检查和来源信息。已登记的核心资产应成为 Skill 的实现或被 Skill 直接引用，不再复制一套平行的模板真源。

## 灵活性与可靠性的边界

Agent 负责语义与构图，程序提供原生操作、测量、执行和反馈：

- 可依据 Skin 规则直接组合文字、形状、线条和媒体，页面组合不必预先入库；
- 现有 Skill 有帮助时调用，只在其声明的自由度内适配；
- 容量或叙事不合适时，调整区域、表达、内容分组或分页；
- 文字和图文排放是正常生成方式；工具不支持的动作如实披露，不能伪造调用成功。

运行时为单份稿件产生的适配属于临时派生结果，不会自动修改核心 Skill，也不会自动晋升为资产。只有重复出现、经过验证并由用户确认的变化，才进入入库线。

系统通过有限反馈与局部修订提高可用交付概率；不承诺一次生成必然成功，也不允许用无限缩字、删减事实、伪造图片或发明关系来假装成功。规则初稿见 [Agent 排版规则](工作流/正式生成/Agent排版规则.md)，当前运行器支持范围与目标分开记录。

## HTML 与 Native PPTX

HTML 继续用于资产入库阶段：复现参考、组件化、数量扩展、审美调整和看板审核。它能降低设计实验成本，但不是目标正式生成线的必经中间格式。

正式生成的目标是：视觉编排阶段通过原生工具及可选 Skills，在既定 Content Frame 中生成和调整原生 PowerPoint 对象。现有 HTML 到 Native 的资产运行时继续复用；新原生工具经过验证再接入正式入口。

## 产品边界

- `PPT源/` 是唯一原始 PPT 来源目录。
- Skin 提供组织身份、主题、页面边界与排版规则；更换 Skin 时复用通用编排器与兼容能力。
- 资产入库线负责建设、审美审核和晋升；正式生成线只读调用核心能力。
- 不让 Agent 无边界自由绘制整份 PPT，不把截图或整页图片作为交付。
- 不要求所有页面使用结构图，也不以 Structure 命中率衡量质量。
- 不允许模型发明事实、媒体、数据、因果或层级。
- 不为低概率风险堆叠全状态穷举、反复哈希、无限重试和多层治理。

东北大学是第一个正式场景，不是最终边界。未来主要替换 Skin 和组织规范，复用 Harness、导演协作方式、视觉 Skills、Native 生成与质量规则。
