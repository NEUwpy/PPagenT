# 产品定义

## 一句话定义

PPagenT 是一个面向固定组织场景、通过 PPT 专用 Agent Harness 调用受控视觉 Skills、可靠生成原生可编辑 PPTX 的生产系统。

它不是让模型从空白画布自由作图，也不是把稿件塞进固定模板。它把已经积累的设计经验封装成可调用、可适配、可验证的能力，再由 Agent 根据具体稿件组织和组合。

## 目标场景

第一目标是学校、科研院所、事业单位和企业中反复发生的工作型演示：有明确组织规范，需要快速、体面、稳定并可继续编辑，不要求每一页都进行高度定制设计。

产品追求的不是偶然生成一份最高分作品，而是提高目标场景中结果稳定达到可用标准的概率。

## 最终形态

目标运行结构是一个逻辑上的 PPT Agent、内容/视觉两个独立上下文和渐进披露的能力库。程序维护持久化 Deck Project、预算与局部反馈。内容阶段负责讲什么，视觉阶段负责整页区域、展示文案和能力绑定。

PageBrief 保存内容与来源；PageComposition 保存区域；PageView 保存实际展示与来源绑定；ArtifactState 保存产物、问题与修订。默认模型无图片输入，通过网格和实际文字/几何数据检查与修正；人工可以查看预览。具体边界以[架构决策](工作流/正式生成/生成线架构决策.md)为准。

## 视觉能力体系

视觉系统由两个并列的大类组成：

- **Skin**：组织身份、颜色、字体、Logo、Shell、Content Frame 和页面安全边界；
- **Layout／版式**：整套节奏、页面类型、内容区域、栅格、留白和主次关系。

Layout 在 Skin 给定的 Content Frame 内组织三类表达能力：

- **Text Skill**：观点、说明、分点、大数字、引语、证据和纯文字页面的成熟排版；
- **Media Skill**：图片、截图、图表、图标及其标题、说明、裁切与占位规则；
- **Structure Skill**：流程、层级、因果、循环、矩阵、分支、网络等拓扑表达。

`Native／QA` 是支撑所有视觉能力的执行与质量层，不与 Skin、Layout 并列成为第三套设计库。它负责生成原生对象、适配 Content Frame、检查和修复确定性错误。

Structure 领域采用三层渐进披露：先加载 Structure 能力摘要，再按 `Logic` 进入比较、并列、顺序、层级等逻辑 Skill，最后才加载具体 Structure／Style Group 的契约与执行器。文字和图片能力也按“能力域 → 表达目的 → 具体实现”组织。这里是 Skill 的逻辑分层，不要求每层都启动新的 Agent。

每个具体 Skill 至少包含：适用语义、容量与内容区域契约、可变参数、允许适配的范围、Native 执行脚本、参考与示例、质量检查和来源信息。已登记的核心资产应成为 Skill 的实现或被 Skill 直接引用，不再复制一套平行的模板真源。

## 灵活性与可靠性的边界

程序没有被 Agent 取代，而是从“决定所有页面”的总控制器下沉为 Skill 内的可靠执行能力：

- 完全匹配时直接调用已审批 Skill；
- 基本匹配时，只在 Skill 声明的自由度内调整数量、尺寸、文字、颜色、区域和组合；
- 一个 Skill 不够时，由视觉导演组合文字、图片和结构能力；
- 容量或叙事不合适时，优先换版式、重组内容或拆页；
- 仍无合适能力时，退化到成熟的文字／图文排版，保证原生可编辑交付。

运行时为单份稿件产生的适配属于临时派生结果，不会自动修改核心 Skill，也不会自动晋升为资产。只有重复出现、经过验证并由用户确认的变化，才进入入库线。

“不失败”指在内容真实、输入有效和运行环境正常时，系统尽量通过上述降级链交付可编辑 PPTX；不代表每次都达到最高审美水平，也不允许用缩小字号、删减事实、伪造图片或临时发明关系来假装成功。

## HTML 与 Native PPTX

HTML 继续用于资产入库阶段：复现参考、组件化、数量扩展、审美调整和看板审核。它能降低设计实验成本，但不是目标正式生成线的必经中间格式。

正式生成的目标是：视觉导演调用 Skills，在既定 Content Frame 中直接生成和调整原生 PowerPoint 对象。现有 HTML 到 Native 的资产运行时在迁移期继续使用；只有经过验证的能力才逐步转为正式 Native Skill，不能为了架构整洁一次性删除当前可交付路径。

## 产品边界

- `PPT源/` 是唯一原始 PPT 来源目录。
- Skin／Shell 固定组织身份、主题和页面边界；更换 Skin 时尽可能复用其他 Skills。
- 资产入库线负责建设、审美审核和晋升；正式生成线只读调用核心能力。
- 不让 Agent 无边界自由绘制整份 PPT，不把截图或整页图片作为交付。
- 不要求所有页面使用结构图，也不以 Structure 命中率衡量质量。
- 不允许模型发明事实、媒体、数据、因果或层级。
- 不为低概率风险堆叠全状态穷举、反复哈希、无限重试和多层治理。

东北大学是第一个正式场景，不是最终边界。未来主要替换 Skin 和组织规范，复用 Harness、导演协作方式、视觉 Skills、Native 生成与质量规则。
