# 产品定义

## 一句话定义

PPagenT 是一个面向固定组织场景，使用受控视觉能力可靠生成原生可编辑 PPTX 的生产系统。

AI 负责理解稿件和选择表达；已验证的视觉能力负责限定结果；确定性程序负责布局、编译和检查。

## 目标场景

第一目标是学校、科研院所、事业单位和企业中反复发生的工作型演示：有明确组织规范，需要快速、体面、稳定并可继续编辑，不要求每一页都进行高度定制设计。

产品追求的不是偶然生成一份最高分作品，而是提高目标场景中结果稳定达到可用标准的概率。

## 当前产品组成

- **Skin／Shell**：字体、颜色、Logo、封面、目录、正文、尾页和 Content Frame。
- **内容导演**：理解整篇稿件、组织叙事、拆页并保留来源证据。
- **视觉导演**：在程序给出的合法候选内选择表达。
- **视觉能力库**：保存 Composition、文字能力和经过审批的 Structure Group。
- **HTML 与 Native 编译器**：由同一布局结果生成原生 PowerPoint 对象。
- **质量门禁**：检查字号、容量、越界、重叠和必要的内容关系。

资产入库线负责建设和审批能力；正式生成线只调用已确认的核心资产。`PPT源/` 是唯一原始 PPT 来源目录，候选资产不能自动晋升。

## 页面表达原则

多数工作型页面是观点、解释、证据、弱关系要点或图文组合，应主要由 Composition + Text／Media 表达。

Structure Group 只在流程、层级、因果、循环、矩阵、分支和网络等拓扑本身承载语义时使用。简单三点并列不必为了“结构化”而画成结构图。

## 当前实现与下一步

当前正式流程已经支持双导演、核心 Structure Group、简单正文兜底、HTML Structure 布局、Native 编译和确定性检查，但仍以“一页一个主 Structure／Composition”为主。

下一步确定建设的是更通用的 Composition、Text 和 Media 组合能力。复杂页面是否需要反馈式编排、是否使用 Harness、是否让模型观察页面截图，都必须经过小型对照实验后再决定。

## 产品边界

- 不让 AI 自由绘制整份 PPT。
- 不把 HTML、截图或整页图片作为最终交付。
- 不承诺任意网页或任意 PPT 无损转换。
- 不要求所有页面使用结构图，也不以 Structure 命中率衡量质量。
- 没有合适结构时使用合法的文字或图文排版；容量仍不合法时拆页或失败关闭。
- 不允许模型发明事实、媒体、数据、因果或层级。
- 正式能力必须经过用户审批和 Native 结果验证。
- 不为低概率风险堆叠重试、穷举状态和治理流程。

东北大学是第一个正式场景，不是最终边界。未来扩展主要替换 Skin 和组织规范，并尽可能复用 Composition、表达能力、编译器和质量规则。
