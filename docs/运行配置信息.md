# 运行配置信息

本文记录 PPagenT 正式生成工作流的模型接入方式。真实 API Key 只保存在本机 Git 忽略文件或 GitHub Secrets 中，不进入代码、Markdown、示例 JSON 或 Git 历史。

## DeepSeek DirectorProvider

当前默认配置：

| 项目 | 值 |
| --- | --- |
| Provider | `src/agent/deepseek-provider-from-env.mjs` |
| API 格式 | OpenAI-compatible Chat Completions |
| Base URL | `https://api.deepseek.com` |
| 请求路径 | `/chat/completions` |
| Model | `deepseek-v4-flash` |
| JSON 输出 | `response_format: {"type":"json_object"}` |
| 思考模式 | 内容、结构、视觉意图与视觉路由均为 `enabled + low` |
| 正式命令 | `npm run agent:run:deepseek -- ...` |

模型名和接口依据 DeepSeek 官方文档：[Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode)。

## 本地 JSON

本机真实配置位于：

```text
config/deepseek.local.json
```

该路径已由 `.gitignore` 排除。可以从受 Git 跟踪的 `config/deepseek.example.json` 复制字段结构：

```json
{
  "apiKey": "replace-with-local-secret",
  "model": "deepseek-v4-flash",
  "baseUrl": "https://api.deepseek.com",
  "roles": {
    "content": { "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 16384 },
    "structure": { "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 4096 },
    "visualIntent": { "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 8192 },
    "visualComposition": { "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 8192 },
    "reviewer": { "thinking": "enabled", "reasoningEffort": "low", "maxTokens": 8192 }
  }
}
```

`chat/completions` 是 DeepSeek 的标准推理协议，不表示使用闲聊模型。当前实测使用低等级 thinking：内容导演负责整稿理解；结构读取负责避免漏项；视觉意图负责关系判断；视觉路由只输出紧凑 Skill 选择表，因此不再要求模型生成容易截断的完整编排对象。

Provider 优先读取环境变量，其次读取本地 JSON。可用环境变量为：

- `DEEPSEEK_API_KEY`
- `PPAGENT_DEEPSEEK_MODEL`
- `PPAGENT_DEEPSEEK_ENDPOINT`
- `PPAGENT_DEEPSEEK_BASE_URL`
- `PPAGENT_DEEPSEEK_THINKING`
- `PPAGENT_DEEPSEEK_REASONING_EFFORT`
- `PPAGENT_DEEPSEEK_MAX_TOKENS`

角色级环境变量使用 `PPAGENT_DEEPSEEK_CONTENT_*`、`PPAGENT_DEEPSEEK_STRUCTURE_*`、`PPAGENT_DEEPSEEK_VISUAL_INTENT_*`、`PPAGENT_DEEPSEEK_VISUAL_COMPOSITION_*` 和 `PPAGENT_DEEPSEEK_REVIEWER_*`，可分别覆盖 `THINKING`、`REASONING_EFFORT` 与 `MAX_TOKENS`。`structure` 只用于一次受限的节点内分点补充，不是第三个导演。

## 运行命令

```powershell
npm run agent:run:deepseek -- `
  --input <稿件.md> `
  --output <输出.pptx> `
  --run-dir <运行记录目录>
```

生产模式只调用内容导演和视觉导演，然后进入核心资产选择、确定性渲染与质量门禁。DeepSeek V4 Flash Provider 当前按文本接口接入，不支持研发模式的逐页 PNG 模型审查；不要以 `--mode development` 运行它并假装完成视觉看图。

也可以运行 `npm run production:workbench`，或双击项目根目录的 `PPA生产工作台.exe`。本地页面读取同一份 `config/deepseek.local.json`，展示模型与 Endpoint，但不会显示或写出 API Key。

## GitHub

如果以后在 GitHub Actions 中运行，不上传 `config/deepseek.local.json`。在仓库设置中创建名为 `DEEPSEEK_API_KEY` 的 Actions Secret，并把它映射为同名环境变量。模型、Endpoint 和非敏感参数可以写进 workflow，真实 Key 不能出现在仓库文件、Issue、日志或提交历史中。

## 密钥轮换

密钥一旦出现在聊天、终端历史、截图或误提交中，应在 DeepSeek 控制台撤销并生成新 Key，然后只更新本地忽略 JSON或 GitHub Secret。
