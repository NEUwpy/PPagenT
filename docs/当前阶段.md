# 当前阶段

本文只记录 PPagenT 现在开发到哪里、当前正在验证什么，以及本阶段不能绕过的约束。产品定位、边界和长期目标见[产品定义](产品定义.md)，对外讲述见[产品叙事](产品叙事.md)，历史变化见[更新日志](更新日志.md)。

## 当前所处阶段

产品定义已把东北大学确定为第一阶段的正式落地场景。仓库当前已有的东北大学 Skin 和相关输出既是前期技术验证结果，也是第一阶段资产建设的起点；它们仍需按入库工作流继续验证和扩充，不能因为已经能生成样例就视为正式场景已经建设完成。

当前主任务已经切换为 `HTML Shell + Visual Skill` 架构原型。《让“六地”红》的继续校准、更多真实稿件压力测试和学术实验系统暂时停止；现阶段只验证案例 PPT 能否经过 HTML 表达、数量扩散、批量编译和脚本化输入重新生成原生可编辑 PPTX。四个检查点通过后，再把东北大学主题抽象为 Shell。近期取舍和长任务停止条件见[方向校正](方向校正.md)。

《为什么做 PPagenT》v0.3.0 暴露了一个根本性旁路：视觉运行时调用了没有蒸馏来源的临时结构变体。该版本只保留为失败诊断样本。

这也证明研发审查不能只检查文本、越界和形式合法性：更重要的门禁是正式流程是否只调用核心资产，以及核心资产本身是否忠实于蒸馏来源并达到可长期维护的质量。

当前状态是：**正式生成线已经用第二份真实稿件完整跑通；v0.6.2 开始把真实稿件暴露的问题收敛为 Skin 文字角色、容器文字适配、对比语义方向、单观点骨架和正文节奏规则。核心资产仍需继续扩充和美化，但系统已能从原稿稳定生成一套可审查的 PPT。**

三层组织树曾用重型入库流程完成 11 个合法状态、13 个非法边界和双环境治理。它证明资产可以被严格验证，也暴露出默认流程过重、Token 和返工成本过高。当前已经把 SHA-256、完整证据闭包和全状态治理降为可选诊断；默认入库改为“来源分析 → 黄金状态 → 声明版式扩散范围 → 主要布局状态 → Skin PPT → 用户确认”。

核心库现登记东北大学封面、正文、尾页，以及双向对比、基础顺序流程、多角色泳道流程、三层组织树、问题与改进措施和本轮通过验收的八项结构资产：中心辐射、循环闭环、时间轴、层级金字塔、转化漏斗、鱼骨原因分析、四象限分析框架、分层架构与生态关系。

正式生成线已经改为“资产包自动发现”。现有 16 项核心资产均在自己的目录内声明语义、数量范围、视觉轮廓、Builder 或 Skin 渲染方式，以及 PageContent 字段映射；视觉导演候选由程序自动生成。核心资产不再依赖中央合同、变体表、Builder 注册表或 RenderPayload 分支的重复登记。

这八项资产已经由代码生成并经用户逐页确认，现已登记各自的 `layoutExpansion` 范围。其他未获用户确认的结构仍属于备选或实验能力。

东北大学 Skin 嵌入测试已经验证组件不得覆盖 Skin、不得绘制测试页头、必须使用统一坐标变换和形状边缘锚点。今后的用户主验收只展示会改变真实布局的主要扩散状态；纯文字压力和非法输入不再重复占用主验收流程。

蒸馏方法现由[资产积累与入库工作流](工作流/资产积累与入库/工作流.md)和设计优先的 Luna Harness 共同约束。本轮不批量入库，也不让 Luna 承担架构实验；由当前架构任务选择一个既有案例页，依次验证 HTML 忠实表达、Visual Skill 数量扩散、HTML → 可编辑 PPTX 批量编译和固定脚本输入。按画面质量、可编辑性、返工次数、运行时间和 Token 消耗判断路线。

本阶段同时冻结新的抽象层。除非真实稿件证明现有对象无法表达，否则不新增 Agent、Schema 层级或治理流程。新增资产由真实稿件的高频缺口驱动，进度改用“无需新增资产即可完成的页面比例”衡量，而不是核心资产总数。

v0.6.1 沿用已经跑通的内容与整页编排，并保留第 55 页蒸馏的核心双栏资产，但只允许真正存在共同评价维度、差异、优劣或取舍的内容进入比较家族。第 8 页的“Skin 可替换、能力可复用”是共同支撑扩展边界的互补事实，已改判为 `parallel`；候选生成器因此确定性排除比较资产，只允许东北大学正文资产。页面采用与第 7 页方向相反的文字主张构图，避免连续重复。整套九页在交付前自动检查 35 个几何父对象、最小 16 磅字号、容器内收和碰撞域，结果为零违规。正式运行仍未调用审查 Agent；当前环境没有 API Key，因此双导演继续使用冻结回放。

《让“六地”红》v0.6.3 是当前第二份真实稿件回归。Codex 暂时代替实时 API 输出两个导演的固定 Schema，程序只调用核心资产与东北大学 Skin。Skin 现在统一声明标题字体、正文字体和各层级字号档位；封面、正文槽位与尾页在写入前根据容器求解换行和字号，不能排下时停止。对比页由 `polarity` 同时控制颜色和符号，视觉重点不再改写褒贬；内容导演还必须保留原稿明确枚举的独立项，使视觉导演能按真实数量发现既有核心资产。本轮继续等待用户研发校准。

## 已跑通的主线

产品入口只要求原始稿件和 Skin；测试阶段默认东北大学 Skin。正式产品链路为：

> 原始稿件 → Skin → 内容导演 → `DeckPlan` / `PageContent` → 视觉导演 → `PageIntent` / `CompositionPlan` / `VisualPlan` → 核心资产选择 → `RenderPayload` → 确定性绘制 → `RenderQualityGate` → PPT

内容导演负责整场叙事、章节、顺序、页数、主次、拆分和压缩。视觉导演负责整套视觉语言、单页表达关系、版式选择和页面节奏；不得退化为各页互不知情的独立匹配。程序负责校验、参数映射、Skin、绘制和每次生成必经的确定性质量门禁。两位导演的 API 行为分别由正式生成工作流内部的独立提示词约束。

内容审查、视觉审查和人工复核属于当前研发试验环，用于发现系统提示词、规则和核心资产的问题；它们不是产品交付链路中的常驻 Agent。

## 禁止旁路

- 不得在稿件专属生成器中直接写死拆页、资产选择和页面布局。
- 不得跳过匹配器，由维护者直接指定一个“看起来合适”的结构资产。
- 不得只复制学校模板文字页，也不得只调用脱离 Skin 的结构组件。
- 不得把手工修好的 PPT 当作 Agent 已经跑通的证据。
- 不得只逐页选择合法组件而忽略整套 PPT 的视觉节奏和重复。
- 不得通过非等比例压缩把结构组件强行塞入 Skin 安全区。
- 不得让视觉导演选择程序未从核心资产包暴露的资产，也不得选择实验变体。
- 不得在某份稿件运行时临时编写结构图；缺少适配资产时必须失败关闭并回到蒸馏流程。
- 不得借用已有资产 ID 包装一个没有对应蒸馏来源的新轮廓。

## 用户确认前仍需满足

- 检查点 1：一个既有案例页能够由 HTML/CSS 忠实表达。
- 检查点 2：同一 Visual Skill 能生成主要数量状态且排版成立。
- 检查点 3：这些状态能够批量生成原生可编辑 PPTX，视觉和结构没有不可接受损失。
- 检查点 4：固定脚本能接收新文案并跑通相同链路。
- 四点通过后，把东北大学主题抽象为 Shell，并验证 Shell 与 Visual Skill 的组合；通过前不全面重构正式运行时。

## 维护规则

开始新一轮工作前先核对本文。本文只保留当前状态；阶段完成后更新本文，并把已发生的变化写入更新日志。
