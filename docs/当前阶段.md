# 当前阶段

本文只记录 PPagenT 现在开发到哪里、当前正在验证什么，以及本阶段不能绕过的约束。产品长期目标见[项目定位](项目定位.md)和[产品定义](产品定义.md)，历史变化见[更新日志](更新日志.md)。

## 当前所处阶段

PPagenT 正在进行**第一份真实稿件的完整流程建设**。

《为什么做 PPagenT》v0.2.0 跑通了结构化输入之后的确定性生产线，但没有从原始稿件自动形成 `DeckPlan` 和逐页内容，也没有从整套 PPT 角度规划视觉节奏。用户复核还发现第 9 页几何畸变，以及中心辐射结构重复造成的死板感，因此本版未通过。

当前不能转去测试第二份稿件；必须先让同一稿件从原稿和 Skin 开始完整运行，并修复已经暴露的视觉问题。

## 本阶段唯一主线

产品入口只要求原始稿件和 Skin；测试阶段默认东北大学 Skin。内部必须经过：

> 原始稿件 → 内容导演 → `DeckPlan` → `PageContent × N` → 视觉导演 → `PageIntent` → 版式家族与视觉变体 → `LayoutDecision` → `RenderPayload` → 确定性绘制 × Skin → PPT → QA

内容导演负责整场叙事、章节、顺序、页数、主次、拆分和压缩。视觉导演负责整套视觉语言、单页表达关系、版式选择和页面节奏；不得退化为各页互不知情的独立匹配。程序负责校验、参数映射、Skin 和绘制。

## 禁止旁路

- 不得在稿件专属生成器中直接写死拆页、资产选择和页面布局。
- 不得跳过匹配器，由维护者直接指定一个“看起来合适”的结构资产。
- 不得只复制学校模板文字页，也不得只调用脱离 Skin 的结构组件。
- 不得把手工修好的 PPT 当作 Agent 已经跑通的证据。
- 不得只逐页选择合法组件而忽略整套 PPT 的视觉节奏和重复。
- 不得通过非等比例压缩把结构组件强行塞入 Skin 安全区。
- 备选资产只有经过真实稿件验证和用户确认后才能晋升核心资产。

## 本阶段完成条件

- 同一个运行入口只读取原始稿件和指定 Skin，其余步骤自动完成。
- 内容导演生成可审计的 `DeckPlan` 和 `PageContent`。
- 视觉导演在整套范围内选择版式家族和视觉变体，避免不必要的重复。
- 每页都保存五层对象或可审计结果，资产选择能够追溯。
- 结构组件进入 Skin 后保持几何比例，并通过逐页视觉检查。
- 最终 PPT 由该入口生成，不需要稿件专属绘图代码补答案。
- 失败后修改的是通用流程、规则或资产，并能重新运行已经通过的稿件。
- 第一份真实稿件由用户确认通过。

## 维护规则

开始新一轮工作前先核对本文。本文只保留当前状态；阶段完成后更新本文，并把已发生的变化写入更新日志。
