# 当前阶段

本文只记录 PPagenT 现在开发到哪里、当前正在验证什么，以及本阶段不能绕过的约束。产品长期目标见[项目定位](项目定位.md)和[产品定义](产品定义.md)，历史变化见[更新日志](更新日志.md)。

## 当前所处阶段

当前工作的主战场是“入的工作流”：与用户一起积累来源、蒸馏结构、做成参数化候选，并在真实 Skin 正文区修到可长期复用。“出的工作流”已经有原稿与 Skin、双导演结构化对象、合法候选、确定性渲染和程序门禁的骨架，但实时 API 与更多稿件迁移尚未完成验证。因此当前不能把一次由维护者临时调整出来的漂亮 PPT 当作产品流程已经成立。

《为什么做 PPagenT》v0.3.0 暴露了一个根本性旁路：视觉运行时调用了没有蒸馏来源的临时结构变体。该版本只保留为失败诊断样本。

这也证明研发审查不能只检查文本、越界和形式合法性：更重要的门禁是正式流程是否只调用核心资产，以及核心资产本身是否忠实于蒸馏来源并达到可长期维护的质量。

当前状态是：**忠实、自适应的视觉蒸馏方法已完成三批验证；v0.6.1 已修正“两个内容块被误判为比较”的语义问题，十五个结构家族已按典型来源重建并通过边界压力测试，正在审计旧候选并继续整理其余来源结构**。

核心库现登记东北大学封面、正文、尾页，以及有真实蒸馏来源的双向对比、基础顺序流程、多角色泳道流程和问题与改进措施。其他结构仍属于备选或实验能力，不得进入正式候选。

第一批候选包括中心辐射、循环闭环、时间轴、层级金字塔和转化漏斗。它们分别支持 3–8、3–6、3–6、3–5、3–6 个结构项，并已完成最小/最大数量真实渲染、逐页目视检查和画布越界检测。候选仍未自动晋升核心；只有进入真实稿件、语义契约成立并经用户确认后，才向视觉导演开放。

第二批候选包括三层组织树、目标与 KPI 映射、鱼骨原因分析、双轨演进路线和研究方法摘要。双轨路线已从旧候选的装饰性交叉曲线纠正为真正共享阶段的两条语义主线。第三批候选包括技术路线流程、分层结论陈述、同心能力系统、文献理论整合框架和全链路运营框架。三批共 30 页边界样本已纳入统一蒸馏审计：最低字号 16 磅，197 个受检几何父对象无重叠或越界，画布无溢出。

第二批还完成了东北大学 Skin 的 10 页嵌入压力测试。结构名称与数量档位只保留在 JSON 和备注中；PPT 可见标题只使用稿件内容，组件不再覆盖 Skin 背景或绘制独立案例页头。关系线已统一使用形状边缘锚点并与形状共用 Skin 坐标变换；鱼骨图进一步加入上下分支关于主骨的可执行镜像约束。该测试使用真实 Skin 正文安全区比例检查字号、重叠、连接、对称、越界和画布溢出。第一批和第三批目前仍只完成独立案例验证，必须补做相同的 Skin 嵌入复核，不能与第二批一起笼统称为可晋升候选。

蒸馏方法已在 `workbench/distillation/结构蒸馏工作流.md` 固化，并由 `npm run distill:audit` 检查来源、语义契约、禁用边界、参数化规则、生成器、案例和渲染证据。旧候选不会因历史上“已经蒸馏”而默认有效，必须经过新方法重审。

v0.6.1 沿用已经跑通的内容与整页编排，并保留第 55 页蒸馏的核心双栏资产，但只允许真正存在共同评价维度、差异、优劣或取舍的内容进入比较家族。第 8 页的“Skin 可替换、能力可复用”是共同支撑扩展边界的互补事实，已改判为 `parallel`；候选生成器因此确定性排除比较资产，只允许东北大学正文资产。页面采用与第 7 页方向相反的文字主张构图，避免连续重复。整套九页在交付前自动检查 35 个几何父对象、最小 16 磅字号、容器内收和碰撞域，结果为零违规。正式运行仍未调用审查 Agent；当前环境没有 API Key，因此双导演继续使用冻结回放。

## 已跑通的主线

产品入口只要求原始稿件和 Skin；测试阶段默认东北大学 Skin。正式产品链路为：

> 原始稿件 → Skin → 内容导演 → `DeckPlan` / `PageContent` → 视觉导演 → `PageIntent` / `CompositionPlan` / `VisualPlan` → 核心资产选择 → `RenderPayload` → 确定性绘制 → `RenderQualityGate` → PPT

内容导演负责整场叙事、章节、顺序、页数、主次、拆分和压缩。视觉导演负责整套视觉语言、单页表达关系、版式选择和页面节奏；不得退化为各页互不知情的独立匹配。程序负责校验、参数映射、Skin、绘制和每次生成必经的确定性质量门禁。两位导演的 API 行为分别由独立执行准则文档约束。

内容审查、视觉审查和人工复核属于当前研发试验环，用于发现系统提示词、规则和核心资产的问题；它们不是产品交付链路中的常驻 Agent。

## 禁止旁路

- 不得在稿件专属生成器中直接写死拆页、资产选择和页面布局。
- 不得跳过匹配器，由维护者直接指定一个“看起来合适”的结构资产。
- 不得只复制学校模板文字页，也不得只调用脱离 Skin 的结构组件。
- 不得把手工修好的 PPT 当作 Agent 已经跑通的证据。
- 不得只逐页选择合法组件而忽略整套 PPT 的视觉节奏和重复。
- 不得通过非等比例压缩把结构组件强行塞入 Skin 安全区。
- 不得让视觉导演选择 `assets/registry.json` 之外的资产或实验变体。
- 不得在某份稿件运行时临时编写结构图；缺少适配资产时必须失败关闭并回到蒸馏流程。
- 不得借用已有资产 ID 包装一个没有对应蒸馏来源的新轮廓。

## 用户确认前仍需满足

- 由用户复核 v0.6.1：第 3 页保留真实比较双栏，第 8 页改为互补事实的文字主张页。
- 由用户复核第一批参数化结构的设计语言；确认后再决定哪些候选进入核心或继续返修。
- 由用户复核第二批在东北大学 Skin 下的十页嵌入样本；确认视觉方向后继续按同一方法处理旧候选。
- 用户指出的问题继续回到通用流程、规则、资产或 Skin 修复，并重跑同一入口。
- 如果核心库缺少所需表达，先从结构样本池选择来源、蒸馏、参数化并登记，再重新运行；不得现场补图。
- 用户确认第一份真实稿件后，再接入实时 API 并用第二份稿件检验迁移能力。

开始新一轮工作前先核对本文。本文只保留当前状态；阶段完成后更新本文，并把已发生的变化写入更新日志。
