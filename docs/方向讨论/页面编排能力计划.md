# 页面编排能力计划

目标与验收标准保持稳定；近期路径依据真实证据动态决定。执行 AI 自主选择方法，重大目标或验收变化需说明并与用户对齐，不能为当前样本降低标准。

## 目标与边界

在大学 Skin＋麦肯锡式下，从稿件形成逻辑完整、表达准确、可读且可编辑的页面。保留内容导演与视觉导演职责，复用已有能力，不提前锁定 PagePlan、Adapter 或 Solver 架构。

以真实整页结果判断能力是否成立。局部机制改进可以记录进展，不能单独关闭端到端能力里程碑。现行架构与入口仍以[产品定义](../产品定义.md)和[正式工作流](../工作流/正式生成/工作流.md)为准，本文只维护能力目标与推进证据。

## 能力里程碑

| 里程碑 | 交付与验收 |
| --- | --- |
| M1 页面策划 | 从论证逻辑决定页面序列、每页职责和核心命题。PPT可审查为何这样讲，来源可追溯；不能以字数或分块覆盖代替合理策划。 |
| M2 信息架构 | 每页命题、信息角色、关系、层级和阅读路径在PPT中明确。结构来自内容关系，不因两组文字就默认双栏；条件、动作和推断边界各有归属。 |
| M3 表达选择 | 依据关系、信息量、数据属性、空间和阅读任务选择文字、表格、结构、技术图示或图表，真实调用与原生可编辑结果可核对；允许不用图示，不为工具改写关系。 |
| M4 视觉编排 | 大学Skin稳定；页面视觉显露论证关系、证据与解释对应，主次、密度和净距合理，最终PPT逐页渲染无明显缺陷。“整齐”或测试通过不足以验收。 |
| M5 自主复现与生产 | 新稿、新上下文能自行完成策划到PPT及有限自修；首轮、自修、外部反馈分开留档。跨稿成立后再接正式入口；无专稿脚本依赖，故障可追踪。 |

里程碑可在同一PPT中交叉取得证据，但任何时刻只有一个主验证问题。内容完整性为M1至M5共同约束，不独占里程碑。只展开近期验证，不预定技术架构、工期或远期步骤。
## 证据与失败

- 机制证据：代码、测试和日志，证明执行机制成立。
- 产物证据：真实 PPTX、渲染与内容核对，证明具体用例成立。
- 独立验证证据：独立复核、新稿或独立上下文复现，检验判断可靠性与适用范围。

三类证据回答不同问题，不机械视为等级。人工复核旧稿不证明跨稿稳定，机制证据不能单独关闭能力里程碑。

失败时保留产物，记录现象、主要原因、判断依据及未知因素；允许多层关联。先诊断，再决定改实现、规则、表达或验证方法，不因单个坏样本立即增加通用规则。暴露边界是验证进展，不是能力通过。

实验闭环是“产物暴露问题→诊断通用提示词或规则→修改→新上下文重新生成PPT”。执行者内部可以多轮自检、反馈与重做；不要求单轮出成品。主任务不把逐页修法注入执行对话，也不将专稿答案包装为通用规则。

## 维护方式

每轮更新当前状态与简短证据索引，详细日志放在产物目录，只回答：试图证明什么；证据支持或推翻什么；什么仍未证明；下一步最值得验证什么。保留首版与修订版，不能用覆盖失败记录制造成功。
