# PPagenT MVP 里程碑与项目进度

2026-09-30 用户对齐。现行路线只有两个大里程碑：**稿件到灰稿；灰稿到成品。** 页面表达与灰稿共用一份契约；灰稿是编译视图和建设检查点。旧流程已归档，不再调度。

## 两大里程碑

| 大里程碑 | 最小通过标准 | 当前状态 |
| --- | --- | --- |
| 稿件到灰稿 | 对真实稿件完成保真读取、分页、页面表达、候选选择、槽位绑定和灰稿编译；用户/Codex 检查页面目的、内容、关系、主次与承载通过 | 未通过；入口、gray-plan-3 与 JEV 布局选择已接入，语义质量和完整闭环待验收 |
| 灰稿到成品 | 消费冻结契约，按 Skin/风格/参数化资产生成原生可编辑 PPTX；内容、关系、页序和槽位保持；完整预览及用户审阅通过 | 未通过；模拟/固定能力已有局部证据，完整受限成稿待验收 |

两段可分别建设、阶段性合并，最后用未参与建设的真实稿件检验连接。测试、回放、日志完整和产物存在都不自动关闭里程碑。

## 新流程的小里程碑

| 顺序 | 小里程碑 | 产物与检查 |
| --- | --- | --- |
| A0 | 参数化资产入库 | 资产说明适用关系、参数、槽位、容量矩阵、拒绝条件、程序入口和原生可编辑证据 |
| A1 | 分页稿成立 | 每页一个主要目的；必要内容、限定、来源和页间关系完整，无静默删件或重复 |
| A2 | 页面表达成立 | 每页有内容 ID、分组/主次/关系、表达类型、候选能力和可解释理由；契约可投影为表单 |
| A3 | 版式/结构选择成立 | 一级页面版式与可选二级结构候选有覆盖；JEV 只选 ID；程序完成区域/槽位绑定和容量检查 |
| A4 | 灰稿里程碑 | 真实文字与结构占位可读；页序、关系、区域、槽位和承载可直接检查；问题能回到责任点 |
| B1 | Skin/风格程序成立 | 视觉 token、页壳、文字层级、间距和结构规则能在声明的样式边界内应用 |
| B2 | 单页结构成品成立 | 同一契约内容进入参数化结构，测量和容量通过，输出原生可编辑对象并通过单页审阅 |
| B3 | 整稿成品成立 | 全部页面输出 PPTX、完整预览、几何/导出证据，内容/关系/页序/槽位指纹保持 |
| C1 | 前后段闭环成立 | 未参与建设的新稿从原稿走到成品；分别报告语义、选择、程序和用户审阅结果 |

**MVP 当前下一交付：**固定一份可读实稿，先把 A1–A4 所需字段在现有 `gray-plan-3` 上跑通并审阅；后段可以用明确标记为模拟的同契约灰稿并行完成 B1–B2。

## 建设和投入使用

建设阶段由用户与 Codex coworker 建资产、规则、程序和检查；main 负责 A1–A4，home 负责 B1–B2，阶段性合并后做 C1。Codex 的视觉能力仅用于建设审阅。

投入使用只包含 DeepSeek v4.1 Flash、JEV 和确定性程序。语义模型负责理解和填充，JEV 在合法候选中判断和选择，程序负责契约、来源、容量、测量、几何、构建和日志。产品不调用 Codex 或视觉模型。

## 稳定性验收

“十次有九次相近”是目标，不是当前结论。按三个比较分开记录：

1. **模型重理解：**固定原稿和要求，多次调用，比较页序、内容、关系和候选。
2. **契约回放：**固定契约、资产和环境，比较绑定、几何、PPTX 和预览。
3. **跨稿闭环：**用未参与建设的新稿检查两段连接和完整质量。

如果分页、主次或容量跨过候选边界，结果可能明显改变；不能用缓存或重复回放代替模型稳定性。
