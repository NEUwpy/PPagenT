# 页面编排能力计划

目标与验收标准保持稳定；近期路径依据真实证据动态决定。执行 AI 自主选择方法，重大目标或验收变化需说明并与用户对齐，不能为当前样本降低标准。

## 目标与边界

在大学 Skin＋麦肯锡式下，从稿件形成逻辑完整、表达准确、可读且可编辑的页面。保留内容导演与视觉导演职责，复用已有能力，不提前锁定 PagePlan、Adapter 或 Solver 架构。

以真实整页结果判断能力是否成立。局部机制改进可以记录进展，不能单独关闭端到端能力里程碑。现行架构与入口仍以[产品定义](../产品定义.md)和[正式工作流](../工作流/正式生成/工作流.md)为准，本文只维护能力目标与推进证据。

## 当前状态

- 当前主里程碑：M1——稿件能被合理编排成页面。
- 当前主验证问题：现有分组与组合流程，能否在不同稿件中保住证据、解读和条件，并形成合理的页面职责与内容组织？
- 已有证据：[P3 试点](../../experiments/content-grouping-pilot/README.md)完成保真实文分组与覆盖检查，经人工复核保留证据与解读关系；表格选型因容量不足回到文本。这是有人参与的单页证据，不是自主分页或跨稿验证。
- 尚未证明：自主分页与页面职责调整、跨稿复现，以及进入结构或图表后仍保持完整内容组织。
- 下一步：阅读当前实现与产物，选择最能检验上述未知的用例，优先暴露能力边界，不以容易成功为选样依据。

## 能力里程碑

| 里程碑 | 完成标准 |
| --- | --- |
| M1：稿件能被合理编排成页面 | 页面职责、论证顺序和内容归属合理；关键事实、条件与边界完整可追溯；能够根据稿件调整分组与分页。 |
| M2：局部表达与整页编排协调成立 | 根据关系、数据和空间选择表达；结构库、技术图示 Skill、图表 Skill 的调用真实且适配；图内外内容共同可读，交付可编辑 PPT。允许不用图示或图表成为正确结果，但不能据此跳过应验证的工具能力；各路径分别记录成熟度。 |
| M3：大学 Skin 下的整页视觉质量成立 | 主次、阅读路径及证据与解释对应清楚；字体、颜色、间距与源结构协调；内容或区域变化时能合理调整，实际 PPT 渲染通过检查。 |
| M4：能力能够跨稿自主复现 | 新稿、独立上下文下完成制作与必要自修，不依赖主任务代写页面或持续逐页指导；分别记录首轮、自修、外部反馈，披露失败与适用边界。 |
| M5：已验证能力进入正式生产流程 | 正式入口可调用已验证能力；内容到产物可追踪，失败能返回适当环节；正常生产不依赖专稿实验脚本，既有能力不退化。 |

允许交叉验证，但任何时刻只维护一个当前主验证问题。其他工作须直接服务该问题，偶然发现的无关问题先记录，不另起建设。只展开最近一个有价值、可验收的推进单元，不预排远期施工步骤或工期。

## 证据与失败

- 机制证据：代码、测试和日志，证明执行机制成立。
- 产物证据：真实 PPTX、渲染与内容核对，证明具体用例成立。
- 独立验证证据：独立复核、新稿或独立上下文复现，检验判断可靠性与适用范围。

三类证据回答不同问题，不机械视为等级。人工复核旧稿不证明跨稿稳定，机制证据不能单独关闭能力里程碑。

失败时保留产物，记录现象、主要原因、判断依据及未知因素；允许多层关联。先诊断，再决定改实现、规则、表达或验证方法，不因单个坏样本立即增加通用规则。暴露边界是验证进展，不是能力通过。

## 维护方式

每轮更新当前状态与简短证据索引，详细日志放在产物目录，只回答：试图证明什么；证据支持或推翻什么；什么仍未证明；下一步最值得验证什么。保留首版与修订版，不能用覆盖失败记录制造成功。
