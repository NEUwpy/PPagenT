# 前半段建设计划：稿件到灰稿

> Plan · 2026-09-30

## 目标

用同一条生成线把一篇完整稿件编译为可检查的灰稿：

`稿件 → 分页稿 → 页面表达契约 → 候选选择与确定性绑定 → 灰稿 → 运行日志 → PPA 工作台`

灰稿是页面表达契约的编译结果，也是建设阶段的直观检查点。表单和灰稿是同一契约的两种投影，不维护两套内容状态。

## 范围

本计划只做第一大阶段：**稿件到灰稿**。

- DeepSeek v4.1 Flash：语义理解、分页、页面表达规划。
- JEV（OpenRouter `~typesafe/jev-latest`）：在程序测量出的合法候选中做窄选择。
- 程序：内容 ID、候选容量、槽位绑定、关系校验、灰稿编译、日志记录。
- Codex 的视觉能力：只用于建设和验收，不进入产品运行时。

第二大阶段“灰稿到成稿”（Skin、字体、具体美化和导出）只保留接口边界，不在本计划实现。

## 共同契约

继续使用当前 `gray-plan-3`，不另造一套表单 Schema。契约至少固定：

- 页：`pageId`、标题、主张、`pagePurpose`、叙事、`sourceIds`、内容组。
- 组：`id`、`role`、`heading`、重要性、`kind`、内容块、表达类型、关系、生产约束。
- 块：稳定 `id`、文本、`sourceIds`、作用域。
- 结构候选：适用关系、输入与槽位、数量和文字容量、合法参数、拒绝条件、可调用实现及验证证据。

页面顺序、页面目的、内容关系、内容 ID、区域和槽位在灰稿检查点冻结；Skin 只处理后半段的风格渲染。

## 里程碑

### A0｜候选资产可调用

**产物**：首批可参数化的版式/结构候选及其容量和适用关系说明。

**通过条件**：候选能被程序测量和调用；不适用、超容量或缺实现时返回明确拒绝，不让模型自由补画。

**边界**：宏观页面版式优先；微观结构可选，不强制两级嵌套。

### A1｜分页稿成立

**产物**：一篇完整稿件的分页稿。

**通过条件**：每页只有一个主目的；页内内容足以说清该目的但不过载；保留原文的条件、程度、否定、时态和来源；所有源内容有去向或明确缺口。

**判断方式**：以语义完整性和候选容量为准，不用统一字数切页。

### A2｜页面表达契约成立

**产物**：每页的 `gray-plan-3` 页面表达：内容组、内容块 ID、主次关系、表达 `kind`、关系、候选要求和选择理由。

**通过条件**：契约可同时投影为表单和灰稿输入；不把视觉细节、Skin 参数或最终像素写进前半段。

### A3｜候选选择与绑定成立

**产物**：每页一个经过测量的候选 ID、关系选择和确定性槽位绑定。

**通过条件**：

- JEV 只回答候选 ID、关系等窄问题，输出是合法枚举或明确拒绝。
- 程序按内容 ID 绑定到槽位，校验顺序、关系、容量、区域和来源。
- 不以换小字体、删内容或任意改关系消除超容量。
- JEV 选不出合法候选时，生成线停在可解释的阻塞状态。

### A4｜灰稿大里程碑

**产物**：含真实文本和必要占位内容的逐页灰稿，以及该次生成的完整日志。

**通过条件**：页序、页面目的、内容关系、来源、区域、槽位和容量可复核；文本可读；灰稿由页面表达契约编译得到；PPA 工作台只从日志和产物呈现状态、输入和输出。

## 贯穿检查点

1. **同线检查**：每次模拟都调用正式生成线的入口；不保留只为演示而存在的旁路。
2. **日志检查**：每个状态点记录输入、输出、状态、错误和产物路径；运行时事件的真实阶段名不得被工作台统一覆盖。
3. **回放检查**：固定输入回放 3 次，比较分页指纹、页面表达指纹、JEV 选择和绑定结果。稳定性是目标，不把“十次九次一样”写成当前结论。
4. **模型边界检查**：语义模型负责理解与规划，JEV 负责窄选择；容量、几何、绑定和拒绝由程序负责。
5. **人工检查**：A4 通过自动检查后，仍需打开真实灰稿核对内容、关系、空白和可读性。

## 建设顺序

1. **先补 A0**：从结构/版式资产中选出首批可测量候选，补齐适用关系、槽位和容量证据。
2. **再跑 A1**：选一篇完整真实稿件，锁定原文和来源，完成分页并记录未决语义问题。
3. **接 A2**：沿用 `gray-plan-3` 生成页面表达；表单只是该契约的编辑/查看投影。
4. **接 A3**：调用 OpenRouter JEV 做候选选择；由 `gray-layout-selection` 和确定性程序完成测量、校验和绑定。
5. **落 A4**：由灰稿编译器输出逐页灰稿；修正事件记录，使日志成为工作台唯一状态来源。
6. **做回放**：同一输入完成固定回放和一篇未调参稿件的端到端检查，再决定是否扩大资产覆盖。

## 现有实现落点

- 语义与契约：`src/runner/gray-semantics.mjs`、`src/workbench/manuscript-normalizer.mjs`。
- 主生成入口与检查顺序：`src/runner/gray-agent.mjs`。
- 候选测量、JEV 选择和绑定：`src/runner/gray-layout-selection.mjs`、`src/runner/gray-layout.mjs`。
- 灰稿编译：`src/runner/gray-draft.mjs`、`src/runner/gray-expressions.mjs`。
- 日志与工作台：`src/workbench/trace-recorder.mjs`、`src/workbench/log-view.mjs`、`src/workbench/gray-run-adapter.mjs`、`src/tools/serve-production-workbench.mjs`。
- 重点验证：`tests/gray-semantics.test.mjs`、`tests/gray-layout-selection.test.mjs`、`tests/gray-agent-flow.test.mjs`、`tests/workbench-log-view.test.mjs`、`tests/gray-run-adapter.test.mjs`。

实施时优先修责任文件，不新增调度器；先让现有入口、契约、JEV 选择、灰稿编译和日志闭环，再扩展候选资产。

## 本轮停止条件

满足 A4 后停止前半段建设，转入用户灰稿检查。以下情况均停在当前节点并记录原因：语义无法确认、来源缺失、无合法候选、容量不足、JEV 返回非法选择、绑定失败或产物不可读。

不在本轮做 Skin 美化、视觉模型产品化、成稿导出、独立部署或旧流程恢复；历史文档和失败证据继续保留为历史资料。
