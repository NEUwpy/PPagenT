# 方向校正

本文用于防止长任务在实现过程中偏离 PPagenT 的主目标。它不重复[产品定义](产品定义.md)；产品边界以产品定义为准，当前优先级以[当前阶段](当前阶段.md)为准，本文负责说明近期取舍和停止条件。

开始长任务前，必须先读这三份文档。若任务要求与本文冲突，先停止并向用户确认，不得把一次技术实验自行升级为项目重构。

## 当前主目标

先在东北大学这一固定场景中证明：用户只提供原稿并选择主题，系统就能以较低运行成本，稳定生成结构清楚、视觉统一、原生可编辑的工作型 PPT。

PPagenT 服务的是数量最多的常规工作型演示，不追求覆盖所有开放场景，也不以每次创造全新视觉为目标。

## 本轮校正

1. **产品验证优先于继续设计架构。** 现有链路已经足以进入真实稿件压力测试。除非真实失败证明现有对象无法表达，否则不新增抽象层、Schema 或 Agent。
2. **建设期设计，运行时调用。** 昂贵的视觉探索、参数化和人工判断尽量在资产建设时完成；正式运行时，模型主要负责内容规划、语义判断、合法资产选择和参数填写。
3. **用能力覆盖率衡量资产库。** 不再把资产数量当进度。新资产应由真实稿件中的高频缺口驱动；Logic 按语义关系组织，一个 Logic 可以包含多个 Structure Group，每组适应已声明的数量和内容 State。
4. **主题与内容能力分层。** 当前已固定 `Shell + Content Frame` 几何：Shell 组织页面骨架，Skin 替换身份与主题值，Structure Group 只在 Content Frame 内表达。完整边界见[Shell 与 Logic 契约](Shell与Logic契约.md)。
5. **HTML/CSS 是 Structure Group 的内部构建表示，不是新产品格式。** 当前用它复现视觉语法并实现响应式数量扩散，再回编译为原生可编辑 PPTX；不因此建设面向任意 PPT 的通用转换器，也不改变 `.pptx` 交付目标。
6. **二层表达暂不进入正式生成。** 父 Structure Group 仍声明真实 Content Slots，但当前只在槽内使用普通文字。以后如果验证一级子 Logic，也不新增 Agent、不改变父拓扑，最大深度仍为 1。
7. **检查保持必要且轻量。** 正式生成只保留确定性的字号、越界、重叠和容量门禁。建设期由维护者和用户看最终页面并纠偏；不为已确认结果重复制造哈希、全状态证据和多轮审查。
8. **产品优先，论文伴生。** 现在不为了论文扩建系统。只在产品运行中顺手保存成本、失败、覆盖率和用户修改等数据，等真实样本形成后再决定是否开展正式研究。
9. **导演只做 AI 擅长的判断。** 内容导演形成版式中立的内容表单；视觉导演像调用 Skill 一样判断 Logic、选择合法 Structure Group 并提供少量语义参数；槽位绑定、State、映射和渲染由程序完成。不得把完整资产合同和内部 ID 重新塞给模型填写。

## 接下来按这个顺序做

### 1. 继续补齐高频 Logic

按能力地图逐项建设，不批量赶数量。每项都经过“多参考提炼 → HTML 黄金状态 → 数量扩散 → 用户确认 → Native 编译”这一条轻量入库线；用户确认 HTML 前不继续做后续步骤。

### 2. 用真实稿件发现缺口

正式生成线已经跑通，接下来用不同工作型稿件检查内容拆页、结构选择、容量和整套节奏。测试与校准流程只读取生产结果，不进入生产线，也不自动修改能力地图或启动入库。若发现原稿需要的 Logic 或 Structure Group 当前不存在，维护者只向用户说明缺口及对应页面；是否建设由用户决定。

### 3. 校准低成本正式运行

继续验证低成本纯文字模型在内容导演、视觉导演和一次受限结构补充中的稳定性，记录失败类型、人工修改和 Token 消耗。目标是形成固定命令和可替换 Provider，不把某个具体模型写成产品前提。

### 4. 暂缓二层结构和论文系统

Content Slots 当前只承载普通文字。一级子 Logic、全面压力测试、论文 benchmark 和复杂用户系统等后续工作，等待一级资产覆盖与正式生成稳定后再决定。


## 长任务开工卡

每个长任务开始前只需明确六件事：

- 本次要验证的一个问题；
- 输入稿件或来源页；
- 允许修改的系统部位；
- 可见产物；
- 完成标准；
- 何时停止并交给用户判断。

默认禁止：顺手重构邻近模块、批量扩资产、增加新的治理层、为低概率风险新增常驻流程、把候选技术写成既定架构。

## 决策状态

### 已确定

- 固定场景优先，东北大学为第一场景。
- 内容导演与视觉导演分工，运行时只调用已验证能力。
- 原生可编辑 PPTX 是交付物。
- 资产按语义关系家族组织，并声明版式扩散范围。
- 父 Structure Group 声明动态 Content Slots；当前正式生成只在槽内使用普通文字。
- 缺少合适结构 Structure Group 时退化为已登记的简单文字 Composition；简单排版仍不成立时再拆页或失败关闭，不现场自由绘图。

### 正在验证

- 更多来源页能否稳定形成忠实、可扩散的 Structure Group。
- 同一 Logic 下多个 Structure Group 是否足以支持视觉导演在整套尺度编排。
- 现有资产对真实工作型稿件的覆盖率。
- 低成本模型在双导演固定 Schema 下的稳定性。

### 暂不开展

- 全面重写渲染运行时。
- 面向所有场景的通用 PPT 生成。
- 大规模继续蒸馏但没有真实缺口依据的资产。
- 为论文提前建设完整 benchmark、训练模型、用户实验或复杂评审系统。
