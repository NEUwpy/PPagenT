# 方向校正：从结构资产建设转向受控编排验证

> 决策日期：2026-09-03<br>
> 阶段性质：结构建设里程碑后的阶段性校正

本文回答“结构建设基本结束以后，PPagenT 应该往哪里走”。产品长期边界见[产品定义](产品定义.md)，当前事实见[更新日志](更新日志.md)，讨论来源见[第四次方向讨论](方向讨论/PPagenT第四次对谈GPT-260903.md)。

## 判断

第四次讨论的核心诊断成立：PPagenT 当前最缺的不是更多完整结构图，而是让已有文字、媒体和结构能力能够在受控空间中组合，并让 AI 对少数复杂页面拥有有限的行动—观察—修正能力。

但讨论中的若干建议仍只是实验假设：Fast／Macro／Agentic 的页面比例尚无代表性数据；具体使用自研 Loop、PenguinHarness、Claude Agent SDK 或其他 Harness 尚未决定；“让模型看一遍截图”是否值得增加成本也需要对照实验。它们不能提前写成产品事实。

## 里程碑判断

35 个正式 Structure Group、18 类 Logic 覆盖、HTML 单源响应布局、Native 编译和资产审查链已经证明“可复用结构能力可以被建设并稳定调用”。这构成第一轮结构资产建设的收官点。

从现在起，结构库默认冻结。只有运行记录反复出现同一种、确由拓扑缺失导致且现有 Structure Group 无法表达的缺口，并经用户明确确认，才重新启动单项入库。资产数量不再是主要进度指标。

## 为什么结构优先不适用于大多数稿件

真实工作稿件的多数页面并不依赖复杂拓扑。它们更常见的表达形态是：

- 一个核心判断，加一段解释或若干证据；
- 两到五个弱关系要点，重点是层级、节奏和留白，而不是连接图；
- 图片、截图、图表或大数字主导，文字负责说明；
- 观点、文字、媒体和一个小型关系结构组成的混合页面；
- 少数页面确实依赖流程、层级、因果、循环、矩阵、分支或网络等拓扑。

把前三类也强制归入 Structure，会造成内容被压缩成字段、结构为了出现而出现、视觉选择重复，以及“有 35 个结构却仍无法自然承载普通稿件”的假繁荣。

因此，Structure 不再是默认页面骨架，而是拓扑语义明确时调用的高级 Macro。简单并列通常由 Grid／Stack 等 Composition 配合 Text 表达，不需要伪装成结构图。

## 目标形态：受控视觉语法上的有限代理编排

PPagenT 的稳定资产分为四层：

| 层 | 作用 | 决策边界 |
| --- | --- | --- |
| Skin／Shell | 组织身份、标题区、页脚、Content Frame | 程序和已登记主题决定 |
| Composition | Stack、Split、Grid、Rail、Hero、受限 Overlay 等空间运算 | AI 在合法参数内选择，程序求解 |
| Expression | Text、Media、Structure Macro | AI 绑定内容并选择表达 |
| Primitive／Compiler | 文本、形状、线、图像、SVG 与 Native PPT 对象 | 程序确定性执行 |

`PageExpressionPlan` 的目标定位是由运行时逐步形成并持续校验的页面状态，不要求模型一次输出一份巨型、脆弱的最终 JSON。每个动作只修改小范围状态，程序立即验证引用、容量和区域合法性。

Harness 只是操作 PPagenT Domain API 的可替换驾驶层，不是产品核心。无论最后接入哪个模型或框架，Skin、Composition、Expression、资产契约、HTML Renderer、Native Compiler 和 Quality Gate 都必须保持独立。

## 三条执行路径

1. **Direct Path**：核心观点、普通段落、弱关系枚举和简单图文页，由确定性 Composition + Text／Media 直接完成；原则上不启动视觉代理循环。
2. **Macro Path**：稿件明确包含拓扑语义，程序筛出合法 Structure Macro；唯一候选可锁定，多候选只做小范围选择和参数绑定。
3. **Agentic Path**：同页有多种表达、区域互相制约或首次编排无法确定时，才启动有限代理。代理通过小工具查看内容、选择 Composition、放置表达、预渲染和校验；动作、渲染和修复次数均有上限，超限退回合法的 Direct Path。

这三条路径是目标架构，不是当前已实现功能。它们各占多少比例必须由真实运行日志得出，不能凭讨论预设。

## 近期只验证五件事

1. 建立少量 Composition Operator，使 Text／Media／Structure 都能进入同一 Region，而不是继续制造整页模板。
2. 将现有 `PageExpressionPlan 0.1` 作为候选运行时状态继续演化，定义 6–8 个最小、可验证的 Domain Action；不先接重型 Harness。
3. 选择普通文字页、明确拓扑页和复合图文页组成小型代表集，对比当前单次视觉决策与有限代理编排。
4. 记录最终成功率、fallback、人工偏好、动作数、模型调用、token、耗时、页面重复和 Structure 实际使用，不预设三条路径比例。
5. 只有小实验显示质量收益足以覆盖复杂度和成本，才把 Agentic Path 接入正式线；否则保留 Direct／Macro 两条确定性路径。

## 停止条件

- 不再批量扩 Structure Group，也不以填满 20 类 Logic 为目标。
- 不把普通并列、段落或大数字包装成新的 Logic。
- 不把任意 HTML、自由绘图或模型生成整页代码带入正式生产。
- 不因一次实验同时重写内容导演、视觉导演、Renderer、Compiler 和看板。
- 不为适配某个 Harness 改写 PPagenT 领域对象；Harness 必须可替换。
- 不恢复反复重试、全状态穷举、哈希链和多 Agent 审查等重流程。
- 不把候选 Schema、原型或实验数据描述成已发布能力。

## 决策状态

### 已确定

- 固定组织场景、原生可编辑 PPTX 和确定性质量门禁保持不变。
- Structure 只在拓扑本身承载语义时使用，现有正式资产继续作为高价值 Macro。
- 大多数页面应由 Composition + Text／Media 表达，Structure 使用率不是越高越好。
- 复杂页面可以探索有限代理编排，但必须在受控视觉语法和明确预算内运行。
- 结构资产建设默认冻结；新增资产仍需用户批准。

### 待验证

- 代表性稿件中三条路径的真实分布。
- 哪些 Composition Operator 足以覆盖大多数普通页面。
- 有限代理相对当前单次视觉决策的质量、成本和失败率收益。
- 文本模型是否只靠确定性指标即可完成修复，哪些页面值得增加一次视觉观察。
- 自研轻量 Loop 是否已经足够；第三方 Harness 只在实验需要时比较。

### 暂不开展

- 继续全面扩建结构库；
- 面向所有场景的通用 PPT Agent；
- Harness 选型或框架迁移；
- 完整2+3架构的一次性大重构；
- 为论文提前建设大规模 benchmark 或复杂治理系统。
