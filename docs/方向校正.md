# 方向校正

本文用于防止长任务在实现过程中偏离 PPagenT 的主目标。它不重复[产品定义](产品定义.md)；产品边界以产品定义为准，当前优先级以[当前阶段](当前阶段.md)为准，本文负责说明近期取舍和停止条件。

开始长任务前，必须先读这三份文档。若任务要求与本文冲突，先停止并向用户确认，不得把一次技术实验自行升级为项目重构。

## 当前主目标

先在东北大学这一固定场景中证明：用户只提供原稿并选择主题，系统就能以较低运行成本，稳定生成结构清楚、视觉统一、原生可编辑的工作型 PPT。

PPagenT 服务的是数量最多的常规工作型演示，不追求覆盖所有开放场景，也不以每次创造全新视觉为目标。

## 本轮校正

1. **真实失败已经证明需要调整表达模型。** 两份历史稿件验证表明，“一页一个 Logic／Structure Group”的对象无法稳定表达一页同时包含多个关系、文字和媒体的复合内容，因此下一阶段正式进入2+3表达改造；不因此新增 Agent，也不把改造扩成通用自由绘图系统。
2. **建设期设计，运行时调用。** 昂贵的视觉探索、参数化和人工判断尽量在资产建设时完成；正式运行时，模型主要负责内容规划、语义判断、合法资产选择和参数填写。
3. **用能力覆盖率衡量资产库。** 不再把资产数量当进度，以“最小重叠、最大覆盖”为资产优化目标：既覆盖常见 Logic，也覆盖 Logic 内真正不同的表述方式，并尽量让一个 Structure Group 适配更多数量、层数和内容状态。只有不可替代的语义拓扑才新增组，被通用组覆盖的近似候选应合并或退出。详细判定按[资产积累与入库工作流](工作流/资产积累与入库/工作流.md)执行。
4. **主题与内容能力分层。** 当前已固定 `Shell + Content Frame` 几何：Shell 组织页面骨架，Skin 替换身份与主题值，Structure Group 只在 Content Frame 内表达。完整边界见[Shell 与 Logic 契约](Shell与Logic契约.md)。
5. **HTML/CSS 是 Structure Group 的内部构建表示，不是新产品格式。** 当前用它复现视觉语法并实现响应式数量扩散，再回编译为原生可编辑 PPTX；不因此建设面向任意 PPT 的通用转换器，也不改变 `.pptx` 交付目标。
6. **采用2+3表达边界。** 页面可以组合 Structure、Text、Media 三种表达；一级 Structure 可以承载二级 Structure、Text 或 Media，二级 Structure 不得继续嵌套 Structure。页面根节点不计入结构深度。背景、边框和色块属于 Surface，不构成第四种内容表达。
7. **检查保持必要且轻量。** 正式生成只保留确定性的字号、越界、重叠和容量门禁。建设期由维护者和用户看最终页面并纠偏；不为已确认结果重复制造哈希、全状态证据和多轮审查。
8. **产品优先，论文伴生。** 现在不为了论文扩建系统。只在产品运行中顺手保存成本、失败、覆盖率和用户修改等数据，等真实样本形成后再决定是否开展正式研究。
9. **导演只做 AI 擅长的判断。** 内容导演形成“核心信息 + 内容块 + 块间关系 + 块内 Logic”的版式中立内容稿；视觉导演像调用 Skill 一样决定 Structure、Text、Media 的组合、两层嵌套、合法资产与展示性派生；区域求解、State、坐标、字号、映射和渲染由程序完成。不得把完整资产合同和底层几何重新塞给模型填写。

## 接下来按这个顺序做

### 1. 固化2+3表达契约并做 HTML 最小验证

先以固定内容验证整页多表达、Structure 最多两层嵌套、统一 Markdown TextRegion、Media 和 Surface 的组合方式。首批覆盖“1+3+N 复合系统”“截图 + 解释 + 结论”“核心观点 + 多项支撑”。先在 HTML 工作台确认，不在确认前生成 Native/PPT 或修改正式资产状态。

### 2. 建立区域契约与确定性求解

在现有 TextRegion、Markdown Renderer 和 Content Slot 基础上定义兼容的 ExpressionRegion，登记允许表达类型、真实矩形、自然／最小尺寸、容量和叠加策略。程序先支持同级多表达，再支持一级 Structure 内嵌二级 Structure；不允许低于最低字号、越界、裁切或未经声明的遮挡。

### 3. 改造双导演数据契约

内容导演从“每页一个 Logic”改为输出核心信息、多个内容块、块间关系和块内 Logic；视觉导演输出稀疏的整页表达方案，并为压缩、合并、概括保留来源引用和派生类型。具体 Schema 字段名在实现前确认，正常生产仍以内容导演一次、视觉导演一次为基线。

### 4. 用历史稿件做最小回归后再接正式线

先复用已经暴露问题的历史稿件，验证多 Logic 页面不再被压成单一并列结构，并记录内容覆盖、表达树、派生文字、区域失败、fallback 和 API 调用次数。通过前不把2+3描述为已经进入正式生产；全面 benchmark、复杂用户系统和论文工作继续暂缓。


## 长任务开工卡

每个长任务开始前只需明确六件事：

- 本次要验证的一个问题；
- 输入稿件或来源页；
- 允许修改的系统部位；
- 可见产物；
- 完成标准；
- 何时停止并交给用户判断。

默认禁止：顺手重构邻近模块、批量扩资产、增加新的治理层、为低概率风险新增常驻流程、把候选技术写成既定架构。

## 决策状态

### 已确定

- 固定场景优先，东北大学为第一场景。
- 内容导演与视觉导演分工，运行时只调用已验证能力。
- 用户上传和 Codex 代为提交必须进入同一个正式生成工作台；Codex 不绕过工作台扮演导演，具体入口边界见[正式生成工作流](工作流/正式生成/工作流.md)。
- 原生可编辑 PPTX 是交付物。
- 资产按语义关系家族组织，并声明版式扩散范围。
- 页面采用 Structure、Text、Media 三种表达，Structure 最多两层；TextRegion／受控 Markdown／Renderer 作为统一文字能力，旧 Text Layout 仅保留正式资产兼容。
- 内容导演输出页面核心信息、内容块、块间关系和块内 Logic；视觉导演负责把这些内容组织为合法表达方案。
- 展示性压缩、合并和概括必须保留内容引用、派生类型并进入运行日志。
- 结构性页面缺少合适 Structure Group 时保留原 Logic 和 `asset-gap`，不硬套相近结构，也不现场自由绘图；该页允许退回通用正文以完成正式交付，但退回事实必须在运行结果中逐页暴露，并说明需要给哪个既有 Logic 补充哪类 Structure Group。

### 正在验证

- 更多来源页能否稳定形成忠实、可扩散的 Structure Group。
- 同一 Logic 下多个 Structure Group 是否足以支持视觉导演在整套尺度编排。
- 现有资产对真实工作型稿件的覆盖率。
- 低成本模型在双导演固定 Schema 下的稳定性。
- 候选 `PageContentBlocks 0.1 / PageExpressionPlan 0.1` 已用 `contentBindings / regionKey / children` 跑通固定内容 HTML；字段是否足以迁移到通用 ExpressionRegion 与正式双导演仍待用户审查后确认。
- 同级多表达和两层 Structure 的确定性区域求解效果。

### 暂不开展

- 全面重写渲染运行时。
- 面向所有场景的通用 PPT 生成。
- 大规模继续蒸馏但没有真实缺口依据的资产。
- 为论文提前建设完整 benchmark、训练模型、用户实验或复杂评审系统。
