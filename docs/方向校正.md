# 方向校正：结构建设结束后的下一阶段

> 更新日期：2026-09-04

本文只记录当前阶段事实、已发现问题、能够确定的方向和仍需验证的可能性。产品长期边界见[产品定义](产品定义.md)，代码与资产现状见[更新日志](更新日志.md)。

## 当前状态

- 已跑通 `原稿 → 内容导演 → 视觉导演 → 核心资产 → HTML布局 → Native PPTX`。
- Shell、Content Frame、资产看板和生产工作台已经形成稳定基础。
- 正式库现有 35 个 Structure Group，覆盖 20 类 Logic 中的 18 类。
- 当前正式视觉流程仍以“一页一个主 Logic／Structure Group／Composition”为主；没有合法结构时使用已登记正文排版兜底。
- 多表达页面、通用区域组合和反馈式视觉编排仍是实验能力，没有进入正式生产。

第一轮 Structure Group 集中建设到此基本结束，结构库默认冻结。新增结构必须来自重复出现、确由拓扑缺失导致的真实问题，并继续由用户确认。

## 当前问题

现有路线把结构图放得过重。真实工作稿件中，大量页面只是：

- 一个观点加解释或证据；
- 几个弱关系要点；
- 图片、截图、图表或大数字加说明；
- 文字、媒体和小型关系结构的组合。

这些内容不需要完整结构图。强行套 Structure 会压缩原稿、制造重复版式，也不能真正提高适用性。

当前 AI 主要负责分类和填写一次性表单。它能够选择资产，但缺少对页面结果进行小范围调整的能力；继续增加 Schema、重试和补丁只会让流程更重。

## 已经确定的方向

1. PPagenT 继续服务固定组织场景，交付原生可编辑 PPTX；不转向自由绘图或任意网页转 PPT。
2. Structure Group 保留为拓扑本身承载语义时使用的高级 Macro，不再承担所有页面。
3. 下一阶段重点是 Composition、Text 和 Media，使普通页面能够通过少量可复用空间规则自然表达。
4. HTML 继续作为受控布局真源，Native 编译和确定性质量门禁保持不变。
5. 当前正式生成线继续保留。新方案先在旁路做最小实验，证明有效后才替换对应环节。
6. 候选资产不得自动晋升；不恢复全状态穷举、反复哈希和多层审查。

## 需要进一步探索

下一步只探索一个问题：复杂页面是否需要“执行一个小动作、查看结果、再调整一次”的反馈闭环，以及这种闭环是否比当前一次性视觉输出更稳定。

最小实验应复用现有内容对象、Composition、Structure Group、HTML Renderer 和质量门禁，不建设第二套系统。`PageExpressionPlan 0.1` 可以作为候选页面状态，但最终字段由实验决定。

实验只需覆盖普通文字页、明确拓扑页和复合页，并比较：

- 内容是否完整、关系是否正确；
- 页面是否通过字号、边界和重叠检查；
- 人工视觉判断是否改善；
- 调用次数、Token、耗时和 fallback 是否可接受。

只有结果证明反馈闭环的收益明显高于复杂度，才继续研究 Harness、视觉截图反馈和更完整的多表达区域；否则就以确定性 Composition + Structure Macro 为主线。

## 当前不决定

- 不决定使用哪一种 Harness 或模型 SDK；
- 不预设普通页、结构页和复杂页各占多少；
- 不预先固定动作数量、工具名称和完整 Schema；
- 不一次性实现完整2+3、多层 Structure 或视觉模型审查；
- 不继续批量扩建 Structure Group。
