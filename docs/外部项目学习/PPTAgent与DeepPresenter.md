## 核心判断

它已经实现了完整的 PPT 生成系统，但目标与 PPagenT 不同：它追求通用生成和视觉自由度，PPagenT 追求固定场景中的稳定复用。它不能替代 PPagenT，但能够提供参考页分析和主题工程方面的创意。

## 它怎么做

仓库包含两代路线：

1. 论文版 PPTAgent 分析参考 PPT，聚类页面功能和版式，提取内容 Schema；生成时先规划大纲，再选择参考页并增删、替换或复制元素。
2. 当前主线 DeepPresenter 使用 Research、Planner、Design/PPTAgent 等角色。Design 路线先建立全局 CSS，再逐页生成固定画布 HTML 并检查。

其提示词的核心并不复杂：确定全局样式；根据内容使用多栏、Z/F 型或海报式布局；按图片比例调整构图；每次生成一页。美感主要来自模型能力、参考素材和 HTML/CSS 布局自由度。

## 效果证据

论文在 500 个任务上报告：

- Qwen2.5 + Qwen2-VL 成功率 `95.0%`，GPT-4o 配置 `97.8%`。
- 设计评分约 `3.27/5`，高于规则基线 `2.37` 和模板基线 `2.95`，低于人工演示 `3.95`。
- 去掉内容 Schema 后成功率从 `95.0%` 降至 `78.8%`。
- 去掉大纲或结构页分析后，连贯性从 `4.48` 降至 `3.36/3.45`。

这些数据证明“分析参考页 + 结构化规划”有效，但论文也承认仍会失败、检索能力有限，并可能因为缺少精细视觉定位而出现重叠。以上是官方论文结果，尚未在 PPagenT 本机复现。

## 与 PPagenT 的差异

| 方面 | PPTAgent / DeepPresenter | PPagenT |
|---|---|---|
| 目标 | 尽量生成任意主题、任意风格的演示 | 先稳定服务一个固定场景 |
| 视觉来源 | 任意参考页或模型自由设计 | 固定主题与已确认的参数化资产 |
| AI 权限 | 可直接修改或设计页面 | 理解内容并从合法能力中选择 |
| 建设成本 | 单次生成仍需较多模型工作 | 前期建库较重，后续重复生成较轻 |
| 主要优势 | 自由度、图片利用和视觉变化 | 稳定、规范、可复用和低边际成本 |
| 主要风险 | 质量依赖模型与参考页，可能重叠 | 覆盖不足时规整有余、漂亮不足 |

## 已作出的决定

| 内容 | 决定 | 理由 |
|---|---|---|
| 参考页的功能与内容 Schema 分析 | 已吸收首轮机制 | 正式 VisualPlan 已增加独立 Page Role，并把候选真实预览交给视觉导演；来源页自动聚类仍待资产蒸馏实验 |
| 把主题做成类似 CSS 的设计系统 | 待验证吸收 | 与固定场景路线一致；主题应承载字体、字号、色彩、版心、间距、Logo 和基础版型 |
| 每次生成临时发明一套视觉方案 | 不采用 | PPagenT 的视觉方案就是选定主题，不应重复设计 |
| 自由 HTML 作为 PPT 中转或正式输出 | 暂不采用 | 当前不值得增加 PPT—HTML—PPT 转换链路 |
| 任意参考页直接用于正式生成 | 不采用 | 会绕过核心资产的蒸馏、参数化和用户确认 |
| 每页默认进行多轮模型视觉检查 | 不采用 | 首轮只看候选预览；正式交付仍由暂存 Native PPT 人工确认，不增加逐页自动重试 |
| 避免为假想问题堆积工程复杂度 | 已吸收 | 与 PPagenT 当前轻量化方向一致 |

## 可做的小实验

### 实验 PA-01：参考页分析是否改善蒸馏

- 选择一张准备蒸馏的来源页。
- 现有做法与“功能 + 内容 Schema + 视觉关系”分析各形成一个资产方案。
- 只生成主要数量状态下的对照页，由用户判断哪一个更忠实、更好用。

### 实验 PA-02：主题规则是否改善单页排版

- 选择现有真实稿件的一页。
- 内容和资产不变；基线使用当前主题，优化页只增加从 CSS 主题体系提炼出的明确排版变量。
- 由用户比较重点、层级、留白、平衡和场景一致性。
