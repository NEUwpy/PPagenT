## 共同规律

这些项目的有效部分不是“多准备几个模板”，而是把整套编排拆成四层：

1. 先判断页面在整套叙事中的功能，而不是从 Logic 直接推出版式；
2. 先规划全套疏密、重心、连续段和转折，再做逐页选择；
3. 用少量 Composition Family 管理变化，避免所有正文退化为同一种卡片网格；
4. 用可核对的逐项规则检查结果，不只依赖一个笼统美观分数。

PPTAgent 的重点是从人类参考稿中归纳功能页与内容 Schema；SlideSpeak 在 planDeck 阶段明确处理 presentation type、audience、density rhythm 和 variance；DeepPresenter 强调先建立全局视觉系统，再让生成结果接受环境中的视觉反馈；PresentBench 使用针对具体任务的细粒度二元检查项，而不是只做整体打分。

## PPagenT 已吸收

| 外部实践 | PPagenT 落点 | 边界 |
| --- | --- | --- |
| 功能页先于版式 | 每页新增独立 `pageRole` | 不改变内容导演已确定的 Logic |
| 整套密度节奏 | `densityTarget`、`visualWeight`、锚点页、安静页 | 不用密度目标删减事实 |
| Composition Family | 视觉导演从候选 `compositionOptions` 选择具体 Composition；程序回算 Family | 只选已登记 Composition，不自由生成 HTML |
| 连续与转折 | `continuityGroup`、`contrastBreakBefore` | 连续复用允许存在，但必须可解释 |
| 视觉反馈 | 视觉模型读取核心候选预览；研发重试可读取上一轮整套渲染 | 预览文字不得成为当前稿件事实 |
| 细粒度评价 | 三连同构、家族占比、密度平坦、缺少锚点、卡片化占比五类审计 | 只有合法替代存在时才把同构记为可避免问题 |

## 明确不照搬

- 不采用每页自由生成 HTML／CSS 作为正式页面事实源；
- 不让视觉模型创造仓库中不存在的 Structure Group；
- 不为追求变化强行跨 Logic、改写关系或补造内容；
- 不以自动整体美观分替代 Native PPT 的确定性门禁和人工确认；
- 暂不引入自动图片生成、自由媒体检索或新的常驻 Agent。

## 当前证据与待验证

- 已确认角色级视觉模型配置、图片消息、日志脱敏和真实 API 连通性；视觉模型成功识别一个核心 Structure 预览。
- 已确认缺少现成 PNG 的资产可从 `example.pptx` 按需生成 Git 忽略的缓存预览。
- 相关 Provider、候选预览、视觉路由、节奏、人工检查点和工作流测试 75/75 通过；规则契约与公开资产审计通过。
- 尚未用一份新长稿完成“旧视觉导演 vs 新视觉导演”的同内容 A/B。因此只能确认机制已接通，不能宣称整套审美已经改善。

下一次真实实验保持内容稿、Skin 和资产库不变，只比较新旧 VisualPlan 的 Composition Family 分布、锚点／安静页、三连同构、卡片化占比和最终人工判断。
