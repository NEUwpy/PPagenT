## 深读一：Paper2Poster / PosterAgent（3.9k stars，NeurIPS 2025）

任务定位：**多模态上下文压缩**——把 20k+ tokens 的论文压成一张可读海报（作者设计稿的压缩比：文字约 14.4×，图约 2.6×）。

三大部件：

1. **Parser（全局组织）**：Marker/Docling 把 PDF 转 Markdown → LLM 生成 JSON 式提纲 → **结构化资产库**：
   - 文本资产：**键=章节标题，值=段级摘要**（"像人第一眼关注章节标题"的层级）
   - 视觉资产：**键=图表题注，值=提取出的图片文件**
   - 这是一次**粗粒度压缩**：保留语义骨架、大幅缩体积，供后续反复迭代。

2. **Planner（局部组织）**：
   - **资产匹配**：LLM 把每个视觉资产语义对齐到最相关章节 → 得到 (章节, 图) 对。
   - **二叉树布局**（关键）：作者明确写了"**LLM 直接预测数值坐标不稳定**"，所以改为——
     把整页画布当一个矩形，**按内容长度估算递归二分**（先左右、再上下……），每一步都保持**阅读顺序**与**宽高比**，直到每个叶子节点对应一个面板（章节）。比例来自内容量（词数、图大小）。
     → 效果：永远填满画布、支持嵌套层级、坐标由程序算而不是模型猜。
   - **面板迭代**：逐节把概要再压成**分层要点**（hierarchically structured bullet points），逐个面板填充。

3. **Painter-Commenter（局部精化）**：
   - Painter = LLM（提炼要点）+ **确定性代码生成器**（python-pptx + 预定义 helper）→ 渲染草案图。
   - Commenter = VLM 看渲染图反馈（"overflow / too blank / good to go"）→ 迭代直到通过或达上限。
   - 防 VLM 幻觉：**zoom-in**（只看该面板区域）+ **in-context 两条示例**（一条严重溢出、一条理想布局）。

评估：VLM 六维评分（元素质量/布局平衡/吸引力/清晰度/内容完整/逻辑流）+ PaperQuiz（用 VLM 读者答题衡量信息传达）。
重要结论：**小模型（Qwen-7B）方案超过 GPT-4o 基线**，归功于 ①结构化多步压缩 ②清晰、有阅读顺序的布局。

## 深读二：HKUDS Paper2Slides（内容规划提示词全文）

四阶段：RAG 索引 → Analysis（结构/图表提取）→ Planning → Creation。规划器 `prompts/content_planning.py` 要点：

- **两种模式**：
  - 学术论文：套固定叙事骨架——封面 / 背景与问题 / 方法（**可跨多页**）/ 结果与实验（**可跨多页**）/ 结论；
  - 通用文档：不套骨架，要求"**识别文档自身的结构并跟随它**"（Identify the document's own structure and follow it）。
- **每页输出**：`{id, title, content, tables[], figures[]}`——content 是"最重要字段"，整段文字；表格/图带 ID 与 focus（突出什么）。
- **保真与质量要求**（提示词原话）：从摘要改写道（COPY FROM SOURCE）；**不许过度简化成模糊的一句话**；**每页内容最少 150–200 词**；保留关键公式（LaTeX）与具体数字；表格只抽取相关行列但**必须是真实数值**。
- **密度档**：sparse / medium / dense 三档控制保留程度（对应我们的"详略"）。
- 特点：页级规划（标题 + 整段内容 + 配图配表），**页内不再细分结构**；排版交给后续 image_generator 整页生成。

## 深读三：AutoPresent（Berkeley，CVPR 2025）

- 幻灯片生成 = **程序生成**：模型输出 python-pptx 程序 → 执行得到 PPTX（非图像、非模板填充）。
- **SlidesLib**：高阶函数库（add_title 等 4 个基础 + search_image/generate_image 等 3 个图像函数），把平均程序长度从 170 行压到 13 行——**给模型趁手的工具比让它写底层代码有效**。
- **迭代精化**：第二轮把"原指令 + 程序 + 渲染快照"给模型，让它改（颜色、间距等）；实验显示能提升质量。
- 结论：程序生成优于端到端图片生成；小模型（8B 微调）接近 GPT-4o。

## 对我们（灰稿/内容规划）的启示

1. **中间表示要有层级**：他们的资产库是"章节标题→摘要"的字典 + 图文配对；我们的来源是平铺段落（s1/s2/s3），页面是平铺的组→块。**"大类结构套结构"的落点**：给规划加一层"章节/论点层级"，页面组与块挂在层级下，而不是平铺。
2. **布局用递归而不是平铺**：PosterAgent 的二叉树（按内容量递归二分、保持阅读顺序）正对我们"一块一块卡片"的机械感；LLM 只给**层级约束**，程序按实文测量解面积——与我们"不预测坐标"的路线一致，差别在**递归嵌套**（我们目前 single/row/column/grid 只有一层）。
3. **通用与细分可以并存**：HKUDS 的做法回答了"要不要按稿件类型细分"——**学术用固定叙事骨架（大类），通用文档用"识别自身结构"（通用规则）**。两种都靠同一套机制（结构提取 → 页级规划 → 生成）。
4. **内容保真要求可直接借鉴**（HKUDS 措辞）："不要过度简化成模糊的一句话"、"每页最少 150–200 词"、"表格抽取真实数值"、密度档位。
5. **视觉反馈回路**：Commenter（VLM 看渲染图，修溢出/空白）+ zoom-in + in-context 示例——我们有现成视觉模型，是性价比最高的一步自动化质检。
6. **局部修订**（MemSlides）：反馈只改最小受影响区域，不重写全稿——与我们"媒介档/视觉档"的边界一致。

## 观察到的共同点（跨项目）

- 都不让模型直接猜坐标；坐标由程序按内容量计算。
- 都先把文档"理解成结构"（章节/资产/树），再做页面。
- 都有"渲染 → 检查 → 修订"的循环（只是检查方式不同：VLM 看图 / QA 回路 / 验证智能体）。
- 内容压缩是显式目标（保留数字、公式、关键限定，砍冗余），不是简单摘要。
